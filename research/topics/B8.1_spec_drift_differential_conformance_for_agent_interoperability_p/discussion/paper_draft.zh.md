## 摘要（Abstract）

诸如模型上下文协议（Model Context Protocol, MCP）与 Agent2Agent（A2A）这样的
agent 互操作协议（agent-interoperability protocols）正在成为跨厂商工具调用与任务
委托的基础底座，并以月度节奏持续修订。人们通常假定一次协议修订会把生态系统干净地
从一个版本迁移到下一个版本，从而"符合 MCP vX"在整个过程中始终是一个可用的安全标签。
我们指出这一假定掩盖了一种未被检验的可能性：一台正在跨越规范性条款（normative
clause）修订进行迁移的已部署服务器，可能在一段可测量的时间区间内，既不符合旧版本
也不符合新版本——即一个**发散窗口**（divergence window）——并且在该窗口内，该条款
所约束的权限（authority）约束可能从*强制执行*（enforced，服务器拒绝未授权动作）
静默降级为*仅可见*（visibility-only，约束只是被通告，而动作仍然成功执行）。这一
安全退化是任何单版本一致性检查（single-version conformance check）与任何静态框架
审计（static framework audit）都无法捕获的，因为它只存在于版本*之间*、只出现在线
路（wire）层面。我们构建了一套差分一致性（differential conformance）测量装置：对
相邻规范版本之间的每一条规范性条款差量（normative-clause delta），我们合成一对匹配
的线路探针（wire-probe pair），该探针对必须先被证明能够区分两个钉定（pinned）的参考
实现，才允许给任何在线服务器打上"两者皆不符合"（neither）的标签；我们以非破坏方式
见证权限执行——读取服务器在授权边界（authorization boundary）上的接受/拒绝决策，
而不是真的执行未授权动作；我们用未变更条款安慰剂（unchanged-clause placebo）把漂移
引发的发散与一般性不一致区分开；并用区间删失生存估计（interval-censored survival
estimation）在对公开服务器目录的固定节奏纵向扫描上估计每个窗口的时间宽度。我们测量
发散窗口的普遍程度与宽度、权限到可见性降级（authority-to-visibility downgrade）的
普遍程度，以及二者如何按条款差量类型集中分布——并讨论这对一个问题意味着什么：agent
协议的一致性审计是否必须是版本差分且持续的，而不是单版本、一次性的。

## 引言（Introduction）

agent 之间的互操作如今运行在公开发布的协议之上。随着大语言模型 agent 被委托代表
委托人执行工具调用、资源访问与跨厂商动作，模型上下文协议（MCP）与 Agent2Agent
（A2A）已成为这些委托所经由的线路格式（wire format），而越来越多的安全与治理推理
建立在服务器所宣称的、对某个具名协议版本的符合性之上。按此框架，"符合 MCP
v2026-07"实际上承担了安全标签的职能：客户端、网关或运营者在决定给予一台服务器多少
信任时，部分依赖于这一标签。这个标签声明起来廉价、依赖起来容易——这正是它值得被
检验而非被默认的原因。

然而这些协议的修订速度，快于已部署服务器可被期望的同步跟进速度。MCP 于 2026-07-28
发布了一个候选版本（release candidate）；A2A 于 2026-05 扩展了其 1.0.1 线；每次
修订都会改变一组规范性（RFC-2119 MUST / SHALL / SHOULD）条款。默认的假定是修订会把
生态系统从版本 N 干净地迁移到 N+1。但一台已开始采用 N+1 却尚未完全放弃 N 的服务器
——或者对某条被修改的条款只实现了一半的服务器——可能在一段区间内，在该条款上*两个*
版本的要求都不满足。在该区间内，每一个与它协商的客户端都在与一种任何已发布规范都
未描述的行为进行互操作。而降级后果最严重的正是*权限*条款：某条在一个版本中要求
服务器*拒绝*未授权工具调用的条款，可能在迁移中途降级为该约束仅仅被*通告*——出现在
能力描述符（capability descriptor）或错误信息里——而未授权调用依旧成功。这是一次
安全退化，并且对当前领域仅有的两类检查均不可见：单版本一致性测试从不与*另一个*
版本比对，静态框架审计从不在一次真实迁移期间触及线路。

最接近的现有工作从相邻但不同的角度切入这一空白。最接近的是规范侧的一致性检查路线，
它把协议规范编译为带类型的中间表示（typed intermediate representation）、进行模型
检查（model checking），并把反例回放到 SDK 中；它认证的是*规范本身*而非已部署的
机群，其分析是单版本的，且其工件（artifact）因协同披露（coordinated disclosure）
被扣留，因此不存在可复现的部署侧检查可供借力。一簇部署侧测量研究——对远程 MCP
服务器的认证安全普查、一项大规模运行时服务器研究、以及一项对暴露于公网的服务器的
动态安全评估——表明对已安装基础做线路级测量是可发表且有信息量的，但它们都是单版本
且对一致性视而不见的：没有条款差量（clause-diff）、没有发散窗口概念、没有以服务器
为单位的时间轴。其中最接近的一项测量了已部署 MCP 服务器的描述-代码不一致
（description-code inconsistency）——服务器所*通告*的可以偏离其代码实际所做的——
但那是静态的、单版本内的，没有随时间的执行状态迁移。在安全侧，一条工作线确立了
能力*可见*（visible）不等于被*授权*（authorized），另一条提出以一组固定的安全
不变式（security invariants）替换执行层；二者都在框架或设计层面运作，都没有在
线路上、在已部署服务器上、跨一次修订去测量某个权限约束的执行是否真的发生了变化。
还有一支论证型工作把这些协议*无法表达*的内容编目成一个断言式的缺口矩阵，而非对照
已部署行为测量出来的矩阵。

把这个问题变成可测量的问题会暴露它自身的困难。规范性条款是一句散文（prose），
因此要判定一台服务器在该条款上"两个版本都不符合"，需要一个其通过/失败真正追踪
条款语义而非某种偶然服务器行为的线路探针——而一个连两个已知版本都区分不开的探针，
不配给未知服务器打标签。单次"neither"判定同样可能是偶发错误、限流（rate-limit）、
或者一台本来就一直坏掉的服务器，这些都不是*由修订引起的*发散。见证一个权限约束
是否被执行，看似必须尝试一次未授权动作——但对在线第三方服务器而言，一次*未被拒绝*
的未授权动作，按定义就已经对某人的生产系统实施了；而一个改变状态的探针会污染面板
（panel）中之后的每一次观测。至于发散窗口的*宽度*——正是它把"有些服务器不一致"
变成"服务器暴露一天还是一个季度"——永远无法从粗粒度轮询日程上直接读出：窗口被扫描
夹逼（bracketed），又被服务器的出现与消失所删失（censored）。

我们的做法是把每一个障碍都转化为一个具体的设计选择而非一句托辞。每条条款差量被
编译成一对匹配探针，探针对必须先*区分*两个钉定的参考实现——一台按版本 N 构建、
一台按 N+1 构建——才被允许给任何在线服务器打"neither"标签，因此线路判定锚定在
已知一致性上而非口头断言上。每个候选发散都对照一组匹配的*未变更*条款测量——它们的
行为不可能被此次修订影响——因此只有当"neither"超过该安慰剂基线并跨扫描持续时才
计为漂移。权限执行以非破坏方式见证：读取服务器在授权边界上的接受或拒绝决策，而
不是把未授权动作执行到底——任何唯一忠实形式必须实施真实变更的探针，仅限于经同意的
参考部署。每个窗口的宽度按带显式分辨率下限（resolution floor）的区间删失时长来
估计，因此粗粒度的扫描日程产出的是诚实的分布，而非有偏的减法。

我们在两个协议（MCP 与 A2A）和一个纵向重采样的已部署服务器公开目录上评估该设计，
以每协议两个钉定参考实现作为唯一的一致性真值标签，以未变更条款安慰剂作为零假设
对照，以服务器内部"变更 vs 未变更"对比作为把漂移与一般性损坏隔离开的手段。

综上，我们的贡献是：
- 对**发散窗口**的形式化——已部署服务器在跨规范性条款修订迁移期间，在该条款上既
  不符合旧版本也不符合新版本的时间区间——带有一个版本括架参照系（version-bracket
  reference frame），用以把真正的窗口与普通的旧/新版本符合区分开；其时间宽度即
  暴露时长的度量。
- 一套差分一致性测量仪器：从规范性条款差量合成匹配的线路探针对，且仅当探针对可
  证明地区分两个钉定参考实现后才准入在线扫描，使线路上的"neither"判定成为经过
  验证的一致性判断，而非任意一次失败请求。
- 一个非破坏的权限执行可观测量（observable）：读取服务器在授权边界上的接受/拒绝
  决策，把可见性-权限之分操作化为一个*被测量的线路迁移*（enforced → advertise-only
  → silent），而无需执行它所检验的未授权动作。
- 一项预注册测量：已部署服务器上发散窗口的普遍程度与区间删失宽度、权限到可见性
  降级的普遍程度，以及二者在条款差量类型上的集中分布——其设计使得（若发散窗口与
  降级被证明普遍存在）可以得出结论：agent 协议的一致性审计必须是版本差分且持续的，
  而非单版本、一次性的。

## 问题定义（Problem Definition）

**形式化设定。** 设 N 与 N+1 为某 agent 互操作协议的两个相邻已发布版本，各为一组
规范性（RFC-2119）条款 C_N 与 C_{N+1}。条款差集 Δ = Δ(N, N+1) 是两版本间被新增、
删除或修改（要求被加强、削弱，或约束被重新定型）的条款集合；每个 δ ∈ Δ 是一条
*规范性条款差量*。对每个 δ 我们构造一对*匹配探针对* (p_δ^N, p_δ^{N+1})：一组线路
交互，其响应把服务器在 δ 上的行为分类为符合 N、符合 N+1、两者皆符合（both）、或
两者皆不符合（neither）。设 S 为一组已部署服务器，每台可经线路端点访问，并可在
固定扫描节奏下于时刻 t₁ < t₂ < ⋯ < t_m 重复观测。对服务器 s ∈ S、差量 δ、时刻 t，
判定为

v(s, δ, t) ∈ { N, N+1, both, neither, out-of-frame }。

当 N 是发布时间先于 s 首次被观测到的符合性的最新版本、且 N+1 是下一个已发布版本时，
称 s 对版本对 (N, N+1) *在框内*（in-frame）；在 δ 上符合更早的 N−1 或更晚的 N+2 的
服务器被标记为 **out-of-frame** 并被排除出窗口估计，从而普通的旧/新版本符合永远
不会被误认为发散。**发散窗口** W(s, δ) 是在 s 处于框内的条件下，v(s, δ, t) =
neither 的极大时间区间。对承载权限的 δ，**执行状态** e(s, δ, t) ∈ { enforced,
advertise-only, silent } 记录未授权动作是在线路上被拒绝、还是仅被通告却仍成功、
还是两者皆无；**降级** D(s, δ) 是与 δ 同时发生的一次已测得的迁移 enforced →
{advertise-only, silent}。估计对象（estimand）是 W 在 S 上的总体普遍程度与区间
删失宽度分布，以及 D 在承载权限的差量中的普遍程度，每一项都附带效度包络
（validity envelope：探针效度、目录覆盖度、时间分辨率）报告。

**为什么难。** 该设定的四条性质阻碍朴素的测量。第一，δ 是散文：探针对只有在
*可证明地分离*一台已知实现 N 的服务器与一台已知实现 N+1 的服务器之后，才有资格对
未知服务器返回"neither"；未经验证的探针会把自身缺陷与服务器缺陷混为一谈。第二，
单次 v = neither 还不构成窗口：必须把它与瞬时错误、与本来就广泛不一致的服务器区分
开，这需要一组*未变更*条款做对照——它们在 C_N 与 C_{N+1} 中逐字相同，因此在构造上
不可能出现版本引发的"neither"——并要求跨扫描持续。第三，执行状态 e 由*未授权*动作
是否被拒绝定义，但对在线的 s 把该动作执行到底，既实施了未授权效果又改变了 s 的
状态，混淆之后的 v(s, ·, t′)；因此执行必须从授权边界上的接受/拒绝决策读出，而非
从动作的完成读出。第四，W 的宽度受扫描节奏下界约束，并被服务器进出 S 所删失：
进入与退出各被两次扫描夹逼（区间删失），在 t_m 仍未闭合或因服务器消失而终止的窗口
为右删失——所以宽度分布必须被*估计*，而不是相减。

## 方法概览（Method Overview）

在概念层面，本研究是一条由五个协作部件组成的单一测量流水线。条款差集与已部署
服务器目录进入流水线；差分探针合成器与非破坏探测挂具（harness）把每台服务器的
线路行为变成经过验证的逐条款判定；未变更条款安慰剂把判定序列变成可归因于漂移的
发散窗口；权限分类器把同一判定流变成执行状态迁移；区间删失估计器把粗粒度扫描日程
变成诚实的窗口宽度分布。

**差分探针合成器**（differential probe synthesizer）把每条规范性条款差量编译为
匹配探针对，且仅当其正确分类两个钉定参考实现后才准入在线扫描。**非破坏探测挂具**
（non-destructive probing harness）把每个权限探针表达为只读、幂等（idempotent）
或试运行（dry-run）请求，使服务器暴露其接受/拒绝决策而不执行未授权动作；任何
不可约的破坏性探针仅限于经同意的参考部署。**未变更条款安慰剂与持续性门**
（placebo and persistence gate）对两版本间逐字相同的条款运行匹配探针，仅当变更
条款的"neither"超过安慰剂基线并跨扫描持续时才计为发散。**权限-可见性分类器**把
每条承载权限差量的线路行为标注为 enforced、advertise-only 或 silent，并从迁移中
读出降级。**区间删失窗口估计器**把每个确认窗口当作删失时长，对照显式分辨率下限
拟合其宽度的生存模型。各部件单向组合：未被归因于漂移的窗口不估计宽度；未经验证
探针产出的判定不归因漂移。

## 方法论（Methodology）

### 差分一致性探针合成（Differential Conformance Probe Synthesis）

**挑战。** 规范性条款差量是自然语言散文；一个其通过/失败被当作一致性判定的线路
探针，必须真正追踪条款语义，否则下游每一个发散计数都是探针的伪影而非生态的事实。

**洞察。** 探针的忠实性无法靠文本论证；它可以对照已知真值*演示*出来。一个可证明
分辨两个已知版本的探针，才赢得评判未知服务器的资格——在参考实现上的差分区分能力，
正是让线路"neither"有意义的仪器验证步骤。

**方法。** 对每条条款差量 δ，我们遵循差分测试（differential testing）纪律
[McKeeman 1998; Yang et al. 2011] 编写匹配探针对 (p_δ^N, p_δ^{N+1})：p_δ^N 是
严格符合 N 的服务器通过、严格符合 N+1 的服务器不通过的交互，p_δ^{N+1} 反之，
因此探针对的联合结果映射到 {N, N+1, both, neither} 之一。任何在线扫描之前，每个
探针对先在两个钉定参考实现——协议官方参考服务器在 N 与 N+1 各自构建并打标签的
版本——上运行，仅当它把 N 参考分类为仅 N、把 N+1 参考分类为仅 N+1 时才被准入。
要求强度与条款身份从规范的 RFC-2119 关键词读出 [Bradner 1997]。条款差量标签
（变更 vs 未变更；承载权限 vs 表示性；差量类型）由至少两名独立标注者给出，接受
门槛为 Cohen's κ ≥ 0.7 [Cohen 1960] 并检查混淆结构；未达门槛将阻断规模化，而非
被吸收进更嘈杂的判定。

### 非破坏权限探测（Non-Destructive Authority Probing）

**挑战。** 判定权限约束是否被*执行*看似必须尝试未授权动作——但对在线第三方服务器，
未被拒绝的未授权动作就已实施在生产系统上，而改变状态的探针会污染面板中之后的每次
扫描。

**洞察。** 执行是*拒绝决策*的属性，不是变更的属性。在授权边界观察服务器的接受或
拒绝，无需把未授权效果执行到底即可见证执行，使测量与危害解耦。

**方法。** 每个权限探针都被表达为非破坏形式——只读或幂等请求，或试运行/仅检查
（check-only）变体——迫使服务器在任何状态改变之前给出接受/拒绝决策。唯一忠实形式
必须实施真实变更的探针，只对经同意的参考或自托管服务器运行，绝不对在线第三方端点
运行；挂具级断言（harness-level assertion）从根上拒绝向在线端点发出改变状态的
未授权调用。当在线权限判定仍无法安全获得时，报告为不可见证（un-witnessable）并
排除、同时报告其数量，而非猜测。任何需要破坏性在线探测的残余发现，按协同披露协议
处理，与既有规范侧一致性工作的扣留工件姿态一致。

### 未变更条款安慰剂与持续性门（Unchanged-Clause Placebo and Persistence Gate）

**挑战。** 单次"neither"判定可能是瞬时错误、限流、或一台在修订发生之前就广泛
不一致的服务器——都不是*由版本差量引起的*发散。

**洞察。** 只有规范漂移才能使*变更*条款双向失败而难度相近的匹配*未变更*条款不
失败。变更-未变更对比是服务器内部的安慰剂，而跨扫描的持续性把持久漂移与瞬时噪声
分开。

**方法。** 在变更条款探针之外，我们对一组匹配的*未变更*规范性条款——相同要求强度、
相似请求形态、在 C_N 与 C_{N+1} 中逐字相同——运行探针，对它们而言版本引发的
"neither"在构造上不可能。变更条款的"neither"仅当持续至少 k 次连续扫描、且其比率
超过未变更条款失败基线时，才被采纳为发散窗口。同一配对设计从一台仪器产出两个可
分别证伪的读数：*总体*对比（变更条款"neither"普遍度减安慰剂基线）检验发散窗口
是否存在；*服务器内部*对比（每台服务器的变更减未变更失败差）检验"neither"是否可
归因于版本差量而非一般性不一致。

### 权限-可见性降级分类器（Authority-Visibility Downgrade Classifier）

**挑战。** 并非每个"neither"都是安全降级；把表示性变化（格式、命名、传输）与动作
是否被授权的变化混为一谈，会夸大安全发现。

**洞察。** 执行-通告之分正是既有框架层工作在概念上画出的可见性-权限轴——但在这里
它直接从未授权线路调用是被*拒绝*还是*边通告边成功*读出，把"权限降级为仅可见"从
概念可能性变成可观测的线路迁移。

**方法。** 每条承载权限的条款差量的线路行为在每个时刻被标注为 *enforced*（未授权
动作在边界被拒绝）、*advertise-only*（约束出现在能力描述符或错误文本中但动作仍
成功）、或 *silent*（既不拒绝也不通告）；降级是与差量同时发生的迁移 enforced →
{advertise-only, silent}。同一标注判定流从一套方案产出两个读数：enforced→
advertise/silent 迁移的*比率*给出降级普遍度；降级与发散窗口在条款差量类型
（added-MUST、strengthened-SHOULD→MUST、retyped-authority、representational）上的
*分布*给出其集中程度。

### 区间删失发散窗口估计器（Interval-Censored Divergence-Window Estimator）

**挑战。** 发散窗口的宽度——把"有些服务器不一致"变成量化风险的暴露时长——无法从
粗粒度、不规则、且服务器不断进出目录的轮询日程上直接读出。

**洞察。** 轮询日程不能靠"末次 neither 减首次 neither"变成诚实的宽度；只有带显式
删失与声明分辨率下限的生存估计，才能把日程转换为站得住的时长分布。

**方法。** 每个确认的（服务器, 条款）窗口被当作区间删失时长：其起点由最后一次
符合与首次"neither"扫描夹逼，终点由最后一次"neither"与首次重新符合扫描夹逼；窗口
在最后一次扫描仍未闭合或服务器离开目录时为右删失。在服务器首次被观测时就已处于
打开状态的窗口没有"最后一次符合"扫描，应作为左截断（left-truncated / delayed-entry）
时长进入估计，而不是把起点定在首次扫描；并且由于面板锚定在一个真实修订日期上，
在首次扫描之前就完成迁移的服务器是不可见的——这种截断会使朴素普遍度偏低、朴素宽度
偏高，因此两项都在估计器中显式携带。Turnbull / Kaplan-Meier 生存估计器
[Kaplan and Meier 1958; Turnbull 1976] 给出中位宽度及置信区间，并显式报告可分辨
地高于扫描节奏下限的窗口比例，使低于下限的短窗口尾部被声明为删失而非计为零。

## 实验（Experiments）

### 实验设置（Experimental Setup）

**测量对象。** 括住研究窗口的两个相邻已发布 MCP 版本（如 2026-07-28 候选版本及其
前任）提供主条款差集，选择理由是其新近、相邻、且规模足以产出可观的规范性条款差量
集 [MCP 2024]。一个 A2A 版本对（1.0.0 → 1.0.1 扩展）作为第二协议，用于检验发散
窗口现象是否与协议无关而非 MCP 特有伪影 [A2A 2025]；由于 A2A 的传输与授权模型
不同于 MCP，A2A 版本对承载*存在性*与*宽度*测量（只需差分探针与安慰剂，二者可直接
迁移），而*权限降级*测量仅当一项书面前提成立时才对 A2A 报告——即 A2A 暴露了一个
非破坏探针可见证的接受/拒绝授权边界，这一点在任何在线扫描之前先在 A2A 参考实现上
检查——否则测量范围限定于 MCP 并明示该限制而非静默丢弃。一个公开的远程 MCP 服务器
目录按固定扫描节奏重采样，提供已部署总体与纵向面板，把已被验证可行的远程 MCP
部署侧测量协议扩展到版本差分、纵向的轴上。每协议两个钉定参考实现（在 N 与 N+1
各自构建并打标签）是全研究唯一的一致性真值标签。

**对照**（真值与零假设，不是要击败的竞争者——这是测量研究，没有任何研究问题被
表述为"我们的流程胜过基线 X"）。*未变更条款安慰剂*——两版本间逐字相同的匹配条款
——是每个变更条款声明被对照测量的零基线；那里的版本引发"neither"在构造上不可能，
因此任何升高的失败都指示一般性服务器不稳定。*钉定参考实现*提供探针被验证所依据的
判定。*一般性不一致这一竞争解释*由服务器内部变更减未变更对比隔离，它把漂移与本来
就广泛不一致的服务器区分开。

**指标。** 逐（服务器, 条款, 时刻）判定与执行状态；变更 vs 未变更"neither"普遍度
及其差；区间删失中位窗口宽度与高于分辨率下限的比例；权限条款上 enforced→
advertise/silent 降级普遍度；窗口与降级在条款差量类型上的分布。

**研究问题（RQ）：**
1. RQ1——差分探针对能否正确区分两个钉定参考实现？
2. RQ2——发散窗口是否存在：持续的变更条款"neither"普遍度是否超过未变更条款安慰剂？
3. RQ3——计入删失后，发散窗口有多宽？
4. RQ4——在承载权限的条款差量中，权限到可见性降级有多普遍？
5. RQ5——"neither"可归因于版本差量，还是一般性不一致？
6. RQ6——发散窗口与降级是否集中于特定条款差量类型？
7. RQ7——非破坏协议能否在不对在线服务器实施任何未授权动作的前提下复现完整交互判定？

#### RQ1：差分探针对能否区分钉定参考实现？

**设置。** 对每条条款差量，将匹配探针对运行于两个钉定参考实现（在 N 与 N+1 打
标签的参考服务器），记录探针对是否把 N 参考分类为仅 N、把 N+1 参考分类为仅 N+1。
任何误分类都经人工检查，归因为条款文本真实存在歧义或探针错误。

**预期结果。** 探针对在至少 95% 的条款差量集上正确分类两个参考；残余误分类经检查
可归因于条款文本歧义而非探针错误。

**证伪条件。** 若探针对在不足 95% 的条款差量上区分参考，或残余失败被追溯为探针
错误而非条款歧义，则被驳斥——任一情形都意味着仪器无法支撑线路"neither"判定，探针
集修复之前不得为任何在线发散声明计分（这是阻断性的仪器效度门）。

**假设（白话）。** 探针必须先证明能分辨两个已知版本，才有资格评判未知服务器。

**指标。** 逐差量参考区分准确率；每个残余失败的裁定原因。

#### RQ2：发散窗口是否存在于安慰剂基线之上？

**设置。** 在被扫描的已部署总体上，比较变更条款上持续（至少 k 次连续扫描）
"neither"判定的普遍度与匹配未变更条款安慰剂基线，采用配对两比例 / McNemar 检验，
跨条款差量做 Holm 校正，α = 0.05 [Holm 1979]。试点阶段：一个协议（MCP）、一个
目录、k = 2；规模化：两个协议、≥ 2 个目录，k 取超过试点观测到的瞬时错误率所需的
持续度。

**样本量理由。** 目录与扫描次数的规模设定为：在试点观测到的误差方差下，10 个
百分点的变更-安慰剂差以约 80% 功效（power）可检出；若试点观测差更小，则触发预先
承诺的目录扩容，而非直接下零结论。

**预期结果。** 持续的变更条款"neither"普遍度在校正检验下超过未变更条款安慰剂基线
至少 10 个百分点。

**证伪条件。** 若变更条款"neither"普遍度落在安慰剂基线 10 个百分点以内或更低，则
被驳斥——那意味着已部署服务器在干净地跟进版本（或对变更与未变更条款同样失败），
发散窗口现象不存在；这一预注册的零结果本身将作为稳健性认证报告：生态的快速迭代
并未产生可测量的差分一致性缺口。

**假设（白话）。** 确有可测量比例的已部署服务器会在两个版本之间卡上一阵子。

**指标。** 变更条款 vs 安慰剂持续"neither"普遍度及校正后差值；逐条款差量分解。

**结果。** *[占位——实验运行后填写]*

#### RQ3：计入删失后发散窗口有多宽？

**设置。** 对每个确认的（服务器, 条款）发散窗口，拟合区间删失 Turnbull /
Kaplan-Meier 估计器，进入/退出由相邻扫描夹逼，对最后一次扫描仍未闭合或因离开目录
而终止的窗口做右删失；报告中位宽度、其置信区间、以及可分辨地高于扫描节奏分辨率
下限的窗口比例。

**预期结果。** 区间删失中位发散窗口宽度超过扫描节奏分辨率下限至少 2 倍——窗口是
多扫描时长而非单扫描闪烁——且估计器的置信区间下界高于下限。

**证伪条件。** 若中位宽度的置信区间下界落在分辨率下限或以下，即数据在该节奏下
无法区分真实多扫描窗口与单扫描瞬态，则被驳斥；此时诚实的报告是窗口存在（RQ2）但
其时长在该节奏下不可分辨，这促成更细的扫描而非宽度声明。

**假设（白话）。** 发散是服务器可能被卡住的持久状态，不是一瞬的闪烁。

**指标。** 区间删失中位宽度及 CI；高于分辨率下限的窗口比例；右删失率。

**结果。** *[占位——实验运行后填写]*

#### RQ4：权限到可见性降级有多普遍？

**设置。** 在承载权限的变更条款中，用非破坏权限探针对每台跨差量迁移的服务器在
差量前后分类其执行状态（enforced / advertise-only / silent），统计表现出与差量
同时发生的 enforced→advertise-only 或 enforced→silent 迁移的服务器比例。

**预期结果。** 在被观测到跨承载权限差量迁移的服务器中，至少达到预注册下限（15%）
表现出与差量同时发生的 enforced→advertise-only 或 enforced→silent 降级。

**证伪条件。** 若不足 15% 的迁移服务器表现出执行降级，则被驳斥；若权限条款上观测
到零降级，则被更强地驳斥——声明的安全一半随即不成立，发现收窄为不含安全退化成分
的互操作发散，并以完整显著度报告而非被掩埋。

**假设（白话）。** 当服务器在权限条款上于版本之间漂移时，有相当份额会一边继续
通告约束、一边不再真正执行它。

**指标。** 权限条款上 enforced→advertise/silent 迁移率；逐条款与逐服务器分解；
被排除的不可见证（无法安全探测）权限判定数量。

#### RQ5："neither"可归因于版本差量，而非一般性不一致？

**设置。** 对每台服务器，计算其变更条款失败率与匹配未变更条款失败率之间的服务器
内配对差；跨服务器检验该差是否大于零（配对符号 / Wilcoxon 检验）。这是竞争解释
消融：若失败于变更条款的服务器以相同比率失败于匹配的未变更条款，则"neither"指示
的是一般性损坏而非漂移。

**预期结果。** 服务器内变更减未变更失败差在总体上大于零——服务器在*变更*条款上的
失败多于匹配的*未变更*条款——因此"neither"可归因于版本差量。

**证伪条件。** 若服务器内变更减未变更差未显著大于零，则被驳斥——失败于变更条款的
服务器对未变更条款同样频繁失败，意味着"neither"判定指示广泛不一致而非规范漂移；
在此结果下发散窗口声明降级为一般部署一致性测量，漂移特定的框架被撤回（预先承诺
的"竞争解释成立"措辞）。

**假设（白话）。** 失败恰好聚集在被改变的条款上，这正是它们与这次修订有关的原因。

**指标。** 服务器内变更 vs 未变更失败差及其检验统计量；差为正的服务器比例。

#### RQ6：窗口与降级是否按条款差量类型集中？

**设置。** 把条款差量划分为类型（added-MUST、strengthened-SHOULD→MUST、
retyped-authority、representational），逐类型计算发散窗口普遍度与权限降级率；以
带预注册最小支持度的逐类型富集（enrichment）检验非均匀集中。

**预期结果。** 发散窗口与权限降级在条款差量类型上非均匀分布——相对于表示性差量，
集中（至少 2 倍富集，log-odds 大于零，带预注册最小支持度）于 added-MUST、
strengthened-SHOULD→MUST 与 retyped-authority 差量。

**证伪条件。** 若窗口与降级率在条款差量类型间统计上均匀（没有类型达到支持度之上
的 2 倍富集），则被驳斥——那意味着漂移是*任何*条款变更的泛性质而非由要求强度与
权限语义结构化——这是一个更弱、可操作性更低的发现，将如实报告而非包装成结构。

**假设（白话）。** 漂移咬得最狠的地方，恰是新施加要求或权限约束被重新定型之处，
而非表面化的变更。

**指标。** 逐类型窗口普遍度与降级率；富集 / log-odds 及支持度。

#### RQ7：非破坏协议能否在无未授权副作用下匹配完整交互判定？

**设置。** 在参考实现上（完整破坏性交互是允许的），逐条款差量比较非破坏权限探针
产出的一致性判定与完整交互产出的判定；并运行挂具级审计：发往*在线*服务器的每个
权限探针都是非破坏的，断言对任何在线第三方端点的改变状态的未授权调用数为零。

**预期结果。** 非破坏协议在至少 98% 的参考服务器条款差量上复现完整交互一致性
判定，且挂具审计确认对任何在线服务器的改变状态未授权调用为零。

**证伪条件。** 效度侧：若非破坏协议与完整交互在超过 2% 的参考条款差量上不一致
（安全可观测量不能忠实见证执行，权限判定必须限定于参考环境），则被驳斥；安全侧：
若挂具审计发现任何发往在线服务器的改变状态未授权调用（这是停止运行条件，不是
指标），则被驳斥。

**假设（白话）。** 我们可以看见门卫是否拦了人，而不必真的闯门。

**指标。** 参考环境上非破坏 vs 完整判定一致率；挂具审计的在线改变状态未授权调用
计数（目标：零）。

**进一步评估。** 若有更多时间，自然的扩展是测量*非相邻*版本跳跃（服务器 N → N+2、
跳过 N+1）的发散窗口，以及第三个协议（ACP）——二者都明确不在本文范围内：前者把
参照系定义从相邻版本对改为版本*路径*，需要自己的 out-of-frame 记账；后者要求对照
不同授权模型重新验证权限可观测量，而非直接延用现有仪器。

### 效度威胁（Threats to Validity）

**构念效度（construct validity）。** 发散窗口与降级构念的可靠性取决于其背后的
探针与标签。探针忠实性不靠断言，而在任何在线扫描之前对照两个钉定参考实现演示
（RQ1）；条款差量标签（变更/未变更、权限/表示性、差量类型）由至少两名独立标注者
以 Cohen's κ ≥ 0.7 验证并检查混淆结构；未达门槛阻断规模化。另一个构念威胁是版本
参照系本身：钉在 N−1 或 N+2 的服务器会被虚假地判为"neither"，因此每个判定都相对
跨服务器观测窗口的相邻版本对计算，out-of-frame 服务器被排除并报告数量。

**内部效度（internal validity）。** 两个混杂威胁"neither"作为漂移的因果解读。
其一，瞬时错误与限流可能伪装成发散；由持续性门（至少 k 次连续扫描）与未变更条款
安慰剂控制，后者的"neither"率给出瞬时错误下限。其二（后果更重），本来就广泛不
一致的服务器会因与修订无关的原因失败于变更条款；由服务器内变更减未变更对比隔离
（RQ5），其失败被预先承诺为把漂移特定声明降级为一般部署一致性测量，而非否定整个
运行。第三个内部威胁是探针自身引发的测量性状态改变，会混淆纵向面板；非破坏探测
挂具（RQ7）加上对在线改变状态未授权调用的挂具断言，设计目标是将其保持为零。

**外部效度（external validity）。** 本研究范围限定为公开目录中可沙箱化、线路可达
的 MCP（以及有条件的 A2A）服务器；普遍度估计仅对该采样总体有效——它相对自托管
部署高估了托管型、维护良好的服务器——将作为跨至少两个目录的目录构成敏感性分析
报告，而非静默泛化。发现进一步限定于实际测量的两个协议版本对，不主张对非相邻版本
跳跃、其他协议、或不通告可解析版本的服务器成立。

**结论效度（conclusion validity）。** 单次扫描无法区分瞬时闪烁与持久窗口，因此
每个宽度声明只经由带显式分辨率下限的区间删失生存估计器获得许可（RQ3），绝不来自
原始首末相减；低于下限的窗口报告为删失而非零。对称地，在服务器首次观测时已打开的
窗口按左截断时长处理，普遍度估计的范围限定为与面板重叠的窗口——在首次扫描之前
完成的迁移被声明为不可观测，而非被静默吸收。普遍度检验跨条款差量集做 Holm 校正
以控制族错误率；即使在预先承诺的目录扩容之后仍功效不足的单元，报告为不确定而非零。

## 相关工作（Related Work）

与本文最接近的单项既有工作是以 AgentRFC [AgentRFC 2026] 为代表的规范侧 agent 协议
一致性路线，其差量值得在综述之前直说：AgentRFC 把协议规范编译为带类型的中间表示、
做模型检查、并把反例回放到 SDK——但它对照自身模型认证的是*规范*，单版本，且工件
因协同披露被扣留；而本文测量的是*线路上的已部署服务器*，跨版本修订做差分、做
纵向，且带可复现仪器。在安全侧，可见性-权限之分归功于既有框架层工作 [Capability
Gates 2026]，元数据非权限不变式归功于一个被提议的替换执行层 [HCP 2026]；本文的
贡献不是这一区分本身，而是其*测量*——在线路上、在已部署服务器上、跨一次规范性
条款修订，使权限约束向仅可见的降级成为可观测迁移而非概念可能性。

**协议一致性与差分测试。** agent 互操作协议的一致性检查仍处萌芽期：AgentRFC
[AgentRFC 2026] 确立了规范侧模型检查路线；一簇不断增长的部署侧测量——远程 MCP
服务器认证安全普查 [Remote-MCP 2026]、大规模运行时服务器研究 [MCPZoo 2026]、
对暴露于公网的服务器的动态安全评估 [Exposed-by-Design 2026]——确立了对已安装基础
做线路级测量是可发表且有信息量的。它们都不比较两个相邻版本、不追踪服务器随时间的
一致性：规范侧路线是单版本的，部署侧研究是对一致性视而不见的快照（后者的重复爬取
增加的是覆盖度，形成不了以服务器为单位的一致性面板）。一条机制设计路线对 A2A/MCP
消息做运行时检查 [Negotiate 2026]，对照的是协商理性约束；它验证线路流量，但检查
对象是协议有意不规定的策略性性质，且是单版本、无部署机群测量、无时间轴。本文仪器
继承经典差分测试思想——以两个实现（这里是两个规范*版本*）互为神谕（oracle）
[McKeeman 1998; Yang et al. 2011]——并首次应用于协议版本间的规范性条款差集而非
编译器。

**权限、可见性与协议治理。** 一条框架层路线论证能力可见不等于被授权 [Capability
Gates 2026]，一条系统路线提出以一组固定的安全不变式与攻击基准替换执行层 [HCP
2026]；二者作用于设计或配置，而非跨修订的已部署线路行为。降级构念最接近的*已测量*
先例是描述-代码不一致研究 [DCI 2026]，它在真实 MCP 服务器上表明通告的能力与安全
边界可以偏离实现的行为；本文承认"通告 vs 实际"的偏离已在彼处确立，并声明静态、
单版本检查看不见的那部分——执行状态作为*与规范性条款差量同时发生的、随时间的迁移*，
从线路上的授权边界读出而非从代码读出。一支论证型工作把 MCP、A2A 与 ACP 无法表达
的内容编目为断言式缺口矩阵 [Governance Gaps 2026]，一个上下文治理机制为 agent
上下文提出可验证溯源 [ContextNest 2026]。本文的权限分类器把*被论证的*可见性-权限
缺口变成*被测量的*执行状态迁移，其发散窗口估计对象把*被论证的*"无法表达什么"矩阵
变成被测量的"未被符合什么"问题——在这些路线提供概念框架之处给出测量。

**删失时长估计。** 窗口宽度估计对象是一个生存分析问题：窗口被扫描日程区间删失、
被目录流失右删失，因此其宽度用 Kaplan-Meier 与 Turnbull 估计器 [Kaplan and Meier
1958; Turnbull 1976] 估计而非相减。用法是标准的；引用它的意义在于：把粗粒度轮询
日程当作删失机制而非真值，正是让宽度声明诚实的纪律——单快照的部署侧测量既有工作
没有机会应用这一纪律。

## 结论（Conclusion）

本文把一个治理假定——服务器通告的协议版本符合性在一次修订之间是稳定的安全标签——
重构为一个带精确可识别性结构的实证问题，而非把一致性当作不言自明的单调性质。核心
方法论赌注是：发散窗口（对两个相邻版本皆不符合）与权限到可见性降级，只有当探针被
验证能区分两个已知版本、"neither"对照未变更条款安慰剂测量、执行以非破坏方式见证、
窗口宽度在显式删失下估计时，才能可信地与普通不一致区分开；更弱的设计会把坏掉的
服务器误当成漂移的服务器，把瞬时闪烁误当成持久窗口。无论测得的普遍度如何，发现都
与决策相关：普遍且宽的窗口加上权限降级，意味着 agent 协议的一致性审计必须是版本
差分且持续的而非单版本一次性的，"符合 vX"在修订的暴露区间内不可信任；而一个测得
的零结果同样有用——它认证生态的快速迭代并*不会*把已部署服务器搁浅在版本之间。两条
局限从一开始就约束该声明，并且是自然的后续步骤而非事后补语：发散窗口宽度受扫描
节奏下界约束，真实的短窗口尾部被删失、只在声明的分辨率下限之上被量化，指向更细或
事件触发的扫描；普遍度估计限定于一个高估托管服务器的公开目录，指向更广的部署采样
作为下一个测量目标。
