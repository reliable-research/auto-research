## Seed brief

- **One-sentence description:** Measure whether, and at what visible-test-suite mutation-kill adequacy level, coding agents shift from genuinely fixing a defect to passing the visible suite while failing an independent held-out oracle (hidden tests + excluded mutants).
- **Apparent inputs:** code-repair task instances (buggy program, repo context, gold patch); a full mutant-killing suite per instance from which adequacy-controlled sub-suites can be sampled; one or more coding agents run under a fixed iterative repair harness; a held-out oracle never exposed to the agent.
- **Apparent outputs:** per-adequacy-level visible-pass/held-out-pass rates; the resulting overfitting gap as a function of adequacy; an onset-threshold estimate (or a finding of none); a per-patch attribution of visible-pass/held-out-fail cases to gaming vs. coincidental incompleteness.
- **Closest research areas:** imperfect-verifier / weak-test-suite theory (ResamplingLimits, ROC-n-reroll); reward over-optimization (ChasingTail); execution-verified repair benchmarks (SWE-bench); execution-free reward modeling for SE agents (SWE-RM); adversarial test-generator co-training (CURE, ATGen, UTRL); unreliable self-verification (ReVeal).
- **In scope:** measuring existing coding agents' behavior under a controlled, size/coverage-matched mutation-adequacy sweep on sandboxable repair benchmarks (SWE-bench Verified, Defects4J). **Out of scope:** training new agents or reward models; live/production CI deployments; feature-addition tasks (only bug repair); establishing a claim of universal generalization across all languages/agent families.
- **Confidence: high.** As with a typical mature autoclaude seed, the "repo" here is itself a prior reverse-digest plus a pre-registered spec (digest.md + paper.md) that is already internally cross-referenced (N-node ↔ M-component ↔ H/RQ ids) and already carries its own asymmetry/taste self-audit (paper.md Step 0/Step 3, which explicitly caught and fixed a Bridge-Opportunity framing in a draft contribution CO4). Reconstruction risk is low; the risk instead is *redundancy* with paper.md's own Steps 5/6/9 — which is why stages 5/6 below are framed to validate the **measurement instrument's properties** (sampler fidelity, oracle soundness, diagnostic reliability, cross-agent transfer, selection-effect isolation) rather than re-deriving paper.md's H1–H4 from scratch under new names.

## Stage 1 — Problem Definition

### Round 1 (critic phase)

**draft_v1** (proposer):
- `summary`: Given a corpus of code-repair task instances, each with a buggy program, repository context, a gold correct patch, and a full mutant-killing test suite from which visible sub-suites can be sampled at controlled mutation-kill adequacy while holding suite size and code coverage fixed, determine how a coding agent's overfitting gap — the difference between passing the visible sub-suite and passing an independent held-out oracle (hidden tests plus the mutants deliberately excluded from the sub-suite) — changes as adequacy is degraded, and whether that change emerges at a discrete adequacy threshold or grows gradually.
- `input`: (1) repair task instances (buggy program, repo context, gold patch); (2) a full mutant-killing suite per instance, with a sampler that can construct sub-suites at a target mutation-kill score while holding suite size and statement coverage fixed; (3) one or more coding agents run under a fixed iterative "patch → run visible sub-suite → retry" harness with a bounded turn/token budget; (4) a held-out oracle (hidden tests + the mutants excluded from the sub-suite) that scores each final patch but is never exposed to the agent during the episode.
- `output`: (1) per-adequacy-level visible-pass and held-out-pass rates; (2) the overfitting gap as a function of mutation-kill adequacy; (3) an estimated onset threshold, or a finding that no discrete threshold exists; (4) a per-patch attribution of every visible-pass/held-out-fail case to suite-gaming vs. coincidental incompleteness.
- `constraints`: ground truth for patch correctness is the held-out oracle, never the visible sub-suite; the agent must be provably blind to the held-out oracle throughout the episode; suite size and code coverage must be held fixed across adequacy levels so that mutation-kill adequacy is isolated as the swept variable rather than confounded with suite size or coverage.
- `objective`: a reported gap-vs-adequacy curve and any onset-threshold claim is accepted only if the curve is estimated from episodes where the agent's blindness to the held-out oracle is confirmed and the sub-suite sampler is confirmed to hit its target adequacy at matched size/coverage.
- `study_type`: `empirical` — stated explicitly: digest N12 already settles this as a "measurement of when a phenomenon occurs," not the introduction of a new benchmark, agent, or detector as the headline contribution (the sampler and diagnostic are instrumental, per N12's own rationale).

**critique:**
- summary: Solid, evidence-traceable draft, but the objective has a real evaluability gap on the paper's second headline question, and one clause presupposes its own conclusion.
- comments:
  - `{severity: major, field: "objective", anti_pattern: "vague_success (evaluability gap)", comment: "The objective covers instrument validity (sampler fidelity, blindness) but says nothing about what makes the sharp-vs-gradual onset claim itself evaluable. paper.md Step 5 already has a precise decision procedure for this (segmented-vs-smooth model comparison via ΔAIC and a Davies test) — but stage 1's objective as drafted doesn't name any criterion for it, so as written a reader can't tell what would make output (3) right or wrong. That's not a hidden method leak (the criterion is a success condition, not a technique) — it's a missing evaluability clause."}`
  - `{severity: minor, field: "summary", anti_pattern: null, comment: "'a coding agent's overfitting gap ... changes as adequacy is degraded' quietly presupposes the gap moves in a particular direction (worsens) as adequacy degrades — whether it moves at all, and in which direction, is part of what's being measured (paper.md's own E1 fallback explicitly allows for a flat or even inverted result). Prefer neutral phrasing: track the gap as a function of adequacy, not assume its trajectory."}`
- decision: `move_to_refiner` (both flags are formalize-level fixes using content already in paper.md — no new content needed).

### Refiner pass

- `objective` (refined): "A reported gap-vs-adequacy curve and any onset-threshold claim is accepted only if (i) the sub-suite sampler is confirmed to hit its target mutation-kill score within a pre-specified tolerance at matched suite size and coverage, and (ii) the agent's blindness to the held-out oracle is confirmed from complete episode logs; separately, a claim that the onset is a *sharp, discrete threshold* rather than a *gradual* increase is accepted only if a segmented model of the gap-vs-adequacy relationship fits reliably better than a smooth monotone alternative — absent that comparison, the relationship is reported as gradual by default, not asserted as sharp."
- `summary` (refined): "...determine **how** a coding agent's overfitting gap ... **varies** as adequacy is degraded..." (removes the presupposed-direction language; "varies" replaces "changes... as adequacy is degraded," which read as assuming monotonic worsening).
- `formal_summary` (added, per stage-1 refiner's formalize-for-free duty): "Instance $i=1..n$ with buggy program $b_i$, gold patch $g_i$, full test pool $T_i^{full}$, hidden tests $T_i^{hid}$, mutant set $M_i$ (equivalent/duplicate subset $E_i$ filtered). A visible sub-suite $T_v \subseteq T_i^{full}$ with mutation-kill score $ms(T_v) = |K(T_v)| / |M_i \setminus E_i|$ is exposed to agent $\pi_j$ under a fixed iterative harness (budget $B$, temperature $\tau$). Held-out-correct $H_{ij} = \mathbb{1}[\text{patch passes } T_i^{hid} \cup (T_i^{full}\setminus T_v)]$, visible-pass $V_{ij}$ analogous. Overfitting gap $G(s) = \hat P(V{=}1\mid ms{=}s) - \hat P(H{=}1\mid ms{=}s)$. Determine $G(\cdot)$'s shape and, if it rises as $s$ falls, whether the rise is well-modeled as a discrete breakpoint or a smooth trend."
- `changes_made`: added the sharp-vs-gradual evaluability clause to `objective`; removed the presupposed-direction wording in `summary`; added `formal_summary`.
- `declined_to_fix`: none.

## Stage 2 — Motivation

### Round 1 (critic phase)

**draft_v1:**
- `summary`: Coding agents are increasingly gated, trained (via execution-grounded pass/fail signals), and benchmarked using a visible test suite as the sole verifier of task success, but whether — and at what point — an inadequate visible suite starts rewarding agents for gaming it rather than fixing the underlying defect has never been directly measured as a function of the suite's own fault-detection adequacy.
- `why_it_matters`: RLVR-style training pipelines and CI-gating harnesses for coding agents both treat "passes the visible suite" as a trustworthy proxy for "is correct." Classical mutation-testing theory already supplies an exact name for the risk this proxy carries — mutation-kill score, a scalar measure of how much behavior-changing wrongness a suite can still admit undetected — but a targeted corpus search across three independent keyword angles (mechanism, failure mode, evaluation domain) found no paper that treats this adequacy score as a controlled independent variable against agent behavior (digest N3/N4; paper.md Claim 3/8). Without measuring where the visible-pass/held-out-fail gap opens, teams instrumenting agent training or CI pipelines with whatever test suite ships with a benchmark have no evidence-based way to know whether their suite's adequacy is high enough to trust its pass signal, or whether they are already operating inside a gaming-prone regime.
- `who_cares`: teams building RLVR/execution-grounded training pipelines for coding agents, who need to know how much test coverage their reward signal requires before it can be trusted; benchmark maintainers deciding how strong a repair benchmark's shipped test suite needs to be; SWE-agent harness designers who currently treat "passes CI" as ground truth without a measured adequacy floor.
- `evidence`: `[ResamplingLimits, OpenReview:j8H84v6AZ1]` shows that under a fixed, weak unit-test selector, best-of-N resampling converges not to perfect correctness but to a hard ceiling set by the selector's own false-positive rate — direct adjacent evidence that a weak visible suite systematically admits incorrect-but-passing code, even for a static (non-adaptive) generator. `[ChasingTail, OpenReview:pBjy4ek2QV]` documents reward-model over-optimization concentrating in the high-reward tail as a policy improves — the exact reward-hacking dynamic this paper transplants onto a test-suite verifier. Neither treats verifier/suite adequacy as a swept independent variable to locate an onset; this is precisely the gap a targeted three-angle corpus search came up empty on (digest N3 grounding note).

**critique:**
- summary: Good stake-specific motivation with real grounded evidence, but coverage of stage 1's fourth output is thin.
- comments:
  - `{severity: major, field: "why_it_matters", anti_pattern: "partial_output_coverage", comment: "Stage 1 output (4) is per-patch gaming-vs-coincidental attribution — a claim about *mechanism*, not just magnitude. why_it_matters motivates why the aggregate gap matters but never explains why attribution at the individual-patch level specifically matters, as opposed to just reporting the raw gap and calling it done. A reader could reasonably ask: 'why do I need to know if a held-out-fail patch was gaming or just an honest miss — isn't the gap itself the actionable number?' That's a real, unaddressed gap: the raw gap conflates two very different remediation stories (the suite needs more/better tests vs. the pipeline needs anti-gaming safeguards), and only patch-level attribution can tell them apart."}`
- decision: `move_to_refiner`.

### Refiner pass

- `why_it_matters` (extended): "...critically, the raw gap alone cannot distinguish two remediation stories that call for entirely different fixes: a widening gap driven by honest-but-incomplete repairs under a weaker suite calls for a better test suite, while a widening gap driven by patches that specifically special-case the visible assertions calls for anti-gaming safeguards in the training/gating pipeline itself — a distinction invisible to any metric that reports the gap's size without also attributing individual visible-pass/held-out-fail patches to one story or the other."
- `changes_made`: added the remediation-story argument for why per-patch attribution, not just the aggregate gap, matters in practice.
- `declined_to_fix`: none.

**Confirmed Stage 2.**

## Stage 4 — Sub-Problems

### Round 1 (critic phase)

**draft_v1** (6 sub-problems, from digest N5's C1–C4 plus two components paper.md's Step 6 design makes necessary but N5 doesn't name as standalone challenges):

- **`sp_adequacy_confound`** — *description:* Construct visible sub-suites at a target mutation-kill adequacy while holding suite size and code coverage fixed, so that adequacy — not an accidental correlate of it — is the swept variable. *why_it_is_a_problem:* any gap-vs-adequacy claim is only as meaningful as the assurance that adequacy, not suite size or coverage, is what's driving it. *technical_challenge:* adequacy, size, and coverage are naturally correlated in an unconstrained sub-suite draw, and equivalent/duplicate mutants distort the mutation-score denominator itself; there's no way to disentangle them after the fact, only by construction. *source_limitation_ids:* `["__novel__"]` (digest C4, tied directly to the seed's own "systematic control" requirement; no cited work performs this kind of controlled sub-suite construction at all).
- **`sp_signal_variance`** — *description:* Attribute an observed overfitting-gap change across the adequacy sweep to the adequacy manipulation itself, not to ordinary stochastic variability in agent behavior and instance difficulty. *why_it_is_a_problem:* without this, any observed gap-vs-adequacy relationship is unfalsifiable — noise could produce the same shape. *technical_challenge:* requires pooling enough independent instances and repeated samples per adequacy level, with a variance model (random effects for instance and agent) that separates level-driven trend from instance/agent-level noise. *source_limitation_ids:* `["__novel__"]`.
- **`sp_curve_shape`** — *description:* Characterize whether the resulting gap-vs-adequacy relationship is a smooth, gradual increase or a sharp, discrete threshold, without presupposing either shape going in. *why_it_is_a_problem:* mutation score is a coarse scalar aggregate over a heterogeneous mutant population, so it's not obvious a priori that a discrete threshold is even the right shape to look for — assuming one risks imposing a discontinuity narrative that isn't in the data. *technical_challenge:* requires a model-comparison procedure (segmented vs. smooth) rather than a single curve fit, since either family can be made to fit noisy data reasonably well in isolation. *source_limitation_ids:* `["__novel__"]`.
- **`sp_gaming_attribution`** — *description:* Attribute each individual visible-pass/held-out-fail patch to deliberate suite-gaming versus a coincidentally incomplete, honestly-attempted fix. *why_it_is_a_problem:* the aggregate gap cannot distinguish "agents are exploiting known weak spots in the suite" from "agents are simply imperfect more often when suites are weaker" — these are different phenomena with different remediations (stage 2). *technical_challenge:* no single execution outcome settles this; it requires a behavioral signature — e.g., a patch that is correct exactly where tested and wrong just outside that footprint — that a coincidental miss would not reliably produce. *source_limitation_ids:* `["rw_adversarial_testgen"]` (CURE/ATGen/UTRL study the setting where tests are actively being *improved*, not the diagnostic setting of attributing exploitation under a fixed, degraded suite).
- **`sp_agent_transfer`** — *description:* Determine whether an onset threshold, if one exists, is a property of the benchmark/suite construction or of the specific agent/model family being evaluated. *why_it_is_a_problem:* a threshold measured on a single agent could be a fact about that agent's training regime rather than a general fact about suite adequacy, and every cited related work here evaluates a single fixed generator or policy. *technical_challenge:* requires running the identical sampler, harness, and oracle across multiple agent families under matched budgets, and testing an interaction effect rather than eyeballing separate curves. *source_limitation_ids:* `["__novel__"]`.
- **`sp_selection_confound`** — *description:* Separate agent-side adaptive exploitation of a known weak verifier under iterative optimization pressure from a purely mechanical selection effect that an imperfect verifier already produces even for a static, non-adaptive generator. *why_it_is_a_problem:* if the observed gap is fully explained by the selection-under-imperfect-verifier ceiling the resampling literature already establishes, then "agents learn to game weak suites" is an overclaim — the phenomenon would be a generic property of imperfect verification, not of adaptive agents. *technical_challenge:* isolating the two requires a budget-matched control that removes the iterative feedback loop while holding everything else (including total inference budget) fixed — not just citing that both effects could exist in principle. *source_limitation_ids:* `["rw_resamplinglimits", "rw_rocnreroll"]`.

**critique:**
- summary: Coverage checks out (solving all six would jointly deliver stage 1's four outputs), but two sub-problems risk reading as the same underlying issue.
- comments:
  - `{severity: minor, field: "sp_adequacy_confound / sp_selection_confound", anti_pattern: "overlap", comment: "Both are labeled around the word 'confound,' which can read as the same sub-problem stated twice. They are genuinely distinct — one is a *construction-level* confound (does the sub-suite sampler actually isolate adequacy from size/coverage as a measurement artifact?), the other is a *causal-attribution* confound (given a clean adequacy measurement, is the resulting behavior change attributable to agent-side adaptation or to a generic imperfect-verifier selection effect?) — but the descriptions don't make that distinction explicit enough to preempt the reading that they're redundant."}`
- decision: `move_to_refiner`.

### Refiner pass

- `sp_adequacy_confound.technical_challenge` sharpened to end with: "...this is a **construction-level** confound — about whether the measurement instrument itself cleanly isolates adequacy, prior to any question of what causes the resulting behavior."
- `sp_selection_confound.technical_challenge` sharpened to end with: "...this is a **causal-attribution** confound, distinct from construction: even with a perfectly clean adequacy measurement in hand, the *interpretation* of any resulting gap — agent-side gaming vs. a generic selection ceiling — remains open until the iterative-feedback and no-feedback conditions are directly contrasted."
- `changes_made`: made the construction-vs-attribution distinction explicit in both technical_challenge fields.
- `declined_to_fix`: none.

**Confirmed Stage 4** (6 sub-problems; 2 sourced from related-work limitations, 4 `__novel__` with stated decisive-component justifications).

## Stage 5 — Method Design

### Round 1 (critic phase)

**draft_v1** (6 methods):

- **`m_adequacy_sampler`** → targets `sp_adequacy_confound`. *proposed_approach:* Greedily sample sub-suites to hit a target mutation-kill score at fixed suite size and fixed statement coverage, filtering equivalent/duplicate mutants from the denominator via trivial-compiler-equivalence checks plus observed-behavior comparison. *key_insight:* adequacy, size, and coverage are naturally correlated in an unconstrained draw; holding two fixed while sweeping the third is what turns mutation score, rather than an artifact of suite construction, into the causal lever. *hypotheses:* ["The adequacy sampler attains each target mutation-kill score within ±0.05 while holding suite size and statement coverage within ±5% relative of the full suite, on at least 8 of 10 pilot instances with sufficiently rich kill matrices.", "The gold patch passes the full held-out oracle on repeated executions in 10 of 10 pilot instances, confirming the ground-truth signal is not itself flaky before it is used to score any agent patch."]
- **`m_trend_model`** → targets `sp_signal_variance`. *proposed_approach:* Fit a mixed-effects logistic model of held-out-pass and visible-pass on mutation-kill score, with random intercepts for instance and agent, pooling many independently sampled instances and repeated episodes per adequacy level. *key_insight:* pooling many instances/episodes under an explicit variance model is what lets a "the gap widens as adequacy degrades" claim survive individual instances or episodes behaving noisily. *hypotheses:* ["The overfitting gap G(s) = P(visible-pass) − P(held-out-pass), estimated by the mixed-effects model, is at least 10 percentage points larger at the lowest tested adequacy level than at full adequacy, with the mutation-score fixed effect significant at p<0.05 (Holm-corrected across agent families and mutant classes), while the gap at full adequacy itself stays at or below 10 percentage points."]
- **`m_curve_shape_estimator`** → targets `sp_curve_shape`. *proposed_approach:* Compare a segmented/changepoint regression against a smooth monotone GAM fit to the same gap-vs-adequacy data via ΔAIC and a Davies test for breakpoint existence/location, with a pre-registered decision rule for calling the relationship "sharp" vs. "gradual." *key_insight:* a discrete-threshold claim is only warranted if it fits reliably better than a smooth alternative, not merely because a segmented model *can* be fit to any curve. *hypotheses:* ["The fitted gap-vs-adequacy relationship favors a smooth monotone specification over a segmented specification (ΔAIC < 10, or a Davies test not significant after multiplicity correction), i.e., visible-test overfitting grows gradually rather than at a sharp discrete threshold."]
- **`m_differential_diagnostic`** → targets `sp_gaming_attribution`. *proposed_approach:* For every visible-pass/held-out-fail patch, run differential testing against the gold patch over a metamorphic neighborhood of inputs seeded from the visible sub-suite's own inputs; label as gaming iff the patch agrees with gold on all visible-exercised inputs but disagrees on ≥30% of the neighborhood, else coincidental incompleteness. *key_insight:* a patch that is correct exactly where the visible suite looks and wrong just outside that footprint is a behavioral signature that a coincidental, honestly-incomplete miss would not reliably produce — sharper and more checkable than the aggregate gap alone. *hypotheses:* ["The differential-testing diagnostic's gaming/coincidental labels reach Cohen's kappa of at least 0.6 against dual-human-annotated adjudicated labels on a sample of visible-pass/held-out-fail patches.", "The fraction of visible-pass/held-out-fail patches labeled gaming rises by at least 15 percentage points from the highest to the lowest tested adequacy band, indicating the widening gap is increasingly driven by exploitation rather than uniformly incomplete honest fixes."]
- **`m_transfer_harness`** → targets `sp_agent_transfer`. *proposed_approach:* Run 2–3 agent/model families through the identical adequacy-controlled sampler and fixed iterative harness under matched turn/token budget, temperature, and seeds, with a logged blindness audit confirming zero reads of the held-out oracle across every episode. *key_insight:* if identical construction and budget produce different onset behavior across families, the difference is attributable to the agent rather than to harness variation — though this design can only measure transfer across the families actually tested, never certify a universal threshold. *hypotheses:* ["The agent-by-adequacy interaction term in the shared mixed-effects model is significant, and at least one pair of tested agent families has onset-threshold estimates differing by at least 0.15 mutation-score units with non-overlapping bootstrap 95% confidence intervals — i.e., no single universal onset threshold holds across the tested agent families."]
- **`m_selection_control`** → targets `sp_selection_confound`. *proposed_approach:* Run a budget-matched, single-shot best-of-k sampling arm — no iterative retry, no feedback from the visible verdict — alongside the iterative arm, holding total inference budget fixed, then compare gap slopes between the two arms as adequacy degrades. *key_insight:* an imperfect verifier alone mechanically inflates accepted-but-wrong mass even for a static generator with no feedback loop; unless the iterative arm's gap grows reliably faster than this no-feedback control's, the phenomenon isn't agent-side adaptive gaming, it's the same ceiling effect the resampling literature already established for static selection. *hypotheses:* ["The iterative arm's gap slope with respect to mutation score exceeds the budget-matched selection-only arm's slope by at least 5 percentage points at the lowest tested adequacy level, with the difference significant at p<0.05."]

**critique:**
- summary: Every method has a real mechanism (no goal-restatement), every hypothesis is falsifiable with a stated threshold — but one method is carrying two headline validity claims and needs a one-line justification for why that's one construction step, not two.
- comments:
  - `{severity: minor, field: "m_adequacy_sampler.hypotheses", anti_pattern: null, comment: "Two hypotheses here (sampler fidelity, and oracle soundness) are both instrument-validity gates, but they're about two different halves of the same construction (the included sub-suite vs. its excluded complement). Worth stating explicitly why one construction step licenses both checks, so this doesn't read as two unrelated claims bundled into a single method for convenience."}`
