# 测试为何看不见设计：测试套件结构性盲区的双预言机测量（Why Tests Cannot See Design: A Dual-Oracle Measurement of Structural Blind Spots in Test Suites）

## 摘要

编码智能体（coding agent）如今直接撰写并修改生产代码，而测试套件（test suite）事实上充当了变更验收的闸门；然而一个"全绿"的套件在实践中几乎完全只是对输入/输出行为的裁决。设计惯例（design convention）——命名、模块分层、事件顺序——可以在同一个行为等价类（behavior-equivalence class）内自由变化，因此一个违反某项惯例却保持可观察行为不变的修改，位于任何数量的额外功能测试都无法跨越的边界之外。这条边界是否真实存在、哪些惯例类别落在边界的错误一侧，此前从未被直接测量过。我们构建了一种双预言机（dual-oracle）测量程序：只有当独立于被测套件的两个来源共同认证一个程序变体既在有界差分检查下行为等价、又被机器可读的规则检查器判定为违反惯例时，该变体才作为*设计变异体*（design mutant）被接纳，覆盖命名、分层/横切、时序/顺序三个类别。一个配对的惯例中性对照组（convention-neutral control）将真正的设计盲区与"杀死任何等价变异体本来就难"这一普遍困难区分开；一个能力匹配的测试套件增强实验（capability-matched augmentation）则区分结构性极限与"更多更强的功能测试即可弥合"的数量性缺口。我们将在成熟的开源 Java 与 Python 受试系统上报告：哪些设计属性类别作为经认证的盲区存活下来、这种存活是否是惯例特异的而非等价性的伪影、以及它是否在更强的套件下仍然持续——以及这对在自主编码智能体工作流中用绿色测试套件把关设计合规意味着什么。

## 引言

编码智能体越来越多地提议、有时直接提交对生产代码库的修改，而是否接受这样一个修改，在今天的多数团队里由一个信号回答：现有测试套件是否仍然通过。这个闸门实现方便、理由充分——套件已经存在、自动运行、失败信号毫不含糊。恰恰是这种便利，使得"这个闸门能看见什么、看不见什么"值得去检验而不是去假设。

然而，一个测试裁决在实践中几乎完全是程序可观察输入/输出行为的函数，因此它在一整类行为完全相同的程序上近乎常数。设计惯例——事物如何命名、哪个模块允许调用哪个模块、两个操作必须以何种顺序发生——恰恰可以在*同一个*行为等价类内部自由变化。一个逆着文档化惯例改名、把调用路由穿过不该跨越的分层边界、或者调换两个最终输出恰好与顺序无关的操作的修改，可以在行为上对套件完全不可见，却正是代码库设计意图所禁止的那种修改。这个缺口是否真实、哪些设计属性类别真正落在其中，从未被测量过——只是被朝着两个方向分别假设过。

最接近的既有工作从 LLM 代码测试一侧和经典软件工程基础一侧逼近这个缺口，在综述更广的图景之前，值得先把两个最近的接触点直接说清：测试用例区分能力的二元矩阵形式化（binary-matrix formalization）是关于"一个测试集能区分和不能区分哪些错误程序变体"的最接近的既有刻画；经典的变异得分（mutation score）文献则是关于测试充分性（test adequacy）本身的最接近的既有刻画——但两者完全围绕*功能上错误*的程序构建，都没有"功能上正确但设计上错误"的变体这一概念。以区分性奖励（discrimination reward）训练测试生成器的工作，纯粹以拒绝功能错误代码的能力为套件打分，因此一个功能正确但违反惯例的变体按该奖励自身的构造总是被接受而非标记。从参考解生成测试的基准构建流水线更直接地做出了同样的承诺，把整个评测建立在功能正确性这一唯一预言机（oracle）之上。而那些在测试套件*之外*还需要形式规格与证明的工作，本身就是"测试对预期行为表达不足"的间接证据，尽管它把这当作基准构建的范围选择，而非对"哪些属性实际被漏掉"的测量刻画。这两簇既有工作——优化功能区分性的 LLM 代码测试路线，以及要么按定义把测试充分性限定于行为、要么在涉及设计一致性时另建机制的经典软件工程路线——并非互不相关：前者提供了应用层面的利害关系（自主智能体正在生成这些工具纯功能性评测的代码），后者提供了理论词汇（变异得分、等价变异体问题），本文将其扩展进两条路线目前都不测量的维度。有一项近期测量值得在此点名而不只是留给相关工作："Does Pass Rate Tell the Whole Story?"（arXiv:2604.05955）已经以观察性方式表明，通过测试的智能体补丁大量违反挖掘出的设计约束，且功能正确性与设计满足度在统计上近乎独立——它确立了绿色补丁*确实*在现场违反设计，但没有回答*闸门为何看不见*：它测量的是补丁总体的合规率，而这里的问题是套件自身的检测边界，通过构造出的、经认证的变体而非观察到的智能体产出来识别。

把这个缺口变成可测量的断言会暴露出它自身的障碍。要认证一个候选变体既真正保持行为、又真正违反惯例，需要两个独立于被测套件的地面真值来源——否则"套件没抓住它"与"它根本不算违规"将无法区分。有些惯例局部于单行代码，但分层与横切规则是调用图或模块边界的属性，普通的单语句变异算子无法在不进行更大规模、更难认证的重写的情况下触及它们。时序与顺序属性是执行轨迹（execution trace）而非最终输出的属性，因此教科书意义上的"杀死"（kill）——最终输出不同——对不改变最终输出的顺序违规在结构上就是盲的。即便构造出了一个违反惯例、保持行为的变体，它的存活本身也不能定论：每个这样的变体按定义也是等价变异体（equivalent mutant），存活可能只反映杀死任何等价变异体的众所周知的困难，与它违反什么无关——而且"某类别被漏掉"的发现只有在同时回答"这是功能测试的永久极限还是更强的套件就能修好"时才有行动意义。

我们的方法把上述每个障碍都变成一个具体的设计决策。候选变异体只有在两个独立于被测套件的预言机——有界差分执行检查与机器可读的惯例检查器——一致认定它既保持行为又违反惯例后，才进入被测集合，因此接纳与否从不由被评测的仪器自身决定。非局部惯例由"在保持调用多重集不变的前提下把调用跨声明边界重定位或重路由"的算子来针对，使变异保持最小、可认证，而非无法认证的大规模重写。杀死判据本身用取自套件自身观察词汇的轨迹顺序断言（决不来自接纳侧检查器，否则检测就成了定义使然）加以扩展，使得最终输出相同的重排序也能登记为违规，而这在仅有输出比对时永远不会表现为行为差异。为排除"存活只是等价变异体普遍难杀"的可能，每个被接纳的设计变异体都配对一个来自同一算子家族的惯例中性变异体，并在两个配对组之间比较杀死概率。为区分结构性极限与数量性极限，同一测量在用能力匹配、区分性优化的测试集增强套件之后重复一次，检验缺口是否在功能测试强度的真实提升下仍然存在。

我们在已自带机器可读命名与分层惯例的成熟开源 Java 与 Python 受试系统上评估该设计，将每个系统未修改的套件与构造出的设计变异体、配对的惯例中性对照、默认功能变异对照臂、以及能力匹配的增强套件进行对比。

概括起来，我们的贡献是：
- 一个双预言机接纳判据：用独立于被测套件的来源认证程序变体同时保持行为且违反惯例，使"套件漏掉了它"成为关于套件的断言，而非关于认证程序自身的断言。
- 一个配对的惯例中性对照：把真正的、惯例特异的测试盲区与杀死任何等价变异体的普遍困难隔离开。
- 对经典输出比对杀死判据的扩展——轨迹顺序断言（trace-order assertions），使时序与顺序违规对基于变异的测量根本上可见。
- 一个能力匹配的增强检验：区分功能测试所能表达内容的结构性极限与更强套件即可弥合的数量性缺口。
- 一份跨命名、分层/横切、时序/顺序类别的实证刻画：成熟测试套件结构上看不见哪些设计属性，以及这对仅凭测试套件成功把关编码智能体变更意味着什么。

## 问题定义

**形式化设定。** 考虑带有现有未修改测试套件 T 的受试程序 P，以及 P 的一个候选变异体 m，属于设计约束类别 c ∈ {NAM（命名）, LAY（分层/横切）, TMP（时序/顺序）}。令 K_T(m) ∈ {0,1} 表示 T 是否杀死 m（某个测试失败；时序类别的杀死判据扩展为包含套件自身执行内可表达的顺序敏感观察——套件既有观察点上的有序 mock 验证与序列断言；接纳侧的轨迹顺序检查器决不计为杀死，理由见方法部分的仪器分离原则）。令 EQ_B(m) ∈ {0,1} 表示有界功能等价——用独立于 T 生成的、规模为 B 的差分执行语料对照 P 认证；令 V(m) ∈ {0,1} 表示一个独立的、机器可读的规则检查器（受试项目自带的命名/分层/轨迹顺序规则）是否判定 m 违反其目标惯例。**被接纳设计变异体集**为 D_c = {m : op(m) ∈ c, EQ_B(m) = 1, V(m) = 1}；**配对中性集** N_c = {m : op(m) ∈ c, EQ_B(m) = 1, V(m) = 0} 共享同一算子家族与局部性足迹但不违反惯例。每类别的**设计变异体存活率**（Design-Mutant Survival Rate）为 DMSR_c = |{m ∈ D_c : K_T(m) = 0}| / |D_c|，与 T 在默认算子下的普通功能变异得分 FMS（存活率 FSR = 1 − FMS）对比。

只有当三个条件同时成立时，一个类别才被报告为真正的、设计特异的、结构性盲区：(a) DMSR_c 相对 FSR 超过预注册的差距；(b) 在 D_c 与配对中性集 N_c 之间比较杀死概率时该差距不再出现（排除普遍的等价变异体效应）；(c) 在用能力匹配的更强功能测试集增强 T 之后差距不闭合（排除数量性解释）。不满足 (a) 的类别报告为不可归类为盲区；仅不满足 (b) 的报告为等价变异体驱动而非设计特异；仅不满足 (c) 的报告为数量受限而非结构性。

**为何困难。** 认证 D_c 成员资格要求 EQ_B 与 V 都来自独立于 T 的来源——否则"T 没能杀死 m"与"m 根本不算违规"（或根本不等价）无法区分，且 EQ_B 本身只在所述预算 B 内可判定，从不是绝对的等价保证。分层/横切类别需要一种算子：在保持调用多重集——因而可观察行为——不变的前提下改变调用相对模块边界的位置，这是比单语句编辑强得多的构造负担。时序/顺序类别暴露了经典杀死判据自身的缺口：纯粹定义为最终输出差异的 K_T(m)，按构造无法登记不改变最终输出的顺序违规，因此判据必须用顺序级检查加以扩展——而且必须同时避开两种方向相反的循环性：*接纳*预言机必须独立于套件（否则"不算违规"与"没被杀死"混为一谈），而*杀死*侧的扩展必须限于套件自身的观察词汇之内（否则，由于接纳已经要求外部轨迹顺序检查器标记该变异体，每个被接纳的时序变异体都会被算作"抓住"，该类别的存活率将按构造钉死在零）。即便以上全部解决，每个 m ∈ D_c 按定义也属于经典等价变异体类，因此单凭 DMSR_c 高于 FSR 的差距无法区分真正的设计盲区与杀死任何等价变异体的普遍困难——这正是与 N_c 的配对中性比较的用途。而今天存在的差距对其是否永久毫无说明：只有能力匹配的功能测试强度的真实提升，才能区分结构性极限与更多更好的功能测试即可消除的极限。

## 方法总览

在概念层面，该测量是一个由七个协作部分组成的单一流水线，围绕一条统治性规则组织：候选程序变体只有在被测套件之外的两个地面真值来源——独立的等价性检查与独立的惯例检查器——一致认定其归属后，才进入测量记录。设计变异体及其配对中性对应物按类别进入流水线；一个跨多受试系统的统计设计把所得的杀死/存活记录转化为条件级画像；能力匹配的增强对照臂则把同一批记录转化为"观察到的缺口是永久的还是仅关乎套件强度"的判定。

**双预言机接纳**模块接收候选变异体，并用独立于被测套件的来源认证它同时保持行为且违反惯例——这是其他所有模块产出都要经过的闸门。**非局部算子目录**构造分层/横切变异：在保持调用多重集的前提下把调用跨声明边界重定位，使非局部惯例根本上可测。**扩展时序杀死判据**在经典输出比对杀死检验之上加入取自套件自身观察点的顺序敏感断言——决不来自接纳侧检查器——使不改变最终输出的顺序违规仍可检测，而不是按定义被检测。**可编码惯例限域**模块把接纳限制在具有机器可读表示的惯例上，并配有经审计的精度闸门：若检查器与人工判断的一致性不达标，该类别降级为探索性。**设计特异性对照**为每个被接纳的设计变异体构建一个配对的惯例中性对应物并比较两者的杀死概率，把真正的惯例盲区与普遍等价变异体效应隔离开。**增强对照臂**在用能力匹配、区分性优化的测试集强化每个套件后重跑测量，区分结构性极限与数量性极限。**多系统、跨类别设计**在两个生态系统的多个受试系统上、在同一个统计模型下测量全部三个类别，使类别级断言是条件的属性而非抽到哪些系统的属性。

## 方法

### 双预言机接纳（Dual-Oracle Admission）

**挑战。** 行为等价与惯例违规在被测对象内部都没有地面真值来源——若任一认证来自被测套件，"套件没杀死它"与"它并非真正等价或违规"将无法区分。

**洞察。** 要求两项认证都来自独立于被测套件的来源，正是把"套件漏掉了它"变成关于套件的断言、而非关于认证程序自身可靠性的断言的关键。

**做法。** 候选变异体只有满足以下两条才被接纳：(i) 用独立于被测套件生成的输入语料运行的有界差分执行检查，在所述输入预算内未发现与原程序的行为差异；(ii) 独立于套件的规则检查器（受试项目自带的命名、分层或轨迹顺序规则）认证其违反目标惯例。两项检查都先对照分层抽样的人工样本审计其自身错误率，然后其下游存活数字才被当作探索性以上的结论。

### 非局部算子目录（Non-Local Operator Catalog）

**挑战。** 分层与横切惯例是调用图或模块边界的属性，不是单条语句的属性，普通的局部变异算子无法在不进行更大规模、更难认证的重写的情况下表达对它们的违反。

**洞察。** 在只破坏分层规则的同时保持调用多重集不变，使变异保持最小且可接纳，而不是变成等价性预言机无法现实认证的大规模结构重写。

**做法。** 一族算子把调用跨声明的模块边界重定位或重路由——例如让上层组件直接调用下层组件的内部——同时保持所发调用的集合及其参数不变，使行为等价性在与局部变异相同的输入预算下仍可认证。

### 扩展时序杀死判据（Extended Temporal Kill Criterion）

**挑战。** 经典杀死判据是最终输出差异；两个操作的顺序若不影响最终输出，其顺序违规按该定义对任何测试都不可见，无论测试多么彻底。

**洞察。** 两种循环性从相反方向威胁这一类别，解决办法是把两件轨迹顺序仪器分派到测量的两侧：*接纳*检查器必须独立于被测套件（否则"不算违规"与"没被杀死"无法区分），而*杀死*侧的扩展只能取材于套件自身的观察词汇——因为接纳已经要求外部轨迹顺序检查器标记该变异体，若同一检查器也计为杀死，则每个被接纳的时序变异体都按定义被抓住，该类别的存活率被钉死在零，对套件毫无说明。

**做法。** 对输出可交换的操作对施加顺序交换算子。杀死判据随之扩展：若*套件自身执行内已可表达*的任一顺序敏感观察被触发——有序 mock 验证、断言序列的测试断言、或套件既有观察点上装配的不变量检查——即便最终输出上没有任何断言会失败，该变异体也额外计为"被抓住"。项目的外部轨迹顺序规则检查器专用于接纳侧地面真值，决不参与 K_T：它定义*该变异体是否违规*，而扩展判据测量的是*套件在获得其全部顺序观察词汇后能否看见它*。

### 可编码惯例限域（Codifiable-Convention Scoping）

**挑战。** 真正隐性或未文档化的惯例完全没有机器可检查的地面真值，但把研究限制在有真值的惯例上，有把整个发现悄悄重定义为"对容易的情形盲"而不明说的风险。

**洞察。** 把这一限制变成明示的、经审计的限域决定——而非未经审视的默认——把一个真实的局限变成读者可以评估的边界条件，而不是一个沉默的边界。

**做法。** 只有可用机器可读规则格式表示的惯例（受试项目已自带或可构建的命名规则、分层规则、轨迹顺序规则）被纳入研究；任一类别的检查器精度若在分层人工审计下低于预注册阈值，该类别报告为探索性而非确证性。

### 设计特异性对照（Design-Specificity Control）

**挑战。** 每个被接纳的设计变异体按构造也是等价变异体，因此观察到的相对功能基线的存活差距可能只反映杀死任何等价变异体的普遍困难，与是否违反惯例无关。

**洞察。** 若套件的杀死概率对配对变异体是否真正违反惯例不携带任何信息，那正是一个惯例盲的套件会产生的结果；反方向的差距反而说明套件通过偶然的结构耦合部分感知到了惯例。

**做法。** 为每个被接纳的设计变异体构造一个来自同一算子家族、同一局部性足迹、同样保持行为但不违反目标惯例的配对变异体。在固定算子家族与局部性的前提下，按类别比较两个配对组的杀死概率。

### 增强对照臂（Augmentation Arm）

**挑战。** 只在一个套件的当前强度下观察到的类别级差距，无法说明该差距是功能测试的永久极限，还是仅仅反映该套件当前的投入水平。

**洞察。** 若差距只是功能测试强度不足，那么该强度的真实、能力匹配的提升——哪怕来自对设计惯例毫无感知的测试——也应使其缩小；在这样的提升下仍存活的差距，是关于功能测试原则上能表达什么的证据，而不只是关于现有测试数量的证据。

**做法。** 用区分性优化的生成测试集增强每个受试套件，其能力由套件自身功能变异得分的预先承诺的提升来验证；在增强前后重测各类别存活率，比较的有效性以该能力提升确实发生为闸门。

### 多系统、跨类别设计（Multi-System, Cross-Category Design）

**挑战。** 从过少、未随机化或过窄的受试系统样本得出的类别级断言，有描述所选系统的特异性而非类别本身属性的风险。

**洞察。** 显式建模系统级变异——而非合并原始计数或凭肉眼检查一两个系统——是让类别级断言在各系统彼此表现不同的情况下仍然成立的关键；同一拟合结构还可重抽样，检验断言不是"恰好纳入了哪些系统"的伪影。

**做法。** 全部三个类别在跨两个生态系统的多个受试系统上测量；一个混合效应模型（mixed-effects model）将杀死结果对变异体类型与类别回归，并对每个系统设随机效应。同一拟合结构另在系统的两个不相交随机半样本上重算，检验类别级分类在划分间一致。

## 实验

### 实验设置

**数据集。** 自带 Checkstyle 与 ArchUnit 配置的 Defects4J 衍生 Java 受试项目——主试点与扩量语料，选择理由是这些项目已自带机器可读的命名与分层地面真值而无需从零撰写。带成熟 pytest 套件与 flake8/import-linter 配置的 Python 子集——跨生态对照臂，用于检验类别结构与半样本发现是否超出单一语言的工具习惯而泛化。约三个额外系统组成的保留集，在主语料固定后抽取，专门保留作半样本可靠性检验的预注册复现集，使该检验不只靠事后重切同一固定语料。

**基线**（用于混杂隔离与合理性检查的比较对象，不是要击败的竞争者——这是一项测量研究，没有任何研究问题被表述为"我们的程序击败基线 X"）。默认功能变异对照臂：在同一未修改套件上用标准算子运行，是定义功能存活率的必要参照，所有设计变异体存活率都与之对比。配对的惯例中性等价变异体对照：由与被接纳设计变异体相同的算子家族与局部性足迹构建但不违反任何惯例，隔离存活是惯例特异的还是仅反映等价变异体普遍难杀。能力匹配的增强套件：用区分性优化的生成测试集强化、并以其自身功能变异得分的提升验证，是"观察到的差距是结构性还是数量受限"的比较对象。

**指标。** 各类别设计变异体存活率及其与功能存活率的对比；被接纳集与其配对中性对照之间的杀死概率差；增强后各类别存活率变化；等价性预言机误标率与违规检查器精度（对照分层人工审计）；类别级分类的半样本一致率。

**研究问题：**
1. RQ1——等价性预言机自身是否足够可信，其认证可被当作地面真值？
2. RQ2——违规检查器自身是否足够精确，其认证可被当作地面真值？
3. RQ3——非局部（分层/横切）算子家族能否以可用的接纳产率构造出来？
4. RQ4——扩展杀死判据是否真的抓住了经典输出比对判据永远抓不住的情形？
5. RQ5——限制在可编码惯例后，仍能接纳足够多的变异体来测量吗？
6. RQ6——存活是惯例违规特异的，还是可由普遍等价变异体效应解释？
7. RQ7——观察到的类别级差距在能力匹配的更强测试套件下是否持续？
8. RQ8——存活率是否随设计属性类别系统性变化？
9. RQ9——类别级分类在受试系统的独立随机子样本间是否稳定？

#### RQ1：等价性预言机自身是否足够可信，其认证可被当作地面真值？

**设置。** 跨类别与系统分层随机抽取至少 300 个被接纳变异体；由人工审计员独立评估每个是否真正保持行为，并与差分执行预言机的认证比较。

**预期结果。** 等价性预言机对照人工审计的误标率低于 5%。

**证伪条件。** 若误标率达到或超过 5% 则被否证——那意味着下游存活数字无法干净地归因于套件而非等价性预言机噪声，相应类别需要收紧等价预算或限制算子家族后其结果才可作确证性处理。

**假设（白话）。** 有界差分执行检查是真实行为等价的足够可信的代理，其认证可为本研究其余部分所依赖。

**指标。** 对照人工审计的等价性预言机误标率，总体与分类别。

#### RQ2：违规检查器自身是否足够精确，其认证可被当作地面真值？

**设置。** 使用与 RQ1 相同的分层人工审计样本，按类别比较机器可读规则检查器的违规裁决与人工审计员的判断。

**预期结果。** 每个类别中检查器精度至少 0.90。

**证伪条件。** 任一类别精度低于 0.90 即对该类别否证——该类别的结果按可编码惯例限域模块的审计精度闸门报告为探索性而非确证性，而不是不声不响地保持全置信度。

#### RQ3：非局部（分层/横切）算子家族能否以可用的接纳产率构造出来？

**设置。** 对每个受试系统施加分层/横切算子家族，记录通过双预言机接纳的候选数量。

**预期结果。** 该类别每个受试系统至少 50 个被接纳变异体。

**证伪条件。** 若多数系统的产率低于每系统 50 个则被否证——那意味着非局部类别只在原则上可构造，规模不足以支撑类别级断言，算子家族需在扩量前修订。

**假设（白话）。** 非局部设计违规可以足够频繁地构造成经认证的变异体来测量，而不只是一个理论类别。

#### RQ4：扩展杀死判据是否真的抓住了经典输出比对判据永远抓不住的情形？

**设置。** 在被接纳的时序/顺序变异体中，识别在差分语料下最终输出确认相同者，并检查其中有多少仍被独立的轨迹顺序检查器标记为违规。

**预期结果。** 至少 50% 的被接纳时序/顺序变异体最终输出确认相同、却被轨迹顺序检查器标记为违规。

**证伪条件。** 若不足一半的被接纳时序/顺序变异体呈现该模式则被否证——那意味着按此操作化的时序类别没有有意义地把顺序违规与最终输出可检测的违规分开，削弱"杀死判据扩展做了真实工作而非重述经典判据"的断言。（方法设计期间考虑并否决了一个裸存在性断言——至少一个这样的变异体——因为太弱而无法失败：在任何非平凡的接纳数量下，单个实例几乎必然出现，构不成有意义的检验。）

**假设（白话）。** 不改变最终输出的顺序违规在被接纳时序变异体中足够常见，使扩展杀死判据承担真实的、承重的工作，而非确认一个近乎空洞的边缘情形。

**指标。** 最终输出确认相同且被轨迹顺序检查器标记为违规的被接纳时序/顺序变异体比例。

#### RQ5：限制在可编码惯例后，仍能接纳足够多的变异体来测量吗？

**设置。** 在应用可编码惯例限域后，跨全部三个类别按类别按系统统计被接纳变异体数量。

**预期结果。** 在 12 个受试系统中至少 9 个里，每类别每系统至少 150 个被接纳变异体——分层/横切类别以其自身 RQ3 的每系统至少 50 个为底线，因此 LAY 产率在 50 到 149 之间不会出现"通过 RQ3 却在本 RQ 失败"的情况。

**证伪条件。** 若不足 12 个系统中的 9 个达标则被否证——那意味着可编码惯例限制无论概念上多么正当，在实践中过窄而无法支撑类别级统计设计，主分析按计划进行前需扩充算子目录或检查器规则集。

**假设（白话）。** 限制在机器可检查的惯例是一个真实的限域选择，但没有窄到让测量无案例可析。

**指标。** 每类别每系统的被接纳变异体计数。

#### RQ6：存活是惯例违规特异的，还是可由普遍等价变异体效应解释？

**设置。** 对每个类别，在固定算子家族与局部性的前提下比较被接纳设计变异体集与其配对惯例中性对照的杀死概率。由于此处支持性结果是一个*小*差异，确证性分析采用双单侧检验（two-one-sided-tests, TOST）等价性程序，预注册边际 0.05，在合并层面（全部系统，混合效应模型内）运行，而不是普通差异检验的"未能拒绝"。合并是功效上的必需，明说如下：在每类别每系统 150 个变异体的预注册底线下，单系统两比例 95% 置信区间最坏情形半宽约 ±0.10——单个系统永远无法确认低于 0.05 的差距——而跨至少 12 个系统合并（每类别每组 n ≥ 1800）后最坏情形半宽约 ±0.03，落在边际之内。有一个类别坦率地更弱：分层/横切的接纳底线更低（每系统 50 个，按 RQ3），其合并最坏情形（每组 n ≥ 600）半宽约 ±0.06——若合并的 LAY 区间无法排除 0.05 边际，该类别的等价性裁决报告为探索性而非确证性，不会不声不响地判为通过。单系统对比在所有情况下仅作描述性报告。

**预期结果。** 合并 TOST 程序在每个类别得出 ±0.05 边际内的等价性结论（两个单侧检验均在 α=0.05 下拒绝）。

**证伪条件。** 若合并 TOST 程序在某个类别未能得出 ±0.05 边际内的等价性结论（无论因为估计差距达到或超过 0.05，还是因为合并区间过宽而无法排除之）则对该类别否证——但注意其指向：此处的*小*差距才是支持真正的、惯例特异盲区断言的结果，因为它表明在等价性已被固定后，套件的杀死行为对违规状态不携带任何信息，从而排除"存活只反映等价变异体普遍难杀"的替代解释。*大*差距（设计变异体存活显著多于或少于配对中性者）反而说明套件通过偶然的结构耦合部分感知了惯例违规——有信息量，但削弱该类别的强盲区断言。读者不应在此预期"差距越大、发现越强"——本 RQ 的极性与本文多数基于差异的检验相反。

**假设（白话）。** 在变异体的行为等价性已被计入后，它是否恰好违反某项设计惯例对套件抓住它的概率不再有影响——套件对惯例本身盲，而不只是普遍不擅长抓等价变异体。

**指标。** 被接纳设计变异体集与其配对中性对照之间杀死概率差的合并 TOST 等价性裁决（边际 ±0.05，α=0.05），分类别，附置信区间；单系统差异作描述性报告。

#### RQ7：观察到的类别级差距在能力匹配的更强测试套件下是否持续？

**设置。** 对非局部类别（分层/横切、时序/顺序），用经验证能使套件功能变异得分至少提升 10 个点的区分性优化生成测试集增强每个受试套件，并在前后重测各类别存活率。

**预期结果。** 增强后的绝对存活率降幅低于 0.10，且在多数受试系统中无统计显著的逐变异体杀死变化。

**证伪条件。** 若增强使非局部类别存活率显著下降 0.10 或更多则被否证——那意味着观察到的差距是数量受限的（更多或更强的功能测试即可弥合）而非功能测试所能表达内容的结构性极限，论文的实践含义将从"需要新的把关机制"转为"继续投资功能测试强度"。

**假设（白话）。** 非局部设计属性的差距并非当前套件投入不足的简单反映；真正更强的功能套件并不能弥合它。

**指标。** 增强后各类别存活率变化，以及逐变异体杀死结果的配对显著性检验，以增强自身的能力提升有效性检查通过为条件。

#### RQ8：存活率是否随设计属性类别系统性变化？

**设置。** 在全部受试系统上拟合预注册的混合效应模型（杀死结果对变异体类型与类别回归，每系统随机效应），检验类别项。

**预期结果。** 在全部受试系统合并下，类别效应统计显著。

**证伪条件。** 若类别效应不显著则被否证——那将支持命名、分层、时序属性上无差别的测试盲，而非特定于非局部性或时序性的结构。

**假设（白话）。** 所报告的类别级结构描述的是被测类别的真实属性，而非恰好纳入哪些具体受试系统的伪影。

**进一步评估。** 若有更多时间，一个自然的延伸是把可编码惯例限制放宽到真正隐性或未文档化的惯例——此处明确出于范围外，因为那需要完全不同的地面真值程序（很可能是专家启发式征询而非机器可读检查器），而非上述双预言机接纳规则的扩展。

## 相关工作

本文最近的两个接触点是测试用例区分能力的二元矩阵形式化与经典变异测试文献自身的测试充分性定义，在综述更广图景前值得把差异说白：两者都给出了"测试套件能与不能区分哪些程序变体"的最接近既有刻画，但都完全围绕*功能上错误*的程序构建——都没有"功能正确却违反设计惯例"的变体概念，而这正是本文接纳程序要认证并测量的对象。这两条既有工作线——优化功能区分性的 LLM 代码测试研究，与要么按定义把充分性限定于行为、要么在涉及设计一致性时另建机制的经典软件工程研究——以一种值得明说的具体方式相互关联：前者提供本文的应用动机（自主编码智能体正在生成这些工具仅按功能评判的代码），后者提供本文向两条线都不测量的维度扩展的理论词汇。

**作为功能正确性预言机的测试与代码评审。** 二元矩阵形式化把错误程序对可信测试用例建模，证明矩阵的秩界定了测试集能分离多少可区分的失败签名——这是区分能力的最接近既有形式化，但每一行按构造都是功能错误的程序，使功能等价却违反惯例的变体成为秩分析不可见的全通过行。对抗训练的测试生成器以区分性奖励为候选套件打分——接受参考实现、拒绝采样的错误程序——按其自身构造总是接受违反惯例但行为相同的变异体，因为该奖励除功能正确性外没有任何通道。聚焦缺陷的自动评审把评测重构为合并请求级关键缺陷检测，仍是功能缺陷目标，对命名、分层或时序惯例没有单独类别。先生成参考解再从中导出执行落地测试的基准构建流水线，在整个流水线层面把功能唯一的承诺写得明白，刻意把"正确"等同于"通过导出的测试"。在测试套件之外为每个任务配备形式规格与证明的基准，本身就是测试对预期行为表达不足的间接证据——但把这当作基准构建的范围选择，而非对测试具体够不着哪些属性的测量刻画。而指出代码与其评判测试可能一起幻觉的多智能体代码生成平台，直接点名了循环性问题，却只靠在同一回路里加更多智能体来解决，没有设计一致性测量所需的那种独立于测试套件的预言机。

**变异测试充分性与架构一致性。** 变异测试的奠基性综述确立了变异得分与等价变异体问题作为该领域的中心障碍——但把两者完全框定在行为变化上：等价变异体按定义是因行为不变而无测试能杀死的变异体，该框架从未问过这样的变异体是否仍违反设计惯例。以已检查覆盖率（checked coverage）评估预言机质量的工作——被执行代码中其结果真正被断言而非仅被运行的比例——揭示成熟套件执行的远多于其检查的，但限于单次执行的输出/断言对，无法刻画像横切关注点或时序顺序这样可能永远不会通过任何单次执行的已检查输出显现的整类属性。经由反射模型（reflexion model）的架构一致性检查专门构建基于模型的机制来比对实现与预期架构，恰恰因为普通测试套件被默认无法检查设计一致性——但这条工作线从未通过套件自身测量该一致性空间实际有多少对其不可见，而这正是本文要产出的机械刻画。

**设计合规测量与轨迹级合规（2026）。** 两簇近期工作在时间上最贴近，必须点名让步。"Does Pass Rate Tell the Whole Story?"（arXiv:2604.05955）从六个仓库的拉取请求中挖掘出 1,787 条设计约束，表明测试解决的智能体议题中完全满足设计者不足一半，且功能正确性与设计满足度统计上近乎独立——迄今为止"绿色套件不是设计闸门"的最强现场证据。我们承认：绿色但违反设计的补丁的*存在与普遍性*因此已被确立；该观察性设计给不出的——也正是本文的估计对象（estimand）——是*套件侧*的刻画：这种漏检是否是功能测试所能表达内容的结构性属性，经由认证的等价变异体、配对惯例中性对照与能力匹配增强对照臂做因果识别，而非今天的智能体恰好如何行为的属性。其次，一条轨迹级程序合规路线——以 AgentLTL（arXiv:2607.02599）为例，它把智能体的工具调用轨迹对照时序逻辑规则做验证，并可据所得合规分数把关或训练——验证的是产出工件的*过程*；本文的估计对象是测试套件自身的*工件级*表达力边界，是不同的对象：一条程序上完全合规的轨迹仍可产出一个违反惯例、行为等价、任何功能测试都无法区分的补丁。

## 结论

本工作把编码智能体变更在实践中被把关方式里内嵌的一个假设——通过的测试套件对设计合规（而不只是功能正确性）有所言说——重构为一个具有精确可识别性结构的可测量问题，而非一个朝任一方向断言的主张。核心方法论赌注是：一个存活差距只有同时越过三道门槛才有信息量——认证它的预言机独立于被测套件、差距被证明是惯例特异的而非普遍等价变异体伪影、且差距在测试套件强度的真实提升下仍然存活。无论哪些类别越过全部三道门槛，发现在两个方向上都与决策相关：越过者意味着对功能测试的任何现实投入都无法关闭那个盲区，设计合规闸门需要根本不同的机制；在增强检验上失败者则意味着修法一直可得，只是投入不足。两个局限从一开始就为该断言划界，且是自然的下一步而非事后附注：研究限于具有机器可读表示的惯例，把真正隐性或未文档化的惯例——很可能是更难也更现实的情形——留给需要完全不同地面真值程序的后续工作；等价性预言机自身的有界预算性质意味着一个类别的盲区地位只强到其经审计的误标率，指向更紧的等价性认证——而非更大的受试系统语料——作为下一个方法论目标。
