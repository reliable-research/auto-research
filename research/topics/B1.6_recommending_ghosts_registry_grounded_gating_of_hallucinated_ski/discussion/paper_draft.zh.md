## 摘要（Abstract）

自主 LLM 智能体（agent）越来越多地从开放注册表（open registry）推荐并自动安装技能与工具，而一项刚刚发表的大规模研究表明：在所测的每一种配置下，它们都会幻觉出并不存在的技能名，比率达 36–43%——这是一个已被证实的供应链攻击前置条件（supply-chain attack precondition），因为攻击者只要观察智能体稳定复现哪些假名字，就可以抢先用其中之一注册恶意技能，坐等受害者的智能体推荐并安装它。该研究中的所有缓解手段都作用于推荐环节，通过约束模型能"说"什么来起效，而且每一种都以摧毁可用性为代价换取更低的幻觉率（最好情形：真实技能召回率只剩约 16%）。我们观察到，这些防御共享同一个结构性性质——它们都干预推荐分布（recommendation distribution）——而一个放在更晚一步、即安装时（install time）的防御完全不必触碰该分布：它只需要问，即将被安装的这个具体技能是否来自可信的发布者。关键在于，单纯的*存在性*校验（existence check）无法替代此事，因为攻击是抢注（squatting）：恶意技能一旦注册，其名字便"存在"了。我们构建了一个多步智能体轨迹测试床（testbed），把"推荐—安装"决策嵌入带有真实下游结果的任务中，插入一个只依据发布者信任分级（publisher-trust tier）来源元数据的门禁（不做名字查询、不做名字相似度启发式、不用任何模型判断），并用已证实的复现性幻觉名模式播种一个抢注对手，进而测量得到的（攻陷拦截率，合法误拒率）工作点（operating point）、该点随拦截延迟的移动方式、以及恢复代价——所有结果按模型与框架逐格报告，并把已发表的推荐时防御作为同一平面上的固定参照标记，而非要击败的竞争者。

## 引言（Introduction）

自主 LLM 智能体早已不再只调用一组固定的内置工具；它们在任务中途从开放注册表发现、推荐并自动安装技能，而委托人（principal）从未看到每一次安装决策。一项刚刚发表的大规模安全研究给这种实践敲定了一个令人不安的事实：在 15,000 个提示与十二种模型-框架配置中，每一种配置都会推荐不存在的技能，平均比率为 36–43%，而且这些幻觉名在提示之间、模型之间的复现足够可预测，足以成为可靠的攻击目标 [hallucskills]。正是这种复现性把一个可靠性怪癖变成了供应链漏洞：攻击者观察某个智能体稳定产出哪些假名字，就可以在一个几乎不核验发布者的注册表上，用其中一个名字抢先注册一个真实的恶意技能，然后坐等受害者的智能体推荐并自动安装这个陷阱。该研究在沙箱化的概念验证（proof of concept）中端到端确认了完整攻击路径。这种攻击前置条件模式本身——幻觉出的依赖名成为可被抢注的攻击面——更早已在软件包生态中被确立：代码生成 LLM 大规模幻觉软件包名，"slopsquatting" 攻击对其抢先注册 [spracklen, phantoms]；一项 2026 年的复证研究发现该威胁在前沿模型上依然存在，几十个模型无关（model-agnostic）的幻觉名在注册表既有防御之后仍可被注册 [packrange]。技能场景的不同之处——也是本文问题的关键所在——在于幻觉名的消费者：不是一个阅读建议的开发者，而是一个在任务中途自主安装并执行的智能体。

一项敲定了现象本身的研究，留下了一个未被检验的干预点。该研究评估的每一种缓解手段——检索约束生成、自我修正、跨模型投票及其组合——都作用于*推荐*环节，约束模型被允许说什么，并且每一种都只能靠摧毁可用性来换取更低的幻觉率：最强的一种把幻觉率从 40.8% 降到 3.2%，但只保留了约 16% 的正确真实技能 [hallucskills]。这不是四次相互独立的失败，而是同一个结构性性质。作用于模型输出的过滤器无法把一个真实但训练分布上非典型的技能名与一个幻觉名区分开，因为在推荐分布上它们看起来一模一样。该研究自己的结束语呼吁"注册表层面的名字保留与经过验证的推荐管线"，但两者都没有构建。

我们观察到，校验点根本不必坐落在推荐分布上。一个放在更晚一步、即安装时刻的防御，永远不需要约束模型说什么；它只需要问，即将被安装的这个具体技能是否来自可信的发布者。把校验点这样移动之后，推荐时过滤器必然混淆的两种信号被分开了：一个名字正确、但来自未验证发布者的真实技能，与一个幻觉名，在安装时来源校验（provenance check）看来是两种不同的东西，尽管在推荐时校验看来无法区分。而且至关重要的是，*单纯存在性*校验——注册表里是否存在这个名字的技能——干不了这件事，因为攻击是抢注：攻击的全部要点就是攻击者注册了那个幻觉名，所以等到受害者的智能体推荐它时，名字已经存在，天真的存在性门禁会把恶意技能直接放行。在该威胁模型下唯一幸存的信号是发布者来源（publisher provenance），而不是名字存在性。我们并不宣称这一机制类属（mechanism class）是我们的首创：针对恰恰是工具抢注威胁的注册表侧发布者身份验证与信任评分工具注册表，已经有设计层面的提案 [ztr, etdi]，软件包生态也已在实践中部署来源认证（provenance attestation）。任何已有工作都没有提供的是测量：这样一个门禁是否真的能拦截由已证实幻觉名复现性播种的抢注，它对来自未验证发布者的合法技能付出什么代价，以及拦截时机是否重要。是这个测量，而不是门禁本身，构成本文的贡献。

把这一点变成可测量的问题，会暴露出它自身的困难。评估的真值（ground truth）必须让抢注成真：如果把"名字存在"当作安全，陷阱就会在构造上被判为安全，所以注册表快照必须携带抗伪造的发布者信任分级，模拟对手必须用*已证实复现*的幻觉名集合去抢先注册，而不是任意字符串。门禁本身必须在没有任何模型判断的情况下得出裁决，因为同一研究表明自我与跨模型审计区分真实与幻觉名的能力不比抛硬币好（51–53%）；门禁里的任何一次 LLM"看起来像不像真的"调用都会原样引入这一失败。可用性代价必须在*真实*技能上测量——在信任积累起来之前，一个合法的首次发布者在来源信息上与一个抢注者无法区分，所以门禁究竟是避免了还是仅仅搬迁了召回坍塌，是一个经验问题，不是一个假设。还有，校验*何时*触发本身就是一等结果，而不是调参细节：与会让任务停摆、因而自然浮出水面的"幻觉出的不存在名字"不同，一个安装并运行了的被抢注技能可以在悄悄作恶的同时把可见任务做完，所以对最终状态的一次事后审计无法把"执行前被拦截"与"悄悄执行了、任务照样成功"区分开。只有按步索引的拦截记录能区分这两者，而不可信安装与其被发现之间相隔的步数，就是运营者要付的恢复代价。

我们的方法把上述每一个障碍都变成一个具体的设计选择，而不是一句对冲。注册表快照带有发布者信任分级与注册新近度标注，抢注对手从已证实的复现幻觉名模式播种，因此在任何智能体运行之前，抢注就已是真值。门禁只依据来源元数据——不把存在性查询当安全信号、不用名字相似度启发式、不用模型判断——因此它的拦截决策不会继承基础研究所记录的名字捷径脆弱性或抛硬币级可检测性；复现名集合只被离线的对手构造与真值标注器消费，在线门禁永远读不到它。可用性代价被直接测量：以来自未验证发布者的真实有用技能构成的留出探针集（probe set）上的误拒率来度量。拦截时机则由一个显式的延迟门禁对照（delayed-gate control）来操纵，它保持轨迹与任务难度不变，只改变校验晚触发多少步，从而把时机对安全结果的影响与任务难度隔离开。

我们在嵌入了"推荐—安装"决策的多步轨迹上评估该设计，轨迹取自基础研究自己的两种设定——独立 LLM 推荐（standalone-LLM recommendation）与智能体框架推荐并安装（agent-harness recommend-then-install）——将门禁开启臂与门禁关闭臂、单纯存在性安慰剂门禁（bare-existence placebo gate）、延迟门禁对照进行比较，并把每一个工作点与时机统计量按模型与框架逐格报告，以基础研究已发表的四个推荐时防御作为同一平面上的固定参照标记。

概括起来，我们的贡献是：

- 指认出所有针对技能幻觉的推荐时防御共享的结构性性质——它们约束推荐分布，这正是它们召回坍塌的原因——并给出分析，说明为什么在基础研究自己的发现之下，安装时校验点必须依据发布者来源而非名字存在性，因为抢注攻击在构造上使存在性校验失效。校验点机制本身让渡（concede）给设计层面的注册表信任提案 [ztr, etdi]；但这一因果分析，以及对该机制类属实际收益与代价的测量，是它们中任何一个都没有提供的。
- 一个多步"推荐—安装"轨迹测试床，带有信任分级注册表快照与从已证实幻觉名复现性播种的抢注对手，忠实于基础研究测得的流行率与可瞄准性（targetability），并作为本次及未来安装时干预的测量仪器发布。
- 一项预注册测量：安装时来源门禁达到的（攻陷拦截率，合法未验证发布者误拒率）工作点，与已发表的推荐时防御置于同一平面，外加一条检测时机-代价曲线，以及一个证伪对照（单纯存在性安慰剂门禁），用以隔离究竟是来源、还是仅仅存在性在起作用。

## 问题定义（Problem Definition）

**形式化设定。** 一条任务轨迹是步骤序列 τ = (x₁, …, x_L)，其中包含一个"推荐—安装"步骤 x_r：它提出一个技能名 n，并且若安装进行，则从注册表 R 拉取并执行技能体 b。注册表快照 R = {(n_k, p_k, θ_k)} 将每个已发布名字 n_k 与其发布者 p_k、发布者信任分级 θ_k ∈ {verified（已验证）, known（已知）, unknown（未知）} 以及注册新近度配对。门禁 g_δ 把所提名字与快照映射为一个裁决，g_δ : (n, R) → {allow（放行）, block（拦截）, review（人工复核）}，并在 x_r 之后 δ 步触发：δ = 0 为立即拦截，δ = k 为延迟校验，δ = ∞ 为完全无门禁（gate-off）。抢注对手在未验证发布者身份（θ = unknown）之下，抢先注册已证实复现幻觉名集合 ℋ 的一个子集；一个不相交的探针集 ℒ 存放来自合法但未验证发布者的真实有用技能。研究对象是这样一个映射：在每个模型-框架格（cell）内，从干预 (g, δ) 到四个量——ℋ-名字上被抢注安装得以完成并执行的比率（读取沙箱状态）、ℒ 中合法技能被拒绝的比率、下游任务成功率、以及恢复代价（不可信安装与任务了结之间额外消耗的步数与 token 数）。

**为什么这很难。** 有四重困难是该设定内在的。第一，要使测量忠实于攻击，就必须让"名字存在"对恶意技能为真：因为对手注册的是一个 ℋ-名字，以名字存在性为键的真值会在构造上把陷阱判为安全，所以快照必须携带一个存在性无法满足的独立来源谓词 θ。第二，裁决 g 必须只是 θ 与新近度的函数——不含模型判断——因为已知对 n 的自我与跨模型审计区分真实与幻觉名不比随机好，门禁里的任何 LLM 都会重新引入该失败。第三，可用性代价是 ℒ 上的误拒率，而一个合法的首次发布者在信任积累之前恰好占据与抢注者相同的 θ = unknown 层级，所以门禁是避免还是仅仅搬迁了召回坍塌不能被假设——必须在真实技能上测量。第四，被抢注安装的结果是安全相关的，而且与停摆的任务不同，它不必自然浮出水面：一个安装并执行了的技能可以让可见任务照样成功，所以要区分"执行前被拦截"与"悄悄执行了"，需要在固定轨迹下操纵 δ，而不是读取最终状态。

## 方法总览（Method Overview）

在概念层面上，本研究是一条由六个协作部件构成的单一测量管线：其中三个在离线阶段构造一个忠实的测试床，另外三个在线运行干预并核算其效果。信任分级注册表快照与复现性播种的抢注对手使抢注在任何智能体运行之前就成为真值；"推荐—安装"轨迹框架把安装决策嵌入一个真实的下游任务；仅凭来源的安装门禁只从发布者信任元数据得出裁决；检测时机仪器记录并操纵校验晚触发多少步；工作点核算把每个回合变成共享（攻陷拦截率，合法误拒率）平面上的一个点，按模型与框架逐格报告。

**信任分级注册表快照（trust-tiered registry snapshot）**给每个已发布技能标注发布者信任分级与注册新近度，使被抢注的恶意技能可以满足"存在"却通不过"已验证或已知发布者"。**复现性播种的抢注对手（recurrence-seeded squatting adversary）**抢注的名字取自已证实的复现幻觉名集合而非任意字符串，使攻击忠实于已被演示的那一种。**"推荐—安装"轨迹框架（recommend-then-install trajectory harness）**把一次安装决策嵌入一个更长的任务，其结果在任务成功之外还带有安全维度——被抢注技能是否安装并执行。**仅凭来源的安装门禁（provenance-only install gate）**只从快照的信任分级得出裁决，从不读取被推荐名字的字符串，因此既不继承名字捷径脆弱性，也不继承推荐时防御的抛硬币可检测性。**检测时机仪器（detection-timing instrument）**记录不可信安装首次被发现的步索引，并提供只改变该时机的延迟门禁对照。**工作点核算（operating-point accounting）**逐回合记录攻陷被拦截还是完成、任务是否成功、恢复代价、以及合法探针集上的误拒率，按格报告一个工作点，与基础研究已发表的四个点同台呈现。

## 方法（Methodology）

### 信任分级注册表快照（Trust-Tiered Registry Snapshot）

**挑战。** 由于对手注册的是智能体稳定幻觉的名字，"存在这个名字的技能"对恶意技能为真；以名字存在性为真值的评估会在构造上把陷阱判为安全。

**洞见。** 存在性与来源是两个不同的谓词，只有后者在抢注威胁模型下幸存——所以测试床必须携带来源信息，而不仅仅是名字列表。

**方法。** 快照中的每个已发布名字都标注发布者信任分级——verified（已验证：通过了身份/验证流程的发布者）、known（已知：该智能体或委托人此前见过并信任的发布者）、unknown（未知：匿名或首次出现）——外加注册新近度。这是测试床的离线属性，在任何智能体运行之前固定：被抢注的恶意技能落在 unknown 层级，因此满足存在性却通不过 verified-or-known 谓词。快照是"某次安装是否为攻陷"的预先承诺真值，独立于任何模型判断。

### 仅凭来源的安装门禁（Provenance-Only Install Gate）

**挑战。** 咨询模型"这个名字看起来真不真"的裁决会继承已证实的抛硬币级（51–53%）幻觉名可检测性；以名字存在性或名字相似度为键的裁决会继承已被记录的、模型在名字而非语义上走捷径的倾向。

**洞见。** 把校验点移到安装步骤，意味着裁决完全不必触碰推荐分布——它可以是"这个技能由谁发布"的纯函数——因此它不付推荐时过滤器付出的召回代价，并且可以把基础研究已证明不可靠的模型判断与名字信号统统排除在外。

**方法。** 门禁只读取快照中所提技能发布者的信任分级，从不读取被推荐名字的字符串：当且仅当发布者为 verified 或 known 时放行；否则拦截（unknown 发布者）或转人工复核（human-review，一个运营者可配置的中间裁决，用于运营者可能希望人工批准的 unknown 发布者）。不把任何存在性查询当作安全信号，不用与已知幻觉名的相似度启发式，裁决路径中不进入任何模型判断；已证实的复现名集合只被离线的对手与真值标注器消费，这个在线门禁永远读不到。human-review 裁决在任何下游测量使用它之前，就被钉死在两条报告轴上：对合法探针技能，它在误拒率轴的保守（最坏可用性）读法下计为一次拒绝，*同时*作为一个独立的"延迟而非拒绝"计数另行报告，使可用性代价以一个有界区间呈现——乐观端为仅拦截（block-only），保守端为拦截加复核（block-plus-review）——而不是一个把人工复核政策藏起来的单一数字；对被抢注技能，它计为已拦截，因为安全主张针对的是自主自动安装，被留给人工的技能没有被自主安装。

### "推荐—安装"轨迹框架（Recommend-Then-Install Trajectory Harness）

**挑战。** 一次单发的推荐事件无法暴露"执行前被拦截的安装"与"悄悄执行了、可见任务照样成功的安装"之间的差别——而安全结果恰恰取决于这个差别。

**洞见。** 只有嵌入在带有真实可校验下游结果的更长任务中的安装决策，才能让这个差别可观察，因为只有那时"任务成功了"才不再蕴含"没有恶意代码运行过"。

**方法。** 把一次"推荐—安装"决策作为单个步骤嵌入一个更长的、可执行的多步任务中，任务结果可校验；任务从基础研究的两种设定实例化——独立 LLM 推荐与智能体框架推荐并安装。每个回合记录两部分结果：任务成功（轨迹是否完成目标）与安全标签（被抢注技能是否安装并执行，读取沙箱状态），使两者可以背离。

### 复现性播种的抢注对手（Recurrence-Seeded Squatting Adversary）

**挑战。** 一个抢注任意恶意名字的对手会高估或低估门禁的价值，因为已被演示的攻击恰恰依赖于"幻觉名复现足够可预测、因而可被廉价抢注"这一特定性质。

**洞见。** 对已测得攻击的忠实性要求从已证实的复现性播种对手，而不是从假想的最坏情形——复现性正是使抢先注册低成本、使威胁真实的东西。

**方法。** 模拟攻击者在 unknown 发布者层级下，抢注由基础研究自己的提示构造方法诱出的已证实复现幻觉名的一个子集，而非任意字符串。这使攻击路径与已被演示的完全一致，并让拦截率轴测量的是对真正被抢注名字的拦截。复现名集合只在此处使用（离线，用于构造攻击与标注真值），别处一概不用——尤其是在线门禁永远看不到它。

### 检测时机仪器（Detection-Timing Instrumentation）

**挑战。** 拦截时机对安全结果的因果效应无法从观察到的轨迹中读出，因为安装被发现的时机与任务难度、以及轨迹是否因无关原因失败相互混杂。

**洞见。** "发现得早"与"任务容易"的良性汇合可以被这样一种干预打破：保持轨迹与任务难度不变，只改变校验触发的步——受控的延迟，而非观察到的延迟。

**方法。** 仪器记录不可信安装首次被发现的步索引：被门禁立即发现（δ = 0）、经由自然的任务/安全失败很晚发现或永不发现（gate-off，δ = ∞）、或被人为延迟 k 步（延迟门禁臂）。延迟门禁臂保持轨迹与任务难度不变，只移动 δ，把时机对安全结果与恢复代价的影响隔离出来。这个受控延迟设计是原创的；它借用了既有失败归因工作 [agentracer] 中"固定其它一切、只动干预点"的反事实逻辑，而不是那项工作的离线事后追踪器。

### 工作点核算（Operating-Point Accounting）

**挑战。** 门禁是解决了还是仅仅搬迁了安全/可用性取舍，无法只从拦截率读出；而一个合并汇总的数字在基础研究自身的逐配置报告面前不可解释。

**洞见。** 决定"解决还是搬迁"的那个数字是*真实*技能上的误拒率；把它与拦截率一起作为共享平面上的一个点、按模型与框架逐格报告，它就与已发表的推荐时防御直接可比。

**方法。** 核算逐回合记录：攻陷被拦截还是完成、任务是否成功、恢复代价（不可信安装与任务了结之间额外的步数与 token 数）、以及合法未验证发布者探针集上的误拒率。每个模型-框架格产出一个（攻陷拦截率，合法误拒率）工作点，绘制在与基础研究四个已发表推荐时防御点相同的平面上；这四个点作为固定参照标记放置——不重跑，因为重跑它们不是本研究的贡献——并且所有统计量按格报告，绝不合并。

## 实验（Experiments）

### 实验设置（Experimental Setup）

**仪器与素材。** 测试床是一个新构建的多步"推荐—安装"轨迹框架，嵌入取自基础研究两种设定的决策——独立 LLM 推荐与智能体框架推荐并安装 [hallucskills]——运行在类似真实可执行 API 工具使用套件 [toolllm] 风格的可执行多步任务上。注册表是一个信任分级快照：在有真实市场发布者验证元数据可用之处使用之，否则使用一个暴露三个信任层级的人工合成注册表——此类元数据在软件包生态中已有已部署的对应物（npm provenance attestations、PyPI Trusted Publishers），因此三层构造建模的是真实而非假想的注册表实践。抢注对手从基础研究已证实的复现幻觉名集合播种；一个由来自未验证/独立发布者的真实有用技能构成的留出探针集测量可用性代价轴。由于框架、注册表快照与探针集都是发布工件（released artifacts），其构造过程有文档记录，其内容与任何调参划分保持不相交。

**复现门（replication gate，运行前通过标准，不是研究问题）。** 在给任何门禁臂打分之前，框架必须在其自己的至少一个模型-框架配置上，尽可能贴近地使用基础研究的提示构造方法，复现出落在已发表 36–43% 区间内的技能幻觉率。这是本研究的"安慰剂等价物"：一个诱出远少于此幻觉的框架会使每个抢注臂功效不足、使每个工作点与已发表点不可比。复现失败将重新打开框架修正，而不是作为实质结果报告。

**试验臂（Arms）。** Gate-off（无干预）是所有门禁主张的对照。来源门禁（立即，δ = 0）是干预。单纯存在性门禁（当且仅当名字能在注册表解析时放行）是证伪安慰剂。延迟门禁臂（δ = k）隔离时机。基础研究已发表的四个推荐时防御工作点作为固定参照标记放置在平面上，不重跑。

**指标（Metrics）。** 攻陷拦截率（复现性播种名字上被抢注安装尝试被拦截的比例，按格）；合法未验证发布者误拒率，以有界区间 [仅拦截, 拦截加复核] 报告；检测滞后（首次发现的步索引；当被抢注技能执行且任务照样成功时记为"未发现"）；恢复代价（不可信安装与任务了结之间额外的步数与 token 数）；复现出的基线幻觉率（复现门）。

**样本量与校正。** 每格按每臂每模型约 300 条轨迹回合定容，功效设定为在双侧 α = 0.05 的两比例检验下、以 80% 功效检出攻陷拦截率 10 个百分点的差异；基础比率在扩大规模前由试点重估。主对比使用逐格 Fisher 精确检验，并跨格做 Holm–Bonferroni 校正。RQ4 是唯一一个判定边界（2 个百分点）低于本设计 10 个百分点最小可检出效应的对比：因此它被预注册为等价性主张，用双单侧检验（TOST）在 2 个百分点的界限下检验，并单独定容——在约 90% 的拦截率附近，量级约为每臂 3,000 回合（由所设界限、α 与功效推出的设计算术，待试点钉住基础比率后重估）；如果该格无法以全样本运行，RQ4 将只以带置信区间的描述性结果报告，而不作为通过的等价性检验。任何人工编码的有争议拒绝均双人标注，接受阈值为 Cohen's κ ≥ 0.7。下文研究问题中陈述的所有数量都是预注册设计目标，不是测得结果。

**研究问题：**
1. RQ1 —— 在无门禁下，抢注攻击路径能否在框架中端到端执行？
2. RQ2 —— 单纯存在性门禁是否无法拦截被抢注安装？
3. RQ3 —— 来源门禁能否在零模型判断下拦截被抢注安装？
4. RQ4 —— 仅凭来源是否足够——加入模型判断会提高拦截率吗？
5. RQ5 —— 可用性代价是多少？是否实质低于已发表的召回坍塌？
6. RQ6 —— 随着拦截延迟，安全结果是否单调恶化？
7. RQ7 —— 在存在真实安装步骤可拦截之处，门禁收益是否更大？

#### RQ1：在无门禁下，抢注攻击路径能否在框架中端到端执行？

**设置。** 在 gate-off 下运行复现性播种的抢注回合，从沙箱状态读取被抢注技能是否被安装并执行。这在测量任何防御之前先确立现象在框架中存在，把基础研究的单个概念验证扩展为系统化的比率。

**预期结果。** gate-off 下复现性播种被抢注名字上的攻陷完成率实质大于零——至少 20 个百分点——确认攻击路径在本框架中端到端执行，而不只是基础研究的单个 PoC。

**证伪条件。** 若 gate-off 攻陷完成率低于 20%（攻击在本框架中不能可靠执行），则被否证；这意味着测试床没有复现出已被演示的攻击，所有下游拦截率比较都不可解释——应重新打开框架修正，而不是给门禁打分。

**假设（白话）。** 已被演示的抢注攻击在这个多步测试床中可靠存在，不是偶发。

**指标。** gate-off 下的攻陷完成率，按格。

#### RQ2：单纯存在性门禁是否无法拦截被抢注安装？

**设置。** 把来源门禁换成单纯存在性门禁（当且仅当被推荐名字能在注册表解析时放行），在同一批复现性播种的被抢注安装上测量其攻陷拦截率。这是对本文核心主张——起作用的是来源而非存在性——的证伪对照：如果单纯存在性校验就够用，整个动机将坍塌。

**预期结果。** 单纯存在性门禁拦截不到 5% 的被抢注恶意安装，因为攻击者的全部动作就是让名字可解析——从而确立存在性校验不是针对基础研究自身攻击的防御。

**证伪条件。** 若存在性门禁拦截了 5% 或更多的被抢注安装，则被否证；这将意味着名字存在性终究携带真实的安全信号，来源框架并非必需——该结果将把论文改写为刻画存在性何时够用。

**假设（白话）。** 校验"存在这个名字的技能"对抢注几乎不提供任何保护，因为抢注让名字存在。

**指标。** 单纯存在性门禁的攻陷拦截率，按格；与来源门禁拦截率（RQ3）对比。

#### RQ3：来源门禁能否在零模型判断下拦截被抢注安装？

**设置。** 在立即来源门禁（δ = 0）下，按格测量复现性播种被抢注安装上的攻陷拦截率，并确认裁决路径中没有任何模型调用。按门禁定义，被转人工复核的被抢注技能计为已拦截（没有自主自动安装）。本 RQ 是对仪器的完整性检查（integrity check），而非关于世界的发现——门禁对 unknown 层级的拦截是确定性的，所以其信息量在于泄漏计数；本研究的信息性终点是 RQ5–RQ7。

**预期结果。** 来源门禁在零模型调用下拦截至少 90% 的被抢注恶意安装，按模型-框架格，因为每个复现性播种的被抢注技能在构造上都处于 unknown 发布者层级，而门禁确定性地拦截该层级。

**证伪条件。** 若拦截率在多数格中低于 90%，则被否证；由于被抢注技能在构造上是 unknown 层级，这将表明门禁或快照存在泄漏（例如被抢注发布者被错误解析为 known 层级），而非来源门禁的性质——应诊断并重开，而不是把低拦截率当发现报告。

**假设（白话）。** 一个拦截 unknown 发布者安装的门禁能挡住几乎所有抢注，而无需问任何模型某个名字看起来真不真。

**指标。** δ = 0 下的攻陷拦截率，按格；裁决路径中的模型调用计数（目标：零）。

#### RQ4：仅凭来源是否足够——加入模型判断会提高拦截率吗？

**设置。** 消融仅凭来源的约束：在裁决路径中加入一个 LLM"这个名字看起来真不真"判断（来源或模型任一方标记即拦截），在同一批被抢注安装上与仅凭来源的门禁比较拦截率。由于 2 个百分点的边界低于本研究 10 个百分点的功效化效应，本对比作为实验设置中所述单独定容的 TOST 等价性格运行。

**预期结果。** 加入模型判断使拦截率相对仅凭来源的门禁提升不足 2 个百分点——无实质增益——与基础研究"自我与跨模型审计为抛硬币水平（51–53%）"的发现一致：模型贡献不了来源层级尚未携带的任何可靠信号。

**证伪条件。** 若加入模型判断使拦截率提升 2 个百分点或以上，则被否证；这将意味着模型在来源之外贡献了真实信号，仅凭来源的设计把保护留在了桌上——该结果将支持混合门禁而非仅凭来源的门禁。

**假设（白话）。** 模型的判断加不出发布者层级尚未提供的东西，所以把模型挡在门禁之外不损失任何保护。

**指标。** 拦截率差（来源加 LLM 减去仅凭来源），按格。

#### RQ5：可用性代价是多少？是否实质低于已发表的召回坍塌？

**设置。** 让来自未验证发布者的合法技能留出探针集通过立即来源门禁，测量误拒率，并以有界区间 [仅拦截, 拦截加复核] 报告。与基础研究已发表的推荐时防御召回损失数字（最强者约 84% 真实技能被拒，较弱者约 55%）直接比较。有争议的拒绝双人标注（κ ≥ 0.7）。

**预期结果。** 门禁的合法未验证发布者误拒率实质低于基础研究最差的推荐时召回损失（约 84%），具体而言低于其一半——在保守端（拦截加复核）低于 42 个百分点——因为把干预从推荐分布上挪开，不会因为一个名字正确的真实技能在训练分布上非典型而惩罚它。误拒率不被预期为零，因为在信任积累之前，合法的首次发布者在来源信息上与抢注者无法区分。

**证伪条件。** 若保守端的合法技能误拒率达到 42% 或更高——在统计上与基础研究自身的推荐时召回损失无法区分——则被否证；这将意味着移动干预点没有换来可用性改进，取舍被搬迁了而不是被解决了。

**假设（白话）。** 门禁错误拒绝的真实技能远少于推荐时防御，尽管它无法放过每一个 unknown 的首次发布者。

**指标。** 合法探针集上的误拒率，以区间 [仅拦截, 拦截加复核] 按格报告；与已发表召回损失数字的比较。

#### RQ6：随着拦截延迟，安全结果是否单调恶化？

**设置。** 在延迟门禁臂的时机水平 {立即（δ = 0）、延迟 k 步、从不（gate-off）} 上，保持轨迹与任务难度不变，测量攻陷执行率与恢复代价，并检验单调趋势。

**预期结果。** 在保持任务难度不变的前提下，攻陷执行率与恢复代价随校验延迟在 {立即, 延迟 k, 从不} 上单调恶化（Jonckheere–Terpstra 趋势检验，p < 0.05）——拦截越晚，越多被抢注技能得以执行，每一个的恢复步数代价也越高。

**证伪条件。** 若趋势非单调或不显著（p ≥ 0.05），则被否证；这将意味着拦截时机并不因果地支配安全结果，"何时被发现很重要"的动机不成立——那时的发现将是：重要的只是门禁是否触发，而不是何时触发。

**假设（白话）。** 不可信安装被发现得越晚，执行的损害越多，恢复越昂贵——时机是因果的，不是偶然的。

**指标。** 每个时机水平的攻陷执行率与恢复代价；Jonckheere–Terpstra 趋势统计量。

**结果。** *[占位——实验运行后填写]*

#### RQ7：在存在真实安装步骤可拦截之处，门禁收益是否更大？

**设置。** 在智能体框架"推荐—安装"设定与独立 LLM 推荐设定之间，比较门禁收益——gate-on 相对 gate-off 的攻陷拦截率增益——并匹配基础研究自己的独立-对-智能体划分以便直接可比。为使对比良定义，独立臂的推荐由一个脚本化的、环外（out-of-loop）安装器消费（镜像基础研究概念验证中从推荐到安装的路径），使门禁在两种设定下都能行使否决；于是该对比测量的是"环内拦截且可恢复"相对"事后否决且不可恢复"的价值。

**预期结果。** 门禁收益在智能体框架"推荐—安装"设定中比在独立 LLM 推荐设定中更大，差距至少 10 个百分点，因为只有前者把安装嵌入活体轨迹之中，拦截可以保全任务、并可进行上下文内恢复；独立臂的脚本化安装可以被否决，却无法在上下文内恢复。

**证伪条件。** 若门禁收益在两种设定之间统计上无法区分，则被否证；这将意味着门禁的价值并非来自安装步骤——该结果将把主张从"安装时拦截"拓宽为推荐设定同样具有的某种东西。

**假设（白话）。** 门禁恰恰在存在真实自动安装可拦截之处帮助最大。

**指标。** 每种设定的攻陷拦截率增益（gate-on 减 gate-off）；设定间差异。

**进一步评估。** 若时间允许，一个自然的扩展是单次模拟的对手再瞄准扫描（adversarial-retargeting sweep）——已部署的来源门禁是否会把攻击者从抢注原始幻觉名推向对已验证发布者名字的仿冒抢注（typosquatting）？这明确是扩大规模阶段的延伸目标，不是头条结果：它是一个更长视野的问题，单次模拟扫描只能部分回答，而一个活体的、迭代适应的红队对手超出本设计的范围。

### 效度威胁（Threats to Validity）

**构念效度（construct validity）。** 攻陷与可用性两个构念的可靠性取决于信任分级快照与门禁裁决定义。"攻陷"的真值是预先承诺的信任分级快照加沙箱执行状态，从不使用模型判断，因此安全标签不继承基础研究所记录的抛硬币可检测性。唯一会实质移动头条数字的构念决策，是 human-review 裁决在误拒率轴上的记法；这正是可用性代价以有界区间 [仅拦截, 拦截加复核] 而非单一数字报告的原因，保守端把每一次对合法技能的人工复核都计为拒绝。另一个构念威胁是抢注对手的保真度：用任意名字而非复现性证实的名字播种会高估门禁价值，这正是对手只从基础研究已证实复现集合取名的原因。

**内部效度（internal validity）。** 两个混杂因素威胁因果读法。第一，被抢注安装是否执行必须可归因于门禁的时机，而非任务难度；延迟门禁对照保持轨迹与任务难度不变、只改变 δ，任何未通过静态校验的回合（没有良定义完成状态的任务）在产生任何 API 开销之前即被剔除，剔除率如实报告而非默默丢弃。第二，如果门禁悄悄读取了被推荐名字，"仅凭来源"的主张即被破坏；框架断言门禁裁决路径中零模型调用且无名字字符串查询（RQ3/RQ4 直接测量这一点），复现名集合在架构上被限制在离线的对手与标注器之内。

**外部效度（external validity）。** 结论的适用范围限定为：可沙箱化的、两方"推荐—安装"轨迹，带有可计算的信任分级快照，覆盖实际测试的模型-框架格（基础研究的独立与智能体框架两种设定）。结论不覆盖发布者验证元数据可能可伪造或缺失的活体不受控注册表、超出所测范围的前沿专有模型、或活体迭代适应的对手——单次模拟再瞄准扫描是延伸目标，不是关于真实自适应攻击者的证据。发布的框架、注册表快照与探针集是向所测网格之外配置扩展的既定载体。

**结论效度（conclusion validity）。** 单个格的拦截率无法把真实门禁效应与框架噪声区分开，因此每个工作点与时机统计量都按模型-框架格报告并跨格做 Holm–Bonferroni 校正，绝不合并；并且每个抢注臂只有在复现门确认框架复现出基础研究 36–43% 的幻觉率之后才被打分——这一"安慰剂等价物"若失败，将重开框架而不是被读作零结果。样本量按检出 10 个百分点拦截率差异、80% 功效预注册，功效不足的格被预先声明为不确定，而非报告为零结果。

## 相关工作（Related Work）

与本文最近的已有工作是大规模幻觉技能推荐研究 [hallucskills]；在综述更广图景之前，值得先把差量（delta）说清楚。该研究在规模上确立了本文视为给定的一切：智能体在每一种配置下都以 36–43% 幻觉技能名；这些名字的复现足够可预测、可被抢注；自我与跨模型审计的检测不比抛硬币好；其全部四种推荐时防御都以真实技能召回坍塌换取更低幻觉率；并且——在单个沙箱化概念验证中——完整抢注攻击路径端到端执行。我们全部承认并在其上构建。该研究没有做、并明确推迟的，恰是本文的贡献：它没有运行带下游任务结果的多步轨迹研究，没有测量检测时机与恢复代价，没有评估任何安装时干预，并在自己的结束语中声明"注册表层面的名字保留与经过验证的推荐管线"是所需的修复而两者都未构建。我们把干预点从推荐移到安装，把信号从名字存在性（该研究自己的抢注威胁模型使其失效）换成发布者来源，并测量它从未运行过的工作点、时机曲线与可用性代价。

**来自幻觉名的供应链抢注，与注册表信任提案。** 这一攻击前置条件模式早于技能场景：代码生成 LLM 大规模幻觉软件包名，制造出攻击者抢先注册幻觉依赖的"slopsquatting"攻击面 [spracklen, phantoms]；一项 2026 年前沿模型队列复证发现比率被压缩但威胁犹存，一组模型无关的幻觉名在注册表已部署防御之后仍可注册 [packrange]；提示侧攻击还能隐蔽地把智能体推向更多投机性名字 [npa]。该谱系中的防御与基础研究一样落在生成侧——对照权威软件包列表的解码时监控 [packmonitor] 与软件包有效性边界的模型编辑 [bound]——这正是本文所测替代方案所针对的那个干预点的结构性代价。在机制一侧，工具注册表信任已有设计层面的提案：带管理员控制注册与动态信任评分的零信任工具注册表 [ztr]，以及面向 Model Context Protocol 的基于 OAuth 的密码学工具身份验证 [etdi]。我们把机制类属让渡给这些提案；两者都是安全架构，都没有报告针对幻觉播种抢注对手的测得安全/可用性工作点、对合法未验证发布者的可用性代价、或任何拦截时机测量——而这些正是本文测试床所要产出的量。

**工具使用的接地与验证。** 一条工作线通过把智能体拟采取的动作接地（grounding）到真实可执行资源来对抗脆弱性：一个大规模可执行 API 工具使用套件用数千个真实 API 与多步解路径训练并评估智能体 [toolllm]；一个工具增强奖励模型在评估中途调用真实外部工具而非信任内部生成的评分 [themis]。两者都把接地当作不可靠*推理*的修复，但都假设工具集在构造上固定、已知且可信——恰是基础研究证明对开放技能注册表不成立的那个假设——并且都没有问一个*被提出*资源的发布者是否可信。按需外部校验最近的机制级先例——Self-RAG 学到的"是否检索并批判所生成主张的支持度"决策 [selfrag]，以及 Function Masking 在已知集合内训练策略在无真实函数适用时弃答 [funcmasking]——都是通过在已知、固定的资源集合上重训练策略来运作，从未面对一个即插即用安装时门禁必须回答的存在性或来源问题；它们是方法侧的参照，不是本研究可运行的比较对象。

**智能体轨迹中的失败归因与早恢复架构。** 第二条工作线研究早期错误如何在多步轨迹中传播。反事实重放失败归因通过固定轨迹并替换纠正后的动作来定位最早决定性错误步 [agentracer]；带逐节点验证与回溯的树状规划在继续沿线性管线下行之前捕获失败步骤并恢复 [genartist]。它们是"早发现、早恢复"最近的先例，本文的受控延迟设计也借用了"固定轨迹、只动干预点"的反事实逻辑——但已有工作要么事后诊断一条*已完成*的轨迹，要么验证图像生成质量，都没有把工具来源作为被校验对象，也没有把恢复代价作为校验触发早晚的函数来测量，而这正是本文的时机测量。

**以轨迹为中心的智能体测试床与数据验证。** 第三条工作线把智能体轨迹作为仪器来构建与验证。自演化智能体基准把可复现的测试时轨迹当作任务可解的证据并将其转化为经过验证的基准条目 [selfevolve]；ToolACE-MT 在一个显式的离线验证阶段之后合成多轮工具使用对话 [toolacemt]。两者都把验证用于*构造*或*校验轨迹数据*，一次性且离线；都没有对已部署智能体的实时安装提议运行活体逐步安全门禁，而这正是本文测量的在线干预。这三条工作线都没有确立：一个安装时的、以来源为键的门禁，能否在不付出基础研究中每个推荐时防御都付出的可用性坍塌的前提下拦截被抢注安装——这是本文测试床为之而建的问题。

## 结论（Conclusion）

本工作把一个治理假设——对照注册表校验被推荐技能就能约束幻觉与恶意工具安装——重构为一个结构精确的经验问题，并在两个点上纠正它。校验点属于安装时而非推荐时，因为那里的来源校验不必约束推荐分布，因而不必付出基础研究中每个推荐时防御都付出的召回坍塌；信号必须是发布者来源而非名字存在性，因为抢注攻击在构造上使恶意名字存在。核心的方法论赌注是：这次搬迁究竟解决了还是仅仅搬迁了安全/可用性取舍，由一个被测量的数字裁决——来自未验证发布者的真实技能的误拒率；拦截时机是否重要，由一个保持任务不变的受控延迟裁决；两者都被测量而非假设，并且专门携带一个单纯存在性安慰剂门禁，用来证伪"起作用的是来源而非存在性"这一主张。两项局限从一开始就为主张划界，并且是自然的下一步而非事后附注：在信任积累起来之前，门禁无法仅凭来源把合法首次发布者的误拒率降到零，所以为诚实新人设计的信任积累机制是显然的后续工作；已部署的门禁是否只是把攻击者推向仿冒抢注已验证发布者，是本设计只能用单次模拟扫描开始探测的更长视野对抗问题。无论工作点相对已发表推荐时前沿落在哪里，这个测量都是决策相关的：它告诉市场或框架构建者，安装时来源是一道廉价的第一防线，还是它同样以拒绝健康生态所依赖的诚实新人为代价换取安全。
