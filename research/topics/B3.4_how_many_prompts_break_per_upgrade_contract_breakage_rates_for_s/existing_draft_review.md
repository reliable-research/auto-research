## Architecture

**Study type**: empirical *measurement-validation* study. The deliverable is not a benchmark score but an **identification procedure** that turns contract breakage under LLM version upgrades into five identified quantities: noise-adjusted excess breakage **∆B** (with symmetric fix rate **F**), contract half-life **t½** (upgrades until half a cohort has broken), compounding sign **γ** (super-/sub-linear accumulation, split γ_cum/γ_dur), misattribution rate **M** (surface reformatting vs genuine capability loss), and per-genre **structural fragility predictors**. "Identified" is defined operationally: each quantity must be separated from three named rivals — within-version sampling churn, a globally-shifted model (uniform capability change), and generic cheap-to-detect drift.

**Pipeline stages (three modules on one shared data plane)**:
1. **M3 — Frozen contract library (substrate)**: mine ~3000 real contracts, ≥500 per genre across three genres (JSON schemas from GitHub/SchemaStore, formatting conventions from API docs, few-shot templates from prompt repos; sources also include IFEval-style rules, WildChat, BFCL). Each compiles to a deterministic executable predicate (schema validator / regex-grammar checker / slot verifier) evaluated on *unconstrained* decoding, iterated against double-blind human adjudication to κ≥0.8 and ≥0.95 agreement, then hashed and frozen **before any model version is queried**. Each contract carries a mechanical feature vector (nesting depth, constraint count, regex complexity, required-field count, enum cardinality, template rigidity) and — where its content admits a closed-form predicate — an **anchor probe** (same task with all format clauses deleted, scored by numeric-equality/string-match/set-membership). Target ≥80% anchor coverage per genre; the anchor-less stratum is excluded from headline quantities and reported descriptively.
2. **M2 — Surface-vs-capability boundary**: a frozen genre-specific canonicalization pipeline where every transform must both byte-level round-trip and preserve a parsed-value content invariant (JSON parse-tree equality mod key order; capture-group equality for conventions; verbatim slot equality for few-shot). JSON scope is honest by construction: only envelope and serialization failures are recoverable; parse-tree-visible failures are capability *by definition*. M is reported as a **bracket [M_low, M_high]** of genuine one-sided confidence bounds with a Bonferroni-allocated ≤5% simultaneous error budget, including a worst-case audit-mislabeling correction (largest-admissible true surface fraction under rater confusion rates φ⁺/φ⁻).
3. **M1 — Upgrade-attribution estimator**: the core identification move. For each contract×transition, ONE reserved held-out draw yields the binary response y_ct (pass at t−1 → fail at t); a contract-specific null flip probability **q_ct = 1 − π_ct·(1 − ω_nonsamp)** is *constructed*, where π_ct = logistic(logit(p_c) + λ_g·δ_t) maps the anchor-measured uniform capability shift δ_t onto the contract's own base rate p_c via a genre sensitivity λ_g calibrated once on synthetic perturbation checkpoints (admission requires TOST equivalence on per-feature format sensitivity + a feature-independent residual format bound + a ≥80% power gate). ∆B, F, hazards, t½, γ, and the fragility regression all consume the *same* single-draw panel against the *same* null — the draft is emphatic (and repeatedly self-correcting) about avoiding sampling-churn double-counting so the placebo null is exactly 1−p_c. γ_cum is identified from a **multi-lineage frailty cloglog hazard** (L≥3 lineages with interleaved cadence, calendar+lineage fixed effects, cumulative-magnitude covariates, selection-aware parametric-bootstrap null).

**Testbeds / ground-truth mechanism** (this is a measurement-validation design, so most arms have injected truth):
- **D1** pseudo-lineages of open-weight checkpoints with injected quantization/LoRA-delta "upgrades" (known ∆B and break timing → known true t½); ≥120 lineages for half-life precision.
- **D2** constructed multi-lineage panels with injected γ regimes (γ>0 / γ<0 / γ=0 frailty-only).
- **D3** real lineages: Llama, Qwen, Mistral (≥10 dated transitions each, checkpoints pinned by hash) plus dated closed-API snapshots — external-validity arm with a full replay protocol (archived raw outputs so analyses are recomputable without re-querying).
- **D5–D7** held-out adjudicated failures (≥500), injected mutation pools with known surface fraction s*, and ~200/genre structural-twin pairs (depth / required-field / rigidity manipulation bundles with matched control twins) for causal attribution of fragility features.

**IVs**: version transition (real or injected), contract structural features, genre, lineage, cumulative exposure E_ct. **DVs**: reserved-draw flips → ∆B, F, t½, γ, M bracket, predictor AUC and coefficients. **Arms/baselines**: naive two-snapshot mismatch (Chen et al.) — expected to overestimate ≥50%; Dima-style drift detector — expected to false-alarm >20% on placebo; IFEval-style loose match — expected ≥30% capability→surface misclassification; genre+base-rate predictor (AUC≤0.55 null); γ=0 static-frailty null. Ten RQs each carry pre-registered checkable thresholds; notably, **t½ and γ recovery are "descriptive-pending-promotion"** — deliberately not yet committed hypotheses, with a pre-registered decision rule scoping the confirmatory headline to ∆B, M, and fragility predictors if promotion doesn't happen by analysis freeze.

**Follow-on: Contract-Aware Version Routing (6829d7ef)**. Direct downstream consumer: it refers to the main study as "COMPACT" and takes its frozen fragility features plus prior-transition ∆B/M aggregates as given inputs, then solves the serving-time decision the main study leaves open — which addressable version should serve each contract, under a freshness/cost budget, with *no oracle access* to the chosen version's outcome. Method is a train-free similarity-weighted non-parametric breakage-risk estimator plus a hysteresis re-routing policy, evaluated by counterfactual offline replay against always-latest / always-pinned / blind-recompilation / drift-signal-only baselines. It is strictly blocked on the main study's data existing (its evaluation replays the main study's collected transition outcomes), so it is correctly a second paper, and it usefully cites SE prior work the main draft misses (Ma et al. CAIN 2024 on silent LLM API update regressions; Chishti et al. 2026 whole-upgrade gating).

## Novelty highlight

**Sharpest claim**: nobody has measured what fraction of a *deployed contract library* a model upgrade breaks as an **identified** quantity — prior work either shows drift exists (raw two-snapshot mismatch) or detects that a model changed (binary signal), but none separates upgrade-attributable breakage from sampling churn, uniform capability shift, and surface reformatting, and none defines contract **half-life** or **compounding sign** at all. The construction of the per-contract null q_ct from an explicit generative model of the reserved draw's only randomness (with the anchor logit-offset carrying the uniform-shift counterfactual) is the paper's genuinely new estimand machinery; the M bracket with a coverage guarantee under adversarial audit mislabeling is a second, separable methodological novelty.

**Nearest prior as the draft states it**: Chen, Zaharia & Zou 2023 (GPT March/June drift — the naive baseline it must beat by construction), Dima et al. 2024 ("You've Changed" black-box change detection — the cheap-drift rival), JSONSchemaBench / IFEval / FORMATSPREAD (single-snapshot compliance, no temporal axis), Miller 2024 / Madaan et al. 2024 (eval-variance statistics without cross-version attribution), Positive-Congruent Training (negative flips, but training-side and unidentified). The related-work axes (static vs longitudinal × drift vs contract × raw vs noise-adjusted) are well drawn.

**What the draft's related work is missing** (known to us, not cited in the main job): (a) the SE-side silent-update literature its own follow-on cites — **Ma et al. CAIN 2024** (documented prompt regressions across silent LLM API updates) and **Chishti et al. 2026** (deployer-side update gating) — both strengthen motivation and must be positioned against; (b) **provider-enforced structured outputs** (JSON-schema modes / constrained decoding now default in major APIs), which is a genuine threat-to-motivation for the JSON genre — the draft implicitly answers it by measuring *native* passing behavior and by having two non-JSON genres, but never says so explicitly; (c) the 2025–26 wave of statistically-rigorous eval work beyond Miller/Madaan. **Operational delta** vs all of these: an estimand + identification design (nulls, anchors, brackets, pre-registration), not a new benchmark or detector.

**Is the novelty load-bearing?** Yes, doubly. The identification framework is the entire methods contribution — without it the paper collapses to "Chen et al. with more models." And the empirical headline (actual ∆B, t½, fragility coefficients on real lineages) is what makes it a paper anyone cites; that half currently has **zero data**. The design is unusually well-armored (placebo nulls, TOST admission gates, pre-registered fallbacks), which is itself a reviewable strength, but also means the paper lives or dies on executing the plan, not on the idea.

## Freshness check vs 2026-08

- **RLVR/verifier crowding**: minimal exposure. B3.4 sits in the external-audit cluster, not the execution-oracle/RLVR lane where the verifier subfield has crystallized; its oracle is a deterministic predicate over *provider* outputs, not a training-time reward. If anything the crowding helps differentiation. Worth one positioning sentence distinguishing contract breakage measurement from verifier-gaming/RLVR work so ICLR reviewers don't mis-shelve it.
- **Production acceptance-gap evidence**: absent (verified — no ReactBench / Faros / METR mentions anywhere in the three files). The motivation currently rests on the Chen et al. 2023 anecdote and a markdown-fence episode. The new production numbers — ReactBench's 60.8% green-tests-fail-static-analysis, Faros's 31.3% zero-review merges with defect rate rising 9%→54%, METR merge-rate data — are about a *sibling* gap (accepting LLM work without adequate verification) but transfer directly to intro ¶2's "dashboards look stable while contracted behavior quietly breaks" claim: they establish that production pipelines demonstrably do not catch what their gates don't encode, which is exactly why silent upgrade breakage goes unnoticed. **Recommend updating the motivation** with this evidence plus Ma et al. CAIN 2024 (the on-point silent-update regression documentation).
- **Model cadence since 2026-07**: releases in the intervening year+ (new frontier-model versions, new Llama/Qwen/Mistral members) supply fresh dated upgrade pairs — the real-lineage arm gets *stronger* by waiting; the lineage list and closed-API snapshot IDs should be refreshed at run time, which the replay protocol already accommodates. The draft's framing ("permanently re-queryable open-weight version chains have only recently matured") remains accurate and is even more true now.
- **One 2026 defensive update needed**: as provider structured-output enforcement becomes the default, the reviewer question "doesn't constrained decoding make JSON breakage moot?" gets sharper. The draft has the right answer (native behavior, convention + few-shot genres, and JSONSchemaBench's own finding that enforcement ≠ correctness) but must state it explicitly in the intro/threats.
