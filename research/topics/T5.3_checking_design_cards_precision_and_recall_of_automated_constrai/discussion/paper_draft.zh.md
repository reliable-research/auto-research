# 一致性而非总分：测量自动化约束验证在哪些方面与人类评审相符

## 摘要

编码智能体（coding agent）产出补丁的速度已经超过团队按显式设计约束逐一人工检查的速度，而自动化约束验证（automated constraint verification）正日益被当作弥合这一缺口的安全手段——但自动验证器的精确率（precision）与召回率（recall）是否真的与人类评审相当、又对哪些类型的约束成立，从未在以"人类一致性"而非"假定完美"为参照的基准下被测量过。我们构建一个三方对齐的评测：带类别标注的设计约束卡（design constraint card）、来自真实 issue 到 pull request 任务的编码智能体补丁、以及对同一批配对做出的多评审员裁定式判断。一个混合验证器——对结构可定义的约束采用确定性规则与架构一致性检查（architecture-conformance check），对意图层面的约束采用带校准、可弃权（abstention）的评判器——按约束类别相对裁定后的参照进行打分，并同时对照人类评审员彼此之间的一致程度，而不是对照一个被假定为绝对正确的地面真值。各类别据此被划分为可自动化（automatable）、必须由人（human-required）或参照不稳定（reference-unstable），并用一个预算匹配的单评判器对照组来分离：观察到的类别分化到底反映约束本身的性质，还是验证器自身构造的产物。我们报告自动化约束检查在哪些地方已经与人类评审相当、哪些地方尚未达到、以及哪些地方人类参照本身噪声过大以致根本无从比较。

## 引言

编码智能体如今被例行地托付在显式设计约束之下产出补丁——模块不得越过的架构边界、补丁不得调用的 API、代码库强制的命名规范、必须保持的安全不变式（security invariant）、以及像"关注点分离"这类约束卡能点名却无法完全写明的设计原则。随着智能体补丁的产量超出任何团队对每条约束逐一人工核查的能力，一种自然的应对方式已经成型：构建一个自动验证器，把它对准约束卡和补丁，让它在人看之前先标出违规。这种做法构建成本低、理由充分，而这恰恰是它值得被检验而非被默认的原因。

然而关于这一实践的一个基本问题仍未被测量：自动验证器抓取约束违规的精确率与召回率是否真的与人类评审相当？这一点是对所有约束类型一致成立，还是只对其中一部分成立？把"调用了被禁 API"和"违反了关注点分离"当作同一种检测问题、并对两者报告一个混合的准确率数字，恰恰掩盖了团队最需要的信息——自动检查在哪里可以放心依赖、哪里仍必须有人来看。更糟的是，这一实践隐含地把人类评审当作绝对正确的参照——但如果评审员彼此之间就"某张卡是否被违反"存在分歧，那么表面上的验证器失败实际上可能是关于卡片含义的未决分歧，而这一区分决定了修复应落在验证器还是卡片本身。

与该问题最近的既有工作已经把全部三个要素——显式设计约束、编码智能体补丁、自动化合规检查器——摆上了台面："Does Pass Rate Tell the Whole Story?"（arXiv:2604.05955，2026 年 4 月）从真实 pull request 中挖掘并验证了 1,787 条设计约束，覆盖六个与 SWE-bench-Verified/Pro 对齐的仓库，并用基于 LLM 的验证器为智能体补丁的合规性打分。我们坦率承认这一重叠，因为差异恰恰是本文安身之处：该基准*信任*其验证器、将其作为打分工具去测量智能体，而本文把验证器本身作为被测对象——按约束类别追问任何这类自动检查器的判断是否真的与人类评审一致、以及人类评审彼此之间的一致程度是否足以充当参照。建立在 LLM 验证器之上的基准，恰恰继承了本研究要测量的那个未被测量的量。第二条相邻线索是围绕缺陷聚焦的合并请求分析构建的自动化代码评审：它以缺陷 oracle 为地面真值，在标记 bug 时权衡精确率与覆盖率，并报告在既有基准上自动生成的评审意见中真正高质量的不足十分之一——这直接证明即使在约束特有的结构进入图景之前，自动化评审的信号质量也远未解决；但它是对照 bug 缺陷 oracle 度量的，而非对照按类别打分的显式设计约束分类学。其余相邻工作各自提供了一块拼图，但都没有直接闭合这个缺口。LLM 评判器的选择性预测（selective prediction）框架通过校准的置信阈值来约束与人类标签的总体分歧，但不分解这种分歧集中在哪类约束上。检查表式与多约束遵循的工作表明逐约束的可验证性本就随约束类型而变——这是本文类别划分所依赖的经验前提——但它们研究的是*生成器*是否满足约束，而不是*验证器*能否相对人类标注的地面真值正确检测违规。执行验证型与免执行型的软件工程基准建立了真实的、仓库规模的编码智能体补丁与整条轨迹的奖励信号，但其 oracle 要么只覆盖可执行测试的那部分约束，要么为轨迹质量打分而非逐约束的人类一致性。而数学与推理任务上的验证器能力研究表明，验证质量并不随模型规模简单增长、且随场景强烈变化——本文认真对待这一警示——但那些研究使用自动的而非人类的地面真值，使得人类评审自身的噪声天花板在任何与本领域相似的场景中都未被测量。

把这个问题变成可测量的，会暴露出它自身的困难。任何验证器的性能报告，其信息量取决于粒度：一个总体准确率数字可以把"句法约束处理得好、语义约束处理得差"的验证器藏在一个看起来尚可的混合分数背后，因此类别层面的分化本身必须以足够的统计功效被测量，而不是仅仅被断言。验证器所对照的人类参照也不保证可靠——评审员彼此之间可能就"补丁是否违反某张卡"存在分歧，除非这种分歧被测量并作为显式天花板报告，否则验证器表面上的失败无法与参照自身的未决噪声区分开。补丁还可能在满足约束字面表述的同时违背卡片的真实意图，或者相反——任何只对卡片文本做表面模式匹配的验证器都无法察觉这一点。并且精确率与召回率在不同约束类型上以不同速率互相牺牲——在一个类别上为召回率调优可能把误报推高到导致现实中工具被弃用的程度，而同一阈值在另一个类别上又可能过于宽松——因此没有任何单一固定的工作点能同时适用于所有约束类型。

我们的方法把上述每个困难都转化为一个具体的、可检验的设计选择。每个验证器分数都按约束类别报告而绝不合并为一个数字，使跨类别的隐藏差异因构造而可见，而非碰运气。人类评审自身的可靠性被直接测量——多评审员小组与自身的一致性被计算并作为显式天花板报告，验证器与裁定参照的一致性是相对这一天花板、而非相对假定完美的参照来评判的；当天花板本身低到不可用时，该类别被报告为参照不稳定，而不是被沉默地照常打分。意图承载的约束被路由到一个在置信度低时可以弃权而非硬猜的评判器，结构可定义的约束则用确定性方式检查——同时一个不做此路由的预算匹配对照组用来分离：观察到的类别分化反映约束本身的性质，还是验证器构建方式的产物。取代单一精确率/召回率阈值的是按类别报告的工作曲线（operating curve），使驱动现实采用决策的权衡逐类别可见。底层补丁语料被刻意做了非显然性（non-obviousness）预筛，使验证器表面上的成功不至于只是"每个违规都一眼可见"的语料的伪影。

我们在构造的、带类别标注的设计卡与来自真实 issue 到 pull request 任务的编码智能体补丁配对上评估该设计，对照一个朴素关键词匹配器与一个预算匹配的单评判器对照组，所有比较均按约束类别、相对被测量而非被假定的人类一致性天花板进行。

综上，我们的贡献是：
- 一个类别分层的评测协议：将自动约束验证器的精确率、召回率及其与人类评审的一致性按约束类别分别报告，而不是报告一个恰恰会掩盖自动化在哪里失败的混合数字。
- 一个被测量而非被假定的人类一致性天花板——直接由多评审员小组计算——验证器的表现相对它评判；并为天花板本身低到不足以支持任何比较的类别，给出显式的"参照不稳定"结论。
- 一个按可操作化程度路由（operationalizability-routed）的验证器设计，配以预算匹配的单评判器对照组，用以分离观察到的可自动化/必须由人分化到底反映约束本身的性质，还是验证器自身的构造。
- 一个经过预筛的、非显然的三方对齐语料——设计卡、编码智能体补丁、裁定后的人类标签——以及按类别的工作曲线报告协议，二者共同使驱动现实采用决策的精确率/召回率权衡逐类别可见，而非藏在单一阈值之后。

## 问题定义

**形式化设定。** 设 C 为设计约束卡的集合，每张卡由类别映射 τ: C → T 指派到 T = {结构（structural）、API、命名（naming）、安全（security）、意图层面（intent-level）} 中的一个类别，且该指派的可靠性本身经过检验（标注者间一致性），而非被假定。设 P 为编码智能体产出补丁的集合，评测单元为卡 c 适用于补丁 p 的配对 (c, p) ∈ C × P。自动验证器 V 将每个配对映射为判断 V(c, p) ∈ {违规, 不违规}，并附带置信度 q(c, p) ∈ [0, 1]。由 r ≥ 3 名独立人类评审员组成的小组给出标签 h₁(c,p), ..., h_r(c,p) ∈ {违规, 不违规}，经裁定得到参照标签 y(c, p)。对每个类别 t ∈ T，令 κ_H,t 表示小组内的人–人一致性（Fleiss' κ），κ_V,t 表示 V 与 y 之间的验证器–人一致性（Cohen's κ），n_t 表示该类别中观察到的违规数。研究对象是一个从 (κ_H,t, κ_V,t, n_t) 到四个类别级标签之一——可自动化、必须由人、参照不稳定、或不确定（inconclusive）——的函数，对每个类别分别计算，绝不作为一个合并统计量。

**估计对象（estimand）。** 关注量是各类别的差距 Δ_t = κ_H,t − κ_V,t，即被测量的人–人一致性与验证器–人一致性之差；分析单元是一个裁定后的（卡, 补丁）配对；参照总体是可由真实 issue 到 pull request 任务构造的、带类别标注的设计卡 × 编码智能体补丁配对；该估计对象服务的决策是按类别的二元委派选择——将该约束类别交给自动验证，或保留强制人类评审——绝不是对"这个验证器"的全文断言。

**为什么难。** 固定类别映射 τ 并不能得到一个均匀可靠的验证目标：各类别在"其真值条件能多直接地从补丁的可观察结构中读出"与"多大程度依赖卡片点名却未编码的设计意图"上存在内在差异，因此在一个类别上调优成功的验证器并不保证在另一个类别上成功，而对整个 C 的合并统计量恰恰会掩盖这一差异。参照 y 本身也不保证可靠——对于评审员彼此就卡片要求存在分歧的类别，κ_H,t 可能很低，此时拿 V 与 y 比较有把参照自身噪声归咎于验证器的风险。即使 y 可靠，V 的判断也可能以纯结构检查无法企及的特定方式失败：补丁可以在满足卡片字面文本的同时违背其设计意图，或者相反，这需要对意图进行推理而非对措辞做模式匹配。并且由于误报与漏报之间可接受的平衡在各类别间并不相同——在一个类别上为召回率调优可能把误报推过导致评审员弃用工具的阈值，而同一工作点在另一个类别上可能过于保守——不能假定任何单一置信阈值在整个 T 上同时可用。

## 方法概览

在概念层面，本研究是一个由五个协作部分构成的单一测量设计。设计卡与编码智能体补丁按类别组织后进入流水线；打分层将所有验证器统计量按类别分开而绝不合并；人类小组不仅提供参照标签，还提供其自身被测量的可靠性；一个路由式验证器构造对结构可定义类别与意图承载类别采用不同机制，并配有检查该路由本身是否在塑造结果的对照组；语料构造步骤确保被打分的补丁一开始就既非显然合规也非显然违规。

**类别分层打分器**取验证器的逐配对判断，对五个类别分别计算精确率、召回率、F1 与一致性统计量，拒绝把它们折叠为一个总体数字。**被测量的人类一致性天花板**取人类小组裁定前的原始标签，按类别计算评审员彼此的一致程度，建立经验天花板而非假定裁定参照绝对正确。**按可操作化程度路由的验证器**对每个（卡, 补丁）配对，将结构可定义类别交给确定性规则或架构一致性检查，将意图承载类别交给带校准、可弃权的评判器；同时一个不做此路由的预算匹配对照组检验所得类别模式是约束内在的，还是路由本身的伪影。**工作曲线报告**层取打分后的判断，按类别报告按置信度阈值化的精确率/召回率曲线，而非单一混合数字。**预筛式语料构造**步骤决定哪些（卡, 补丁）配对进入研究：丢弃人类小组认为显然的配对，并要求保留的违规数达到最低数量后类别才被纳入分析。

## 方法论

### 类别分层打分器

**挑战。** 一个总体准确率数字可以把"在句法可检约束上表现好、在语义约束上表现差"的验证器藏在一个看起来尚可的混合分数背后。

**洞察。** 让隐藏的类别差异浮现的是报告粒度而非验证器工程——无论是否被测量，这种差异本就存在于数据中，因此让它可见是关于结果如何计算的设计选择，而非关于验证器本身。

**方法。** 相对裁定参照的精确率、召回率、F1 与 Cohen's κ 对五个约束类别分别独立计算。每个可自动化/必须由人/参照不稳定/不确定的结论都在类别层面作出；不把任何跨类别合并统计量作为主结果报告。由于所有结论均按类别打分，类别分类学本身被当作测量工具并在打分前先行验证：每个类别锚定于一个具名的外部来源（结构约束对应架构一致性文献，API 使用与命名对应静态分析规则分类学，安全对应安全不变式检查表，意图层面对应设计原则文献）；类别边界在留出的试点标注轮上细化，一致性低于阈值的类别对以具名操作合并或重划，而非静默重标；指派可靠性由至少两名独立标注者在 κ ≥ 0.7 下验证；检查标注者的混淆结构，使一个类别系统性坍缩进另一个类别被报告为分类学定义不良而非照常打分；类别集在语料扩张前冻结。

### 被测量的人类一致性天花板

**挑战。** 把人类评审当作绝对正确的参照来评判验证器，会把真实的验证器失败与评审员自己对卡片要求的未决分歧混为一谈。

**洞察。** 既然人类评审是度量验证器的标尺，标尺自身的可靠性就必须被直接测量而非假定——只有相对一个已知可达的天花板，才能有意义地说验证器"不及"它。

**方法。** 由至少三名独立评审员组成的小组在裁定前标注每个（卡, 补丁）配对，并按类别计算原始评审标签之间的 Fleiss' κ 作为显式天花板。验证器相对裁定参照的 Cohen's κ 通过对二者差距的自助法（bootstrap）置信区间与该天花板比较，而非与假定完美的参照比较；天花板本身低于可用性下限的类别被报告为参照不稳定，而不是当作参照可信来打分。

### 按可操作化程度路由、带校准弃权的验证器

**挑战。** 补丁可以在满足约束卡字面措辞的同时违背其底层设计意图，或者相反——这是对卡片文本做表面模式匹配无法察觉的失败模式，并且集中在没有可靠逐项可检谓词的意图承载类别中。

**洞察。** 不可归约为确定性检查的约束就不应被强行塞进确定性检查；而一个必须以同等置信度回答每个配对的验证器，恰恰会在其判断最不可靠的地方被迫硬猜——弃权把被迫的错猜转化为诚实的转交。

**方法。** 结构可定义类别用确定性规则或架构一致性机制检查。意图承载类别被路由到一个 LLM 评判器（LLM-as-judge）机制，它对卡片的文本连同其设计理由进行推理，并经过校准，在低于给定置信阈值时弃权——转交人类评审。一个预算匹配的对照组使用无卡片分解、无类别路由、无校准弃权的单发评判器，在每配对总 token 开销与完整路由验证器相同的条件下运行；比较二者可以分离观察到的类别模式反映约束自身的可操作化程度，还是路由机制本身。

### 按类别的工作曲线报告

**挑战。** 精确率与召回率在每个约束类别上以不同速率互相牺牲，因此一个统一施加的固定置信阈值从构造上就对至少一部分类别是错的。

**洞察。** 服务采用决策的可报告单元是曲线而非点——一个混合的、类别无关的阈值恰恰隐藏了团队判断"验证器对某类约束是否可用"所需的权衡信息。

**方法。** 按类别计算按置信度阈值化的精确率/召回率工作曲线，并与一个不使用任何结构或语义推理的朴素关键词/正则匹配器对比。朴素匹配器已落入人类一致性带的类别被报告为无需进一步验证器工程，无论完整验证器在那里是否也胜过它。

### 预筛式语料构造

**挑战。** 一个"每个违规都一眼可见"的（卡, 补丁）配对语料会让任何验证器配置——包括朴素关键词匹配器——都显得准确，把真实的可自动化/必须由人分化藏在语料难度的伪影之后。

**洞察。** 违规与合规配对之间的类别平衡并不保证真实难度；配对可以平衡却平凡，因此难度必须被直接预筛，而非仅从计数推断。

**方法。** 配对从真实的 issue 到 pull request 编码智能体任务播种，而非合成模板。人类小组预筛候选配对，丢弃被判为显然合规或显然违规者，以评审员对该配对的判断用时是否低于非显然性阈值来度量。一个类别只有在保留了最低比例的非显然配对与最低数量的裁定违规后才进入主分析；未达标的类别被报告为不确定，而非折入总体。

## 实验

### 实验设置

**数据集。** 一个构造的设计卡语料，按五个约束类别标注并分解为逐项可检谓词——这是任何类别分层结果的必要底座，因为没有带类别标注的卡就没有分层的单元。从真实 issue 到 pull request 任务（SWE-bench / SWE-bench Verified 风格）播种的编码智能体补丁——之所以专门使用生态真实的补丁，是因为非显然性预筛要有意义就必须如此；完全合成的语料会让违规被有意构造得显而易见，使预筛失去意义。构造的违规补丁变体，在真实智能体补丁自然产生的违规过少、不足以让某类别留在分析中时按类别补充——用以避免把语料稀缺误当作关于约束可操作化程度的零结论。在类别覆盖允许时，卡片还可以从设计感知 issue 解决基准（arXiv:2604.05955）挖掘并验证过的约束清单播种：该清单提供带 pull request 出处、已与 SWE-bench-Verified/Pro 实例对齐的约束；任何如此播种的卡都在本文的五类别分类学下重新标注，并通过与构造卡相同的标注者间可靠性关卡。

**标注预算（预注册设计目标）。** 本研究由标注主导，因此预算预先写明而非事后发现：按每类别约 120 个保留（卡, 补丁）配对 × 5 个类别 ≈ 600 个配对计，≥3 名评审员的小组在每个配对标签约 6 分钟的估计下，主标注轮约需 180 评审员小时；另加非显然性预筛约 40 小时（在更大候选池上做更轻的、以丢弃为导向的判断）、分歧裁定约 30 小时、双人编码错误分类轮约 20 小时——合计约 270 评审员小时，是需要资助的标注工程的量级，而非一个周末试点。行走骨架（walking skeleton）阶段（API 使用与意图层面两个类别，各约 40 个配对）约花费其中 15%，并且是终止测试（kill-test）：若试点的 Fleiss' κ 或保留违规数使完整设计的功效目标不可达，则不运行全量标注。

**基线**（作为健全性检查与竞争性解释的比较对象，而非要击败的对手——这是一项测量研究，没有任何研究问题把"我们的验证器击败基线 X"作为主张）。一个不做 AST 解析、不用 LLM 推理的朴素关键词/正则匹配器，确立了验证器值得构建所需越过的下限——并且更有信息量的是，它揭示哪些类别已经不需要进一步的验证器研究，因为朴素匹配器在那里已达人类一致性带。一个无卡片分解、无类别路由、无校准弃权的单发 LLM 评判器，其每配对总 token 开销与完整路由验证器匹配，用以分离观察到的类别模式是约束内在的还是路由/分解机制的伪影。一个仿照既有 LLM 评判器选择性预测工作的校准选择性评判协议作为最接近的已发表校准评判设计在旁描述性报告，不附加任何通过/失败判据。

**指标。** 相对裁定参照的按类别精确率、召回率、F1；按类别的 Cohen's κ（验证器–人）与 Fleiss' κ（人–人，即被测量的天花板）并列；二者差距的自助法置信区间；以及由此得出的按类别分类（可自动化 / 必须由人 / 参照不稳定 / 不确定）。

**研究问题：**
1. RQ1——验证器在结构可定义的约束类别上是否达到可靠的精确率/召回率标准？
2. RQ2——意图层面类别的表现是否显著差于结构类别，而不只是数值更低？
3. RQ3——人类评审参照本身是否可用——评审员彼此的一致程度是否足以充当天花板？
4. RQ4——哪些类别达到人类一致性带（可自动化）、哪些不及（必须由人）、哪些不确定？
5. RQ5——观察到的类别表现分化反映约束自身的性质，还是验证器的路由机制？
6. RQ6——哪些类别连朴素关键词匹配器都已足够？完整验证器在其余类别上是否有改进？
7. RQ7——单一置信阈值是否对所有约束类别都可用，还是可采用的工作点因类别而异？
8. RQ8——评测语料按类别是否足够非平凡，以支撑真实结论而非易例伪影？

#### RQ1：验证器在结构可定义的约束类别上是否达到可靠的精确率/召回率标准？

**设置。** 对四个结构可定义类别（架构边界、API 使用限制、命名/风格、安全不变式）分别计算相对裁定参照的精确率与召回率及其 Wilson 95% 置信区间。样本量：每个类别保留至少 30 个裁定违规（按语料预筛）作为纳入下限；下方的区间宽度算术是对照该下限写明的，而非含糊带过。

**预期结果。** 双档设定，与样本量实际能支持的水平匹配。第一档（全部四个结构类别，在 30 违规下限处）：每类别精确率 ≥ 0.85、召回率 ≥ 0.80，且二者的 Wilson 95% 置信区间下界 ≥ 0.60。第二档（仅限保留 ≥ 80 个裁定违规的类别）：置信区间下界 ≥ 0.75。分档是 Wilson 算术所迫而非偏好：在 n = 30 时，观测召回率 0.80 的下界约为 0.63，即使 0.90 也只有约 0.74，因此在 30 违规下限处设 0.75 的下界目标会仅因样本量而被否证；在 n = 80 时观测召回率 0.85 的下界约为 0.75。

**否证条件。** 若任一结构类别的点估计低于其精确率/召回率标准，或其置信区间下界低于其样本量所注册的档位界限，则被否证——那将意味着即使是最可操作化的约束类别在原型成熟度下也尚不可靠地可自动化，这与本研究原本预期的意图层面差距是实质不同的发现。

**假设（通俗表述）。** 结构可定义的约束——其真值条件可由补丁的可观察结构计算——应当是自动验证器最接近人类可靠性的地方；若并非如此，那本身就是主要发现。

**指标。** 按类别的精确率、召回率及其 Wilson 95% 置信区间。

#### RQ2：意图层面类别的表现是否显著差于结构类别，而不只是数值更低？

**设置。** 以逐配对的验证器正确性（相对裁定参照的对/错）对类别拟合逻辑回归，纳入智能体协变量并以卡为聚类单元计算标准误；将意图层面类别的 F1 与四个结构类别中的最小 F1 比较。

**预期结果。** 意图层面类别的 F1 至少比结构类别最小 F1 低 0.15，且回归中的类别效应经似然比检验在 α = 0.05 下统计显著。

**否证条件。** 若 F1 差距小于 0.15，或类别效应不显著，则被否证——二者任一都意味着本研究围绕的意图/结构分界并未作为一个独立的显著效应成立，而只是类别间的普通噪声。

**假设（通俗表述）。** 结构与意图层面约束类别之间的差距不只是数值上更低的分数，而是类别的真实、统计上可区分的效应。

**指标。** 按类别 F1；类别系数的似然比检验统计量与 p 值。

#### RQ3：人类评审参照本身是否可用——评审员彼此的一致程度是否足以充当天花板？

**设置。** 对 ≥3 名评审员小组裁定前的原始标签，按五个类别分别计算 Fleiss' κ。

**预期结果。** 每个类别的 Fleiss' κ 至少为 0.4，从而确立人–人参照是可用的，而非仅被假定可用。

**否证条件。** 任一类别的 Fleiss' κ 低于 0.4 即对该类别否证——该类别随即被报告为参照不稳定，且其在 RQ1/RQ2/RQ4 中的任何验证器比较都被视为不可解释，而非关于验证器的证据。

#### RQ4：哪些类别达到人类一致性带（可自动化）、哪些不及（必须由人）、哪些不确定？

**设置。** 对每个参照可用（RQ3）的类别，计算人–人天花板 κ_H,t 与验证器–人一致性 κ_V,t 之间的差距 Δ_t，并给出 95% 自助法置信区间（10,000 次重采样，按卡聚类），对五个类别的"必须由人"检验施加 Holm 校正；观察违规数少于 30 的类别无论区间如何一律强制记为不确定（按 RQ8 的关卡）。

**预期结果。** 至少两个类别被分类为可自动化（Δ_t 置信区间上界 ≤ 0.10），意图层面类别被分类为必须由人（Δ_t 置信区间下界 > 0.10），且至多一个类别不确定。

**否证条件。** 若达到可自动化带的类别少于两个，或意图层面类别的置信区间未越过必须由人的界限，或不确定类别多于一个，则被否证——任一情形都意味着假定的结构/语义分界并未干净地产生预期的可自动化/必须由人划分。

**假设（通俗表述）。** 可自动化/必须由人的划分不是全有或全无——多数但非全部结构可定义类别应达到与人类可比的一致性带，而意图层面类别不应。

**指标。** 按类别的 Δ_t 及其自助法置信区间；由此得出的三分类。

#### RQ5：观察到的类别表现分化反映约束自身的性质，还是验证器的路由机制？

**设置。** 在同一语料上运行预算匹配的单发评判器（无卡片分解、无路由、无弃权），并将其按类别的 F1 模式与完整路由验证器的模式比较。由于"模式一致"是一个等价性主张，就按等价性来检验：对每个类别，对两种配置的 F1 之差计算 95% 自助法置信区间（按卡聚类），并以双单侧检验（TOST）对照预注册的 ±0.05 边际来主张等价——绝不靠目测点估计，因为在 30–80 违规规模下，按类别 F1 的抽样噪声本身就可能超过 0.05。

**预期结果。** 对每个类别，F1 之差的自助法置信区间完全落在 ±0.05 内（TOST 等价成立），表明观察到的可自动化/必须由人分化反映约束内在的可操作化程度，而非路由或分解机制。

**否证条件。** 若任一类别的差值置信区间完全落在 ±0.05 边际之外，则被否证——那意味着路由/分解设计本身在塑造哪些类别看起来可自动化，任何可自动化/必须由人的主张都必须报告为工具条件性的（instrument-conditional），而非关于约束本身。若某类别的置信区间横跨边际（既未确立等价也未确立差异），该类别的 RQ5 结论报告为功效不足-不确定（underpowered-inconclusive），而非向任一方向裁定。

**假设（通俗表述）。** 若一个类别看起来可自动化或必须由人，那应当是约束类型的属性，而非验证器恰好如何构建的产物。

**指标。** 两种验证器配置的按类别 F1；按类别 F1 差值及其聚类自助法 95% 置信区间与对照 ±0.05 边际的 TOST 等价性裁定。

#### RQ6：哪些类别连朴素关键词匹配器都已足够？完整验证器在其余类别上是否有改进？

**设置。** 在同一语料上为朴素关键词/正则匹配器打分；将其按类别相对裁定参照的一致性与 RQ4 的人类一致性带比较，并经 McNemar 检验（α = 0.05，五类别 Holm 校正）将其成对决策与完整验证器比较。

**预期结果。** 朴素匹配器已落入人类一致性带的类别被报告为无需进一步验证器工程；在其余类别上，完整验证器的成对决策以统计显著的水平改进朴素匹配器。

**否证条件。** 若在朴素匹配器自身已足够的带之外的任一类别上，完整验证器未能以显著水平改进朴素匹配器，则（在真正要紧的方向上）被否证——那意味着新增的路由/LLM 评判器机制在真正需要它的类别上没有赚回其复杂性。

**假设（通俗表述）。** 有信息量的问题不是复杂验证器在总体上是否击败朴素验证器——混合验证器总体上胜过关键词匹配器并不令人意外——而是朴素匹配器已经把哪些具体类别处理得足够好以致那里不再需要验证器研究，以及新增机制在其余类别上是否物有所值。

**指标。** 朴素匹配器按类别相对人类一致性带的一致性；按类别的 McNemar 检验统计量与 Holm 校正 p 值。

#### RQ7：单一置信阈值是否对所有约束类别都可用，还是可采用的工作点因类别而异？

**设置。** 按类别计算按置信度阈值化的精确率/召回率工作曲线；按类别找出精确率达到 0.85 的最低置信阈值。

**预期结果。** 没有任何单一置信阈值能在全部五个类别上同时越过 0.85 的精确率下限——精确率最大化阈值在类别间显著不同。

**否证条件。** 若存在一个类别不变的置信阈值在全部五个类别上同时越过 0.85 精确率下限，则被否证——那意味着统一工作点处处可用，与本设计假定的按类别权衡相反。

**假设（通俗表述）。** 由于精确率与召回率在不同约束类型上以不同方式互相牺牲，不应有任何单一部署阈值能同时适用于每个类别——工作点本身就是一个按类别的设计决策。

**指标。** 按类别的精确率/召回率工作曲线；按类别精确率首次达到 0.85 的阈值。

#### RQ8：评测语料按类别是否足够非平凡，以支撑真实结论而非易例伪影？

**设置。** 在通过人工预筛的配对中，按类别计算其中位评审判断用时超过预设非显然性阈值的份额，以及按类别保留的裁定违规数。

**预期结果。** 每类别至少 20% 的存留配对被判为非显然，且每类别保留至少 30 个裁定违规，该类别方可纳入 RQ1–RQ7 的分析。

**否证条件。** 任一类别未达任一标准即对该类别否证——该类别在所有其他 RQ 中一律报告为不确定，无论其原始精确率/召回率数字如何，而不是在功效不足或人为容易的基础上折入主结论。

**假设（通俗表述）。** 结论的可信度不超过其所测语料的可信度；真实违规过少或只有显然违规的类别撑不起任何结论，无论其原始数字多干净。

**机制分析（补充）。** 在确立类别差距"存在"及"在哪里"之外，一个预注册的错误分类轮解释"为什么"：对每个经裁定小组不同意的验证器错误，第二个独立编码轮（两名评分者，分歧经裁定）将其分类为 (i) 字面–意图错配，(ii) 结构/模式匹配失败，或 (iii) 其他。预算覆盖两个行走骨架类别（API 使用与意图层面）上的全部错误，加上全量规模下每类别至少 20 个错误的分层抽样，以错误分类表（类别 × 机制类型计数）与主线 Δ_t 数字并列报告。预先承诺的解读：若字面–意图错配主导意图层面错误、而结构/模式匹配失败主导结构类别错误，则观察到的差距被机制性地确认为由字面/意图区分导致；若结构失败反而主导意图层面错误，则差距是评判器组件的工程伪影，而非意图层面约束本质上必须由人的证据。

## 相关工作

与本文最近的既有工作是 "Does Pass Rate Tell the Whole Story?"（arXiv:2604.05955，2026 年 4 月）的设计感知 issue 解决基准，在综述更广图景之前值得把差异说明白：该工作从真实 pull request 中挖掘并验证显式设计约束（495 个 issue、1,787 条约束、六个与 SWE-bench-Verified/Pro 对齐的仓库），并用基于 LLM 的验证器自动检查智能体补丁的合规性——本研究的每一个底座要素它都具备。差异在于测量的方向：在那里，验证器是被信任的工具、智能体是被测对象；在这里，验证器是被测对象，而裁定后的多评审员人类判断——其自身一致性按类别被测量为显式天花板——是参照。按类别的验证器–人一致性差距、人–人天花板、参照不稳定结论，均不出现在该基准的设计中，而这恰是本文要闭合的缺口；反过来，其挖掘并验证过的约束清单是本文卡片语料的天然播种来源。

**自动化代码评审与 LLM 评判器校准。** 缺陷聚焦的自动化代码评审围绕合并请求与关键 bug 检测重构评审流程，结合静态代码切片提供依赖感知的上下文与显式权衡精确率与覆盖率的多角色流水线，并报告在既有基准上自动生成的评审意见中真正高质量的不足 10%。LLM 评判器的选择性预测框架仅在估计的人类一致性置信度越过校准阈值时才作答，将不确定案例升级到更强评判器级联，以约束总体分歧风险。二者都确立了自动化评审与自动化评判承担真实、非平凡的精确率代价，但都不按显式约束分类学分解这一代价——缺陷聚焦工作完全没有约束类别的概念，选择性评判框架只在总体上约束分歧，而不问哪些类别驱动了弃权。

**约束分解与指令遵循。** 检查表式对齐工作将指令分解为原子的、可分别检查的是/否要求，论证全局评分准则会漏掉指令特有的要求——本文的卡片分解直接借用这一模板。复杂指令遵循基准合成配有验证机制的多约束指令，并表明约束满足度随约束数量增长而退化，确立了逐约束可验证性本就随类型而变。二者都为可自动化/必须由人划分提供了经验前提，但都研究*生成器*是否满足约束，而非*验证器*能否在已产出的补丁中相对人类标注正确检测违规——即本文直接测量的检测精度问题。

**软件工程智能体评测。** 执行验证型基准将真实 GitHub issue 与解决它的 pull request 配对，以 fail-to-pass 测试作为仓库规模编辑的客观正确性 oracle，并且是本文语料所取真实编码智能体补丁的来源。免执行奖励模型转而为整条智能体轨迹打分，其动机是测试套件不完备或与真正要紧的东西错位。设计感知 issue 解决（arXiv:2604.05955）将这条线索延伸到执行 oracle 之外，经 LLM 验证器以挖掘的设计约束为同样仓库规模的补丁打分——但如上所述，它把该验证器当作可信工具而非测量对象。在相邻的奖励作弊（reward hacking）场景中，EvilGenie（arXiv:2511.21654）确实用人类评审验证了其自动检测器——LLM 评判器、留出测试与编辑检测——发现评判器在无歧义案例中有效；但该验证是总体层面且领域特定的，没有约束分类学，也没有测量人类评审员彼此的一致程度。这些工作都没有测量自动检查器在固定、显式的逐补丁约束上、按约束类别、相对人–人一致性天花板与人类评审的相符程度——执行 oracle 只覆盖可执行测试的那部分约束，轨迹级奖励模型从未为分离单张卡的合规性而构建，而设计感知基准的验证器恰恰是本文要测量其可靠性的那个工具。

**验证器能力测量、架构一致性与工具采用。** 验证动力学分析在数学与推理任务上实证解耦问题难度、生成器能力与验证器能力，表明验证器质量并不随模型规模简单增长，并警示单一总体准确率数字掩盖真实的分场景差异——这是本文类别分层报告的直接动机。架构一致性技术（Reflexion models）计算意图中的高层设计模型与实际源码结构之间的收敛与分歧，是结构可检、可自动验证的设计约束的典范，尽管其底层工具早于编码智能体二十年，且不提供关于语义或意图层面约束的任何证据。静态分析工具采用的访谈研究发现，导致开发者在实践中弃用自动检查器的主因是误报而非漏报——确立了支配现实可用性的是精确率而不只是召回率，本文按类别的工作曲线报告正是为把这一发现变得可操作、而非仅仅引用它而构建。

## 结论

这项工作把一个已嵌入编码智能体产出检查方式中的治理假设——自动验证器可以被信任去抓设计约束违规——变成一个带显式参照的被测量主张。核心方法论承诺是：验证器与人类评审的一致性，只有相对人类评审员彼此的一致程度才可解释，也只有按约束类别而非一个混合数字报告才有意义；跳过任一承诺的研究，都无法把真正可自动化的类别与侥幸的总分区分开，也无法把真正必须由人的类别与被误归于验证器的未决评审噪声区分开。无论哪些类别最终可自动化，这一发现都在直接、实用的意义上关乎决策：它告诉团队自动约束闸门在哪里可以信任、人类评审在哪里仍然必要，而不是把这一决策留给未经检验的假设。两个局限从一开始就框定这一主张。设计的范围限于固定的编码智能体与仓库集合、以及一个经标注者间一致性验证的五类别分类学；同样的可自动化/必须由人划分是否对其他智能体、语言或更细粒度分类学成立，是自然的下一步而非本文主张。而本设计可能产出的参照不稳定结论本身就有信息量——一个人类评审员彼此无法达成一致的类别，不是要修的验证器故障，而是在自动化能被有意义地评估之前要先解决的卡片设计问题，指向更清晰的卡片撰写作为伴生研究方向，而非仅仅更多的验证器工程。
