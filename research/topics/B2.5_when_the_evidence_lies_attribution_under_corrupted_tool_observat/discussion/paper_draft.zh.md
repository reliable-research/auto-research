# 轨迹不等于真相：测量模式合法工具污染下的归因盲区

> 由 `pipeline.md` 中六个已确认阶段产出组装而成，已通过研究品味审计（`taste_audit.md`：🟢）。**2026-08-21 修订**，依据 `review_2026-08.md`：针对 The Misattribution Gap（arXiv 2605.22842）、Who&When Pro（arXiv 2607.09996）、Don't Blindly Trust It（arXiv 2606.21409）以及 2026 年归因方法浪潮（CHIEF、FALAT、Ma et al.）完成先承认后主张 (concede-and-claim) 定位；新增预注册的运行预算/降级阶梯 (descope ladder)。状态：**规格说明 / 论文草稿——尚未运行任何实验。** 下文所有数字均为预注册的设计目标，而非结果。

## 摘要 (Abstract)

面向 LLM 智能体的自动失败归因 (automated failure attribution)——判定一条失败轨迹应归咎于计划 (plan)、某个工具 (tool)、还是执行层 (execution)——正被产业化地用于驱动真实干预：重训规划器、修补工具、整理数据。然而迄今提出的每一种归因方法都把它所读取的轨迹日志 (trajectory log) 当作可信证据，因此当一次工具调用返回语义错误但语法合法的观测 (observation) 时，这些流水线自身运行的合法性检查对它完全不可见，而其被污染的内容还会进一步被当作证据，用于指控消费了它的计划层与执行层。我们构建一个由三个独立合法性检查把关的模式保持型污染注入器 (schema-preserving corruption injector)，用反事实孪生重放 (counterfactual twin-replay) 验证每个污染的因果决定性 (causal decisiveness)，并让现有的 LLM 裁判 (LLM-judge)、训练型追踪器 (trained-tracer) 与运行时监视器 (runtime-monitor) 归因方法——对注入元数据保持盲态——在匹配的显性错误 (overt-error) 与智能体侧故障 (agent-side-fault) 对照下运行。一个仅一句话的信任许可 (trust-license) 提示干预用于探测所测偏差是可移除的信任假设、还是更深层的推理局限；一个预注册、双人标注的映射准则 (mapping rubric) 把每种方法的原生输出对照共享的计划/工具/执行真值评分。我们报告当前归因方法的误归因率 (misattribution rate)、其方向、以及机制探针的结果，并讨论这对把轨迹当作真值的自动调试流水线意味着什么。

## 引言 (Introduction)

多智能体与工具使用 (tool-using) LLM 系统失败得足够频繁、失败位置也足够分散，以至于靠人工阅读轨迹日志来判定责任已成为瓶颈。自动失败归因——把一个 LLM 裁判或训练型追踪器指向日志、要求其说出责任智能体与步骤——被产业化的目的正是消除这一瓶颈：Who&When 基准以人工归因"代价高昂且不一致"来论证自身发布的动机，AgenTracer 则把其追踪器的输出定位为"失败观察与系统改进之间缺失的接口"。在这两种表述中，归因裁决都不是学术性的：它旨在告诉团队应重训、修补或重试哪个组件。

然而这一自动化背后的一个核心假设，在每种归因方法每一步都要读取的那个通道上，仍然未经检验：这些方法都把轨迹日志中的工具观测当作对所发生之事的可信证据来消费，没有任何步骤会追问这些观测本身是否可能是错的。记忆投毒 (memory-poisoning) 文献最近为一个*不同的*证据通道记录了类似的失败——被对抗性投毒的持久记忆，防御方一致地将其误读为模型失败——但瞬时的工具观测通道，其污染并非来自攻击、而是来自一个明白无误的错误取值，尚无对应的测量。一次工具调用返回的值若语法合法、能被干净地解析、并通过流水线运行的每一项模式 (schema) 检查——却只是数字错了、实体错了、或读数过期了——不会留下任何可被合法性检查捕捉的表面痕迹。更糟的是，构成失败证据的那份轨迹日志正是由受怀疑的那次工具调用产出的，因此一个照单全收地读取日志的诊断程序，在开始推理谁之过之前，就已把污染继承进了自己的前提。如果归因方法系统性地把这些工具导致的失败改判为计划或执行失败，那么它们驱动的每一个下游修复都瞄准了一个从未损坏的组件，而真正的缺陷——把格式良好的工具输出当作真值来信任——则始终无人处理、无人监控。

最接近的现有工作从相邻但不同的角度切入这一空白。Who&When 把归因形式化为识别"纠正之即可让失败轨迹翻转为成功"的智能体-步骤对，并在多种上下文管理策略下评估 LLM 裁判归因——但其决定性错误 (decisive error) 定义只在自然发生的智能体错误上被行使，从未在"日志自身的工具观测被污染却格式良好"的条件下检验。AgenTracer 用反事实重放与程序化故障注入训练了一个专用追踪器，但其故障空间是智能体动作而非工具返回——一个被训练来识别坏动作的追踪器，按构造从未见过决定性错误是一条说谎观测的轨迹。Who&When Pro 把注入构建的归因评估扩展到 12,326 条轨迹，其黄金标签 (golden label) 在注入时刻按约定 (by convention) 分配，但其构建过程中没有任何环节认证被注入故障的表面不可检测性 (surface undetectability)，它测量的是谁在被假定忠实的日志上归因得好，而非当日志本身说谎时归因会发生什么。一个并行的因果推断方法 Causal Agent Replay 与我们同样依赖 do-observation 式的反事实替换，但它提出并在带模拟工具 (mocked tools) 的合成因果模型上验证的是一个*替代性*归因器，而非测量现有已部署方法在真实工具观测的已验证、模式合法污染下是否误归因——两项工作共享机制，而非研究问题。与本文精神最接近的 The Misattribution Gap 记录了污染证据通道下的误归因——记忆投毒攻击被归因与安全工具一致地误读为模型失败——但其通道是被植入对抗性政策文档的持久共享记忆库，其诊断对象是安全分类器与防御方修复决策，而非本文测量的计划/工具/执行归因方法族。Don't Blindly Trust It 直接操纵工具反馈通道，在匹配的智能体循环中对比忠实、误导与缺失三种观测，但测量的是坏证据下智能体的任务表现，而非对智能体的诊断——误导性观测会破坏智能体已是已知结论；它们是否也会破坏*对智能体的归责*，才是本文的问题。面向工具返回通道的安全工作，如 ChatInject 与 MCP-SafetyBench，表明工具输出可以被主动污染，但测量的是攻击是否成功，而非任何下游诊断是否正确定位了它——且其污染是旨在改变行为的指令载荷 (instruction-bearing payload)，与普通字段里一个明白错误的取值属于不同威胁模型。ResiliBench 把工具不可靠性建模为显性信号——超时、非法输入、可见的操作失败——智能体必须对其自适应，把格式良好但取值错误的静默情形留在了范围之外。而 SupervisorAgent 这样的轻量运行时监督器，其触发条件是显式错误发生、重复行为、或观测长度超限——恰恰是模式合法污染不会发出的那些信号。

把这一空白变成可测量的论断，会暴露它自身的困难。制造一个可验证地是失败决定性原因（而非仅仅与失败相关）的被污染工具观测，需要排除"智能体其实恢复了"或"被污染字段从一开始就不承重 (load-bearing)"的可能。同一个污染还必须不留任何可被合法性检查捕捉的表面信号，而这与"具有决定性"是真正独立的两个性质：一个污染可以不可检测却与失败无关，也可以原则上可检测却仍是实际原因；混淆两者会让任何测得的偏差沦为构造的伪影 (artifact) 而非被测方法的属性。一旦被污染轨迹存在，把"真正有缺陷的计划"与"对坏信息作出局部合理响应的计划"区分开，需要一个反事实——给定正确观测这一步会是什么样——而受测的归因方法都无法访问它，只有实验者自己的注入真值可以。并且由于不同归因方法用互不兼容的原生词汇报告裁决——一个智能体名字、一段自由文本理由、一个离散监视器标志——把它们对照同一套"工具""计划""执行"概念评分，需要一个映射选择，而这个选择若不加约束，本身就足以制造或掩盖一个偏差。

我们的方案把上述每个障碍都变成一个具体的设计选择而非托辞。模式保持型注入器改变一个工具观测的内容，同时三个独立检查——模式再验证、解析器接受、上下文合理性筛查——共同认证该污染合法且不起眼，使不可检测性成为被验证而非被假设的性质。反事实孪生重放程序只保留"仅撤销被污染观测即可翻转结果"的轨迹，提供不可检测性本身无法给出的决定性原因保证。随后，现有归因方法在对注入元数据盲态的条件下，对照两组匹配对照运行——共享相同根因但发出可见信号的显性工具错误，以及把同一个错误取值注入智能体自身动作的对照——使任何测得的偏差能被专门归于观测通道，而非归于发现细微错误取值这件事的一般性困难。此后，在裁判提示中加入一句信任许可，检验一个已被发现的偏差是可移除的假设还是更深的局限；而一个在看到任何结果之前就固定、并报告自身信度的映射准则，防止计划/工具/执行评分本身成为结论的隐藏来源。

我们在 AgentDojo 的工具调用任务与 GAIA 的长程助手任务上评估该设计，以 Who&When 的人工标注日志作为独立来源的真实计划失败对照，并配以朴素多数类归因器、匹配的显性错误轨迹、以及匹配的智能体侧故障臂。

综上，我们的贡献是：
- 识别并形式化自动失败归因中的一个结构性不对称：合法性检查认证工具观测的*形式*，而诊断本身把观测的*内容*当作不加质疑的前提消费，使一个模式合法的谎言既对检测不可见，又被主动用作指控消费它的层的证据。
- 一个经反事实重放验证的污染测试床，把因果决定性与表面不可检测性分离为注入故障的两个可独立检查的性质，而非把它们合并进单一合法性检查。
- 一个匹配对照协议——显性工具错误，加上在不同因果位点共享同一错误取值的智能体侧故障臂——用以隔离任何测得的归因偏差是否特定于工具观测通道。
- 一个最小化的信任许可提示干预，检验测得的偏差是可移除的结构性信任假设、还是更深的反事实推理局限，无论结果如何都产出一个具体的、可证伪的设计建议。
- 对误归因方向及其对污染类型、位点与细微度依赖性的实证刻画——不只是当前归因方法在说谎证据下是否失败，而是失败如何分布。

## 问题定义 (Problem Definition)

**形式化设定。** 考虑轨迹 τ = (q, (a₁,o₁), …, (a_T,o_T))，将任务 q 与智能体动作序列 a_t、工具观测序列 o_t 配对，由程序化检查器 (programmatic checker) V(τ) ∈ {0,1} 评分。污染算子 μ 把选定观测 o_t 映射为变异后的 o′_t，同时保持模式与解析合法性——变异后的值通过类型检查，并被框架自身的解析器如原值一样接受。孪生重放算子 replay(τ, t, o) 从第 t 步起以替换后的观测 o 重新执行 τ，在框架允许处固定随机种子与解码温度。归因方法 A 把（可能被污染的）轨迹映射为责任层与步骤，A(τ) = (ℓ̂, t̂)，其中 ℓ̂ ∈ {plan, tool, execution}，经由方法特定的映射准则 R_A 把该方法的原生输出转换到这一共享标签空间。研究对象是：对于真值为注入步骤 t 处 ℓ = tool 的轨迹，A 报告 ℓ̂ ≠ tool 的比率，是否超过同一方法在"工具故障显性而非模式合法"的匹配轨迹上的错误率。

**为何困难。** 固定 μ(o_t) = o′_t 并不能自动确立 o′_t 是 V(τ) = 0 的原因：被污染的运行可能因与被变异字段无关的原因失败（或成功），因此"步骤 t 处 ℓ = tool"的真值标签只有在 V(τ_corrupted) = 0 且 V(replay(τ_corrupted, t, o_t)) = 1 时才站得住——这是孪生重放条件，而非 μ 单独的性质。独立地，μ 必须产出一个对 A 可用的任何表面检查都与合法观测不可区分的 o′_t，这一性质与孪生重放条件正交：污染可以满足其一而不满足其二。即便两者都成立，R_A 本身仍是一个设计选择——不同归因方法以互不兼容的原生词汇报告 ℓ̂，而一个事后宽松或严苛到足以改变 ℓ̂ 取值的映射，会让测得的误归因率成为 R_A 而非 A 的伪影。并且，区分"A 归咎计划是因为计划真有缺陷"与"A 归咎计划是因为那是对被污染 o_t 的合理解读"，需要真 o_t 下的反事实结果——恰是 replay(τ, t, o_t) 提供给实验者、却对 A 本身隐瞒的东西，因为 A 必须像任何已部署方法一样盲态诊断。

## 方法总览 (Method Overview)

在概念层面，本研究是一条包含五个协作部件的单一测量流水线，每个部件都把上文的一个困难转化为可检查的性质而非假设。一条轨迹与一个目标工具观测进入流水线；污染-验证阶段仅当候选变异同时越过合法性门槛与因果决定性门槛时，才将其转化为带真值标签的处理案例 (treatment case)；随后现有归因方法在盲态下对照该处理案例与两组匹配对照运行；每个 LLM 裁判方法的信任许可变体探测任何测得偏差背后的机制；一个预注册的评分准则把每种方法异质的原生输出转化为一个可比裁决。

**模式保持型污染注入器**接收候选工具观测与变异算子，产出污染变体，仅当其通过三个独立合法性门时才向前传递——这是真值构建的表面不可检测性一半。**反事实孪生重放判据 (oracle)** 接收合法候选，通过以恢复原观测重新执行轨迹，确认该污染是失败的决定性原因——因果决定性一半。**盲态归因测试台**接收得到的已验证处理集，连同匹配的显性错误与智能体侧故障对照集，让每个受测归因方法对三者全部运行，且对每条轨迹的来源保持盲态。**信任许可探针**给每个 LLM 裁判方法加一句许可其不信任工具观测的提示后重跑，隔离任何测得偏差是否为可移除的信任假设。**预注册映射准则**在看到任何结果之前把每种方法的原生输出转换为共享的计划/工具/执行标签，其自身的标注者间信度与每个下游数字并列报告。

## 方法论 (Methodology)

### 模式保持型污染注入器

**挑战。** 表面可检测的污染只能测量归因方法是否费心验证输入，而非它们能否诊断一个格式良好的谎言。

**洞察。** 没有任何单一合法性检查能认证不可见性，因为每项检查测试的东西不同——类型结构、运行时解析、上下文合理性——因此同时通过三者才使一个污染既合法又不起眼。

**方法。** 一个类型化变异算子库——数值扰动、同类型实体替换、布尔翻转、列表截断/重排、过期值替换——在受控步骤索引处应用于每条轨迹的一个工具返回。每个候选仅在满足以下条件时保留：(a) 对照该工具声明的模式/返回类型重新验证通过，(b) 被框架原生解析器无错误地接受，(c) 被一个与任何裁判或智能体骨干 (backbone) 家族不相交的合理性筛查模型判定为"在上下文中不属自明荒谬"。

### 反事实孪生重放判据

**挑战。** 不可检测性本身不能确立污染导致了失败——被污染的运行可能因无关原因失败，或智能体可能干脆恢复了。

**洞察。** 因果决定性与表面隐蔽性是分离的性质；只有以恢复原观测重新执行轨迹，才能排除不可检测却与失败无关的污染。

**方法。** 每个通过合法性门的候选都与一次孪生重放配对，后者在同一步骤把原观测替换回去，在框架允许处固定种子与温度。仅当被污染运行未通过任务的程序化检查器、且孪生通过时，候选才晋升入已验证处理集——按 3–5 倍过量生成以吸收未通过此检验的候选造成的产率损失。

### 盲态归因测试台与信任许可探针

**挑战。** 测得的误归因率可能反映的是硬性能力上限，而非"把轨迹当作可信证据"这一可修的默认行为，两种解释要求不同的修复。

**洞察。** 如果一句允许不信任方法本已可访问之证据的话就能可测量地改变其裁决，那么该偏差更适合用结构性信任默认而非能力上限来解释——因为能力没有变，变的只是许可。

**方法。** 每个受测归因方法——Who&When 的各 LLM 裁判变体、AgenTracer 式训练型追踪器、以及事后重放的 SupervisorAgent 式运行时监视器——在对注入元数据盲态下，对已验证处理集与两组对照集运行。对每个 LLM 裁判变体，第二次运行恰好增加一句提示，声明工具观测可能悄然出错、应独立复核；有无这句话时误归因率的配对差即为机制读数。

### 匹配对照设计

**挑战。** 被污染轨迹上的原始误归因率无法说明偏差是特定于工具观测，还是仅仅反映了注意到任何细微错误取值的一般性困难。

**洞察。** 实验者自己的重放验证真值，恰好提供了受测归因方法都无法访问的反事实比较，把"给定智能体所见，计划步骤看起来情有可原"从不可证伪的借口变成被测量的量。

**方法。** 在与处理集相同的任务与步骤位点上构建两组对照集：显性工具错误臂（异常、超时、空返回），共享工具层根因但发出可见信号；以及智能体侧故障臂，把同一个错误取值注入智能体自身的动作而非工具的观测，在语义差异与细微度上匹配。误归因在全部三臂间比较，并另按被归咎的层（计划 vs. 执行）关于污染算子家族、注入位点（前/中/后三分位）与细微度作交叉表。

### 预注册映射准则

**挑战。** 归因方法以互不兼容的原生词汇报告裁决，一个不受约束的到共享计划/工具/执行本体 (ontology) 的映射可能事后制造或掩盖偏差。

**洞察。** 在看到任何结果之前固定映射，消除了实验者在已知某映射将产生何种答案后再挑选宽严的机会。

**方法。** 在检视任何实验结果之前，为每个归因方法写下一个确定性映射准则，把该方法的原生输出（智能体名、自由文本理由、离散标志）转换为 {plan, tool, execution}。该准则通过在留出样本上的双人标注验证，按方法报告 Cohen's κ，作为信任任何下游误归因数字的前提；一项敏感性分析将准则争议轨迹从头条比较中排除。

## 实验 (Experiments)

### 实验设置

**数据集。** AgentDojo（Debenedetti et al., 2024）——真实工具调用任务（邮件、银行、差旅、Slack），带程序化检查器与结构化、可注入的工具返回；作为试点阶段域，是给注入器与重放判据装配仪器成本最低的域。GAIA（Mialon et al., 2023）——长程多步助手任务，其中一个早期观测在许多步之后仍然承重；专门用于压力测试位点因素（前/中/后注入三分位）以及在比 AgentDojo 更长因果链下误归因方向的类型依赖性。Who&When 的人工标注失败日志——独立来源的真实计划失败对照，其观测经独立核实为干净，避免只靠合成数据自标注"真实"计划失败的循环论证。

**比较对象**（合理性检查下限，而非要击败的对手——这是一项测量研究，没有任何研究问题被表述为"我们的程序击败基线 X"）。常数"总是预测计划"归因器给比较垫底：任何在被污染集上准确率不超过朴素多数猜测的方法，根本不是在对被污染证据做归因。显性工具错误臂确立"当故障发出可见信号时方法能定位工具故障"——这是每个污染观测论断的必要比较对象。匹配的智能体侧故障臂——同一个错误取值，注入智能体动作而非工具观测——隔离任何偏差是否特定于观测通道。

**安慰剂有效性门（在任何研究问题被评分之前检查）。** 显性错误臂与常数归因器都不携带零假设预测，因此都不能证明流水线本身无伪影。首先评估两个按构造为零 (null-by-construction) 的部件：一个*假注入臂 (sham-injection arm)*，让恒等变异（o′_t = o_t）走完完全相同的注入-重放-序列化机制，要求每个方法在假处理孪生与未触碰孪生上的归因分布统计不可区分（等价边际 ±3 个百分点）；以及一个*标签洗牌安慰剂 (label-shuffle placebo)*，在匹配的任务-步骤对内将语义污染/显性错误臂标签置换 1,000 次，要求置换后的 Δ-trust 差距以零为中心。任一部件出现非零结果即整体作废该轮运行——任何研究问题都不得从无效运行中评分。

**前提坍塌与类型无关分支。** 若方法连显性、发信号的工具故障都无法可靠定位（多数方法 m_A(D_overt) > 40%），则本研究要测量的模式合法性区分尚不可解释；在该格中，发现退化为以常数归因器下限为锚的能力审计，下文 RQ5–RQ6 仅作描述性报告、不按通过/失败评分。独立地，若没有任何污染类型、位点或细微度因素能预测归咎方向（RQ6），诚实的发现是盲区在污染家族间无差别而非类型靶向——一种更简单、仍可报告的失败几何，区别于 RQ6 方向论断本身的成立与否。

**人类标注者参照臂（描述性，预注册）。** 从已验证处理集分层抽取 10% 子样本，另由对注入元数据盲态的人类评分者用同一计划/工具/执行本体标注。此臂不设通过/失败标准；预先注册使人类结果的任一方向都无法事后被挑选。若人类同样被骗，则人工标注的归因真值——现有基准赖以构建的标签与分类学——本身就暴露于本研究测量的污染通道，作为对被抽样层的范围声明报告；若人类未被骗，人类比率成为信任许可降低量（RQ3–RQ4）所对照的修复上界。

**运行预算与降级阶梯（预注册）。** 在规模化目标下（三臂 × 每臂每框架 ≥300 条已验证轨迹 × 3 框架），仅已验证语料就包含约 2,700 条轨迹；按 RQ2 在承重字段上 20% 的验证产率下限，构建语义污染臂意味着每框架约 4,500 个过门候选——共约 13,500 个，每个都需要一次污染运行加一次孪生重放，即在归因评分（5 个方法覆盖全部臂，外加三个裁判变体的配对信任许可重跑）之前就有约 27,000 次构建量级。若试点阶段成本核算显示超出预算，预注册的降级顺序为：(1) 放弃第三个框架，保留 AgentDojo 与 GAIA 及完整臂结构；(2) 将 GAIA 位点分层因素降为描述性读数；(3) 将每臂 n 向 RQ3/RQ6 功效带最小值缩减，任何落到功效带以下的格报告为 INCONCLUSIVE（不确定）而非静默欠功效。任何降级步骤都不得砍掉一个臂：匹配对照对比是本文的识别策略，失去它会把研究变成不可解释的单臂比率。

**指标。** 层归因准确率及其补——误归因率；Δ-trust 差距（模式合法污染上的误归因率减去匹配显性错误对照上的）；误归因案例中的方向份额（归咎计划 vs. 执行的比例）；步骤定位准确率（精确与 ±1）；对照假阳性率（真实计划失败被错误归咎于工具层）；映射准则上的 Cohen's κ。

**研究问题：**
1. RQ1——自动合法性筛查是否近似人类不可检测性？
2. RQ2——承重字段靶向是否驱动已验证污染产率？
3. RQ3——信任许可提示是否降低误归因？
4. RQ4——信任许可的降低是否是部分而非完全的？
5. RQ5——误归因偏差是否特定于工具观测通道？
6. RQ6——误归因是否偏向计划层，且偏斜是否依赖污染类型？
7. RQ7——计划/工具/执行映射准则是否可靠？

#### RQ1：自动合法性筛查是否近似人类不可检测性？

**设置。** 分层抽取 150 个通过全部三道自动合法性门的被污染观测（每算子家族 30 个），嵌入其周围轨迹上下文，连同 50 个被注入器在合理性门处拒绝的候选构成的校准集。将两组呈现给一位独立的人类评分者，其对哪些观测被污染或被拒绝保持盲态。

**预期结果。** 至少 90% 的过门污染被独立评为在上下文中合理，而被拒候选校准集的这一比率显著更低（目标：低于 60%）。

**证伪条件。** 若过门合理性比率低于 90%，或其不显著高于被拒候选校准集的比率，则被驳斥——任一情形都意味着自动筛查是人类不可检测性的弱代理，任何下游误归因论断都需重新审视：它测的是真正不可见污染下的诊断，还是细心读者本就会标记的污染下的诊断。

**假设（平实表述）。** 自动合法性门是"阅读轨迹的人是否会察觉异样"的相当忠实的代理。

**指标。** 过门集 vs. 被拒候选集上的人评合理率。

#### RQ2：承重字段靶向是否驱动已验证污染产率？

**设置。** 对承重字段（未污染运行中被智能体自身后续步骤引用的字段，经字符串/AST 轨迹匹配识别）与非承重字段分别尝试污染注入，按算子家族与任务域匹配；对每组 100 个试点候选分别计算孪生重放验证产率。

**预期结果。** 承重字段候选的验证产率至少 20%，而非承重字段候选的产率显著更低（目标：低于 10%）。

**证伪条件。** 若承重字段产率低于 20%，或两组产率统计不可区分，则被驳斥——任一情形都意味着承重字段靶向并非验证产率的驱动因素，构建流水线在规模化阶段于预算内可行之前需要不同的靶向启发式（或更大的过量生成）。

**假设（平实表述）。** 靶向智能体后续步骤实际使用的字段，而非污染任何过得了合法性门的字段，才是让已验证真值构建具备可行性的关键。

**指标。** 每组的孪生重放验证产率。

#### RQ3：信任许可提示是否降低误归因？

**设置。** 方法内配对设计：对三个 LLM 裁判变体中的每一个，在每框架相同的 ≥300 条已验证污染轨迹上各运行两次——一次带、一次不带那句信任许可。由于 McNemar 功效取决于不一致对 (discordant pair) 比率而非 n 本身，仅当观察到至少 72 个不一致对（在预注册的 5 个百分点降低下约 0.8 功效）时才对该裁判变体的降低条款评分；低于该数，降低裁决预先声明为不确定，配对差以置信区间报告而非报告为零结果。

**预期结果。** 至少 2/3 的裁判变体中，许可使误归因率绝对降低至少 5 个百分点（配对 McNemar，α = 0.05），且在真实计划失败对照上无显著假阳性增加（非劣效边际：3 个百分点）。

**证伪条件。** 若多数裁判变体在许可下无显著误归因降低，或任何降低以计划失败对照上超过 3 点边际的假阳性增加为代价，则被驳斥——前者意味着偏差并非简单可移除的默认，后者意味着许可以一种错误换另一种而非修复归因。许可下误归因*显著增加*被预注册为反方向结果，以完整显著性报告——许可主动伤害归因——而非折叠进无降低的措辞。

**假设（平实表述）。** 裁判并非无能力使用不信任信息；它们默认不启用，除非被提示。

**指标。** 每裁判变体的配对误归因率降低；计划失败对照上的假阳性率。作为不附假设的预注册描述性读数，每份裁判理由额外记录被污染观测是否被标记为可疑、责任却仍被安放他处——以零额外运行成本分离"从未注意"与"注意到但推翻"。

**预期结果。** 许可降低但不消除误归因——多数裁判变体的许可后误归因率仍高于其显性错误对照率，原 Δ-trust 差距的多数（目标：高于 50%）保持完整。

**证伪条件。** 若多数裁判变体的许可后误归因率与显性错误对照率统计不可区分，则向"完全修复"方向驳斥；若这与 RQ3 自身的证伪（无显著降低）同时发生，则向"全无效果"方向驳斥。落在两者之间的结果——有降低、但未降到显性错误对照的地板——是唯一与所述部分修复假设一致的结果。

**假设（平实表述）。** 知道证据可能说谎，不等于知道哪条证据在说谎；残余误归因反映的正是这一剩余的反事实推理缺口。

#### RQ5：误归因偏差是否特定于工具观测通道？

**设置。** 试点：一个单智能体工具调用框架，2 个骨干裁判家族，AgentDojo 上每臂（语义污染、显性错误、智能体侧故障）100 条已验证轨迹。规模化：3 个框架，每臂每框架 ≥300 条已验证轨迹；规模化阶段另交叉一个裁判能力层级——同一模型家族内一个弱裁判与一个前沿裁判，在一个框架上——预注册检查该差距在前沿层级不消失（排除"弱裁判伪影、下一代模型即修复"的对立解读）。臂间按方法做两比例检验（任务匹配对用 McNemar），跨 5 个归因方法作 Holm 校正。由于显性错误通常在故障步截断轨迹、而模式合法污染让智能体继续运行，故障-显现距离 (fault-to-manifestation distance) 是该对比的具名混杂：Δ-trust 差距另按故障后后缀长度分层报告，并预先承诺如下解释——若差距在后缀长度层内坍塌，则归于故障-显现距离而非观测通道，通道特异性单独依赖智能体侧故障对比。

**预期结果。** Δ-trust 差距（语义污染上的误归因减显性错误对照上的）对 5 个方法中的严格多数至少 10 个百分点且显著为正（Holm 校正 p < .05）——以这些方法通过显性错误能力门槛为条件（m_A(D_overt) ≤ 40%；见上文前提坍塌分支）——同时智能体侧故障臂上的误归因保持在显性错误对照的几个点以内。多数标准预先承诺为分数形式——通过预注册冒烟测试的基线中的严格多数——使规则在某基线被弃用时仍有定义。

**证伪条件。** 若 Δ-trust 差距对多数方法与零统计不可区分（或为负），则被驳斥——那意味着方法定位模式合法工具污染与定位显性错误差不多可靠。*显著为负*的差距——方法在语义污染上好于显性错误——被预注册为反方向发现，以其自身的完整显著性报告，不折叠进零结果措辞。通道特异性子论断的驳斥条件：若智能体侧故障臂的误归因率与工具观测臂相当或更高——那意味着任何偏差反映的是发现细微错误取值的一般性困难，而非工具观测通道特有的东西，"信任不对称"表述将无法通过该检验。

**假设（平实表述）。** 归因方法并非单纯不擅长在任何位置发现细微错误取值；它们是特定地在错误取值以工具观测而非智能体动作形式到来时不擅长。

**指标。** 每方法的 Δ-trust 差距；智能体侧故障臂相对显性错误对照的误归因率。

#### RQ6：误归因是否偏向计划层，且偏斜是否依赖污染类型？

**设置。** 在 RQ5 的误归因案例中，按算子家族、注入位点三分位与细微度对被归咎层（计划 vs. 执行）作交叉表，覆盖 AgentDojo 与 GAIA；对计划份额相对 0.5 作精确二项检验，加一个混合效应逻辑回归（固定效应：三个网格因素，另以故障后后缀长度为协变量控制；随机截距：任务与框架）。**基于功效的评分带（由最初欠功效的 n=50 设计修正而来）：** 在预注册目标 π_plan = 0.65 下，n=50 的精确二项检验功效仅约 0.51，会有约一半概率把真实偏斜误报为"方向弥散"；因此评分规则按格而非单一固定 n——n ≥ 120 个误归因案例对方向论断评分（在临界计数 72/120 处功效约 0.89），50 ≤ n < 120 预先声明为 INCONCLUSIVE 而非按零结果评分，n < 50 仅作描述性报告。

**预期结果。** 误归因案例中合并的计划份额显著高于 0.5（目标：至少 0.65），且至少一个网格因素是归咎方向的显著预测因子（似然比检验，p < .05），偏向计划的偏斜在细微、靠后、数值/过期值污染上增强。

**证伪条件。** 方向上：若计划份额与 0.5 无显著差异（精确二项），或反而偏向执行，则被驳斥。类型依赖上：若没有任何网格因素（算子家族、位点三分位、细微度）在混合效应模型中是显著预测因子，则被驳斥——任一结果都意味着误归因发生时在方向上是弥散的而非导向某一层，这是一种不同的、仍可报告的失败几何，而非预测的偏斜。

**假设（平实表述）。** 误归因发生时并非计划与执行之间的掷硬币——计划批评紧邻阅读被污染观测的下游，而执行裁决锚定在污染不会触发的机械信号上。

**指标。** 计划份额及其置信区间；三个网格因素的混合效应模型系数。

#### RQ7：计划/工具/执行映射准则是否可靠？

## 相关工作 (Related Work)

最接近的先行工作是 Who&When 与 AgenTracer：Who&When 已把归因形式化为由 LLM 裁判阅读轨迹日志识别决定性智能体-步骤对，AgenTracer 已用反事实重放与程序化故障注入训练追踪器——但两者都未控制、也未表征"日志自身的工具观测被污染却格式良好"的情形，而这恰是本文要测量的空白。两项 2026 年的工作在两翼上离得最近，在此预先承认：Who&When Pro 把注入构建的归因基准测试扩展到 12,326 条黄金标签轨迹——标签在注入时刻按约定分配，无表面不可检测性认证，无匹配通道对照；The Misattribution Gap 为被对抗性投毒的持久记忆记录了污染证据通道下的误归因，与此处测量的非对抗、瞬时工具观测污染互为姊妹通道与威胁模型（下文完整定位）。一个并行的因果推断方法 Causal Agent Replay 与我们同样依赖同机制的观测替换干预，但提出的是替代性归因器而非测量现有方法的偏差——见下文。

**面向 LLM 智能体的自动失败归因。** Who&When 把归因形式化为识别"纠正之即让失败轨迹翻转为成功"的决定性智能体-步骤对，发布人工标注数据集并在多种上下文管理策略下评估 LLM 裁判归因。AgenTracer 把决定性错误定位转为可训练的预测问题，经由反事实重放与向智能体动作的程序化故障注入生成监督，再用强化学习训练追踪器。MAST 从对自然发生轨迹的人工标注中导出经验扎根的多智能体失败模式分类学。Causal Agent Replay 把智能体运行建模为结构因果模型 (structural causal model)，经 do(·) 干预分配责任——包括替换工具结果的 do_observation 操作，与我们的孪生重放判据是同一个概念动作——但仅对带模拟、无副作用工具的合成因果模型作验证，未检验现有已部署归因方法是否恰在真实工具观测的已验证、模式合法语义污染下误归因；它提出新归因器，而非审计已在使用中的那些。Who&When Pro 将这一家族产业化：一条严格受控的流水线仅在精确重放成功前缀后注入失败，产出横跨 3 种模态、26 个基准的 12,326 条带黄金标签的失败轨迹——但标签在注入时刻按约定分配，无不可检测性认证、无对照匹配的决定性回环验证、也没有任何"注入故障是观测通道中格式良好的谎言"的条件。一个快速拥挤的 2025–26 浪潮进一步扩展了方法家族——CHIEF 把扁平日志转为层级因果图，用反事实筛查从传播症状中甄别根因；FALAT 把归因构造为依赖引导的搜索，恰因后续步骤可能仅仅由于依赖更早被污染的状态而显得错误；因果推断变体经性能反转与 Shapley 信用分配步骤级责任——然而浪潮中的每个成员都把轨迹的工具观测当作可信输入来推理；忠实日志上传播的*智能体*错误正是它们处理的情形，而说谎的日志正是它们不处理的情形。所有这些工作都把轨迹日志（或对 Causal Agent Replay 而言，实时重执行的轨迹）当作在各自选定混杂校正后的忠实证据——Who&When 的决定性错误定义与 MAST 的分类学都只在自然发生的智能体错误上行使，AgenTracer 的故障空间是智能体动作而非工具返回，Causal Agent Replay 的验证空间是合成与模拟的——因此没有一个控制、甚至表征本文测量的特定情形：真实归因方法在真实基准轨迹上、其工具观测被污染却格式良好时的行为。

**工具返回通道的安全性与可靠性。** ChatInject 构造伪造聊天模板角色标签的恶意工具输出，使低权限工具内容被解释为高权限指令。MCP-SafetyBench 把包含工具投毒在内的多层攻击分类学嵌入针对真实 MCP 服务器的可执行任务。ResiliBench 构建带参数化概率错误模式——超时、非法输入、操作失败——的模拟工具注册表，测量智能体能否在执行不确定性下调整工作流。三者共同确立了工具返回通道要么可被主动攻击、要么普遍不可靠，但都没有追问下游诊断是否正确定位了由此产生的失败：ChatInject 与 MCP-SafetyBench 测量指令载荷上的攻击成功率，与普通字段里一个明白错误的取值分属不同威胁模型；ResiliBench 的错误模式按设计是显性的，以智能体必须适应的可见失败形式浮现，而非静默、格式良好的谎言。在被操纵变量本身上离得最近的 Don't Blindly Trust It，在匹配的智能体循环中对比忠实、误导与缺失三种工具反馈，发现价值反转——受益于干净工具的智能体在误导反馈下可能比完全没有反馈时表现更差——确立了该现象对*任务表现*的代价，却未测量其对*诊断*的代价，而后者正是此处的估计对象 (estimand)。

**工具返回之外的污染证据。** 记忆投毒文献提供了与我们估计对象家族最近的邻居。The Misattribution Gap 表明记忆层攻击——一份政策格式的文档被洗入共享向量库、随后以可信上下文的身份重现——产生的智能体不当行为被归因与安全工具系统性地误读为模型失败：在 64 例记录在案的失败中，归因一致地归咎于模型，四个安全分类器零检出；作者的反事实组合测试随后识别出因果条目，与我们的孪生重放判据是同一个概念动作。因此，"污染证据通道下的误归因"不再是未经检验的想法，我们直白地承认这一优先权。定义本文的差异有三重：被污染的通道（瞬时、逐步的工具观测，而非持久记忆库）、威胁模型（普通字段里非对抗、模式合法的错误取值，而非需要来源信息丢失的攻击）、以及受测的诊断对象（已部署的计划/工具/执行归因家族——LLM 裁判、训练型追踪器、运行时监视器——在盲态下配以匹配通道对照与方向估计对象运行，而非安全分类器与防御方修复决策）。

**运行时监督与混杂隔离。** SupervisorAgent 添加一个轻量元智能体在运行时监督高风险交互通道，由一个免 LLM 的触发过滤器激活，其键控信号为显式错误发生、重复行为或观测长度超限。BreakingAgentBackbones 论证端到端智能体基准难以把失败归于骨干 LLM 而非工具包装器或控制流，并通过隔离单次 LLM 调用及其完整上下文作安全评分来解决——而非检验轨迹级归因是否错误定位故障。前者的监督信号恰是模式合法污染不会发出的；后者虽为本文测量的归因混杂问题提供了动机，却以移除轨迹而非在轨迹上检验归因作答。

## 结论 (Conclusion)

本工作把每条自动失败归因流水线中隐含的假设——轨迹日志是可信证据——重构为一个具有精确、可检查结构的实证问题，而非把格式良好的工具观测视为自明可靠。核心的方法论押注是：只有当因果决定性与表面不可检测性作为注入故障的两个分离性质被分别验证、且任何偏差被证明特定于工具观测通道而非"注意到细微错误取值"的一般性困难之后，一个声称的归因偏差才是可信的；更弱的设计有把偶然相关、映射噪声或一般性取值发现困难误当作真实归因缺陷的风险。无论当前方法呈现何种模式，该发现都与决策相关：一个为正的、方向特定的 Δ-trust 差距意味着依据归因裁决重训规划器或加固执行的团队常在追逐错误的组件；零结果则意味着轨迹即证据的假设比结构论证所暗示的更稳健。任一结果也都补全了记忆投毒文献已为持久存储勾画的图景——被投毒的记忆被误读为模型失败——方式是测量每个归因方法每一步都要读取的那个污染证据通道，且在一个完全不需要攻击者的威胁模型下。两项局限从一开始就为该论断划界：本研究覆盖逐一验证的单观测污染，把复合多观测污染留给后续工作；映射准则的信度（RQ7）本身可能在计划/工具/执行边界真正模糊的轨迹上暴露分歧——这是本设计选择报告而非解决的局限。
