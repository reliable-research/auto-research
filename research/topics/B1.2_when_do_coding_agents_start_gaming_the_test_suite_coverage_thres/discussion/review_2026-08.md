**Framing firewall note.** The draft's headline sentence ("the slack between passing a suite and being correct is exactly the suite's surviving-mutant set") survives verb-stripping: the named object is the size/coverage-matched adequacy-swept sub-suite construction plus the gap-curve estimand — a mechanism, not a bridge verb. Consistent with `taste_audit.md`'s 🟢.

**Overall novelty stance: 🟢 novel-with-conceded-neighbors — carried by claims 1+5 (the adequacy-swept gap curve), conditional on naming the 2025–26 gaming-benchmark cluster.**
Honest one-sentence delta: *Relative to SpecBench/ImpossibleBench/EvilGenie — which establish that coding agents do game their visible tests at some fixed suite construction — this paper's real contribution is making the suite's own mutation-kill adequacy the manipulated variable, so it can localize when gaming starts, attribute it per-patch, and separate adaptive exploitation from the mechanical selection ceiling.*

## 2. Feasibility verdict

**Feasible with real but bounded risk; a minimum-viable kill-test exists.**
- The CPU-only pilot (RQ1 sampler fidelity + RQ2 oracle soundness on 10 instances, plus QuixBugs piloting) is a genuine kill-switch that spends no GPU/API budget before the design's hardest assumption (constructibility of low-`ms` sub-suites at matched size/coverage on real instances) is tested. Mutant-generation cost is bounded by restricting mutation to gold-patch-touched files; Defects4J reuses precomputed kill matrices.
- Power arithmetic: primary RQ3 comparison carries a stated 80–90% power target with a pre-committed enlargement rule; per-cell power for RQ4/RQ7 correctly deferred to the pilot's variance estimate (pipeline F11, needs real compute — acceptable for a pre-registered spec).
- Annotation load (100 patches × 2 annotators + adjudication, RQ5) is modest and realistically schedulable; it is the critical path only if left until after the sweep.
- Main risks, addressed by this pass's fixes: (a) scale-up size (~36,000 episodes ≈ 3×300×8×5, arithmetic checks out) had no compute bound or descope order → F5; (b) instance attrition at low adequacy levels had no pre-declared handling at the confirmatory grid level → folded into F5; (c) 3-level random effect → F4.

## 4. Numbered findings

1. **[major]** Intro + Related Work omit the 2025–26 agent test-gaming measurement cluster: **ImpossibleBench** (arXiv 2510.20270, 2025-10 — agents' propensity to exploit tests via spec-vs-test-conflicting task variants of SWE-bench/LiveCodeBench; "cheating rate"), **EvilGenie** (arXiv 2511.21654, 2025-11 — reward hacking on LiveCodeBench problems, detected via held-out tests, LLM judge, test-edit detection, human-verified; observes explicit hacking by production agents), **SpecBench** (arXiv 2605.21384, 2026-05 — quantifies reward hacking of long-horizon coding agents by the visible-validation vs. held-out-composition pass-rate gap). 2. **[moderate]** **Probe to Generate** (arXiv 2604.01518) uncited, and the draft's absolute claim that SWE-bench ships "no measure of, or control over, those tests' adequacy" is stale — this work both measures the slack (77% of Verified instances admit a surviving reference-patch variant) and closes it via variant-guided test augmentation.
