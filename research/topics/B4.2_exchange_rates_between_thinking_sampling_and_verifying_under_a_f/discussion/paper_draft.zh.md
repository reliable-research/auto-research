# 为验证器定价：思考、采样与验证之间以美元计价的兑换率

> 由 `pipeline.md` 中六个已确认的阶段产出组装而成，通过品味审计（`taste_audit.md`：🟢）。状态：**规格说明 / 论文草稿——尚未运行任何实验。** 下文所有数字均为预注册的设计目标，而非实验结果。（2026-08-21 评审修订后版本；见 `review_2026-08.md`。）

## 摘要

在固定美元预算下部署一个 LLM 推理系统，意味着要把预算拆分给三个可用的杠杆（lever）：加长思维链（chain-of-thought, CoT）推理、抽取更多独立样本、以及付费调用验证器（verifier）在候选中做选择。我们指出，这一选择建立在一个现有预算分析从未定价过的不对称性之上：花在验证上的一美元本身买不到任何准确率，因为验证器只能对生成美元已经产出的候选重新打分——然而此前每一项针对这些杠杆的分配研究都以 FLOPs、token 或轨迹（trajectory）为预算计价单位，且没有任何一项把验证器自身的调用成本记入其候选被生成时所受的同一约束。我们把思维链长度、样本数与验证器调用以同一美元单位计量，在所得分配网格上拟合单一的交互感知响应面（interaction-aware response surface）而非逐杠杆独立扫描，将同一协议原样复制到按可校验性（verifiability）排序的任务族上，并把任何归因于验证器的准确率增益与预算匹配的多数投票（majority-vote）对照及真值选择上限（ground-truth selection ceiling）进行分解比对。我们报告所得的每美元准确率前沿（accuracy-per-dollar frontier）、杠杆两两之间的估计兑换率（exchange rate），以及该前沿的形状究竟是测试时计算（test-time compute）的普适性质，还是取决于任务族的可校验程度。

## 引言

在计量计费的预算下部署大语言模型进行推理已不再是纸上谈兵。对托管模型的每一次调用都附带美元价格，而一个要在该价格下回答难题的系统有三个常见的花钱杠杆：让模型在作答前思考更久、抽取多次独立尝试再加以合并、或者把部分预算花在一个先检查再挑选答案的第二模型上。每个杠杆都很容易加进现有流水线——这恰恰是为什么各团队往往三者并用，却很少审视这种组合是否值回它消耗的预算。

然而这三个杠杆之间有一个特定的不对称性，从未被任何现有的权衡分析定过价。花在更长推理或额外样本上的一美元可以凭自身产出一个此前不存在的正确答案；花在验证上的一美元则不能：验证器只能对生成过程已经产出的候选重新打分，因此它的全部贡献都派生于同一预算中花在别处的美元。如果验证是免费的，这只是学术层面的区分——但它并不免费：每次验证器调用都消耗自己的输入与输出 token，其计价方式与它所评分的调用完全相同。因此，边际一美元究竟应当用于再生成一个候选、还是用于检查已有候选，是一个实打实的计量权衡，而非固定的流水线选择——而现有研究没有一项把它当作这样的权衡来定价。

与此缺口最接近的既有工作从相邻但不同的角度切入。计算最优分配研究——包括 Snell 等人的按难度条件化的策略选择，以及 Plan-and-Budget 这类步级 token 预算法——都确立了固定计算量*如何分配*与花多少同等重要，但两者都以 FLOPs 或 token 计价、只在单一任务族内评估、且从不把验证器自身的调用成本记入其所竞争的预算。另一条理论线路研究"先采样后验证"（sample-then-verify）流水线：给无验证器轨迹蒸馏的次优性设界、把验证器引导的采样刻画为最优传输（optimal transport）、为频率过滤的 best-of-N 选择推导极小极大最优遗憾（minimax-optimal regret）、把生成器-重排器系统建模为有噪通信信道——这些框架都把验证器视为带有形式化性能界的可用资源，却没有一个允许验证器自身的成本进入它所要刻画的预算约束。第三条线路孤立刻画单一杠杆：思维链长度与准确率之间的倒 U 形关系，或采样覆盖率（coverage）随样本数近似对数线性增长——都在固定另外两个杠杆的前提下进行，无法把某一杠杆的价值对另外两者的成本做归一化。第四条更近的先例在十九个开源推理模型上绘制了经验性的计算-准确率帕累托前沿（Pareto frontier），我们承认本文也使用其前沿绘制方法——但其计算轴是跨模型的单一 FLOPs 度量，从未分解为思考长度、样本数与验证器调用三个杠杆，也没有任何美元计量把验证或选择成本与生成成本分开记账。第五条同期线路已经用真实美元为 LLM 推理决策定价——为智能体工作流按美元计价的投机执行（speculative execution），以及企业级编码智能体的推理经济学（inference economics）案例研究——因此美元计价本身已不再新颖；但这些工作定价的是投机调度决策或部署配置选择，而非思考、采样与验证之间的分配，也没有一项把验证器的调用成本记入与之竞争的生成预算。与本文所研究权衡最接近的既有工作是一项针对网络搜索智能体的非对称验证（asymmetric verification）研究：它已经在同一共享单位下把预算拆分给探索杠杆与验证杠杆——但只在单一领域内，成本以轨迹和工具调用而非美元计量，且完全没有思维链长度这一维，无法补全本文所需的三杠杆图景。

把这一不对称性变成可测量的问题，本身就会带来一系列困难。三个杠杆的计价粒度不同——输出 token、每个额外样本翻倍的输入加输出成本、以及验证器自身的输入加输出成本——因此把它们映射到一个公平的美元单位是一个设计问题，而非查表。任一杠杆的边际价值取决于另外两者的设置：只有一个候选可筛时验证器一文不值，候选池越大它的信息量越高；而更长的推理同时改变验证器所要阅读内容的准确率与长度（从而改变成本）。各任务族在答案可被检查的成本与可靠性上差异巨大——从可执行测试、精确匹配答案到评分细则（rubric）判断——因此在一个任务族上测得的兑换率不能假定迁移到可校验性画像不同的另一族。模型无法被强制输出恰好目标数量的 token，"匹配预算"只能瞄准而无法钉死，迫使所有比较都基于实际（realized）而非名义（nominal）成本。并且，由于覆盖率——多个样本中是否有某个恰好正确——与选择质量——验证器是否挑中了正确的那个——都是同一生成候选池的函数，归因于验证器的准确率增益同样可能是任何选择规则（哪怕免费的）都能从更多候选中获得的增益。

我们的方法把上述每个障碍都转化为一项具体的设计决策，而不是含糊带过。逐调用美元计量器把每个生成与验证 token 记在一张实验开始时冻结的价目表（price sheet）上，同时保留一套供应商中立的平行记账，使定性结论可以对价目表扰动做稳健性检验，而非默认与之无关。在整个分配网格上拟合单一的交互感知响应面，而非逐杠杆拟合，使"杠杆之间是可加还是交互"本身成为拟合的可检验输出，而非实验设计中预设的假定。完全相同的测量协议在按可校验性先验排序的任务族间原样复制，使任何跨族的有效分配差异都能归因于可校验性，而非测量方式的不一致。只保留期望成本落在各目标预算预设容差带内的网格配置，并在其上叠加对实际成本的回归校正，使"匹配预算"描述的是实际收集到的数据，而非请求的设置。最后，每一个归因于验证器的准确率增益都要对照一个把相同美元花在更多候选而非验证器上的预算匹配多数投票对照，以及一个零成本真值选择上限，使验证器的测得价值从不被假定，而总是被证明经受住了最廉价的替代解释。

我们在覆盖可执行代码、精确匹配数学、多项选择科学题与按评分细则打分的开放域问答的任务族上评估该设计，并把所得每美元准确率前沿与固定地板分配（floor allocation）、预算匹配多数投票组、零成本真值选择上限、以及一个换算到同一美元单位的现有 FLOPs 原生分配策略进行比较。

综上，我们的贡献是：
- 对测试时预算分配底层不对称性的识别与形式化：验证是一个二阶杠杆，其价值始终派生于花在生成上的美元，使其与另外两个杠杆的兑换率成为分配本身的函数，而非固定常数。
- 一个以美元计价的测量工具，把思维链长度、样本数与验证器调用以同一货币计量（含验证器自身的调用成本），并内置显式的价目表稳健性检验而非仅仅假定。
- 一个交互感知的分配网格与跨族复制协议，联合检验每美元准确率前沿的形状是测试时计算的普适性质，还是特定于任务族可校验程度的性质。
- 一个覆盖率/选择分解——预算匹配的多数投票对照加真值选择上限——把真正的验证器价值与任何等价免选择替代方案本可从同一候选池获得的准确率分离开来。

## 问题定义

**形式化设定。** 设查询 q 抽取自任务族 F。一个分配 a = (L, N, V) 固定思考 token 上限 L、样本数 N 与验证器模式 V。一张冻结价目表 P = (p_in, p_out) 把每次生成与验证器调用的输入输出 token 换算成美元；实际成本 c(q,a) 是在分配 a 下回答 q 所需的每一次调用（生成与验证均计入）经此换算后的总和。预算档位 B_k 定义匹配成本箱（matched-cost bin）𝔅_k = {a : |𝔼[c(·,a)] − B_k| ≤ ε·B_k}。准确率 Acc_F(a) 是该族评分器在分配 a 上的平均成功率。研究对象为：对每个 (F, B_k)，(𝔼[c], Acc_F) 上的非支配集——即每美元准确率前沿——沿该集合的杠杆两两边际替代率（marginal rate of substitution, MRS），以及该集合的分配构成在 F 之间是否稳定。若某 (F, B_k) 单元中没有任何被评估分配能在匹配或更低成本下以预设幅度（≥5 个准确率百分点，按预注册的 B0 门槛）超过固定地板分配，则该单元被排除出兑换率与前沿形状论断，单独报告为**分配无意义（allocation-moot）**，而非被悄悄丢弃或记作杠杆可互换的证据。

**为何困难。** 冻结一张价目表并不能自动给出对三个杠杆的公平记账：思考 token 只按输出计价，额外样本同时放大输入与输出成本，验证器调用则消耗其自身的输入（受审候选）与输出（判决）token——因此把分配 a 换算成单一实际成本 c(q,a) 是一项设计决策而非查表，且所有下游论断都继承该决策所固定的约定。a 中任一分量的边际价值取决于另外两个分量：同样的 V 增量在 N 大时比 N=1 时更值钱，而更长的 L 同时改变 V 所需筛查内容的准确率与长度（从而改变验证器自身的阅读成本），故任何两杠杆间的兑换率都不能不经检验就被假定在全网格上恒定。各任务族在 Acc_F 可被计算的成本与可靠性上差异巨大（从可执行测试到评分细则判断），因此在一个族上测得的前沿不为可校验性画像不同的另一族背书。由于 c(q,a) 经由随机的生成过程实现，任何分配的成本都无法事先钉死，𝔅_k 的成员资格只能瞄准，且必须用实际而非名义成本做事后校正。最后，由于 V>0 时 Acc_F(a) 同时反映生成了多少候选与 V 挑选得多好，观察到的准确率增益在缺少把选择质量与覆盖率隔离的对照时，不能归因于验证。

## 方法概览

在概念层面，本研究是一条含五个协作部件的单一测量流水线，每个部件封住上文的一个难点。查询与分配进入流水线；共享美元计量器把每次调用（生成与验证均计入）变成同一可比成本；对所得网格的交互感知曲面拟合把成本与准确率变成前沿、一组边际替代率、以及对杠杆是否可加的显式检验；同一协议的跨族复制把单一前沿变成关于其形状普适还是族特异的裁决；覆盖率/选择对照则把任何归因于验证器的准确率增益变成一个经受住了最廉价对手解释的论断。

**统一美元成本计量器**读取每次生成与验证器调用的 token 用量，按一张实验开始时冻结的价目表折算为美元，并同时保留供应商中立的平行记账，使结论可对价目表扰动做检验而非默认稳健。**交互感知响应面**取所得（成本，准确率）网格，把准确率拟合为思考上限、样本数与验证器模式的联合函数并带显式交互项，使某一杠杆的价值是否依赖其余杠杆的设置成为被测量而非被假定消去的量。**按可校验性分层的复制**把完全相同的协议原样重跑在按检查成本与可靠性先验排序的任务族上，把单族前沿变成跨族稳定性裁决。**匹配成本分箱与实际成本校正**把网格固有的随机实际成本变成预设容差箱加事后回归校正，使"匹配预算"是所收集数据的属性而非所请求设置的属性。**覆盖率/选择分解**取前沿上每个验证密集点，对照预算匹配多数投票与真值选择上限，使验证器的表观价值只有在经受住"这些美元换成额外样本也能买到同样准确率"的替代解释后才被断言。

## 方法论

### 统一美元成本计量器

**挑战。** 三个杠杆的计价粒度与不对称性各异——思考 token 只计输出，额外样本使输入与输出成本同时翻倍，验证器自身的输入加输出 token 还要另外计费——没有任何单一查表能把一个分配换算成一个公平的美元数。

**洞察。** 成本通约（cost commensuration）无法解析地解决——输入与输出 token 之间、生成调用与验证调用之间不存在唯一"真实"兑换率——但它可以被变成一个显式、可检查、带声明敏感带的记账约定，而非悄悄嵌入最终上报数字的隐含假设。

**方法。** 一个逐调用记账层直接从推理引擎的用量字段记录每次生成与验证器调用的输入输出 token 数，按一张实验开始时冻结的价目表折算为美元，并把每一美元归属到产生它的杠杆。一套平行账目以供应商中立的归一化 token 单位表达同样的成本，使任何结论都可以脱离冻结价目表的具体数字被复查。

### 交互感知响应面

**挑战。** 任一杠杆的边际价值很可能取决于另外两者的设置——候选池越大验证器越值钱，推理长度改变验证器要读的内容——把三个杠杆当作独立计价，会悄悄假定掉本研究恰恰要测量的结构。

**洞察。** 若杠杆间可加权衡，测一次的单一兑换率就处处适用；直接拟合交互项正是把这个方便假设变成可检验论断而非设计默认值的手段。

**方法。** 单一响应面模型把准确率联合回归到思考上限、样本数与验证器模式上，带样本数×验证器模式和思考上限×验证器模式的显式交互项，在全网格上一次拟合而非逐杠杆拟合。每个交互项通过似然比检验（likelihood-ratio test）对照可加（无交互）模型。

### 按可校验性分层的复制

**挑战。** 单一任务族上测得的前沿不为其向可校验性画像不同的族迁移背书，且可校验性天然与任务族间的其他差异——难度、答案格式、评分噪声——相互混杂。

**洞察。** 把测量协议在各族间逐字节保持一致——同一计量器、同一分箱、同一统计检验——正是使观察到的跨族差异可归因于可校验性、而非各族恰好被测得不一致的原因。

**方法。** 完全相同的匹配成本网格协议在四个按可校验性类别先验排序的任务族上运行——可执行代码、精确匹配数学、多项选择科学题、按评分细则打分的开放域问答——并用族对之间在匹配预算档位上有效集分配构成的 Aitchison 距离置换检验（permutation test）来检验跨族相等性。

### 匹配成本分箱与实际成本校正

**挑战。** 由于无法强制模型输出恰好目标数量的 token，任何分配的美元成本都无法事先固定，"匹配预算"比较就有在不同实际成本上悄悄比较的风险。

**洞察。** 解法不是更好的长度控制机制，而是显式的接受准则加事后校正："匹配预算"变成实际收集数据的被测属性，而非对所请求设置的假定。

**方法。** 每个网格配置的期望成本由试点 token 统计估计，只保留期望成本落在各目标预算档位预设容差带内的配置。拟合的准确率-成本曲面还在箱内按每条查询的实际（而非名义）成本做回归校正，使箱内残余成本差异被计入而非忽略。

### 覆盖率/选择分解

**挑战。** 覆盖率——众多样本中是否有正确的——与选择质量——验证器是否挑中正确的——都是同一生成候选池的函数，因此验证密集分配下的准确率增益，在未排除"同样的美元花在更多候选、不用验证器也会有同样增益"之前，不能归因于验证器。

**洞察。** 把准确率增益专门归因于验证、而非其美元本可购买的候选的唯一办法，是一个把完全相同的美元花在更多样本且完全不用验证器的对照——加上一个真值选择上限，钉死任何选择器（无论多好）能从同一池中实现的上界。

**方法。** 对拟合前沿上的每个验证密集点，预算匹配多数投票对照在同一成本箱内把验证器的美元重新分配为额外样本，同时在相同思考上限与样本数下运行一个零成本真值 oracle 选择组。验证器的测得准确率价值只在超过其预算匹配多数投票对照处才被断言；oracle 组则给出该价值中任何选择器在同一池上所能实现部分的上界。

## 实验

### 实验设置

**数据集。** MATH-500（数学，精确匹配）——试点任务族，评分无歧义、成本低，适合在铺开前先验证成本计量器与首次交互面拟合。HumanEval+ 加一个 LiveCodeBench 切片（代码，可执行）——预注册可校验性排序下最验证密集的族，分层复制与覆盖率/选择分解都需要一个验证器杠杆最有发挥空间的族。GPQA-Diamond（研究生级科学，选项匹配）——可校验性排序上的中间锚点，使排序论断不沦为数学与开放问答之间的两点比较。FRAMES 加一个 SimpleQA 子集(开放问答，按评分细则打分)——可校验性最弱的族，既检验排序在最弱信号端是否成立，也因为评分细则裁判本身就是类验证器工具，使覆盖率/选择混杂在此最尖锐。

**样本量与统计功效（power）。** 试点阶段每族运行 n ≥ 300 道题（数学、代码），预注册在 Acc ≈ 0.6 处对 5 个百分点的配对对比达到功效 ≥ 0.8；跨族复制阶段在全部四族上每族运行 n ≥ 500 道题。任何 (族, 预算) 单元、或任何具体的交互项或边际替代率检验，若其*实际*功效低于其预注册效应下限对应的 0.8，则仅就该单元或该检验预先声明为**不可判定（INCONCLUSIVE）**——绝不评为通过/未通过，也绝不悄悄并入汇总。有一项数据集算术约束在此言明而非留待日后发现：GPQA-Diamond 只有 198 题、HumanEval+ 只有 164 题，因此多项选择族必须取自更大的 GPQA 池（448 题的主集或 546 题的扩展集），代码族的 LiveCodeBench 切片必须贡献至少 336 题，n ≥ 500 的复制目标才可达；若某族实际题池仍不足，则对其受影响单元适用上述 INCONCLUSIVE 规则，而非悄悄下调目标。

**基线**（作为健全性对照与上限，而非要击败的竞争者——这是一项测量研究，没有任何研究问题被表述为"我们的流程胜过基线 X"）。固定地板分配（最小思考上限、单样本、无验证器）是必要的"分配到底值不值得做"门槛：若某 (族, 预算) 单元中没有任何配置能在匹配或更低成本下以预设幅度（≥5 个准确率百分点，按预注册 B0 门槛）超过该地板，则按问题定义的排除规则，该单元被排除出兑换率与前沿形状论断并报告为**分配无意义**，而非被悄悄并入前沿。预算匹配多数投票对照把验证密集分配的验证器美元在同一成本下重新分配为额外样本。一个按难度条件化的计算最优分配器，从其原生 FLOPs 匹配形式换算成美元后，检验一个没有成本计量器时调出的分配策略换算后是否恰好落在美元最优前沿附近。零成本真值 oracle 选择器为覆盖率/选择分解提供覆盖率上限——是健全性界限，不是要击败的目标。

**指标。** 每个网格点的实际美元成本与该族准确率；每族每预算档位带自助法（bootstrap）置信带的非支配每美元准确率前沿；交互项系数及其似然比统计量；每个前沿点的分配（美元份额）向量与跨族 Aitchison 距离置换统计量；以及匹配思考上限与样本数下的 oracle 减验证器准确率差距。

**研究问题（RQ）：**
1. RQ1——前沿形状排序对价目表扰动是否稳健？
2. RQ2——验证器的兑换率是否与样本数交互？
3. RQ3——验证器价值与样本数的交互是否强于与思考长度的交互？
4. RQ4——前沿形状是否随任务族不同？
5. RQ5——验证密集美元份额是否遵循预注册的可校验性排序？
6. RQ6——匹配成本箱能否在不启用预声明容差放宽修正案的情况下填满？
7. RQ7——实际成本校正对前沿置信带是否起承载作用？
8. RQ8——验证器价值能否经受预算匹配的纯覆盖对照？
9. RQ9——oracle 与验证器的准确率差距是否随样本数增大而缩小？

#### RQ1：前沿形状排序对价目表扰动是否稳健？

**设置。** 在输入/输出 token 价格比与生成器/验证器价格比上施加 ±3× 扰动、其余不变，对每个被测（族×预算）单元重算前沿形状排序（哪个族在其最高准确率有效点上最验证密集）。

**预期结果。** 在至少多数被测单元中排序在扰动下保持不变——计量器的定性结论不是某张特定价目表的伪影，尽管绝对美元数值是。

**证伪条件。** 若在 ±3× 扰动下超过半数被测单元的排序发生改变，则被驳斥——那意味着前沿形状发现是价目表伪影而非杠杆的结构性质。

**假设（通俗表述）。** 定性故事（何处哪个杠杆占优）不依赖于测量它所用的具体价目表，尽管确切美元数字依赖。

**指标。** 扰动带内的排序一致率，按单元与汇总。

**结果。** *[占位——实验运行后填写]*

#### RQ2：验证器的兑换率是否与样本数交互？

**设置。** 在试点网格（MATH-500）上拟合交互感知响应面，用似然比检验对照可加模型检验样本数×验证器模式交互项，在适用处对族与公平性参照做 Holm 校正。

**预期结果。** 交互项在至少一个任务族上统计显著，意味着在某一样本数下测得的验证器兑换率不能原样迁移到另一样本数。

**证伪条件。** 若似然比检验在任何被测族上都未发现显著的样本数×验证器模式交互，则被驳斥——那意味着可加（恒定兑换率）模型已经足够，更复杂的曲面一无所加。

**假设（通俗表述）。** 在某一样本数下买入的验证器，换个样本数就不值同样的钱。

**指标。** 每族的交互项系数及其似然比统计量。

**结果。** *[占位——实验运行后填写]*

#### RQ3：验证器价值与样本数的交互是否强于与思考长度的交互？

**设置。** 在样本数×验证器模式与思考上限×验证器模式两个交互项都显著的单元中，比较其拟合幅度。

**预期结果。** 在多数此类单元中样本数交互的幅度超过思考上限交互的幅度——验证器价值更多取决于它筛查多少候选，而非每个候选多长。

**证伪条件。** 若在多数合格单元中思考上限交互的幅度等于或超过样本数交互的幅度，则被驳斥。

**假设（通俗表述）。** 主要改变验证器边际价值的是它筛查的候选池大小，而非每个候选的长度。

**指标。** 每个合格单元的交互项幅度之比。

**结果。** *[占位——实验运行后填写]*

#### RQ4：前沿形状是否随任务族不同？

**设置。** 在全部四个任务族上运行完全相同的匹配成本网格协议，对每对族在匹配预算档位上的有效集分配构成计算 Aitchison 距离置换检验（10,000 次置换），对六个族对与被测预算档位做 Holm 校正。

**预期结果。** 置换检验在 Holm 校正 α = 0.05 下对 6 个族对中的至少 2 对拒绝跨族分配构成相等。

**证伪条件。** 若没有任何族对在任何被测预算档位上显示显著差异，则被驳斥——那意味着单一分配策略一经测得即可跨可校验性区制迁移而无需调整。

**假设（通俗表述）。** 花测试时预算的有效方式并非对每类任务都相同。

**指标。** 每个族对与预算档位的 Aitchison 距离与置换 p 值。

**结果。** *[占位——实验运行后填写]*

#### RQ5：验证密集美元份额是否遵循预注册的可校验性排序？

**设置。** 在每族的最高准确率有效点上计算验证器占总支出的美元份额，把四族与预注册排序（可执行代码 ≥ 精确匹配数学 ≥ 多项选择 ≥ 评分细则开放问答）比较。

**预期结果。** 排序成立，且代码对开放问答的差距在多数被测预算档位上绝对美元份额至少 0.10。

**证伪条件。** 若观察到的排序与预注册可校验性排序相矛盾（例如开放问答反而是最验证密集的族），或代码对开放问答的差距在所有被测预算档位上都低于 0.10，则被驳斥。

**假设（通俗表述）。** 检查起来更便宜更可靠的任务族，在其最佳有效点上把更多预算花在验证上。

**指标。** 每族每预算档位的验证器美元份额向量。

#### RQ6：匹配成本箱能否在不启用预声明容差放宽修正案的情况下填满？

**设置。** 统计期望试点成本落在各目标预算档位 ±10% 预设容差带内的不同网格配置数，按族与预算档位。

**预期结果。** 在 ±10% 容差下每个匹配成本箱至少有 8 个配置，无需触发预声明的放宽到 ±15% 的修正案。

**证伪条件。** 若任何箱需要预声明放宽修正案才能凑足 8 个配置，则被驳斥——那意味着网格的成本粒度比假定的粗，该箱内所有下游前沿比较所依托的配置数少于预期。

**假设（通俗表述）。** 按设计的网格足够细，能在每个预算档位比较多个不同分配而无需放松匹配准则。

**指标。** 每箱配置数，按族与预算档位。

#### RQ7：实际成本校正对前沿置信带是否起承载作用？

**设置。** 每族每预算档位计算两次前沿置信带——一次用实际成本回归校正，一次只用名义成本分组——比较带宽。

**预期结果。** 在多数被测箱中，实际成本校正的带比仅名义分组的带更窄。

**证伪条件。** 若两种方法在多数箱中得到等宽（或校正反而更宽）的置信带，则被驳斥——那意味着校正步骤徒增复杂度而不改进精度，名义成本分组已经足够。

**假设（通俗表述）。** 计入每条查询的实际成本而非只看其落入哪个名义箱，能实质性收紧前沿估计。

**指标。** 每箱两种方法下的置信带宽。

#### RQ8：验证器价值能否经受预算匹配的纯覆盖对照？

**设置。** 对拟合前沿上每个验证密集点，经配对自助法（10,000 次重采样）与其把相同美元以零验证器成本重新分配为额外样本的预算匹配多数投票对照比较准确率，跨族 Holm 校正。

**预期结果。** 强验证器条件相对其预算匹配多数投票对照的准确率增益在至少一个任务族上统计显著。

**证伪条件。** 若没有任何任务族显示相对预算匹配多数投票对照的显著增益，则被驳斥——那意味着每一项测得的"验证器价值"发现都可被同样美元本可购买的额外候选完全解释。

**假设（通俗表述）。** 至少在某处，验证器比单纯用同样的钱买更多候选更值钱。

**指标。** 每族的配对准确率差与自助法置信区间。

#### RQ9：oracle 与验证器的准确率差距是否随样本数增大而缩小？

**设置。** 在固定思考上限下，在每个任务族上比较零成本真值 oracle 选择器与强验证器在递增样本数下的准确率差距。

**预期结果。** 差距随样本数增加而缩小——而非持平或扩大——至少在一个任务族上如此。

**证伪条件。** 若在所有被测族上差距随样本数持平或扩大，则被驳斥——那意味着额外候选并不能帮助验证器逼近覆盖率上限，一笔恒定或增长的可实现准确率被永久留在桌上。

**假设（通俗表述）。** 给验证器更多候选可选，能让它捕获池中已潜在的更多准确率，而非只捕获固定比例。

## 相关工作

与本文最接近的既有工作是针对网络搜索智能体的非对称验证研究，值得在综述全景之前先把差量说清楚：该工作已经在同一共享单位下把预算拆分给探索杠杆与验证杠杆——但只在单一领域内，成本以轨迹与工具调用而非美元计量，且完全没有思维链长度这一维，使本文瞄准的三杠杆、美元计价、跨任务族问题完全开放。

**计算最优与步级分配。** Snell 等人把推理时方法形式化为固定计算预算下的提议者-验证者（proposer-verifier）组合，并跨 best-of-N、引导搜索与顺序修订策略学习按难度条件化的分配策略；Plan-and-Budget 把查询分解为子问题并在收益递减模型下跨子问题分配固定 token 预算。两者都确立了测试时计算的分配（而不仅是数量）很重要——但都以 FLOPs 或 token 计价、只在单一任务族内评估、且从不把验证器自身的调用成本记入其所竞争的同一约束。

**先采样后验证理论。** 一组理论结果从不同角度刻画先采样后验证流水线：其一把无验证器轨迹蒸馏与基于验证器替代方案之间的次优性差距界定为时程与样本数的函数；其二把验证器引导采样刻画为最优传输，把可达性能分解为传输成本与由验证器 ROC 几何决定的项；其三为频率过滤后重排的选择规则证明了作为覆盖率、奖励模型误差与候选数函数的极小极大最优遗憾；其四把生成器-重排器系统建模为有噪通信信道并推导误差随假设数的渐近衰减率。四者都把验证器反馈当作带形式化性能界的可用资源，但没有一个让验证器自身的计量成本进入其所要刻画权衡的预算约束。

**单杠杆规模化刻画。** 关于思维链长度的工作把每个额外推理步建模为同时降低每步难度并增加误差累积风险，推导出链长与准确率之间非单调的倒 U 形关系；关于重复采样的工作表明覆盖率——众多独立样本中至少一个解出问题的比例——随样本数近似对数线性增长，同时指出常见选择策略在没有验证器时的水平远低于该覆盖率上限。两者都在固定另外两个杠杆的前提下孤立刻画单一杠杆的规模化行为，没有机制把该杠杆的价值对另外两个杠杆的成本归一化。

**跨模型计算-准确率前沿。** 一项近期实证研究在横跨稠密、混合专家（mixture-of-experts）与 Mamba 混合架构的十九个开源推理模型上绘制任务准确率与推理计算之间的帕累托前沿，发现任务相关的饱和拐点与混合专家架构的优势。我们直接承认该文的前沿绘制方法——两文都报告非支配的准确率-计算集合并寻找其饱和处——但其计算轴是模型自身推理 token 用量的单一 FLOPs 度量，是*跨模型*而非在单一模型*内*跨思考长度、样本数与验证器调用的分配比较，也没有美元计量把验证或选择成本与其记入的生成成本分开。其跨模型饱和拐点发现与本文的跨族可校验性排序发现是对计算-准确率关系的互补读法，不是对同一对象的竞争测量。

**美元计价的推理经济学。** 一条近期工作线用真实美元为 LLM 推理决策定价：面向智能体工作流的成本感知投机执行按分开的输入与输出 token 费率为每次投机性下游启动定价，并按期望美元价值规则决策；一项企业级编码智能体案例研究在实际美元成本上（含提示缓存效应）比较云 API 服务与本地量化模型。我们承认，作为预算单位的美元计价因此已不再新颖——这些工作确立的正是本文计量器所面向的部署现实。但它们的决策对象与我们的在种类上不同：一个决定*是否启动一次投机操作*，另一个决定*购买哪种部署配置*，两者都没有在思考长度、样本数与验证器调用之间分配固定预算，没有拟合任何一对杠杆之间的兑换率，也没有把验证器自身的调用成本记入其产物被重新打分的生成预算。三杠杆、美元计价的分配估计对象（estimand）仍无人认领。

**双杠杆领域特定分配。** 最接近的既有工作——深度网络搜索智能体的非对称验证——把测试时预算拆分给探索（搜索智能体并行生成候选答案）与验证（同一脚手架被重新提示以检查候选），表明把预算移向更便宜的验证杠杆能改善准确率-成本权衡。这是唯一一项把本文所研究三杠杆中的两个在同一共享成本单位下计量、并把其权衡当作真正分配决策而非固定流水线选择的既有研究——但它在单一领域内进行，成本以轨迹与工具调用计量而非与思维链长度轴共享的美元单位，也没有其发现是否迁移到可校验性画像不同任务族的第四象限问题。

## 结论

本工作把一个日常部署选择——如何在思考、采样与验证之间拆分计量预算——重塑为一个精确的测量问题而非工程默认值，方式是识别并定价一个此前所有分配分析都未言明的不对称性：验证的价值始终派生于花在生成上的美元，而其自身的调用成本此前从未被记入与之竞争的同一分配预算——即便在近期美元计价的推理经济学文献中也是如此，那些工作定价的是调度与部署决策，而非这一三杠杆分配。核心方法论赌注是：只有当三个杠杆共享一个美元单位、其交互被拟合而非假定消去、且任何归因于验证器的增益都对照过最廉价的对手解释——同样的美元换成更多候选也能买到同样准确率——之后，这一派生价值结构才是可测量的。无论前沿形状与杠杆兑换率结果如何，该发现都具备决策相关性：普适、族无关的前沿意味着分配策略一经测得即可跨部署复用；族特异的前沿则意味着每个新任务族都需要先做自己的测量才能分好预算。两个局限从一开始就为该论断划界，并且是自然的后续步骤而非事后补记：本设计关于前沿*形状*的结论意在对价目表扰动稳健，但其绝对美元量级必然绑定于被测的具体模型与价目表，跨定价制度与模型家族的泛化是明示承认的局限而非本设计能支持的论断；覆盖率/选择分解能界定、但不能排除比此处被测验证器更强的验证器会把 oracle 差距缩得比报告更小的可能性。
