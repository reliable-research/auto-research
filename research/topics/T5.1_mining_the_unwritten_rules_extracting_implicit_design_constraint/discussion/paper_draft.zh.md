# 通过测试不等于通过评审：从评审历史挖掘编码 Agent 补丁对不成文设计约束的合规性并加以测量

> 由 `pipeline.md` 中六个已确认阶段产出组装而成，经审计（`taste_audit.md`：🟢）。状态：**研究方案 / 论文草稿——尚未运行任何实验。** 下文所有数字均为预注册（pre-registered）的设计目标，而非实验结果。本文为 2026-08-21 评审修订后（`review_2026-08.md`）版本的中文译本。

## 摘要

编码 agent（coding agent）正被越来越多地信任去自主开启拉取请求（pull request, PR），而几乎所有用于认证它们的基准——从 fail-to-pass 单元测试到端到端自由职业任务评分——都把通过项目测试套件视为补丁可合并（mergeable）的判据。然而人类维护者实际采用的判据还包括错误处理、架构与 API 约定，这些约定从未写进任何规格说明、linter 规则或测试之中，项目自己的贡献者也只能通过长期累积评审反馈才逐渐吸收：一个补丁完全可能同时携带最大的行为证据与零合规证据。我们构建了一条流水线：从历史 PR 评审线程中挖掘每仓库（per-repository）的隐式设计约束目录（catalog），只接纳那些确实引发过代码变更的候选，并要求在多个线程中达到支持度阈值后才收录为规则；我们在信任目录与下游合规裁判（compliance judge）的规模化标注之前，先用盲态人工标注验证两者；随后将经过验证的测量工具应用于通过测试的编码 agent 补丁及其匹配的人类金标（gold）补丁，覆盖多个仓库与多个 agent 系统。与并行工作中用 LLM 校验器验证按 issue 索引的设计约束的做法（*Does Pass Rate Tell the Whole Story?*，arXiv 2604.05955）不同，我们的目录是仓库级、经复现度过滤（recurrence-filtered）且经人工审计的，且我们的比较是在完全相同任务上的 agent 对匹配人类补丁对照；与对 agent 执行轨迹做过程性合规验证（AgentLTL、MANTRA）不同，我们检查的是产出的工件（artifact）——补丁文本——是否符合那些从未被写下来的规范。我们报告目录的抽取精确率与召回率、挖掘出的约束中无法用现有静态分析工具表达的比例，以及通过测试的 agent 补丁相对于匹配人类补丁按类别划分的违规分布——从而量化测试套件成功究竟在多大程度上落后于设计约束合规。

## 引言

自主拉取请求已不再是研究上的猎奇。随着大语言模型 agent 被越来越多地委托去针对真实仓库开启、修改并重新提交补丁，"什么样的补丁可被接受"这一问题已悄然收窄为一个单一的、机器可检查的信号：它能否让失败的测试通过。围绕该信号构建的基准推动了快速且可测量的进展，它也确实是有用的信号——但它不是人类维护者在决定是否合并时实际采用的那一个。

然而这一收窄背后的一个核心假设从未被检验：维护者对补丁施加的要求——错误应当如何处理、变更不得跨越哪些架构边界、几个等价 API 中哪一个是项目的首选——是在评审对话中确立的，从未编码进测试套件。这不是一个小的疏漏。一个补丁可以通过项目的全部测试，却仍然违反某条会让它被打回修改的规范，因为这两个信号在构造上（by construction）就是正交的：评审强制执行的规范没有任何理由出现在 fail-to-pass 检查中，而一条失败断言也没有任何理由编码维护者对错误处理的品味。只认证第一个信号的基准对第二个信号完全沉默。

这一空白已不再无人注意——但本文为它构建的测量工具尚不存在。最接近的先行工作 *Does Pass Rate Tell the Whole Story?*（arXiv 2604.05955）提出了设计感知的 issue 解决（design-aware issue resolution）：它从与 SWE-bench 对齐的仓库的真实 PR 中挖掘并验证设计约束，自动将补丁与之比对，从而独立确立了本文的出发前提——功能正确性与设计约束合规性是两回事。我们坦率承认这一共享论点，并在测量工具与估计量（estimand）上与之区分：其约束按单个 issue 索引、由基于 LLM 的校验器验证，而本文挖掘的目录由仓库级反复出现的规范构成，只有跨多线程、多评审者复现并通过引发变更（change-inducing）行为过滤器的候选才被接纳，并经盲态双人工标注验证；它孤立地测量 agent 补丁的合规性，而本文在完全相同的任务上将通过测试的 agent 补丁与匹配的人类金标补丁逐类别对比——这是按 issue 的约束检查从未尝试的对照。其余工作从相邻但不同的角度接近这一空白。DefectCR 这样的自动代码评审系统为单个合并请求生成实时评审意见，但明确以缺陷检测优先于"风格性评论"，丢弃而非编目评审中的约定执行内容——即使像 CodeReviewer 这样从历史（diff, 评论）对中学习生成貌似合理评审意见的系统，其吸收的任何约定知识也只潜藏在模型权重中，从不浮现为可审计的、每项目的规则，无法用于检查一个新的、未见过的补丁。基于评分准则（rubric）的生成质量工作，如 RLAC，在精神上更接近——一个习得的批评者提出对给定输出最可能失败的准则——但准则是对每个输出即时生成的，而不是被挖掘为一个稳定的、有历史支持的清单，因此它能报告某处失败，却永远说不出一个代码库究竟执行哪一类规范、执行频率如何。而将 agent 评测落地于真实仓库的基准，如 SWE-bench 与 SWE-Lancer，完全通过测试或专业评分的端到端检查定义补丁正确性；SWE-Lancer 自己的动机部分即承认这类评分低估了整系统层面的期望，但两个基准都没有把约定符合性当作独立信号来测量。

把这一空白变成可测量的对象会暴露它自身的困难。项目中任何地方都不存在隐式约束的形式化真值来源——不在规格说明、文档或 lint 配置中——因此任何抽取方法都必须从非结构化的评审对话中归纳一般规则，而其中绝大多数评论根本不是约束，这使得"把携带约束的评论与噪声区分开"成为第一个难题，它与"识别两条措辞不同的评论陈述的是同一条规则"是两个不同的问题。测试结果在构造上对此不携带任何信号，因此任何合规判断都必须作为独立的测量工具来构建并独立验证，而不能借用现成的判定器（oracle）。三个自然的约束类别既不互斥、粒度也不均匀——一条禁止跨模块边界抛出裸异常的规则同时是错误处理与架构问题——因此类别标注的一致性必须被测量，而非假定。而这整个测量所依赖的人类判断本身就有噪声：评审者彼此不一致，规范随项目生命周期漂移，评审结论背后的理由即便结论本身明确也常常表述不足。

我们的方法把上述每个障碍都转化为一项具体设计选择。候选只从确实引发了后续代码变更的评审评论中挖掘，这把"大多数评论不是约束"从逐条主观判断变成可检查的行为过滤器；同一规则的不同措辞实例在规则语义层面合并，且只有跨多个独立线程复现后才被收入目录，因此一条目录条目反映的是反复出现的规范，而非某位评审者的一次性措辞。合规裁判被构建为独立于测试结果运行，并在其标签被规模化信任之前用盲态人工标注验证，因此报告出的违规是关于规范的证据，而非未验证工具的伪影。类别在测得的标注者间信度（inter-annotator reliability）下指派，结果同时在单条目录条目层面与类别层面报告，使真正跨边界的规则无法悄悄扭曲某一类别的计数。最终的比较——违规分布跨类别的形状，以及其中 agent 与人类金标补丁之间的差距——由限定在近期时间窗口内、跨多位评审者与线程聚合的证据计算得出，从而没有任何单个噪声判断或单条漂移规范能独自支撑一项报告的发现。

我们在取自 SWE-bench Verified 的仓库上评估该设计，将经过验证的测量工具应用于来自多个独立编码 agent 系统的通过测试补丁及其匹配的人类金标补丁，并将目录引导的合规判断与无目录（catalog-free）的判断替代方案对比，以分离挖掘目录本身的贡献。

综上，我们的贡献是：
- 对编码 agent 补丁的测试套件成功与设计约束合规之间不对称性的形式化——该前提已由并行工作（arXiv 2604.05955）独立确立，我们予以承认——并推进到该工作未测量的估计量：基于评审挖掘的、仓库级不成文规范上的按类别违规分布，以及其中通过测试的 agent 补丁与匹配人类金标补丁之间的差距。
- 一条经过验证的流水线：直接从 PR 评审历史中挖掘每仓库、带类别的隐式设计约束目录，无需任何预先存在的项目约定形式化规格，其抽取精确率与召回率以人工标注为基准测得。
- 一个被构建并门控（gated）为独立于测试结果的合规裁判，其标签在规模化使用前经盲态人工标注验证；并附带一个无目录消融（ablation），以分离挖掘目录相对于即兴准则猜测的具体贡献。
- 一份经验性刻画：通过测试的编码 agent 补丁最常违反哪些类别的隐式约束——错误处理、架构约定还是 API 约定——以及该违规率与相同 issue 上人类作者补丁相比如何。

## 问题定义

**形式化设定。** 考虑仓库 r 及其拉取请求评审线程集合 T_r = {t}。每个线程 t 包含锚定于 diff 块 h_t 的行内评论 c_t、拉取请求结论 v_t，以及任何后续提交 F_t。挖掘出的目录 K_r = {k} 收集条目 k = (stmt_k, scope_k, cat_k, supp_k, ev_k)——规范化的规则陈述、适用范围、类别 cat_k ∈ {错误处理, 架构, API, 其他}、支持计数，以及回链到支持它的线程的证据链接。补丁 p——针对同一 issue 的 agent 补丁 pᵃ 或其匹配的人类金标补丁 pᵍ——触及文件集合 files(p)。裁判 J(p, k) ∈ {违规, 合规, 不适用} 依据一条目录条目评估一个补丁。研究对象有二：(i) K_r 能否以人工标注为基准、以测得的精确率与召回率被抽取出来；(ii) 在匹配的 agent 与人类金标补丁上，J(pᵃ, k) = 违规 相对于 J(pᵍ, k) = 违规 的按类别分布。

**为何困难。** 仓库中任何地方都不存在 K_r 中任何条目的形式化真值来源，因此抽取必须从 T_r 的非结构化对话中归纳一般规则，而其中大多数线程根本不携带约束——这是一个分类问题，区别于识别两个携带约束的线程是否重述同一规则的问题，后者要求在规则语义而非表面文本层面匹配。裁判 J 没有现成判定器可依赖，因为 fail-to-pass 测试结果在构造上对 cat_k 沉默；J 因此必须作为独立测量工具被构建并验证，其输出才可作为证据。类别空间 {错误处理, 架构, API} 既不互斥、粒度也不均匀——同一条 stmt_k 可以合法地横跨两个类别——因此 cat_k 的指派必须测量标注者间信度而非假定正确。而 v_t、F_t 以及对 J 的任何人工标注本身有噪声：标注者不一致，仓库规范随生命周期漂移，v_t 背后的理由即便 v_t 本身明确也常表述不足，因此任何按类别的比较都必须由跨多线程、多评审者聚合的证据计算，而非单一来源。

## 方法概览

在概念层面，本研究是一条由五个协作部分组成的单一测量流水线。历史评审线程与仓库上下文进入流水线；行为过滤器与抽取步骤把原始对话变成约束候选，聚类合并阶段再把候选变成经过验证、带类别的目录；本身经过独立验证的合规裁判随后将该目录应用于通过测试的补丁；稳定性层最终把逐补丁判断变成对任何单个噪声结论都稳健的条件级违规分布。

**引发变更候选抽取器**（change-inducing candidate extractor）接收原始评审线程，只保留确实引发了后续代码变更的评论，对每条这样的评论及其周边 diff 上下文运行一次 LLM 抽取，输出规范化规则陈述或明确的"无约束"结论——应对"大多数评审对话不是约束"的困难。**约束目录构建器**接收所得候选，聚类并合并同一规则的不同措辞实例，只有获得多个独立线程支持后才将条目收入目录——应对同一规则以高词面变异性出现的困难。**合规裁判**接收经过验证的目录与一个补丁，独立于该补丁是否通过任何测试逐条判定违规状态——应对测试结果在构造上不携带此信号的事实——并且其自身在标签被规模化信任之前经盲态人工标注验证。**类别标注**模块指派并测量每条目录条目类别标签的信度，同时报告类别级与条目级结果——应对三个命名类别可能真实重叠的困难。**稳定性与比较设计**在限定时间窗口内跨多位评审者、线程与补丁聚合违规证据，计算按类别违规分布与 agent 对人类金标差距——应对底层人类真值本身有噪声的事实。

## 方法细节

### 引发变更候选抽取器

**挑战。** 项目中不存在隐式约束的形式化真值来源，因此有效的抽取方法必须从非结构化评审对话中归纳一般的、可复用的规则，而其中绝大多数单条评论根本不是约束——这是分类问题，不是匹配问题。

**洞察。** 一条评论是否表达了被强制执行的期望，不必只凭措辞判断：如果同一 PR 中的后续提交恰好编辑了该评论锚定的行，那么评审者的期望就以该行为被实际执行了——这把"这是不是一条约束"从主观解读变成可检查的行为过滤器。

**方法。** 只有当某条评论之后的后续提交编辑的行与其锚定 diff 块重叠时，该评论才被保留为抽取候选。每条保留的候选连同其 diff 块与周边文件上下文送入 LLM 抽取步骤，输出带临时类别与范围的规范化祈使句规则陈述，或对被判定为不可泛化的评论（一次性修复、提问、称赞）输出明确的"无约束"结论。一个关键词/指令模式抽取器（对 should/must/please/avoid/never 及代码元素提及的正则匹配）并行运行，作为机制必要性检查而非竞争者：如果它恢复的约束不比 LLM 抽取器少，说明语义理解在候选识别中并未真正起作用。

### 约束目录构建器

**挑战。** 同一底层约束以高度的词面与语境变异性出现——不同评审者与线程措辞不同，有时只被部分陈述，有时只由被要求的修改暗示而非明说——因此去重必须在规则语义而非表面文本上进行，这与判断单条评论是否为约束是真正不同的问题。

**洞察。** 一条稳定、可接纳的目录条目应当要求不止一次出现的佐证：把"这是反复出现的规范还是某位评审者的一次性措辞"从目测判断变成预先规定、可计数的接纳规则，就在原本会被任意裁决的地方消除了歧义。

**方法。** 候选规则陈述用句向量（sentence-embedding）模型嵌入并聚类；LLM 将每个簇合并为一条规范目录条目，携带不同支持线程数与不同评审者数的支持计数。支持线程少于三个的条目被隔离而非收入目录。目录中真正"不成文"的内容通过将每条已接纳条目映射到现有 ruff、pylint 与 import-linter 规则清单来检查；无法在其中任何一个表达的条目被视为相对于该被检查工具面（tool surface）的不成文内容证据，而非"任何静态分析工具都永远无法表达它"的绝对断言——这是一个更窄、也更可辩护的主张。

### 合规裁判

**挑战。** 测试结果在构造上不编码这些约束，因此补丁可以在所有测试上行为正确却仍违反规范——这意味着合规信号必须作为完全独立的测量工具来构建，没有现成判定器可依赖或校准。

**洞察。** 这样构建的裁判应当被预期在已通过全部测试的补丁上找到违规；如果它持续找不到，这本身就有信息量——那将意味着本文赖以立论的不对称性在实践中并不成立，而正是裁判的独立有效性使这成为可被真实检验的可能，而非被假设掉的问题。

**方法。** 对给定补丁，检索适用于其触及文件的目录条目，LLM 裁判对每个（补丁, 条目）对给出违规/合规/不适用标签，附 file:line 定位与一句话理由。在该裁判的任何标签被规模化用于支持比较性断言之前，先在留出的（补丁, 规则）对样本上测量其与盲态双人工标注的一致性，只有该一致性越过预注册阈值后，裁判标签才被作为证据。

### 类别标注

**挑战。** 三个命名类别——错误处理、架构约定、API 约定——既不互斥、粒度也不均匀，因此对挖掘条目指派类别在某些情形下天然有歧义，不能靠构造假定正确。

**洞察。** 只在类别聚合层面报告按类别结果，会让真正跨边界条目的歧义悄悄扭曲它恰好被归入的那个类别；同时在单条目层面报告，则让这种歧义可见、可审计，而非藏在一个数字里。

**方法。** 两名标注者独立为每条目录条目指派类别（或"其他"）；分歧经仲裁解决，并报告 Cohen's kappa。所有下游按类别结果同时在聚合层面与单条目层面报告，使类别指派曾有争议的条目可被识别，而非被无声吸收进某一类别的计数。

### 稳定性与比较设计

**挑战。** 这整个测量依赖的人类判断——评审结论、标注者标签——本身有噪声：评审者不一致，规范随项目生命周期漂移，结论背后的理由即便结论明确也常表述不足，因此单对、单线程的发现可能恰恰是这种噪声的伪影。

**洞察。** 这种噪声无法被设计消除，只能被约束：把挖掘限定在近期时间窗口内，限制单个目录需要平均掉的漂移量；跨多位评审者、线程与补丁聚合支持与违规证据，限制任何单个噪声判断能独自支撑一项发现的程度。

**方法。** 每个仓库的挖掘限定在近期的有界时间窗口内。违规证据跨多个独立抽取的（agent, 人类金标）匹配补丁对、按仓库与 agent 系统聚合，从中计算按类别违规分布与 agent 对人类金标差距，作为同一比较设计的两个可分别证伪的读数：分布本身的形状，以及其中差距的大小。

## 实验

### 实验设置

**数据集。** SWE-bench Verified（500 个经人工验证的仓库-issue 任务）提供试点仓库、issue 集合，以及每个被测 agent 补丁的匹配人类金标补丁——正是这一配对使匹配对比较成为可能。公开的 SWE-bench 排行榜提交补丁提供来自多个独立 agent 系统的通过测试补丁，使违规分布不是任何单一 agent 个性化风格的伪影。PR 评审历史语料从 SWE-bench Verified 取 issue 的同一批仓库中采集，使目录与被判定补丁来自同一批项目的真实规范，而非语料错配。

**基线**（健全性与必要性对照，而非要击败的竞争者——这是一项测量研究，任何研究问题都不表述为"我们的流程胜过基线 X"）。关键词/指令模式抽取器检查语义理解在候选识别中是否真正起作用，还是朴素词面模式匹配已能恢复同样多的约束。现有 linter 与架构规则清单（ruff、pylint、import-linter）确立目录中已被形式化的比例——这正是"不成文"在操作层面的含义。无目录的零样本 LLM 裁判——改编 RLAC 的按输出即时生成潜在准则的协议，而非与 RLAC 自身报告的结果比较——分离一个稳定的、多线程支持的挖掘目录是否能发现同模型无目录裁判自己发现不了的东西；此处的零结果（目录引导与无目录判断实质一致）不会推翻正交性发现，但会推翻目录自身的具体贡献。匹配的人类金标补丁是 agent 对人类比较的必要参照分布，也是"何必做这件事"的对照：若人类金标补丁违反目录的比率已与 agent 补丁相同，就不存在 agent 特有的合规差距可刻画。

**指标。** 以人工标注为基准的抽取精确率与召回率；linter 可表达率；裁判对人类一致性（Cohen's kappa）；类别标注的标注者间一致性（Cohen's kappa）；按类别违规率与 agent 对人类金标匹配对差值。

**研究问题：**
1. RQ1 —— 挖掘目录能否越过以人工标注为基准的预注册精确率门槛？
2. RQ2 —— 识别约束是否需要语义理解，还是朴素词面模式已经足够？
3. RQ3 —— 目录内容是否确实不存在于现有静态分析工具中？
4. RQ4 —— 合规裁判与盲态人工标注的一致性是否足以支撑规模化信任？
5. RQ5 —— 通过测试的补丁是否仍携带经验证的约束违规？
6. RQ6 —— 类别指派的信度是否足以支撑按类别比较？
7. RQ7 —— 按类别违规分布是均匀的还是偏斜的？
8. RQ8 —— 通过测试的 agent 补丁违反挖掘约束的频率是否高于匹配的人类金标补丁？

#### RQ1：挖掘目录能否越过以人工标注为基准的预注册精确率门槛？

**设置。** 从试点仓库分层抽取 300 条目录条目，双人标注为真实项目约束或伪约束；召回率通过让标注者独立从 100 个留出评审线程中挖掘约束、再检查流水线恢复了其中多大比例来估计。两个比例均计算 Wilson 95% 置信区间。

**预期结果。** 目录条目精确率的 Wilson 95% CI 下界不低于 0.60。

**证伪条件。** 若 300 条样本上的精确率 CI 下界低于 0.60 则被驳斥——此时论文的后备立场是宣称抽取只有在人在环（human-in-the-loop）核验下才可行，并把实际达到的精确率及其 CI 作为工作点报告，而非宣称全自动化。

**假设（通俗表述）。** 隐式约束可以被挖掘为一个目录，其条目以经声明并经检验的比率是真实项目规范而非噪声。

**指标。** 精确率（Wilson 95% CI）；召回率代理（Wilson 95% CI）；底层双人标注一致性的 Cohen's kappa（报告但不设门槛——门槛针对精确率本身，而非标注者一致性）。

**结果。** *[占位——实验运行后填写]*

#### RQ2：识别约束是否需要语义理解，还是朴素词面模式已经足够？

**设置。** LLM 抽取器与关键词/指令模式基线在同一批引发变更的评论上运行，其线程级约束检测输出用配对 McNemar 检验比较，α = 0.05。

**预期结果。** LLM 抽取器的配对线程级检测准确率显著更高，McNemar p < 0.05 且方向利于 LLM，并以至少 8 个百分点的最小配对准确率差作为效应下限（effect floor）——没有该下限的显著性不满足假设。

**证伪条件。** 若 McNemar 检验无显著差异、或 p < 0.05 但配对准确率差低于 8 个百分点、或关键词基线表现持平或更好，则被驳斥——上述任一情形都意味着在此样本量下语义抽取未被证明优于词面模式匹配；此时论文将从候选识别主张中撤下"基于 LLM"的表述，只保留（仍受门控的）流水线实际达到的精确率/召回率作为工作点。（这一比较是对机制的必要性检查，不是宣称本文系统胜过某个需要击败的对手系统。）

**假设（通俗表述）。** 把真正的约束与普通评审闲谈区分开，需要理解评论及其周边 diff 实际在说什么，而不只是匹配表面短语。

**指标。** 配对线程级检测准确率；McNemar 统计量与 p 值；以百分点计的配对准确率差（效应下限指标）。

**结果。** *[占位——实验运行后填写]*

#### RQ3：目录内容是否确实不存在于现有静态分析工具中？

**设置。** 每条已接纳目录条目（支持 ≥ 3 线程）检查其能否表达为 ruff、pylint 或 import-linter 规则清单中的现有规则。

**预期结果。** 少于一半的已接纳条目可在三个被检查工具中的任何一个表达（linter 可表达率 < 0.50）。

**证伪条件。** 若 linter 可表达率达到或超过 0.50 则被驳斥——此时论文将主张收窄为"挖掘出的约束中有可测量的少数相对于被检查工具是不成文的"，而非宣称目录大部分不成文。本检验明确限定于这三个被检查的常用静态分析工具；它无法排除某个未检验的静态分析面（项目自有的定制 linter 规则、类型检查器、专用 AST 检查器）已能表达某条条目，"不成文"内容的主张被报告为限定于该被检查工具面，而非"任何工具都无法表达"的绝对断言。

**假设（通俗表述）。** 目录捕获的是现有常用静态分析工具尚未形式化的规范——不只是重新发现 linter 已经检查的东西。

**指标。** linter 可表达率。

**结果。** *[占位——实验运行后填写]*

#### RQ4：合规裁判与盲态人工标注的一致性是否足以支撑规模化信任？

**设置。** 400 个（补丁, 规则）对由自动合规裁判与两名盲态人工标注者独立标注；一致性以 Cohen's kappa 计算。

**预期结果。** 裁判对人类一致性达到 κ ≥ 0.6。

**证伪条件。** 若 κ 低于 0.6 则被驳斥——预先承诺的应对是 RQ5/RQ7/RQ8 退回到规模缩小的全人工标注样本，而非规模化信任自动标签。

**假设（通俗表述）。** 自动裁判可以被构建到与人类合规判断足够一致、从而在规模上替代人类——但前提是这种一致性被实际测量并设门槛，而非被假定。

**指标。** Cohen's kappa（裁判对人类，汇总及分类别）。

#### RQ5：通过测试的补丁是否仍携带经验证的约束违规？

**设置。** 在裁判有效性确立（RQ4）后，将经过验证的裁判应用于留出的通过测试补丁样本，测量经确认违规（裁判输出经人工抽查佐证）的比率。

**预期结果。** 在通过测试的补丁中发现非零的经确认违规率。

**证伪条件。** 若通过测试补丁上的经确认违规率与零在统计上不可区分则被驳斥——这将直接驳斥论文核心的正交性主张，因为它意味着测试套件成功已经携带了本文论证其在结构上不可能携带的合规信息。

**假设（通俗表述）。** 通过项目测试套件的全部测试，并不意味着补丁没有挖掘约束违规。

**指标。** 通过测试补丁中的经确认违规率，附 95% CI。

#### RQ6：类别指派的信度是否足以支撑按类别比较？

**设置。** 两名标注者独立为每条目录条目指派类别（或"其他"）；分歧经仲裁解决，计算 Cohen's kappa，并报告经仲裁归入"其他"的分布。

**预期结果。** 类别标注达到预注册的 kappa 阈值，且剩余分歧集中于被仲裁为"其他"的条目，而非均匀散布于三个命名类别。

**证伪条件。** 若 kappa 低于预注册阈值，或分歧大致均匀散布于全部三个类别而非集中于有歧义的跨边界条目，则被驳斥——两者任一都意味着类别方案本身（而不只是个别疑难案例）不可靠，按类别比较（RQ7、RQ8）将只能在条目层面报告。

**假设（通俗表述）。** 三类别方案的信度足以支撑按类别违规比较，其真实歧义局限于可识别的、跨边界的少数条目，而非动摇整个方案。

**指标。** Cohen's kappa（类别指派）；经仲裁归入"其他"的条目比例。

#### RQ7：按类别违规分布是均匀的还是偏斜的？

**设置。** 在全部被测通过测试补丁上计算按类别违规率，用卡方拟合优度检验比较均匀性，α = 0.05，并做按仓库分层的敏感性检查（因为同一仓库内的补丁不独立）。补丁按仓库 × 类别 × 组别（agent/人类金标）分层；任何通过测试补丁数少于 20 的仓库 × 类别单元格被预先声明为该层不可下结论（inconclusive），并从按仓库敏感性表中排除，而非被无声合并进一个零结果。只有当 5 个试点仓库中至少 4 个越过每类别 n ≥ 20 的阈值时，汇总（非分层）检验才作为主分析；否则主张被明确收窄到越过阈值的仓库。

**预期结果。** 分布非均匀，错误处理与架构约定的违规率各自超过 API 约定的违规率，卡方拟合优度 p < 0.05，并以 Cramér's V ≥ 0.15 为效应下限——没有该下限的显著性不满足假设。

**证伪条件。** 若卡方检验不能在 α = 0.05 拒绝均匀性、或拒绝了均匀性但 Cramér's V 低于 0.15、或 API 约定的违规率不低于其他两类中的任何一类，则被驳斥。若非均匀性本身不成立（卡方不能拒绝均匀性，或 V < 0.15），类别排序主张作为失去意义（moot）被放弃——不只是收窄——仅保留独立越过自身门槛的 agent 对人类金标比较（RQ8）。若非均匀性成立但先验的 EH/ARCH > API 排序不成立，论文报告观察到的排序作为发现，而非先验预测的排序。

**假设（通俗表述）。** 违规并非均匀散布于约束类别——某些类别的不成文规范在结构上更容易在通过测试的套件下幸存。

**指标。** 按类别违规率及 Wilson 95% CI；卡方统计量与 p 值；Cramér's V（效应下限指标）。

**结果。** *[占位——实验运行后填写]*

#### RQ8：通过测试的 agent 补丁违反挖掘约束的频率是否高于匹配的人类金标补丁？

**设置。** agent 补丁与其匹配人类金标补丁的按类别违规率用每类别的匹配对 McNemar 检验比较，跨三个类别做 Holm-Bonferroni 校正，α = 0.05。

**预期结果。** 校正后至少一个类别中，agent 违规率超过匹配人类金标至少 8 个百分点（匹配对率差）——没有该下限的显著性在该类别中不满足假设。

**证伪条件。** 若校正后没有类别显示显著的 agent 对人类金标差距，或某类别越过显著性但匹配对差距低于 8 个百分点（后者报告为"检测到但很小"，不算满足假设），则被驳斥。若所有类别均不成立，论文将报告：在此样本上，通过测试的 agent 与人类在挖掘约束合规性上统计不可区分——这是对合规差距大小的一个直接的、可发表的界，而不是需要隐藏的零结果。

**假设（通俗表述）。** 通过测试的编码 agent 补丁不仅不与相同 issue 上人类作者的补丁同等合规——在至少一个约束类别中，它们可测量地更不合规。

**指标。** 每类别 agent 对人类金标匹配对差值（效应下限指标）；每类别 McNemar 统计量与 Holm-Bonferroni 校正后 p 值。

**结果。** *[占位——实验运行后填写]*

**机制分析（次要，不作门控）。** 在头条的按类别比率（RQ7）与 agent 对人类差距（RQ8）之外，将经验证的违规与 (a) agent 系统身份交叉制表，检查超额违规是集中于特定 agent 系统还是均匀散布于 ≥3 个被抽样系统；与 (b) 补丁大小/触及文件数交叉制表，检查违规可能性是否随补丁大小增长——后者将指向暴露机会混淆（exposure-opportunity confound）而非真实的逐补丁合规差距。该分析解释 RQ7/RQ8 的分布，但不门控头条主张。

**进一步评估。** 若有更多时间，两个自然的扩展按设计（而非疏忽）落在本研究范围之外：刻画测试*失败*补丁中的违规（本研究只考察通过测试的补丁，因为那正是基于测试的基准会认证补丁可接受的情形）；以及检验把挖掘目录反馈进 agent 生成回路能否降低其违规率（一个训练/干预问题，区别于本文回答的测量问题）。

## 相关工作

最接近的先行工作是 *Does Pass Rate Tell the Whole Story?*（arXiv 2604.05955），在综述更广的领域图景之前值得先把差异说清楚。该工作提出设计感知的 issue 解决，从与 SWE-bench 对齐的仓库的真实 PR 中挖掘并验证设计约束，自动将补丁与之比对——同一论点，同一底层数据。我们承认共享的前提，并在测量工具的每一条轴上与之区分：其约束按单个 issue 索引、由基于 LLM 的校验器验证，我们的约束是仓库级规范，只有跨多个独立线程与评审者复现、通过引发变更行为过滤器、并经带预注册一致性门槛的盲态双人工标注验证后才被接纳；它孤立测量 agent 合规性，我们在完全相同任务上将 agent 与匹配的人类金标补丁对比；且只有本文测量挖掘目录中有多少确实不存在于被检查的静态分析面。在较早的近邻中，DefectCR 已为单个合并请求端到端自动化代码评审，RLAC 已把生成质量视为对多条隐式准则的满足——但 DefectCR 明确丢弃而非编目约定风格的评论，RLAC 对每个输出即时生成一条最可能失败的准则，而非挖掘一个稳定的、有历史支持的每项目清单；两者都不产出本文旨在抽取的显式、可审计、多线程验证的目录，也都没有把它应用于"通过测试的补丁是否合规"这一具体问题。

**边界：成文规则，以及轨迹对工件。** 两条并行工作线被有意置于本文范围之外。其一，编码 agent 对*成文*贡献规则——CONTRIBUTING 与 AGENTS 文件——的合规性已被直接考察（arXiv 2607.26819）；本文的对象是其补集，即从未被写下的规范，且本文的不成文度测量（RQ3）正是区分两者的东西。其二，一个正在成型的过程性合规（procedural-compliance）簇验证 agent 的*执行*是否符合流程规格：AgentLTL（arXiv 2607.02599）对 agent 轨迹检查时序逻辑义务，MANTRA（arXiv 2605.06334）合成经 SMT 验证的轨迹合规基准。那条线回答的是"agent 的行为是否遵循了流程规则？"——针对运行时事件序列；本文回答的是"产出的工件——补丁文本——是否符合仓库的设计规范？"——一个事后检查的静态属性，其规范挖掘自人类评审对话。路由规则是明确的：任何自然表述为运行时或工具调用事件上时序义务的候选约束属于轨迹合规线，不属于本目录；两者是监督栈中互补的层，谁也不包含谁。

**从代码历史归纳规则。** 一长串工作只从代码或编辑本身归纳约定与规则：NATURALIZE 从代码库学习表面命名与格式约定，Getafix 从历史编辑学习修复模式，MUDetect 挖掘 API 误用模式，经典规格挖掘（specification mining；Daikon；Ammons et al.）从程序运行推断不变量。所有这些都要求规范在代码本身留下规律性印记——因此无法捕获唯一证据是评审者陈述理由的规范，例如分层规则，或合规代码根本不会可见违反的错误处理策略。评审对话正是对这类规范唯一有信息量的底层数据，这也是本文挖掘线程而非代码的原因。

**以人为中心的 agent 评测分类学。** 在论点层面，近邻是 From Correctness to Collaboration（Dong et al., arXiv:2512.23844），它与本文共享核心前提——只看正确性的 SE agent 评测遗漏了维护者真正要求的东西，包括一个明确的"遵循标准与流程"行为类别——并且像本文一样用人类判断验证其分类学而非断言之。差异在于挖掘什么与测量什么：它从静态的企业 agent 规则文件与从业者访谈中导出定性的、跨公司的四期望分类学，而本文挖掘动态的、每项目的 PR 评审对话本身，把每条目录条目落地在特定仓库自身评审历史上的多线程、多评审者支持要求中（而非某人已经选择写下的规则），并把合规性变成在已通过测试补丁上、对照匹配人类金标的、按类别测得的违规率——一个分类学式设计不产出也不尝试的定量 agent 对人类差距主张。它"除非被明确引导，agent 被当作静态工具对待"的发现本身就间接支持本文赖以立论的不对称性：即便已写下的规则文件，离开这里挖掘的持续评审对话，也无法自行认证合规。

**自动代码评审与评审意见学习。** DefectCR 运行仓库感知的静态切片、多个候选生成评审模型与一个校验元评审器，产出合并请求级发现，明确以缺陷检测优先于风格性评论；CodeReviewer 在大规模（diff, 评审意见）对上预训练编码器-解码器，生成貌似合理的评审意见并估计变更质量。两者都在单个合并请求层面运作，其编码的任何约定知识要么被整体过滤掉、要么潜藏于模型权重，不产出持久的、可审计的、每项目的目录来独立于产出它的模型去检查一个新的、未见过的补丁。

**基于准则与仓库上下文感知的生成质量。** RLAC 把自由形式生成质量视为对多条潜在准则的满足，由习得的批评者提出对给定输出最可能失败的准则、校验器只检查那一条；Coeditor 把先前编辑编码为显式 diff，用检索到的签名与预训练序列模型预测与开发者持续意图一致的后续编辑。两者都捕获了某种项目特定期望，但只是隐式且按实例的——RLAC 每次即时生成准则而非挖掘稳定清单，Coeditor 对先前 diff 的条件化说不出某次编辑违反了哪条规则，因此都无法报告一个代码库执行哪一类规范、被违反的频率如何。

**基于测试的 agent 基准与约束密集生成。** SWE-bench 完全通过从配对的 GitHub issue 及其解决 PR 导出的 fail-to-pass 仓库测试定义补丁正确性，SWE-Lancer 用专业编写的端到端测试与市场报酬为真实自由职业软件任务评分，且 SWE-Lancer 自己的动机部分承认基于测试的评分低估了整系统期望。FHE-Coder 表明在另一个约束密集领域（密码学）的可靠 agent 生成需要显式供给约束，将生成落地于精选的密码方案文档——但每项目设计约定按定义没有等价文档可检索，因此该途径无法迁移到本文研究的设定。

**代码评审的奠基性经验研究。** Bacchelli 与 Bird 对微软代码评审的混合方法研究发现，在缺陷检测之外，评审在现实中的主要产出包括知识传递与代码约定的执行；Bosu et al. 构建了开发者认为哪些评审意见类型有用的分类器与分类学。两者都以经验确立了约定执行是代码评审真实且核心的部分——但都止步于人类可读的评论类型分类学，而非可对先前未见的、agent 作者补丁进行检查的、机器可应用的每仓库规则集。

## 结论

本工作把编码 agent 补丁的测试套件成功重新定位为必要但不充分的认证信号，把"通过测试"与"能通过人类评审"之间的差距变成可直接测量的量而非被假定的量。并行工作（arXiv 2604.05955）已独立确认了这一前提；本文在其之上的贡献是测量工具——从评审历史挖掘、经复现度过滤、经人工审计的仓库级目录——以及估计量：按类别违规分布与匹配的 agent 对人类差距。核心的方法论押注是：只有先验证测量工具自身，这一测量才可信——目录的可信度不超过其对人工标注的精确率与召回率，合规判断的可信度不超过其与盲态人工标签的一致性——更弱的设计有风险报告并不真实存在的规则的违规，或报告实为未验证裁判伪影而非真实 agent 行为的合规差距。无论当前编码 agent 呈现哪种按类别模式，该发现对任何把测试通过率当作自主生成 PR 充分认证的人都具有决策相关性：持续的 agent 对人类合规差距将意味着基于测试的基准系统性高估了 agent 补丁离免人工评审可合并还有多近，而零结果本身也是对该差距大小的一个有用的、可发表的界。两项局限从一开始就为该主张划界，并直接指向未来工作而非事后补充：本研究只限于通过测试的补丁，测试失败补丁中的违规、以及把挖掘目录反馈进 agent 自身生成回路能否降低其违规率，均留为开放问题；"不成文"主张（RQ3）限定于实际检查过的静态分析工具，不是"任何工具都无法形式化某条条目"的断言，这指向更广的静态分析面作为下一个自然的方法论目标。
