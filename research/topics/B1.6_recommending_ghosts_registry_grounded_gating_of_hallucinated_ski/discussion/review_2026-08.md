## 2. Feasibility verdict (se-paper-reviewer, R1 lens)

**Feasible as scoped — pilot-first design is sound; two arithmetic/definitional defects found
(Findings N3, N4), both fixable on paper before any spend.**

- **Budget class.** Pilot ≈ 300 episodes × 3–4 arms × 1–2 models ≈ 900–2,400 trajectory
  episodes plus a few hundred replication-gate queries; at multi-step-trajectory token counts
  this is low-thousands of dollars of API spend and ~2–3 person-weeks of harness engineering
  (digest N6's estimate is consistent). No training, no GPU requirement. Realistic.
- **Kill-test discipline is good.** RQ1's ≥20% gate-off compromise-completion floor and the
  36–43% replication gate are genuine pre-spend walking-skeleton criteria; failure reopens the
  harness rather than being reported — correct.
- **Power arithmetic** checks out for the 10pp primary contrast (two-proportion, 80% power,
  α=0.05 → ~300–390/arm depending on base rate; 300 is adequate for base rates away from 50%)
  — **except RQ4**, whose 2pp decision threshold is far below the 10pp minimum detectable
  effect the stated n=300 buys (Finding N3).
- **Assumption load** (all stated or now stated in the draft): (i) the harness can re-elicit
  recurring hallucinated names with the base study's prompt method — plausible given the twin's
  RQ2, and gated; (ii) trust-tier metadata is constructible — real analogues exist (npm
  provenance attestations, PyPI Trusted Publishers), and the synthetic-registry fallback is
  declared; (iii) sandbox execution state suffices as security ground truth — standard.
- **One definitional gap** (Finding N4): RQ7's standalone-LLM arm has, by the draft's own
  words, "no autonomous install to block," which as written makes the between-setting contrast
  degenerate (the gate's block rate is undefined or trivially zero-benefit in that arm).
  Needs the standalone arm's install semantics pinned before pre-registration.

## 3. Staleness verdict (se-paper-reviewer, R2 lens)

**Motivation: current.** The base paper is one month old, re-verified real today, and nothing
in the 2026-07/08 window supersedes the framing. The four measured defense operating points
the draft uses as reference markers are the current published frontier for skill registries.

**Related work: stale in one dimension — [major].** As of 2026-08 the draft reads as if
HallucSkills is the only squatting-from-hallucination precedent. It is not: the
package-hallucination / slopsquatting lineage (Spracklen et al. 2024/USENIX Sec'25 →
Importing Phantoms 2025 → 2026 frontier-cohort replication, plus recommendation-time defenses
PackMonitor and BOUND, and the NPA attack on agent skills) established the same
attack-precondition pattern in package ecosystems two years earlier, and the MCP security line
(ETDI, ZTR) already proposed registry-trust mechanisms. A 2026-08 reviewer in cs.SE/cs.CR
knows this literature cold. Additionally, the 2026 replication reports that registries have
begun deploying defenses (PyPI Security / Socket.dev coordinated disclosure) — the draft's
threat framing survives this (53 of 127 model-agnostic names remained registrable after
existing defenses, per that paper's abstract), and citing it *strengthens* the
recurrence-seeded adversary's realism.

## 4. Findings (numbered, severity-tagged)

- **N1 [major] — Uncited mechanism twins (novelty positioning).** ETDI (arXiv:2506.01333) and
  Zero-Trust Tool Registry (arXiv:2504.19951) propose registry-side publisher-identity /
  trust-tier gating against tool squatting, at design level, without empirical evaluation.
  Draft contribution 1 claims the checkpoint-relocation observation as if unprecedented.
  **Fix:** concede-and-claim — cite both, re-scope contribution 1 to the causal analysis +
  measurement; add them to the Related Work nearest-neighbor block. *(Applied.)*
- **N2 [major] — Missing package-hallucination/slopsquatting lineage (staleness).**
  Spracklen et al. (arXiv:2406.10279), Importing Phantoms (arXiv:2501.19012), the 2026
  frontier-cohort replication (arXiv:2605.17062), NPA (arXiv:2605.29354), PackMonitor
  (arXiv:2602.20717), BOUND (arXiv:2607.02052) — all absent. **Fix:** add a supply-chain
  lineage thread to Related Work; one sentence in the Introduction situating skill-name
  hallucination in this lineage and naming what is different (autonomous mid-trajectory
  install/execute); note deployed provenance analogues (npm provenance, PyPI Trusted
  Publishers) where the registry snapshot is described. *(Applied.)*
- **N3 [moderate] — RQ4 decision threshold below the powered MDE (conclusion validity).**
  The study is powered for a 10pp difference at n≈300/arm, but RQ4's expected-outcome /
  falsification boundary is 2pp — undetectable at that n (at a ~90% base block rate, a 2pp
  equivalence margin needs on the order of 3,000 episodes/arm under TOST). **Fix:** state RQ4
  as an equivalence claim tested with TOST at a pre-registered 2pp margin and size that cell
  separately, with the arithmetic shown. *(Applied.)*
- **N4 [moderate] — RQ7 standalone-arm install semantics undefined (design).** If the
  standalone setting truly has no install step, the between-setting block-rate contrast is
  degenerate and RQ7's falsification condition can never fire. **Fix:** define the standalone
  arm as recommendation piped to a scripted out-of-loop installer (mirroring the base study's
  PoC path), so the gate can veto in both settings and the contrast measures in-the-loop
  interception vs post-hoc veto. *(Applied.)*
- **N5 [minor] — RQ3 reads as a finding but is an integrity check.** The draft already
  concedes blocks are deterministic by construction; one clause added marking RQ3 as an
  instrument-integrity check whose informative content is the leak count. *(Applied.)*
- **N6 [minor] — pipeline.md verification caveat now obsolete.** The arXiv API resolves
  2607.12340 today; the "could not be independently re-confirmed" note should not be left as
  the last word. *(Dated note appended to pipeline.md.)*
- **N7 [minor] — "just-published" phrasing in Abstract/Intro will age poorly.** Left as-is
  (accurate at draft date); flag for the camera-ready pass. *(Not changed — no defect today.)*
