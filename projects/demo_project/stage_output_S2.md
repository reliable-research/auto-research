| **基准体系 (Reference Baseline)** | $R$ | **代表性对比基线**：<br>1. **Zero-Shot Direct Generation**：单次贪婪采样无纠错；<br>2. **Self-Debugging / Reflexion**：经典自反思基线（直接使用无过滤的自生成断言或解释器崩溃报错驱动多轮纠错）；<br>3. **CodeT (Mutual Consistency)**：采样 $N \times M$ 用例并仅通过执行一致性多数投票重排序代码（非迭代局部自愈范式）；<br>4. **LDB (Runtime Debugger)**：在无测试净化条件下利用运行时变量断点执行反馈的自纠错基线。 |
| **优化目标 (Target)** | $T$ | 在无金标约束 $C$ 与计算预算 $B$ 内，通过机制 $X$ 实现多轮自纠错对代码隐性逻辑缺陷的**正向单调修复**，同时**严格抑制由幻觉断言诱发的错误代码破坏**，在终局真实功能正确性上显著超越基线体系 $R$。 |
| **衡量指标 (Metric)** | $M$ | **可验证判定指标体系**：<br>1. **功能净增益 ($\Delta\text{Pass@1}$)**：$\text{Pass@1}^{(K)} - \text{Pass@1}^{(0)} \ge +8\%$（在金标隐藏测试集上评测）；<br>2. **负向翻转率 (Negative Flip Rate, $NF$)**：第 0 轮原本通过金标测试但经第 $K$ 轮纠错后变为错误的样本比例，目标严格压制至 $NF \le 5\%$（基线通常高达 15%~25%）；<br>3. **净修复比率 (Net Gain Rate, $NGR$)**：$NGR = PF - NF > 0$（其中 $PF$ 为从错到对的正向翻转率 Positive Flip Rate）；<br>4. **合成断言可信度 (Oracle F1)**：模型通过门控机制采纳的断言对金标语义的精确率 (Precision) 与召回率 (Recall)。 |
| **核心范围 (Scope - G)** | $G$ | Python 独立自包含算法与数据结构任务（HumanEval、MBPP、HumanEval-ET、EvalPlus），重点针对语法正确但存在边界逻辑缺陷、静默语义错误的用例。 |
| **排除范围 (Scope - N)** | $N$ | 涉及跨文件依赖的仓库级缺陷修复（SWE-bench 类）、依赖人机协同交互调试的任务、依赖形式化定理证明器（如 Dafny/Coq）的形式化验证环境、无限制增大采样空间的暴力搜索（Sampling $> 100$）。 |
| **适用卡项 (Review Cards)** | $K$ | **主要贡献类型：方法 (Method)**。适用审查准则：S2-M (问题合同边界卡)、S3-M (算法机制设计可伪卡)、S4-M (实验协议与反直觉消融卡)、S5-M (经验证伪与替代假说击穿卡)。 |

```markdown
## 2 形式化问题定义、研究对象与边界定位（S2）

### 2.1 形式化研究对象与问题合同 (Formal Problem Contract)

本研究致力于在无外部人工标注与金标测试套件的自监督约束下，解决中量级代码大语言模型（LLM）通过自合成测试执行反馈进行多轮代码纠错时的“共模偏差负向崩塌”问题。我们将该问题形式化为以下可操作、可检验的问题合同 $\langle U, C, I, B, X, R, T, M \rangle$：

*   **研究单位 ($U$)**：以单道函数级算法代码合成任务 $\tau = (\text{prompt}, \text{entry\_point}) \in \mathcal{D}$ 为不可分割的独立处理单元。输入仅包含自然语言功能规格说明（Docstring/Specification）与目标函数原型。
*   **前置条件 ($C$)**：
    1.  *Zero-Gold Oracle*：任务执行全程禁止引入任何外部金标测试集或人工介入；
    2.  *Multi-Round Execution Closed-Loop*：代码迭代轮次 $k \in \{1, \dots, K\}$，且 $K \ge 2$；代码必须经由本地 Python 解释器实际运行由模型自生成的测试套件，并接收执行 Traceback 反馈；
    3.  *Base Model Capacity*：基座模型锁定为 7B~8B 级别开源权重模型（如 Qwen2.5-Coder-7B-Instruct），不依赖专有超大前沿模型的能力黑盒。
*   **信息边界 ($I$)**：
    *   $\mathcal{I}_{\text{allowed}} = \{\text{Docstring}, \text{Signature}, \{c^{(0)}, \dots, c^{(k-1)}\}, \{t_{\text{syn}}^{(1)}, \dots, t_{\text{syn}}^{(k)}\}, \text{Traceback}_{\text{interpreter}}\}$；
    *   $\mathcal{I}_{\text{leakage}} = \emptyset$（严格阻断 Gold Test Cases、隐藏测试输入、参考代码及外部搜索环境）。
*   **计算预算 ($B$)**：单任务修复迭代轮次上限 $K = 3$；单轮自合成测试用例数 $N \le 10$；单轮候选代码采样数 $M \le 5$；单次执行超时时间 $t_{\text{limit}} \le 3.0\text{s}$；推理总 Token 上限严格控制在 Baseline 单次贪婪采样的 8 倍以内。
*   **可变对象 ($X$)**：断言解耦、差分执行验证与置信度门控过滤机制（Assertion Disentanglement, Grounding, and Confidence-Gating Mechanism）。该机制介于测试合成器与补丁生成器之间，负责判定自生成测试用例中每个断言的可信度，仅允许高置信度测试的执行反馈参与驱动代码自修复。
*   **基准体系 ($R$)**：涵盖 Zero-Shot Direct Coding、标准 Self-Debugging (Chen et al., 2023)、Reflexion (Shinn et al., 2023)、CodeT (Chen et al., 2023) 及 LDB (Zhong et al., 2024)。
*   **优化目标 ($T$)**：在条件 $C$ 与预算 $B$ 下，使得代码在隐藏金标测试集上的功能正确率随着自修复轮次 $k$ 呈现单调非递减提升，消除净负增益，打破模型对自身错误断言的盲目拟合。
*   **衡量指标 ($M$)**：
    *   主目标：金标功能通过率增益 $\Delta\text{Pass@1} = \text{Pass@1}^{(K)} - \text{Pass@1}^{(0)} \ge +8\%$；
    *   稳定性约束：负向翻转率 $NF = \frac{|\{\tau \mid c^{(0)} \text{ pass} \land c^{(K)} \text{ fail}\}|}{|\{\tau \mid c^{(0)} \text{ pass}\}|} \le 5.0\%$；
    *   有效性判据：净修复率 $NGR = PF - NF > 0$（其中 $PF = \frac{|\{\tau \mid c^{(0)} \text{ fail} \land c^{(K)} \text{ pass}\}|}{|\{\tau \mid c^{(0)} \text{ fail}\}|}$）。

### 2.2 核心范围与明确排除边界 (Scope G and N)

为确保研究具有明确的证伪边界并杜绝过度泛化承诺，界定如下研究范围：
1.  **纳入的核心范围 ($G$)**：
    *   标准独立算法问题集，包括 HumanEval、MBPP、HumanEval-ET 及 EvalPlus 基准；
    *   错误类型聚焦于：语法正确、可通过基础类型检查，但存在静默语义逻辑缺陷（Silent Semantic Errors）、边界条件处理不当（Off-by-one, Edge Cases）的代码；
    *   要求自然语言 Docstring 具备足够的语义约束以使逻辑判定在理论上自包含。
2.  **明确排除的非目标范围 ($N$)**：
    *   **排除跨文件与工程级任务**：如 SWE-bench 类仓库级 Bug 修复，因其主要瓶颈为跨模块上下文定位而非纯断言逻辑偏差；
    *   **排除人机协作与交互式澄清场景**：不引入人类用户作为外部 Oracle 进行反馈；
    *   **排除具备形式化完备规格的环境**：如附带 Dafny / Lean 形式化证明的目标系统；
    *   **排除无上限采样筛选**：排除如 $N > 100$ 的超大规模蒙特卡洛采样搜索策略。

### 2.3 近邻工作剖析与实质差异 (Nearest Neighbors & Substantive Differences)

本项工作紧邻于当前基于 LLM 的程序自纠错与测试驱动生成两条技术路径的交叉点，但具有明确的不可替代性：

1.  **与 Self-Debugging / Reflexion 的实质差异**：
    Self-Debugging 和 Reflexion 建立了以解释器反馈为驱动的闭环。然而，当缺少外部正确测试用例时，这两类工作直接将模型自主合成的未检验断言作为客观真理。实证表明，在中量级模型上，合成断言会将模型的先验理解偏差硬编码为逻辑真理，导致严重的正向翻转率被负向翻转率完全抵消（$NF > 20\%$）。本工作在自纠错闭环中引入显式“断言不可信”假设，通过可变对象 $X$ 构建断言过滤门控，阻断有害反馈。
2.  **与 CodeT 的实质差异**：
    CodeT 采用“生成代码池 + 生成测试池”的双向执行一致性评估，其本质是**静态后验代码选择 (Selection/Reranking)**，而非**交互式迭代修复 (Iterative Repair)**。当基座模型对某个边界逻辑普遍存在认知缺陷（代码池中所有样本均存在同种缺陷）时，CodeT 无法通过定位错误来生成原本不存在的正确补丁。此外，CodeT 依赖庞大的多重采样笛卡尔积，严重违背轻量预算 $B$。本工作在受限预算下，聚焦于提取执行 Traceback 中的有效信号进行局部代码变异修复。
3.  **与 LDB (Runtime Debugger) 的实质差异**：
    LDB 关注于将“程序级崩溃堆栈”细化为“变量级行运行时状态快照”，提升了反馈信息的粒度。然而，LDB 的核心前提仍是假定驱动执行的测试断言具有准确的判决力。若断言本身为假，变量级跟踪反而会引导模型在错误的逻辑路径上进行过拟合。本工作正交于 LDB，解决的是前置的“断言可信度判别”核心矛盾。

### 2.4 主要贡献类型、审查适用卡与替代义务 (Contribution Positioning & Obligations)

本研究选定主要贡献类型为 **方法 (Method)**。后续阶段的执行与评审严格受以下卡项与替代义务约束：
*   **适用审查卡**：S2-M（问题合同卡）、S3-M（方法机制设计卡）、S4-M（实验协议设计卡）、S5-M（经验验证与消融卡）。
*   **免除义务**：免除大规模预训练/指令微调的算力开销验证；免除理论计算复杂性上界的数学绝对收敛证明。
*   **必须履行的替代义务 (Compensatory Obligations)**：
    1.  **机制的形式化定义**：必须在 S3 阶段给出断言解耦、打分门控与过滤机制 $X$ 的确定性数学公式或严格伪代码，杜绝黑盒不可控 Prompt 堆叠；
    2.  **严格消融证明 (Fair Ablation)**：必须在 S4/S5 阶段设计严格的受控消融实验，分别切除“输入生成”与“断言门控”，证明性能提升确实来自机制 $X$ 对断言共模偏差的消除，而非来自提示工程带来的额外采样多样性；
    3.  **多基准与多基座跨域验证**：必须在不少于两个基准测试（HumanEval、MBPP）及两款主流开源基座模型（Qwen2.5-Coder-7B、LLaMA-3-Code-8B）上验证指标 $M$ 的无缝通用性。
```
