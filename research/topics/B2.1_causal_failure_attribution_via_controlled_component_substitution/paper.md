## Step 0 — Core Asymmetry (升维)

**The asymmetry:** In a plan–executor–tool agent pipeline, every downstream component inherits the symptoms of an upstream fault through generated text, and no deterministic triggering test exists to certify a post-hoc blame label — so attribution ground truth cannot be annotated backward from a failing trajectory; it can only be manufactured forward, by injecting exactly one known fault into a reproducibly-succeeding run and requiring the task outcome to flip.

**判据 (deletion test).** Delete the domain nouns: "every downstream *thing* inherits the symptoms of an upstream fault, and no test certifies a post-hoc label, so ground truth cannot be annotated backward — only manufactured forward." As a generic statement this is **FALSE**: for ordinary software, Defects4J annotates ground truth *backward* from real bugs precisely because a deterministic triggering test mechanically certifies each fault (digest N3, [Defects4J, Just et al. 2014]). The claim is true only where components are stochastic natural-language stages entangled through each other's outputs (C1) and where replay is non-deterministic (C2) — i.e., the domain nouns are load-bearing, so this is an asymmetry, not a bridge.

## Step 2 — Archetype

- **Primary: Resource/Benchmark** (digest N12 = `benchmark`). The contribution slot holds the artifact: a labeled fault-trajectory corpus (CO1, "Defects4J for agents") plus the controlled-substitution protocol that manufactures its labels (CO2, M1–M3).
- **Secondary: Empirical measurement** (CO3) — the attribution-method accuracy report is a *demonstration* of the resource, not the headline.
- **Intro logic:** "what becomes possible" — with by-construction ground truth, any attribution method's blame assignment becomes mechanically checkable (M5), ending validation-by-human-agreement.
- **Evidence standard:** leakage control (base-task reproducibility gate, no-op controls, outcome-flip filter) + honest baselines with a trivial-heuristic floor. **Not** a SOTA table; a low-accuracy result on all methods is a valid benchmark finding.

## Step 5 — Formal Problem Definition

**Estimand (guidance.md §3.4 R1).** The quantities of interest are (a) the per-fault-class
outcome-flip rate `FlipRate(δ_c)` and (b) each candidate attribution method's component-attribution
accuracy `Acc(m)`, conditional on certification; the unit of analysis is one substitution trial (a
single injected fault applied to one reproducibly-succeeding base task, replayed k times); the
reference population is tool-use agent trajectories produced by a fixed plan–executor–tool
scaffold on GAIA-style tasks; the decision this feeds is whether a candidate attribution method's
blame assignment can be trusted as causally grounded evidence for which pipeline stage to fix,
rather than accepted as a plausible-sounding post-hoc narrative.

**Notation.** A tool-use pipeline is a triple of component slots `K = {plan, tool, obs}` around a fixed executor ε. A task `t` with scaffold `A` yields a run `R(t) → (τ, y)`: trajectory τ, outcome `y ∈ {succ, fail}` from the task's outcome test. `δ_c` is a fault operator on component `c ∈ K` drawn from fault-template library M1; `δ_∅^c` is the **class-matched** no-op substitution on component `c` (swap `c` for a semantically equivalent good copy **via the same edit pathway as `δ_c`**, so each per-class comparison is normalized against the substitution disturbance of the same component — R3: class-matching removes the per-component edit-disturbance differential a pooled no-op arm would leave in; generator validated per B0-a's R2 plan); `δ_id` is the zero-tier **identity replay** (no edit at all, k replays from the same checkpoint), separating intrinsic replay stochasticity from edit-induced disturbance. Replays: `k` independent re-executions from the injection checkpoint (M2); `flip(t, δ_c)` = 1 iff base run is majority-success and post-injection runs are majority-failure over k replays. Ground-truth label `ℓ(τ) = c` iff `δ_c` was applied and `flip = 1` (M3). An attribution method `m: τ → ĉ ∈ K`.

**Adjective → definition → measurement** (every load-bearing adjective in the digest Claims either gets a computable quantity or is deleted):

| Adjective / verb | Formal definition | Measured by |
|---|---|---|
| *reproducible* (base task) | `succ` in ≥ 4 of k=5 temperature-0 replays of the recorded trajectory | Stage-0 gate (M2 replay) |
| *known-good* | the checkpointed component state from a reproducible base run | checkpoint identity |
| *outcome flip* | base majority-succ ∧ ≥ 3 of k=4 post-injection replays fail | M2/M3 counter |
| *failure tracks the substituted component* | `FlipRate(δ_c) − FlipRate(δ_∅^c) ≥ 0.20` for class c (class-matched no-op) | RQ1 arms |
| *heuristic-sufficiency rate* | `Acc(B0-b)` on the certified tier, overall and per class — the fraction of certified faults a frozen surface heuristic already attributes correctly | B0-b / combination rule CR-1 |
| *mechanically verifiable* (attribution) | correctness decidable as `1[m(τ) = ℓ(τ)]` with no human judgment in the loop | M5 scorer |
| *causally grounded* (label) | label produced by the labeling invariant of Step 3 (inject ∧ flip ∧ control-no-flip) | M3 filter logs |
| *accuracy* | `Acc(m) = (1/N) Σ 1[m(τ_i) = ℓ(τ_i)]`; per-class variant conditions on `ℓ = c` | M5 |
| *confusion* | 3×3 matrix `P(ĉ = j | ℓ = i)` over K | M5 |
| *realistic* (faults) | **DELETED as a claim adjective.** Replaced by a reported quantity: agreement rate between injected labels and a 200-trajectory human audit, plus the Who&When contrast (t1). No claim will assert faults are "realistic". |
| *anomalous-looking* (heuristic blame) | operationalized as baseline B0-b (below) | B0-b accuracy |

## Assumptions (A1–A6)

Each assumption's `gate` is a named PG-\* check that must pass **inside the walking skeleton**
(Step 9) before scale-up, per guidance.md §3.2 ("assumption verification is an activity, not a
paragraph"); Step 9's pass criterion is the conjunction of PG-2/PG-3/PG-4 in miniature, with
PG-1/PG-5/PG-6 deferred to the stages named below because they require artifacts (a 200-trajectory
sample, a public-weights check) the 20-task skeleton is too small to produce.

- **A1 (corpus).** ≥ 60 base tasks exist that a fixed scaffold solves *reproducibly* (defn above) on GAIA-style tasks. *Fails if* temperature-0 replay is still flaky. *Detected by* Stage-0 yield count. **Gate PG-1** (Stage-0, pre-Stage-1): yield < 30 tasks ⇒ **one** pre-registered scaffold redesign, then re-run Stage 0 once. *Consequence if failed:* blocks Stage 1 entirely — no substitution trial can be run without a reproducible base pool, so E1–E4 (H1–H4) cannot start. *If yield < 30 persists after the single redesign*, the failure is unrecoverable and routes to **F-G1's PG-1 branch** (see Global fallback): the reproducibility yield itself becomes the paper's headline measurement — never loop on scaffold redesign a second time.
- **A2 (environment).** Orchestrator-message-level edits (DoVer-style) can swap one component while the other two replay from checkpoint without format breakage (t3). *Fails if* swapped plans crash the executor for non-fault reasons. *Detected by* the walking skeleton's no-op arm. **Gate PG-2** (walking skeleton, Step 9): crash rate on any `δ_∅^c` arm > 10% ⇒ harness bug, not science. *Consequence if failed:* blocks all H1–H4 — a crashing no-op arm invalidates the no-op control every fault-class comparison depends on (goal.md §5's placebo-first rule).
- **A3 (yield).** Injected faults flip outcomes often enough to build a corpus: `FlipRate(δ_c) ≥ 0.30` per class. *Fails if* agents route around faults. *Detected by* walking-skeleton flip counts. **Gate PG-3** (walking skeleton, Step 9): fallback — strengthen fault templates (pre-registered as template-severity knob, not post-hoc cherry-picking — severity level fixed before RQ scoring). *Consequence if failed:* degrades the affected fault class's corpus size (restricts scope to the classes that clear the floor); does not block classes that do clear it.
- **A4 (stochasticity bound).** `FlipRate(δ_∅^c) ≤ 0.10` for **each** class-matched no-op arm, and `FlipRate(δ_id) ≤ 0.05` for the identity-replay tier, under k=4 replays at temperature 0. *Fails if* the pipeline is chaotically sensitive (C2) **or** the edit pathway itself disturbs outcomes. *Detected by* walking-skeleton arms 3–4 (class no-op + identity replay). **Gate PG-4** (walking skeleton, Step 9), **disambiguated by tier**: (i) `δ_id` passes but some `δ_∅^c` fails ⇒ the *edit pathway* is the artifact — a harness defect per guidance.md situation 1: fix and re-run the skeleton, never k↑ and never a finding; (ii) `δ_id` itself fails ⇒ intrinsic stochasticity — k↑ (to 8) once, then F-G1. *Consequence if failed:* blocks H1 (RQ1) for the affected class — a non-null placebo invalidates that class's flip-rate comparison (goal.md §8's hard gate) — and, if `δ_id` still fails after the k↑ retry, triggers the global pivot F-G1 (whose stochasticity claim is licensed precisely because the identity tier, not the edit tier, is what failed).
- **A5 (label unambiguity).** Single-component injection yields a unique locus: the injected `c` is not itself confounded (e.g., a polluted observation is not also a broken tool). *Fails if* fault templates straddle classes. **Gate PG-5** (pre-Stage-2 scale-up, per guidance.md §3.4 R2's five-step instrument-validation sequence): ① categories are already grounded in the pipeline's own architecture (the three fault classes are exactly the three component slots K={plan,tool,obs}, not an invented taxonomy); ② the fault-template library is drafted wide and refined on a held-out calibration subset (named merge/split of templates that straddle two classes) before the full audit set is drawn; ③ validated against **≥2 independent human raters** on a 200-trajectory audit sample, computing **Cohen's/Fleiss' κ ≥ 0.7** (not raw percent agreement, which overstates chance-corrected agreement) between raters and against the constructed label; ④ the confusion structure is inspected — disagreements must land on adjacent classes (e.g., tool/observation, where a broken tool can manifest as a bad observation) rather than a systematic three-way collapse; ⑤ freeze (hash) the taxonomy before Stage-2 scale-up. *Consequence if failed* (κ < 0.7, or systematic — not adjacent — confusion): re-taxonomize templates per guidance.md situation 7 and re-validate before release; do not scale an unvalidated instrument.
- **A6 (baselines).** M4 methods are runnable: WhoAndWhen judge prompts reproducible, ablation/leave-one-out and DoVer-style intervention implementable on our harness; AgenTracer used only if weights/prompts are public, else dropped with a stated note. *Detected by* a one-trajectory smoke test per method. **Gate PG-6** (pre-Stage-1, before E2–E4 run): smoke-test failure for a given method ⇒ that method is dropped from the E2–E4 comparison with a stated reason, never silently omitted. *Consequence if failed:* restricts the method population in E2–E4 (fewer compared methods); does not block E1 (RQ1), which does not depend on M4.

## Step 6 — Pre-Registered Experiments

### E1 — RQ1: Does failure track the substituted component? (digest RQ1; M2, M3; C1, C2; CO2)

- **Assumption:** A1, A2, A3, A4.
- **Hypothesis H1 (binary):** For **each** fault class c ∈ {plan, tool, obs}: `FlipRate(δ_c) ≥ 0.30` **and** `FlipRate(δ_c) − FlipRate(δ_∅^c) ≥ 0.20` (class-matched no-op), with the difference significant at α = 0.05 (BH-corrected across the 3 classes, cluster-robust per Verification). H1 **passes iff all three classes pass**; partial pass is pre-declared as H1-partial (see fallback).
- **Metric:** Outcome-flip rate = `P(flip = 1 | δ_c)` vs `P(flip = 1 | δ_∅^c)` (digest N8 metric 4, class-matched), n ≥ 100 injection trials per class + n ≥ 100 **class-matched** no-op trials per class (`δ_∅^c`; see B0-a) + n ≥ 100 identity-replay trials (`δ_id`), k = 4 replays per trial.
- **Verification:** Per class, flip-rate difference vs the class-matched no-op arm `δ_∅^c`, with **cluster-robust inference at the base-task level** — trials sharing a base task form one cluster; the test is a two-proportion comparison with cluster-robust variance (equivalently, a cluster bootstrap of the rate difference resampling base tasks, not trials): one-sided, α = 0.05, Benjamini–Hochberg across the 3 classes; report 95% cluster-bootstrap CIs on all rates. **Honest power:** the stated n gives > 0.9 power for the *significance component* at the design alternative (true gap 0.30 vs base rate 0.10) under trial independence; because H1's pass criterion is a conjunction (point-estimate gap ≥ 0.20 **and** significance), the pass probability at a true gap of exactly 0.20 is ≈ 0.5 by symmetry — H1 is powered against the 0.30 design alternative, **not** the floor. Per-class power under base-task clustering is re-computed by cluster-bootstrap simulation on the walking-skeleton pilot before Stage-1 scoring (thresholds frozen first); a class whose simulated power < 0.8 is pre-declared INCONCLUSIVE, never scored as null (situation 5).
- **Fallback (pre-committed wording, pattern-neutral):** If a strict subset of classes passes: *"Failure tracks the substituted component for the fault classes that clear the certification margin — {certified class list} — but not for {uncertified class list}; substitution-based ground truth is therefore certified for that subset only, and the released corpus is partitioned into a certified tier and an uncertified tier, named per class."* (Applies verbatim whichever classes pass. The *expected* pattern — executable faults certify, semantic plan corruption does not — is a prediction only; a reversed pattern is reported at full prominence per guidance.md situation 4, not smoothed into the expected wording.) If **no** class passes → F-G1.

### E2 — RQ_INF_1a: Do attribution methods beat the trivial floor? (digest RQ_INF_1; M4, M5; C3, C4; CO1, CO3)

- **Assumption:** A1–A6 (labels exist per E1).
- **Hypothesis H2 (binary):** Each non-trivial method m ∈ {LLM-judge (3 WhoAndWhen context strategies), ablation/leave-one-out, DoVer-style intervention, FAPO/CRM-style step-localizer} achieves `Acc(m) − Acc(B0-b) ≥ 0.10` absolute, paired test p < 0.05 (cluster-robust, below). H2 passes iff ≥ 3 of the **runnable** method families pass; if PG-6 leaves 3 runnable families the rule is all-but-one (≥ 2 of 3); with ≤ 2 runnable families H2 is pre-declared INCONCLUSIVE. H2 is scored under combination rule CR-1 (heuristic-ceiling branch) whenever `Acc(B0-b) ≥ 0.90` on the certified tier.
- **Metric:** Top-1 component-attribution accuracy `Acc(m)` (digest N8 metric 1) on the certified corpus (Stage-1 target n ≈ 300, ~100/class; Stage-2 n ≈ 3,000).
- **Verification:** McNemar-style test on paired correct/incorrect vs B0-b per method, with **base-task-cluster-robust inference** (paired differences sharing a base task are one cluster; a cluster bootstrap of the paired accuracy difference resampling base tasks), α = 0.05 with BH correction across the full method × fault-category grid (digest analysis plan); 95% cluster-bootstrap CIs; 3×3 confusion matrices reported for every method regardless of outcome.
- **Fallback (pre-committed wording, applies only when `Acc(B0-b) < 0.90`):** *"On causally certified labels, current attribution methods do not exceed a trivial surface heuristic: the accuracy previously reported against human-agreement labels does not survive mechanical verification, indicating those labels reward symptom-matching rather than causal localization."* (This is the benchmark's strongest possible negative finding and is publishable as-is.) If `Acc(B0-b) ≥ 0.90`, this wording is **superseded** — its symptom-matching diagnosis presumes a low floor — and CR-1's heuristic-ceiling wording governs instead.

### E3 — RQ_INF_1b: Is there headroom below the ceiling? (digest RQ_INF_1; N9 direction 2)

- **Assumption:** A1–A6, E1 passed.
- **Hypothesis H3 (binary):** The best-performing method's `Acc ≤ 0.90`, with 95% bootstrap CI upper bound < 0.95 — i.e., mechanical verification exposes a ≥ 10-point gap below the by-construction ceiling of 1.0.
- **Metric:** max over **non-trivial** methods of overall `Acc(m)` (B0-b is excluded from the max; its accuracy is reported separately as the heuristic-sufficiency rate, Step-5 table); per-class accuracies.
- **Verification:** Cluster bootstrap CI (10,000 resamples, **resampling base tasks rather than trials**) on the best method's accuracy; declared on Stage-1 n ≈ 300, confirmed at Stage-2.
- **Fallback (pre-committed wording):** *"Single-component faults at this severity tier are solved by existing methods; the benchmark's certified tier functions as a competence certificate rather than an open challenge, and we release a harder single-fault tier — faults at the lowest severity level that still clears E1's certification margin, restricted to trajectories where the fault-to-failure distance is ≥ 3 steps — constructed from the same fault-template library, harness, and labeling invariant (still exactly one injected fault per trajectory), as the open problem."* Budget: the harder tier reuses the existing harness and severity knob (A3/PG-3) as a config change, at ≤ 25% of the Stage-2 injection budget; it is a re-parameterization of already-built machinery, not a new collection effort.

### E4 — Secondary: plan-vs-tool asymmetry (digest N9 direction, Claims bullet 3)

- **Assumption:** A1–A6, E1–E2 passed.
- **Hypothesis H4 (binary):** For the LLM-judge family: `Acc(judge | ℓ=plan) ≤ Acc(judge | ℓ=tool) − 0.10`, paired-bootstrap p < 0.05 (cluster-robust, below).
- **Metric:** per-class accuracy from the M5 confusion matrix.
- **Verification:** class-conditional **cluster-bootstrap** difference test (resampling base tasks), BH-corrected with the E2 grid. **Severity confound (R3):** certification selects only outcome-flipping faults per class, and the PG-3 severity knob is set per class, so surviving severity distributions may differ across classes — class identity would then be confounded with fault subtlety. Constraint: the H4 comparison is run on **severity-matched template pairs** (plan and tool templates at the same pre-registered severity level), and `Acc(B0-b | ℓ=c)` is reported per class alongside as a difficulty proxy; if the plan–tool gap vanishes under severity matching, H4's claim is downgraded to a severity effect, pre-committed wording: *"The apparent plan-fault difficulty is carried by fault severity composition, not by fault class itself."*
- **Fallback (pre-committed wording):** *"Attribution difficulty is not ordered by fault class for post-hoc judges; confusion structure, not class identity, carries the diagnostic signal."* (H4 failing does not threaten CO1/CO2. A significant **reversed** ordering is not folded into this null wording — see CR-5.)

### Mandatory baselines

- **B0 — "why do this at all" control (two named arms):**
  - **B0-a: class-matched no-op substitution arms** (`δ_∅^c` for each c ∈ K, n ≥ 100 each) **plus a zero-tier identity-replay arm** (`δ_id`, n ≥ 100): swap component `c` for an equivalent good copy via the *same edit pathway* as that class's fault injection, no fault; `δ_id` replays from the same checkpoint with no edit at all. Justifies RQ1's existence — if `δ_∅^c` flips outcomes as often as real faults, "failure tracks the component" is unmeasurable and the labels are noise; the identity tier disambiguates *why* (edit-pathway artifact vs intrinsic stochasticity — A4/PG-4's tiered rule).
    - *δ_∅ generator validation (R2, five steps, pre-Stage-1):* ① equivalence classes grounded per component in the harness's own recorded artifacts (plan: a paraphrase of the recorded plan step preserving its action and arguments; tool: an independently instantiated binding with identical signature and endpoint; obs: a re-serialization of the recorded observation with formatting-only changes); ② generators drafted wide and refined on the walking-skeleton trajectories with named accept/reject rules; ③ equivalence audited by **≥ 2 independent human raters** on a 50-swap calibration slice — each swap judged "introduces no task-relevant information loss, addition, or error" — **κ ≥ 0.7** between raters and ≥ 95% of swaps rated equivalent required; ④ failures inspected — must be formatting-adjacent, not semantic drift; ⑤ freeze (hash) generator prompts/rules before Stage-1 scoring. An unvalidated `δ_∅` is treated as absent (goal.md §8), since every E1 comparison is normalized against it.
  - **B0-b: surface-heuristic attributor**: blame the component hosting the *last step before the first observable error signal*, where the error signal is a **frozen deterministic detector** — a fixed rule/regex set over the recorded trajectory: (i) tool-return status/error fields and non-zero exit codes, (ii) empty or schema-invalid tool payloads against the tool's declared schema, (iii) executor-emitted retry/exception strings from a fixed pattern list; no LLM call, no human judgment (ties, or no signal fired → majority class). Justifies RQ_INF_1's existence — if this trivial heuristic already matches ground truth at ≥ 0.90, single-fault attribution at this severity tier is symptom-reading and no method-ranking benchmark is needed there (routing pre-committed: CR-1). B0-b is the floor in H2. (Random and majority-class attributors are also reported, per digest M4-e.)
    - *B0-b detector validation (R2, five steps, pre-Stage-1):* ① signal categories grounded in the harness's own logged fields (status codes, schema validators, exception patterns); ② pattern list drafted wide, refined on the walking-skeleton trajectories with named add/merge/remove operations; ③ validated against **≥ 2 independent human raters** marking "first observable error step" on a 50-trajectory calibration slice, **κ ≥ 0.7** required between the detector and each rater; ④ disagreements inspected — must be off-by-adjacent-step, not a systematically missed signal class (in particular: plan-corruption trajectories may fire *no* signal — the no-signal→majority-class rate is reported per fault class, not hidden); ⑤ freeze (hash) the pattern list before Stage-1 scoring.
- **B-alt — strongest-alternative-explanation control:** The rival explanation for "intervention-based methods (DoVer-style) beat post-hoc judges" is **compute/access, not causal reasoning**: intervention methods consume k extra replays and checkpoint access. B-alt is a **budget-matched post-hoc judge**: the LLM-judge granted the same replay budget (k additional sampled trajectories of the same failing run, provided as text) and self-consistency voting, so total model-calls and observable evidence are matched to the intervention arm. If B-alt closes the gap, the paper's claim about *do-then-verify* narrows to a compute-parity statement — pre-committed wording: *"Intervention access adds no attribution accuracy beyond an equal budget of passive resamples."* This comparison is itself pre-registered as **secondary hypothesis H-sec** (verbatim, the Stage-5 battery's second hypothesis; RQ5 `rq_compute_parity_control` in the experiment design): *"The accuracy advantage of intervention-based methods over post-hoc judges will narrow to below 0.10 absolute once the judge is given an equal replay budget of passive resamples (the budget-matched control) — i.e., intervention access adds no attribution accuracy beyond an equal budget of passive resampling."* Verification: paired accuracy difference between the DoVer-style intervention method and its budget-matched judge counterpart on the certified tier, base-task-cluster-robust paired bootstrap, BH-corrected alongside E2's method × class grid, same powered-cell/INCONCLUSIVE rule as E2. If H-sec passes (gap < 0.10), the pre-committed compute-parity wording above is the paper's claim; if it fails, the surviving gap is reported at full prominence as the do-then-verify advantage. This gives the Abstract's budget-matched-control clause a claim-map row (below) rather than a promise backed by no hypothesis (design-review F11). A second rival — "injected faults are merely distribution-shifted, making methods look bad" (t1) — is controlled by reporting each method's accuracy on the human-labeled Who&When set alongside the certified corpus, with the gap stated explicitly (label-space mapping: Who&When's blamed *agent/step* is mapped to the component slot hosting it — plan steps → plan, tool-call steps → tool, observation-ingestion steps → obs — with unmappable steps reported as a coverage rate, not silently dropped).
- **B-alt-2 — contamination/memorization control (ported from the Stage-4 draft fix into this binding spec):** The rival explanation for post-hoc-judge accuracy is **memorized task familiarity, not causal reasoning**: base tasks come from a publicly released benchmark, so a judge may recognize that a step deviates from a remembered correct solution path — which is not the same as identifying which pipeline component the injected fault touched. Control: a held-out subset of ≥ 30 base tasks not present in the benchmark's public release (or task instances with surface-paraphrased wording that breaks exact-string memorization) is scored separately in E2–E4. Pre-committed downgrade wording: *"Method m's accuracy on the held-out/paraphrased subset falls ≥ 10 points below its full-corpus accuracy; its headline accuracy is therefore reported as memorization-assisted, and only its held-out accuracy is treated as evidence of causal attribution ability."*

### Power statement and thin-cell rule (E1–E4, guidance.md §3.4 R8 / situation 5)

**All E1–E4 inference is cluster-robust at the base-task level**: trials, no-op runs, and method
predictions sharing a base task form one cluster (Stage 2 generates ~3,000 trials from only ~200
base tasks, so the effective sample size is the cluster count, not the trial count); every test
uses cluster-robust variance or a cluster bootstrap resampling base tasks, and every CI is a
cluster-bootstrap CI. E1's pre-registered n (≥100 injection + ≥100 class-matched no-op trials per
class) gives >0.9 power for the *significance component* at the design alternative (true gap 0.30
at base rate 0.10) under trial independence; at the 0.20 effect floor itself the conjunction
criterion passes with probability ≈ 0.5 (stated honestly in E1, not hidden). The same discipline
extends to E2–E4, stated once here rather than repeated per experiment: at Stage-1's target n≈300
(~100 certified trajectories per fault class), a per-class or per-method cell with **≥80 certified
trajectories** is a *necessary* condition (under independence it gives ≥0.8 power to detect a 0.10
absolute accuracy gap via a McNemar-style paired test at α=0.05, finite-sample normal
approximation) — but the **binding** powered-cell check is a cluster-bootstrap power simulation
run on the walking-skeleton pilot's observed base-task clustering, thresholds frozen before
Stage-1 scoring: a cell is powered iff simulated power ≥ 0.8 for the 0.10 gap at α=0.05. This is
the powered-cell rule for E2 (`rq_floor_beat`), E3 (`rq_ceiling_gap`), and E4
(`rq_plan_tool_asymmetry`). **Any cell failing either check — fewer than 80 certified trajectories
after A3's yield gate (PG-3) and A5's certification filter, or simulated cluster-robust power
< 0.8 — is pre-declared INCONCLUSIVE for that class in E2–E4 — never scored as a null result and
never silently dropped from the denominator.**
Stage-2 (n≈3,000, ~1,000/class) is designed to clear this floor with margin for every class that
passed E1's per-class certification; if a class remains under-powered at Stage-2 scale, the honest
options are guidance.md situation 5's three: collect more (config-only), narrow the claim to the
powered cells, or stop — never quietly relax the 0.10 floor.

### Global fallback F-G1

F-G1 fires on any of three pre-registered triggers: (a) the central hypothesis family fails — H1 fails on **all** classes even after the single pre-registered k↑ retry; (b) **PG-4 identity-tier failure** — `δ_id` exceeds its bound even after the k↑ retry (intrinsic stochasticity, not a harness artifact, per A4's tiered rule); (c) **PG-1 hard failure** — fewer than 30 reproducibly-solved base tasks even after the single pre-registered scaffold redesign. In all three: pivot from *Resource/Benchmark* to *negative-result measurement study* (empirical archetype). Pivoted abstract sentence, pre-committed: *"We show that the foundational premise of substitution-based failure attribution does not hold for tool-use agents — single-component injected faults do not move task outcomes above the stochastic replay baseline — implying that intervention-certified ground truth is unobtainable at current stochasticity levels and that published attribution accuracies rest on labels no controlled experiment can validate."* Under trigger (c) the pivoted headline quantity is the reproducibility yield itself — the fraction of benchmark tasks a fixed scaffold solves reproducibly under temperature-0 replay, reported with the same gates and both placebo tiers. The harness, no-op controls, identity-replay measurements, and flip-rate measurements are released as the artifact of that paper.

### Fallback-combination rules (CR-1–CR-5, pre-committed — never invented at verdict time; guidance.md §3.1 rule 4)

- **CR-1 — heuristic-ceiling branch (`Acc(B0-b) ≥ 0.90` on the certified tier).** B0-b's own justification names this as premise-collapse for the method-ranking question; per guidance.md §3.3 it must route, not be buried. Pre-committed wording, verbatim: *"On single-fault, outcome-flip-certified trajectories, a frozen surface heuristic — blame the component hosting the last step before the first logged error signal — already matches the by-construction ground truth at ≥ 0.90: for this severity-selected slice, attribution is symptom-reading, and no method-ranking benchmark is needed there. The paper's contribution accordingly narrows to (a) the heuristic-sufficiency rate itself, reported per fault class as a finding — the measured boundary of where attribution is trivial — and (b) the residual slice where the heuristic fails (no logged error signal, or a signal on a non-faulted component), which is released as the challenge tier; H2 and H3 are re-scored on that residual slice only, powered cells permitting, else pre-declared INCONCLUSIVE."* When CR-1 fires it supersedes E2's fallback wording and governs E3's interpretation.
- **CR-2 — H1-partial + anything downstream.** E1's pattern-neutral certified-subset wording leads; E2–E4 wordings apply within the certified tier only (already stated per-experiment); uncertified classes are INCONCLUSIVE cells, never nulls.
- **CR-3 — H2 fails ∧ H3 fails ∧ `Acc(B0-b) < 0.90`.** E3's competence-certificate wording leads (the best family is near ceiling, so the certified tier is too easy for it), and E2's wording is restricted to the named families that failed to clear the floor; both are reported together, E3 first — the two wordings are complementary here, not contradictory, because they name different method families.
- **CR-4 — H2 fails ∧ H3 passes.** E2's fallback wording is the headline negative finding (the benchmark has headroom AND methods sit at the trivial floor); E3's main wording is reported as supporting context.
- **CR-5 — wrong-direction results (situation 4).** A significant reversed H4 ordering is reported at full prominence with the pre-committed sentence: *"Plan-fault attribution is more accurate than tool-fault attribution for post-hoc judges — the opposite of the propagation-diffuseness prediction — indicating that error-signal salience, not causal distance, drives judge accuracy."* Reversed E1 patterns are handled by E1's pattern-neutral wording plus full-prominence reporting. No wrong-direction result is ever folded into a null wording.
- Precedence: F-G1 (any trigger) supersedes all CR rules; CR-1 supersedes CR-3/CR-4 where both could fire.

### Release, versioning, and longevity (A3 evidence standard — maintenance statement)

The corpus is released in **versioned tiers keyed to scaffold and backbone** (`corpus-v1-<scaffold>-<backbone-id>`), each release recording scaffold, backbone, k, all frozen thresholds, and the fault-template/detector/generator hashes (A5/B0-a/B0-b freezes). Post-hoc attribution methods are evaluable from the released trajectories alone; intervention-based methods require live checkpoint-replay and are therefore certified **per backbone**. To bound backbone-deprecation rot — the reason a "Defects4J for agents" cannot simply pin a closed API model the way Defects4J pins the JVM — at least one full corpus tier is built on a **pinned open-weights backbone** (fixed weights hash) so re-certification and intervention baselines remain runnable after any API model is retired; the harness, gates, and a re-certification script ship with the corpus. A new backbone ⇒ a new certified tier via the same config-not-code scale path; certified labels are never silently reused across backbones.

## Step 9 — Walking Skeleton

**One binary question:** *Do tool-break injections flip outcomes at ≥ 0.20 above the no-op control on a reproducible base set?* (Gates PG-2/PG-3/PG-4 — Assumptions A2/A3/A4 — checked in one loop; the E1 criterion in miniature. PG-1 is checked by Arm 1's own yield count; PG-5 and PG-6 are deferred to pre-Stage-2 and pre-Stage-1 respectively, per the Assumptions section, since they need artifacts — a 200-trajectory audit sample, a per-method smoke test — this 20-task skeleton is too small to produce.)

- **Arms (4):**
  1. **Base + gate:** 20 GAIA-style tasks, one plan–executor–tool scaffold, temperature 0; keep tasks passing the reproducibility gate (target ≥ 12 survivors).
  2. **Tool-break injection:** 1 fault template (tool → error-returning stub) × survivors, k = 3 replays each.
  3. **Class-matched no-op substitution:** `δ_∅^tool` (equivalent tool binding via the same edit pathway as arm 2) on the same survivors, k = 3 replays each.
  4. **Identity replay:** `δ_id` (no edit, replay from the same checkpoint) on the same survivors, k = 3 replays each — the zero tier that lets PG-4's edit-artifact-vs-stochasticity disambiguation run in miniature.
- **Deterministic metrics only:** reproducibility yield count, flip counts per arm, crash count on `δ_∅^tool` (A2 check). No LLM-judge, no accuracy scoring, no statistics beyond raw proportions.
- **Expected cost:** ≈ 20 base×5 + 12×3×3 ≈ 210 runs; at $0.10–0.50/run ⇒ **$21–105, < 1 day wall-clock** (digest N6 feasibility).
- **Pass criterion (explicit):** yield ≥ 12 tasks ∧ crash(δ_∅^tool) ≤ 10% ∧ `FlipRate(tool-break) − FlipRate(δ_∅^tool) ≥ 0.20` ∧ identity-replay flips ≤ 1 of the survivors (coarse pilot check of A4's `δ_id ≤ 0.05` bound), with ≥ 10 labeled trajectories produced. **Skeleton passed ⇒ scaling to 3 fault classes × 5 templates × 200 tasks × k=4 (with per-class `δ_∅^c` arms) is a config change (template list, task list, k, no-op variant list), not a code change** — the harness, gate, filter, and scorer interfaces are all exercised in the skeleton.

## Abstract v0 (draft, mechanism-first — DRAFT BEFORE RESULTS; no numbers are findings)

In a plan–executor–tool agent pipeline, ground truth for failure attribution cannot be annotated backward from a failing trajectory — downstream components inherit upstream faults' symptoms and no triggering test certifies a blame label — but it can be manufactured forward: inject exactly one known fault into a reproducibly-succeeding run, hold the other two components fixed, and keep the trajectory only if the outcome flips against a no-op-substitution control. We formalize this labeling invariant, build the substitution harness that enforces it, and release a corpus of fault-labeled tool-use trajectories spanning corrupted plan steps, broken tools, and polluted observations — a Defects4J for agents. The corpus makes any attribution method's blame mechanically checkable; we measure LLM-judge, ablation, and intervention-based methods against by-construction labels, with budget-matched and surface-heuristic controls isolating causal access from compute and symptom-reading.
