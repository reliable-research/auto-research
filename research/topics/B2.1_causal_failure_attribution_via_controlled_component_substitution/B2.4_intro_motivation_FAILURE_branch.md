## Motivation

LLM agents are deployed not to answer but to *act* — they call tools, query databases,
edit files, execute commands, and coordinate multi-step workflows. When such a run fails,
the operative question is **why**: a flawed plan, a wrong tool, a misread error, an early
stop. The answer is load-bearing because it drives what happens next — retry, repair,
escalate, fine-tune, or abandon.

Current failure-attribution *formulations* answer it under a hidden assumption: **every
failed trace contains a culpable agent decision.** Whether a task admits *any* solution
is fixed by its specification before any agent acts and is certifiable by a mechanical
check over the environment; attribution reads only the post-hoc trace, in which the
counterfactual that defines blame — the earliest step whose correction would flip failure
to success — **provably does not exist on an unsolvable instance.** A required column may
be dropped, a needed tool removed, a stated goal contradicted by a stated constraint. A
vocabulary with no word for "the task was infeasible" cannot express the correct
diagnosis, and an attributor restricted to that vocabulary misattributes *every*
certified-unsolvable instance by construction.

Whether this formulation-level blind spot translates into a *practical* failure of
deployed attribution, however, is an empirical question the field has never measured —
because measuring it requires ground truth about solvability that is independent of agent
behavior, and neither human labels (do not scale) nor the agent's own failure (circular)
can supply it. This paper supplies the instrument and reports the measurement. **Our
central result is a negative one, and it is good news: once the `unsolvable` outcome is
made available, current attribution pipelines distinguish "the agent failed" from "the
task was infeasible" far better than the formulation-level analysis predicts** — the
measured false-blame rate is [XX.X%], below our pre-registered 20% floor. The blind spot
is real in the *label space*, not in the *models*: the fix is a vocabulary change, not a
capability the field lacks. What remains unresolved — and what the second half of the
paper measures — is the *calibration* of that judgment and its failure direction: how
often solvable-but-failed tasks are prematurely written off as impossible (the cop-out
rate), and at what confidence the `unsolvable` verdict can be trusted to gate retries.

## Introduction

When an autonomous LLM agent is handed a task — write a SQL query, book a flight through
a tool API, run a build script — and the run ends without success, automated debugging
systems ask: **what did the agent do wrong?** Failure-attribution systems localize the
plan, tool call, or execution step responsible, and their verdicts increasingly drive
automated repair, retry, escalation, and training data for the next agent. The strongest
formulations make the target explicit: attribution identifies the earliest agent step
whose *counterfactual correction* would have flipped failure into success
\citep{who_when,agentracer}.

That definition presupposes a correcting step *exists*, and excludes a practically common
case: the task may have been **infeasible before the agent ever acted** — a required
schema element absent, a necessary tool removed, a requested resource nonexistent, a goal
that contradicts the environment. On such an instance no success-flipping correction
exists, so an attributor with no `unsolvable` outcome must still nominate a culprit — a
*label-restricted* attributor misattributes every certified-unsolvable instance by
construction, at an expected false-blame rate near 1.0. We confirm this arithmetic
empirically as our B0-a control ([XX.X%] measured). But the control settles only what the
label space forbids; it says nothing about what the models *can do* once the vocabulary
permits the right answer. The open empirical question — the one this paper measures — is
whether attributors **given** the `unsolvable` outcome actually use it correctly: neither
falsely blaming the agent for impossible tasks nor hiding behind "unsolvable" as a safe
excuse for hard ones.

Measuring that has been blocked by ground truth, not modeling. A misattribution rate
needs solvability labels that are independent of agent behavior; human labels do not
scale to the pair counts a rate estimate needs, and the agent's own failure is circular —
it defines "unsolvable" as "whatever the agent did not solve," the exact conflation under
study. Ground truth must come from the task specification alone. We construct matched
solvable/unsolvable pairs differing only by a typed mechanical mutation — remove a
required schema element, delete a necessary tool, eliminate an environment resource,
contradict a task constraint. The solvable member retains a passing reference solution;
the unsolvable member is certified by an oracle script verifying the altered element is
*required* and admits *no substitute* (schema-graph unreachability for SQL,
tool-signature non-coverage for function calling, an environment-state assertion for
stateful tasks). Every pair passes a leakage audit — a text-only probe (AUROC [EE], below
the pre-registered 0.60 gate), surface-statistic matching, and a two-rater human check —
so no measured rate is an artifact of detecting the mutation rather than reasoning about
feasibility. Prior work touches parts of this without isolating it: attribution
benchmarks assume solvability \citep{who_when,agentracer,elephant}; MAST catalogs *how*
systems fail without certified task-level infeasibility \citep{mast}; APB \citep{apb}
measures the *acting agent's* calibrated refusal, not a third-party attributor reading a
finished trace; and rigorous-benchmark guidance \citep{abc} certifies each task *is*
solvable — the mirror image of our move. No prior testbed dissociates
*unsolvable-for-anyone* from *unsolved-by-this-agent* by construction.

Over this instrument, the headline measurement disconfirms the over-blame hypothesis we
pre-registered. Across **[N]** matched pairs spanning **[D]** domains, **[K]** backbones,
and **[M]** attribution strategies *equipped with the `unsolvable` outcome*, the
false-blame rate on certified-unsolvable instances is **[XX.X%]** — below the
pre-registered 20% floor, and **[YY.Y pp]** below the label-restricted control arm. Per
our pre-committed fallback (F1), we report this as a **certification finding**: the
formulation-level blind spot is closed by a label-space change alone, without new
architectures, training, or prompting beyond naming the outcome. The result is not
symmetric, however. The reverse error persists: the cop-out rate — labeling a
*failed-but-solvable* task `unsolvable` — is **[ZZ.Z%]**, and the risk–coverage analysis
shows the `unsolvable` verdict is trustworthy only above a confidence of **[C*]**, below
which precision degrades to **[PP%]**. The oracle-calibrated ceiling probe reaches
**[AUROC = CC]** against the best deployed strategy's **[DD]**, locating the remaining
gap in **[calibration design / an information ceiling / INCONCLUSIVE]** per the
pre-registered three-branch rule. The practical upshot inverts the paper's original
worry: the danger in deployed systems is less that impossible tasks waste retries, and
more that the newly available `unsolvable` label — if adopted without a calibration gate
— becomes an uncalibrated escape hatch for hard-but-solvable work.

This paper makes four contributions:

1. **A certification that the infeasibility blind spot is a label-space defect, not a
   capability defect.** The label-restricted control misattributes near-universally by
   construction ([XX.X%]), while the same pipelines given the `unsolvable` outcome
   false-blame on only **[XX.X%]** of certified-unsolvable tasks — pre-registered floor
   not met, fallback F1 invoked, reported as the finding it is.
2. **A mechanically certified paired-task instrument.** Solvable/unsolvable pairs whose
   ground truth is a script-certified *required-and-no-substitute* oracle — not human or
   LLM judgment — gated by a leakage audit (text-only AUROC **[EE]** < 0.60 per domain),
   released so the certification can be re-run per backbone and per domain.
3. **The calibration boundary of infeasibility attribution.** Per-domain risk–coverage
   curves for the `unsolvable` verdict, the measured cop-out rate **[ZZ.Z%]** on
   failed-but-solvable controls, and the operating threshold **[C*]** below which the
   verdict should not gate retry decisions — the quantity a practitioner adopting the
   label actually needs.
4. **A ceiling-probe dissociation.** An oracle-calibrated reader evaluated on held-out
   pairs separates what a trace *can* reveal (**[AUROC = CC]**) from what deployed
   strategies extract (**[DD]**), locating the remaining calibration gap per the
   pre-registered three-branch rule.

As agents move into more complex environments, some failures come from impossible
specifications rather than bad reasoning. Our measurement shows the field does not need
new machinery to recognize them — it needs to *adopt the outcome into the label space and
calibrate it*. The released instrument makes both steps cheap to verify.
