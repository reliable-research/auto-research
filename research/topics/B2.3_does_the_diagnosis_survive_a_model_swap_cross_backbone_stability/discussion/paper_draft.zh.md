# 同一故障，不同判决？LLM 智能体失败归因的跨骨干模型稳定性

## 摘要

面向 LLM 智能体流水线的失败归因（failure attribution）框架会将一条失败的任务轨迹标注为规划（planning）、工具使用（tool-use）或执行（execution）失败，这些标签正日益决定哪个团队去修补哪个组件，以及一个项目是否继续沿用当前的骨干模型（backbone）。然而，我们所知的每一个归因框架都只在一个固定的执行栈内部验证其标签，因此一个看似描述失败本身性质的标签，实际上可能是产生并评判该轨迹的特定骨干模型的性质——而从业者每次在不重新核验诊断的情况下更换底层模型时，都在依赖这一未经检验的假设。我们通过在 GAIA 与 WebArena 风格任务上进行程序化的单层故障注入（fault injection），以构造方式将智能体失败的*原因*固定，然后追问：一个固定的、预注册的归因程序给出的标签能否在更换执行骨干模型后存活。每一个一致性统计量都以失败重叠率（failure-overlap rate）为门控报告，而非盲目给出；一个将供应商不相交（vendor-disjoint）的评审者模型与智能体骨干模型交叉的评审者×智能体因子设计（judge-by-agent factorial），将任何不稳定性分解为智能体驱动、评审者驱动与表面风格三种份额；一个真值准确性检验则揭示彼此一致的骨干模型是否也与被注入的层一致。我们将报告这些来源中哪一个占主导，以及失败归因究竟是任务的性质，还是至少部分地是恰好产生该失败的骨干模型的性质。

## 引言

自主 LLM 智能体如今在真实工具与真实环境上运行多步流水线，而当其中一条流水线失败时，总得有人说清"为什么"。过去两年，这个"为什么"本身已成为一个形式化、有基准可依的任务：失败归因工具读入一条失败轨迹并输出一个标签——计划错了、某个工具调用被误用、最后的执行步骤走偏了——团队则据此决定修补哪个组件、将哪个基准结果当作修复生效的证据，以及（越来越常见地）智能体背后的底层 LLM 是否值得保留。换言之，归因已悄然成为智能体失败分诊的承重基础设施。

然而，关于这套基础设施的一个基本问题仍未被检验：如果骨干模型换了，标签还成立吗？归因工具是针对一个执行栈产生的轨迹构建并验证的——一个智能体骨干模型，往往还由一个骨干模型来评判——而每个下游使用者随后把得到的标签当作对失败本身的描述，而非对"失败与产生该轨迹的骨干模型的配对"的描述。从业者会出于成本、延迟或能力升级的考虑，例行地更换智能体脚手架背后的底层 LLM，与此同时继续信任一个从未针对这种更换重新验证过的诊断工具。如果标签随骨干模型而变，那么建立在标签之上的每一个决定——团队修补哪个模块、哪篇论文声称的修复被记为改进——实际上都是关于（任务，骨干模型）二元组的断言，却被悄悄报告成了只关于任务的断言。

与本文最接近的已有工作从归因问题内部逼近这一空白，但从未跨过本文要检验的那条轴。Who&When 将自动失败归因形式化为一个一等的评判问题，把决定性错误（decisive error）定义为其纠正能使失败轨迹翻转为成功的最早的智能体—步骤对，并评估了多种 LLM 评审策略；AgenTracer 将同一思想规模化：向成功轨迹程序化注入故障，使被注入的步骤按构造即为决定性错误，再在所得监督信号上训练一个紧凑的追踪器。两者是与本文最接近的工作——都通过决定性错误定义在单一执行栈内做失败归因——且这条工作线此后已经工业化：Who&When Pro 将前缀重放式故障注入扩展为一个含 12,326 条轨迹、跨 26 个基准的黄金标签基准，并报告了不同模型家族的归因模型在标注*同一批*固定轨迹时的系统性差异。然而这些工作——包括它所引领的最新一波归因方法与基准——没有一个将同一任务、同一注入故障在多于一个智能体骨干模型下重新执行，因此没有一个能回答其标签究竟是失败的性质，还是产生被标注轨迹的骨干模型的性质；这正是本文新增的轴。第二条相邻的工作线使流水线的评审者一侧独立地变得可疑：LLM 评审者已被证明会系统性偏袒与自己相关的生成器的输出，也会被自动发现的结构化表面扰动翻转判决——两者均在简短的成对偏好任务上演示——而与我们的评审者轴最接近的是：读取智能体轨迹的多个评审者骨干模型之间的骨干间一致性已被直接测量（且发现很低），但对象是需求满足性判断；然而，没有任何现有设计在失败层归因上、对照注入真值、同时联合变动评审者骨干与智能体骨干，因此在归因场景中评审者侧与智能体侧的方差从未被分离过。第三条更远的工作线确立了骨干级比较本身作为一条正当的评估轴，但只针对单次模型调用上的攻击敏感性得分，且刻意剥离了恰恰使失败层诊断变得含糊的多步传播。

把"标签能否在更换后存活"变成一个可测量的问题，本身就带来一系列困难。程序化故障注入可以让被注入的层在每个骨干模型下保持固定，但没有任何东西能让由此产生的证据保持固定：更强的骨干模型可能干脆从注入的故障中恢复，根本不产生可归因的失败；而由于这种恢复是骨干能力的函数而非随机噪声，可用于比较的失败池以一种结构性的、而非偶然的方式收缩。即便在确实发生的失败中，一个固定的评审者读取多个不同智能体骨干模型产生的轨迹时，也无法区分"智能体行为不同"与"评审者对不同生产者不一致"——不稳定性有两个可能来源，除非评审者本身也被变动，再多的轨迹数据也无法将其解缠。骨干模型之间在最终标签上的分歧本身也是含糊的：它可能意味着底层失败证据真的发生了分化、评审者忠实报告了这种分化，也可能意味着证据相似却被标注得不一致——只有对照注入真值的检验，而非骨干模型之间的一致性本身，才能区分这两种情况。雪上加霜的是，计划/工具/执行的边界并非自然类别——糟糕的计划常常导致格式错误的工具调用——因此固定编码本（codebook）必然会舍弃一部分真实的含糊性而非消解它；同时每个模型家族的轨迹都携带该家族特有的冗长程度与格式风格，给以文本为输入的评审者提供了一条与失败发生位置无关的表面捷径。

我们的方法将上述每个障碍都转化为一个设计决策而非一句托辞。每个一致性统计量都与失败重叠率并排报告，并预先承诺当重叠率偏低时，以能容忍缺失（已恢复）单元格的统计量为主统计量，使删失（censoring）成为被测量的量而非无声的偏差。评审者×智能体因子设计将若干供应商不相交的评审者骨干与若干智能体骨干在同一轨迹集上交叉，把任何不稳定性分解为智能体驱动份额、评审者驱动份额及其交互，而非报告一个混杂的数字。每个失败单元格都与注入的真值层交叉列联，揭示彼此一致的骨干模型是否也与真值一致——即归因*稳定*（stable）与归因*正确*（correct）之间的区分。每条轨迹的风格归一化与改写版本由一个不同于研究中所有智能体和评审者的改写器模型（rewriter）生成，用以隔离分歧中有多少由表面形式而非实质驱动。最后，一个固定的、预注册的编码本连同显式的平局裁决规则（tie-break rule），在使用前经人工标注者验证，把残余的类别含糊性转化为一项被报告的敏感性，而非不可见的噪声源。

我们在构建于 GAIA 与 WebArena 风格任务之上的故障注入套件上评估该设计，在交叉模型家族与能力档位的骨干模型网格下执行，并辅以对 Who&When 自然失败日志的检验，以考察同一发现是否在合成故障注入之外成立。

综上，我们的贡献是：
- 指出自动失败归因底层的不对称性：故障注入把失败的原因在各骨干模型间固定住，但没有任何东西固定归因程序必须读取的证据，因此每个计划/工具/执行标签都在无声地断言一个其测量流水线从未确立的不变性（invariance）。
- 一个删失感知（censoring-aware）的测量协议：以失败重叠率为门控报告每个跨骨干一致性统计量，当恢复导致的缺失率偏高时，将容忍部分重叠的统计量提升为主统计量，而非在一个未报告的、依赖骨干模型的子样本上报告一致性。
- 一个评审者×智能体因子设计：从单一拟合结构中将归因不稳定性分解为智能体驱动、评审者驱动与表面风格驱动的份额，并配以真值准确性检验，把标签的*稳定性*与标签的*正确性*分离开。
- 一份实证回答：当前 LLM 智能体失败归因是任务的性质，还是至少部分地是恰好产生并评判该失败的骨干模型的性质——若是后者，这种依赖是按模型家族与能力档位结构化的，还是各骨干模型各自特有的。

## 问题定义

**形式化设定。** 考虑任务集 T 与故障层集合 L = {plan, tool, exec}，每层配有程序化注入器（injector）ι_ℓ。单元格 c = (t, ℓ) ∈ T × L 携带机器可读的注入记录 r_c 与真值层 ℓ*(c) = ℓ，在注入时即固定。骨干模型集合 B（|B| = K）在同一固定脚手架下充当智能体的执行模型；在骨干 b 下运行单元格 c 产生轨迹 τ(c, b) 与由任务程序化检查器给出的失败标志 F(c, b) ∈ {0, 1}。评审者集合 J 在冻结的提示词与编码本下应用归因程序 A_j: τ ↦ L，可选地读取风格归一化轨迹 ν(τ) 而非原始轨迹。失败交集（failing intersection）ℐ = {c : ∀b ∈ B, F(c, b) = 1} 是在每个受测骨干下都失败的单元格集合，失败重叠率 Ω = |ℐ| / |T × L|。研究对象是 c ∈ ℐ 上标签分布 {A_j(τ(c, b))}_{b∈B} 相对于 ℓ*(c) 的性质，以及该分布如何沿 B、J、T 分解。

**为何困难。** 在注入时固定 ℓ*(c) 并不能固定归因程序实际观察到的东西：轨迹 τ(c, b) 是执行骨干 b 的函数，而一个强到能绕过注入故障的骨干贡献的是 F(c, b) = 0 而非一个可标注的失败——于是 ℐ 本身是 T × L 的一个依赖骨干模型的非随机子样本，任何在其上计算的一致性统计量若不与 Ω 并排报告便无法解释。即便限制在 ℐ 内，单个评审者 j 读取多个 b 值下的 τ(c, b) 时，也无法把可归于 b 的变异与可归于 j 自身跨生产者不一致的变异分开，因此分摊不稳定性要求同一 τ(c, b) 被多于一个 j 观察。{A_j(τ(c, b))}_b 中的分歧本身在两种情形之间是含糊的——轨迹真的不同且各自被正确标注，或轨迹相似却被不一致地标注——只有与 ℓ*(c) 的比较，而非骨干模型间的一致性本身，才能区分它们。最后，L 是对一个单一失败可能真正跨越两层的空间的规定性划分（stipulated partition），因此在上述任何测量开始之前，就必须先固定一条消解该含糊性的决策规则；并且 τ(c, b) 的信息内容与每个骨干特有的表面风格纠缠在一起，除非该风格被实验性地与内容解耦。

## 方法概览

在概念层面，本研究是一条由六个协作部件组成的单一测量流水线。故障注入套件与多骨干执行治具（harness）为每个单元格在每个受测骨干下产生轨迹与失败标志；删失感知的度量策略把由此得到的失败单元格集合转化为一个即使该集合很小也保持可解释的稳定性判决；评审者×智能体因子设计把同一批轨迹转化为对"判决为何如此"的分解；真值准确性检验与风格归一化臂各自隔离对观察到的分歧的一种特定替代解释；家族×能力交叉设计则追问残余的不稳定性是结构化的还是各自特有的。

**删失感知稳定性协议**接收各骨干的失败标志，产出一个以失败重叠率为门控的稳定性判决——稳定（stable）、部分稳定（partially stable）或模型特异（model-specific）——当重叠率偏低时将容忍缺失的统计量提升为主统计量。**评审者×智能体因子设计**让若干供应商不相交的评审者（而非一个）读取同一批失败轨迹，将标签不稳定性分摊为智能体驱动、评审者驱动与交互份额。**表现—准确性检验**（manifestation-accuracy check）在失败交集上将跨骨干一致性与注入真值交叉列联，暴露骨干彼此一致却与真值不一致的单元格。**风格归一化臂**将每条轨迹经由一个保内容、去风格的改写器重渲染并重新评判，隔离跨骨干分歧中有多少追随表面形式而非实质。**编码本平局裁决门控**为跨层失败固定一条预注册的决策规则，经人工标注者验证，并报告在替代规则下的敏感性重评分。**家族—能力交叉**按供应商谱系与能力档位组织骨干网格，追问残余不稳定性是否被二者之一所模式化。

## 方法论

### 删失感知稳定性协议

**挑战。** 更强的骨干模型可能从注入故障中恢复而非失败，因此可用于跨骨干一致性统计的单元格集合本身就是"正在比较哪些骨干"的函数——未报告的删失结构可使任何单一一致性数字变得空洞。

**洞见。** 删失无法通过设计消除，因为恢复是骨干模型的真实行为而非采样噪声；但它可以被显形：把失败重叠率作为一等量报告，并预先承诺低重叠下哪个统计量具有权威性，就把一个隐藏的偏差变成了一个可核查的设计选择。

**方法。** 当失败重叠率 Ω ≥ 0.5 时，以在失败交集 ℐ 上计算的 Fleiss' κ 为主稳定性统计量；低于该预注册阈值时，改以在全部失败（可能部分重叠）单元格上计算的 Krippendorff's α 为主。失败重叠率与各骨干的恢复率与每个一致性数字并排报告；稳定性判决（稳定 / 部分稳定 / 模型特异）只相对于在任何数据收集前固定的预注册 κ/α 区间给出。

### 评审者×智能体因子分解

**挑战。** 当一个固定评审者读取多个不同智能体骨干产生的轨迹时，观察到的任何标签不稳定性都同时相容于两种互不相容的解释——智能体行为不同，或评审者跨智能体不一致——再多的智能体侧数据也无法将它们区分。

**洞见。** 只有让评审者身份独立于智能体身份变动、同时控制评审者—智能体相关性的设计，才能把不稳定性归于特定来源而非报告一个含糊的聚合量；在此交叉设计上的单一拟合结构还能在一次测量中产出两个可分别证伪的读数——总体稳定性区间与其内部的按层排序。

**方法。** 三个供应商不相交的评审者骨干与六至八个智能体骨干读取同一轨迹集。交叉分类混合效应模型（cross-classified mixed-effects model）以任务、智能体骨干、评审者骨干的随机效应及其交互回归标签匹配，通过自举置信区间与似然比检验给出方差份额。一个 200 条轨迹的人工编码本子集（要求标注者间 Cohen's κ ≥ 0.7）在信任任何评审者标签之前锚定评审者效度；该子集按（智能体骨干 × 注入层）从试点阶段失败轨迹分层随机抽取，并被排除在所有主结论估计之外，使工具验证与评估数据互不重叠。

### 表现—准确性检验

**挑战。** 骨干模型之间的一致性本身无法区分"各骨干以相同且正确的方式呈现并诊断故障"与"各骨干以不同方式呈现故障却收敛到同一个错误标签"——二者在简单的两两一致性数字里看起来完全一样。

**洞见。** 将一致性与注入的真值层交叉列联可直接暴露"一致但错误"（agree-wrong）单元格，把一种原本不可见的失败模式——稳定但不准确的诊断——转化为可报告的量，而非折叠进聚合一致性统计。

**方法。** 对失败交集中的每个单元格，按骨干、按层列联联合结果 {所有骨干一致且匹配真值；所有骨干一致但与真值不符；骨干之间分歧}，并同时报告各骨干对照注入记录的准确率。

**预先承诺的解读。** 还须预判对任何跨骨干分歧的另一种读法：注入故障在不同骨干下可能真的级联到不同的决定性层，此时分歧是对分化的下游失败的忠实报告而非测量不稳定。编码本的"最早因果决定层"平局裁决恰在此情形下把真值钉在注入层上，而 agree-wrong 列联会报告收敛标签与之分道扬镳的频率。预先承诺的读法是：无论分歧反映的是不稳定的测量还是真正分化的因果表现，本文的重新划界结论都成立——单骨干标签无法跨更换迁移；只有"评审者本身不可靠"这一更强的解读会在因果分化情形下被撤回。

### 风格归一化臂

**挑战。** 给定骨干产生的每条轨迹都不可分离地携带该骨干特有的措辞、冗长度与格式，因此原始数据中不存在能让统计控制单独分离"评审者响应可识别骨干的风格"与"评审者响应实际发生了什么"的自然变异。

**洞见。** 隔离风格贡献需要一种在保持内容固定的同时摧毁可识别骨干的表面形式的实验操纵，而非事后调整。

**方法。** 每条轨迹额外经一个固定的改写器模型渲染——该模型不同于研究中的每个智能体与评审者骨干——它剥除可识别模型的标记、规范化工具调用格式，并在保持内容的前提下对推理文本进行释义。风格份额（style-share）计算为原始臂与风格归一化臂之间平均两两跨骨干分歧的相对下降。

**改写器保真门控（预注册）。** 释义步骤本身是一件可能悄悄摧毁其本应保存的证据的工具：一个把真正分化的失败证据抹平为相似文本的改写器，会出于内容原因缩小归一化臂的分歧，从而虚增风格份额。在任何归一化臂标签进入估计之前，改写器必须在改写后失败轨迹的分层样本上通过内容保真检验：注入故障的机器可读表现（来自注入记录 r_c）必须在改写后的轨迹中仍可识别，且评审者在改写轨迹上对照注入真值的准确率相对原始臂的下降不得超过一个与编码本哈希一起、在 Stage-2 评判前固定的容差。未通过逐轨迹证据检验的改写重生成一次，仍未通过则剔除，剔除率与风格份额并排报告；未通过样本级门控则整个归一化臂被封锁，RQ5 报告为 INCONCLUSIVE（不可下结论），而非在受损工具上计算。

### 编码本平局裁决门控

**挑战。** 计划/工具/执行的边界是规定的而非从数据中发现的，一个真正跨两层的失败会被所选的平局裁决惯例推向一侧——即使骨干行为毫无变化，不同惯例也能产生不同的表观分歧率。

**洞见。** 固定的平局裁决规则无法消解真正的跨层含糊性，但能把一个原本不可见的分歧来源转化为被测量、被报告的敏感性，把标签定义钉住，使残余分歧可归于骨干效应而非漂移的类别边界。

**方法。** 一个预注册的编码本固定"最早因果决定层"平局裁决规则，在用于任何 LLM 评审标注之前，要求两名人工标注者在 200 条轨迹子集上达到 Cohen's κ ≥ 0.7。完整骨干网格另在替代规则（最晚决定层）下重新评分，并将两种规则下主稳定性区间判决的变化作为敏感性检验报告。

### 家族—能力交叉

**挑战。** 即使智能体、评审者与风格的贡献被分离之后，任何残余不稳定性仍可能是跨骨干的无结构噪声，或是供应商谱系与能力档位的系统函数——这两种可能对重新验证成本能否摊销具有相反的实践后果。

**洞见。** 由于家族与能力档位在实践中本身相关，只有显式交叉二者的设计——而非仅在可得骨干间抽样的设计——才能判断任一因素单独是否模式化了不稳定性。

**方法。** 骨干网格将模型家族与能力档位交叉（每家族两个规模，若可得）。家族内两两一致性均值与跨家族两两一致性通过尊重任务聚类的置换检验比较，并以 Spearman's ρ 将各骨干的故障恢复率与其干净运行能力相关联。

## 实验

### 实验设置

**数据集。** GAIA（级别 1–2）——具有确定性、程序化成功检查器的工具使用/助理任务；用作试点阶段域，因为可检查的单步工具任务给故障注入真值一个干净、无歧义的参照物。WebArena 风格任务——可复现的网页智能体任务，具有更丰富的多步工具交互；用作规模化域，检验发现是否能从短的确定性 GAIA 式任务泛化到更长视野的工具链。Who&When（自然失败的多智能体日志）——用于检验在合成单层注入故障上建立的稳定性区间发现（下文 RQ1）是否能在有机产生的、由人工标注的失败上复现，其真值层来自专家一致而非注入保证的构造；没有这一检验，任何稳定性发现的适用范围将仅限于合成故障制品。

**基线**（健全性检查比较项与参考标注器，而非要击败的竞争者——这是一项测量研究，没有任何研究问题被表述为"我们的程序击败基线 X"）。Who&When 的 all-at-once 与 step-by-step 两种 LLM 评审协议框定归因程序自身设计空间内的上下文粒度效应；其中 all-at-once 协议是预注册的主归因程序——其单次轨迹级评判与估计量（estimand）"每条失败轨迹一个标签"的分析单元相匹配——与编码本哈希一起在任何标注前冻结，step-by-step 协议仅作为次级稳健性臂运行，绝不作为主数字来源。AgenTracer 式反事实重放标注在预算允许的子集上充当独立参考标注器，用因果重放定义的决定性步骤核对固定评审者的标签。机会水平一致性（由保持标签边缘分布的置换给出）是任何"一致"断言的统计下限。跨骨干多数投票伪共识是健全性基线，仅当 RQ4 的 agree-wrong 质量可忽略时才可提升为承重贡献。同骨干重测臂（同一骨干在 T=0 重跑、外加 T=0.7 的三个种子）是"为什么要做这件事"的控制，区分真正的跨骨干分歧与普通的 LLM 或评审采样噪声。两个流水线级安慰剂臂补齐控制组：评审者重测臂在 T=0 下对同一轨迹用冻结评审者评判两次，把评审者采样噪声与智能体重执行的非确定性隔离；无操作注入臂将未注入的成功轨迹提交给评审者，验证其不会在无故障处幻觉出一个故障层。

**指标。** Fleiss' κ（Ω ≥ 0.5 时的主稳定性统计量）与 Krippendorff's α（Ω < 0.5 时为主），均分层报告；失败重叠率 Ω 与各骨干恢复率；各骨干对照注入真值层的归因准确率；agree-wrong 质量；交叉分类混合模型给出的评审者骨干与智能体骨干方差份额；风格份额；家族内与跨家族两两一致性；以及故障恢复率与干净运行能力之间的 Spearman 相关。

**聚合与稀薄单元格纪律（预注册，适用于 RQ1–RQ7 与 SC1）。** 来自 GAIA 系与 WebArena 系任务家族的单元格为每个主判决合并计算；作为预注册的次级检查，每个假设的区间/阈值判定还在每个家族内单独重算，一个假设只有当合并判决与至少一个家族内判决一致时才算家族稳健（family-robust）——两者皆不一致则将该断言从一般陈述降级为按家族条件化的陈述，绝不只报告合并数字。另外，任何低于其预注册最小计数的比较单元格报告为 **INCONCLUSIVE**，而非零结果，并保留在所有分母中而非被无声丢弃：共同失败任务少于 20 的（骨干对 × 层）单元格对 RQ4 的 agree-wrong 质量为 INCONCLUSIVE；失败轨迹少于 15 的（评审者骨干 × 智能体骨干）单元格对 RQ3 的方差份额估计为 INCONCLUSIVE（但保留在报告的分母中）；RQ6 的家族对比在合并的家族内臂少于 3 对或跨家族臂少于 6 对时整体 INCONCLUSIVE，此时不在每家族 n=1 对的分辨率上作任何家族级推断断言。

**计算预算核算与成本门控（预注册）。** 按其自身声明的目标，Stage-2 设计意味着约 900 个单元格 × 6–8 个骨干 × 3 个种子 ≈ 16,200–21,600 次智能体执行，以及横跨原始臂、归一化臂与各控制臂约 9 万次评审调用——而在 WebArena 风格切片上，单条轨迹可达数万 token，因此主导开销的是评审成本而非智能体执行。与其在试点前给这一设计贴一个臆测的美元数字，试点阶段本身兼作成本测量工具：由试点测得的单轨迹智能体执行成本与单次评审调用成本外推到整个网格，并在规模化之前、连同行走骨架（walking skeleton）已有的通过标准一起，据此外推固定一个硬性的 Stage-2 预算上限。若外推的全网格成本超出上限，则先适用预先批准的收缩轴（从主网格中去掉最弱能力档位并作描述性报告），然后才考虑降低任何单元格的 n——绝不允许无声地稀释单元格。

**研究问题：**
1. RQ1——归因标签能否在更换智能体执行骨干后存活？
2. RQ2——执行层归因是否比计划层归因跨骨干更一致？
3. RQ3——观测到的不稳定性中有多少可归于评审者骨干而非智能体骨干？
4. RQ4——骨干彼此一致时，它们是否也与注入真值一致？
5. RQ5——观测到的分歧中有多少由表面风格而非实质驱动？
6. RQ6——跨骨干一致性是否按模型家族结构化？
7. RQ7——删失（故障恢复）是否按骨干能力结构化？

此外，一项工具验证敏感性检验——**SC1**：编码本的平局裁决规则是否在做实质性工作，抑或残余分歧集中于骨干效应而与规则选择无关？——与主结果并排报告。SC1 于 2026-07-05 从主 RQ6 降级，因为其目标阈值溯源于讨论阶段记录而非预注册假设机制中的 H 编号（见 SC1 小节）；它不参与任何聚合投票与回退规则。

#### RQ1：归因标签能否在更换智能体执行骨干后存活？

**设置。** 试点阶段：60 任务 × 3 故障层 × 4 骨干（每个不同模型家族一个），T=0。规模化：约 900 个（任务，层）单元格 × 6–8 个骨干（交叉家族与能力档位）× 3 个种子，在 GAIA 与 WebArena 风格任务上。失败交集 ℐ 上的 Fleiss' κ；若 Ω < 0.5 则在全部失败单元格上用 Krippendorff's α；所有置信区间用 10,000 次任务级聚类自举；跨骨干与层的 Holm 校正，α = 0.05。

**预期结果。** 跨骨干一致性显著低于完美：主稳定性统计量的 95% 置信区间整体位于预注册"稳定"区间（κ 或 α ≥ 0.8）之下，落入"模型特异"（< 0.6）或"部分稳定"（0.6–0.8）范围。

**证伪条件。** 若主统计量的 95% 置信区间在所有层与家族对上整体位于 0.8 及以上，则向"稳定"方向被驳斥——这在相反方向上同样有信息量（诊断是任务性质，单骨干归因基准正在认证一种确实可迁移的东西——此前没有任何归因论文实际检验过这一断言）。

**部分区间决策规则。** 若合并统计量落在部分稳定区间（0.6–0.8）或其置信区间跨越 0.8，预注册的后果是：按层分解成为主结果，断言变为 RQ2 的层排序；此时面向从业者的决策按层而非按流水线作出——只有当某层的按层统计量位于稳定区间（≥ 0.8）时，其归因标签才被视为可跨骨干更换迁移，低于该区间的层的标签须按骨干重新验证。

**假设（通俗表述）。** 在受测范围内，LLM 智能体的失败归因并非完全骨干不变；诊断至少部分地是产生该失败的骨干模型的性质。

**指标。** 每层、每个骨干对的主稳定性统计量及其置信区间；每个数字旁并排报告失败重叠率 Ω。

#### RQ2：执行层归因是否比计划层归因跨骨干更一致？

**设置。** 与 RQ1 相同的 Stage-2 网格与拟合结构；分层的 κ（或 α）两两比较（执行 vs 计划、执行 vs 工具、工具 vs 计划），Holm 校正显著性检验。

**预期结果。** κ_exec 超出 κ_plan 至少 0.10（绝对值），Holm 校正 p < 0.05——执行层故障留下更机械可读的痕迹（例如工具调用直接报错），因此比需要更多依赖模型的解释性判断的计划层故障被更一致地归因。

**证伪条件。** 若计划—执行差距不足 0.10（绝对值）或未达显著，或排序反转（计划层归因反而比执行层更一致），则被驳斥——任一情形都会动摇"机械可读性"这一关于哪些层更容易被一致诊断的解释。

**假设（通俗表述）。** 一致性在故障层之间并不均匀；更机械可观察的失败比更依赖解释的失败被更一致地诊断。

**指标。** 分层稳定性统计量与两两对比及 Holm 校正 p 值。

#### RQ3：观测到的不稳定性中有多少可归于评审者骨干而非智能体骨干？

**设置。** 三个供应商不相交的评审者骨干 × 6–8 个智能体骨干，作用于同一 Stage-2 轨迹集（原始臂）；交叉分类混合效应模型（标签匹配 ~ (1|任务) + (1|智能体骨干) + (1|评审者骨干) + 交互）；方差份额来自似然比检验与自举置信区间；200 条轨迹的人工编码本子集锚定评审者效度（κ ≥ 0.7 门控）。

**预期结果。** 评审者骨干方差份额超过总随机效应方差的 0.20，似然比检验 p < 0.05——评审者是一个非平凡的、可独立识别的不稳定来源，而非轨迹的惰性读取器。

**证伪条件。** 若评审者骨干方差份额在统计上与零不可区分，则被驳斥——那意味着在该范围内评审者实际上可互换，RQ1 中发现的任何不稳定性纯粹是智能体行为性的，而非部分源于评判制品。

**假设（通俗表述）。** 归因不稳定性中有相当一部分来自"哪个模型在做诊断"，而不仅是"哪个模型产生了失败"。

**指标。** 评审者骨干、智能体骨干、任务与交互的方差份额及自举置信区间。

#### RQ4：骨干彼此一致时，它们是否也与注入真值一致？

**设置。** 在失败交集 ℐ 上，将联合结果 {agree-correct（一致且正确）、agree-wrong（一致但错误）、disagree（分歧）} 对照注入真值层按骨干、按层列联；agree-wrong 比例的任务聚类自举置信区间。

**预期结果。** agree-wrong 质量至少占 ℐ 的 5%，95% 置信区间下界高于 2%——相当比例的共同失败单元格显示骨干收敛到同一个*错误*的层，证明稳定性与正确性是可分离的结果。

**证伪条件。** 若 agree-wrong 质量在统计上与零不可区分（置信区间上界不高于 2%），则被驳斥——那意味着跨骨干共识本身是可靠的正确性信号，将跨骨干多数投票从健全性基线升级为归因标签的有效伪神谕（pseudo-oracle）。

**假设（通俗表述）。** 骨干彼此一致与骨干正确不是同一个断言；稳定但错误的诊断是一种真实且不可忽略的失败模式。

**指标。** 每层的 agree-correct / agree-wrong / disagree 比例；各骨干对照注入记录的准确率。

#### RQ5：观测到的分歧中有多少由表面风格而非实质驱动？

**设置。** 在原始臂轨迹集内，每条轨迹额外经一个固定改写器模型（不同于所有智能体与评审者骨干）渲染，剥除可识别模型的标记、规范化工具调用格式并对推理文本作中性释义；归一化臂由同一批评审者重新评判，并以预注册的改写器保真检验（见方法论）为门控：只有当被审计样本上注入故障的表现在改写后仍存活、且评审者在改写轨迹上的真值准确率保持在原始臂的预定容差内时，归一化臂标签才进入本估计。风格份额 =（原始臂平均两两分歧 − 归一化臂平均两两分歧）/ 原始臂平均两两分歧，配自举置信区间。

**预期结果。** 风格份额至少 10%，95% 置信区间下界大于 0——原始跨骨干分歧中可测量但部分的份额可归于表面形式，大部分分歧无法仅由风格解释。

**证伪条件。** 若风格份额的置信区间包含零或为负，则被驳斥——那意味着风格归一化并不减少分歧，RQ3 识别出的任何评审者侧效应并非简单的表面形式制品。

#### RQ6：跨骨干一致性是否按模型家族结构化？

**设置。** 将两两一致性（按 RQ1 的主统计量）在 Stage-2 骨干网格上拆分为家族内对与跨家族对；对家族划分作尊重任务级聚类的置换检验，跨域 Holm 校正。

#### RQ7：删失（故障恢复）是否按骨干能力结构化？

**设置。** 每个骨干的故障恢复率（其未在注入单元格上失败的比例）与其干净运行能力（干净运行任务成功率）在 Stage-2 骨干网格上作 Spearman's ρ 相关。

**功效说明（预注册）。** 在 K = 6–8 个骨干下，Spearman's ρ 在 α = 0.05（双侧）的精确置换显著性阈值约为 K = 6 / 7 / 8 时的 0.89 / 0.79 / 0.74——中等相关 0.5 在此 K 下按算术不可能达到 p < 0.05，因此以 0.5 为下限的"ρ 加 p"复合判据按构造即不可确认。故确认阈值定为实际 K 下的精确临界值，且 ρ 点估计及其任务级聚类自举置信区间是首要报告量。

**预期结果。** 故障恢复率与干净运行能力正相关：若 ρ 达到上述随 K 调整的精确显著性阈值则确认；ρ ∈ [0.5, 阈值) 预先声明为**提示性-INCONCLUSIVE**（连同置信区间作描述性报告，绝不宣称为已确认效应，也绝不计为驳斥）——预期更强的骨干更常从注入故障中恢复，意味着可分析的失败交集 ℐ 系统性地偏向较弱骨干的失败。

**证伪条件。** 若 ρ < 0.5（点估计低于预注册效应下限），则被驳斥——那意味着删失并非简单的能力代理，失败交集并不能仅凭骨干强度可预测地倾斜。

**假设（通俗表述）。** 可供研究的失败集合不是骨干行为的中性样本；它是能力偏斜的，这影响任何主一致性数字应如何解读。

**指标。** 各骨干故障恢复率与干净运行成功率之间的 Spearman ρ。

## 相关工作

与本文最接近的先前工作是 Who&When 工作线——Who&When、其继任基准 Who&When Pro 与 AgenTracer——在纵览更广的图景之前值得把差异说清楚：这些论文将自动失败归因形式化为决定性错误评判问题、将注入故障真值工业化到规模，并对照它验证强标注程序——但没有一个将同一任务、同一注入故障在多于一个智能体骨干下重新运行，因此没有一个能回答其标签是失败的性质还是产生被标注轨迹的骨干的性质，而这正是本文要检验的轴。

**LLM 智能体失败归因。** Who&When 形式化决定性错误归因——其纠正能把失败轨迹翻转为成功的最早智能体—步骤对——并评估多种 LLM 评审策略（all-at-once、step-by-step、先智能体后步骤的混合流水线），发布了人工标注的失败日志数据集。AgenTracer 把同一决定性错误思想变成学习问题：向成功轨迹程序化注入故障使注入步骤按构造即为决定性错误，将其与自然失败轨迹的反事实重放统一，并训练一个紧凑追踪器预测责任智能体与步骤。Who&When Pro 是与我们最接近的工具（instrument）：它通过精确重放成功前缀后注入失败，构造了 12,326 条带黄金标签的失败轨迹，横跨 3 种模态与 26 个基准，其跨模型分析记录了不同家族的归因模型标注失败时的系统性模式。我们完全让步注入式语料工具本身——规模化的前缀重放故障注入是他们的——并指出其模型家族分析是我们问题的评审者侧一半、以观察方式提出：归因模型在来自某个固定栈的*固定*轨迹上彼此不同。这条工作线中没有任何论文做的是：固定注入故障并在智能体骨干网格下重新执行它，因此智能体驱动的轨迹分化、评审者驱动的标注方差及其交互在任何观察到的差异中仍然混杂；我们的评审者×智能体因子设计正是为了分离它们而存在。更广的 2025–26 归因浪潮——因果图筛查（CHIEF）、重复重放上的谱分析（FAMAS）、干预驱动调试（DoVer）、GAIA 类域上的标注错误分类学（AgentErrorBench）、以及非注入的长视野根因基准（LongRCA Bench，与本文同期）——都是在单一固定执行栈内改进或评估归因器；DoVer 关于多个不同干预可各自独立修复同一失败的发现，从干预侧独立佐证了我们编码本平局裁决门控所要控制的层含糊性问题。纵观整条工作线，跨骨干标签稳定性既未被测量也未被声明。

**LLM 评审者可靠性。** 独立于智能体归因本身，LLM 评审者已被证明在多个轴上是不可靠的评分者：Preference Leakage（Li 等）表明评审者会沿三种具体的相关类型（同一模型、继承关系、同一家族）系统性抬高与自己相关的生成器输出的分数；BiasScope（Lai 等）表明评审者可被结构化表面扰动可靠地翻转，且这些扰动由迭代式偏差发现框架自动发现而非从固定清单手工设计。MENLO（Whitehouse 等）记录了评估者沿语言轴同样不具条件不变性，即使微调后成对 LLM 评审准确率在 47 种语言变体间仍显著波动。三者都确立了 LLM 评审者携带未经验证的依赖，但都作用于简短的成对偏好或单响应判断。最近有一个例外触及智能体轨迹：一项 Agent-as-a-Judge 研究测量了六个评审者骨干在开发者智能体运行的需求级判断上的骨干间一致性，发现其有限（Fleiss' κ ≤ 0.231），且评审者骨干与评估语言交互——这是"评审者骨干是智能体轨迹上一个活跃实验变量"的直接证据，我们对此坦率让步。但其轴是需求满足性而非失败层归因；它只变动评审者、从不变动产生轨迹的智能体骨干；且没有可据以判定对错的注入真值。没有任何先前工作在已知故障层的轨迹归因场景中分离评审者侧与智能体侧方差，这正是本文评审者×智能体因子设计要封闭的空白。值得注意的是，BiasScope 自身的设计刻意将其教师模型限制在基于推理的偏差分析上、正是为避免在自己的流水线中触发偏好泄漏——这为本文假设台账（A4）同样采用的供应商不相交评审设计提供了先例。

**骨干级比较与失败分类学。** Breaking Agent Backbones 主张智能体安全评估的正确分析单元是单次骨干 LLM 调用而非整个智能体，并在相同攻击场景上比较众多骨干 LLM——确立了骨干级比较作为一条正当的评估轴，但仅限攻击敏感性得分，且其快照抽象刻意剥离了恰恰使失败层诊断变得含糊的多步传播。多智能体系统失败分类学（MAST）从主流多智能体框架的专家标注轨迹中归纳出失败分类学，并通过阅读*同一批*轨迹的人类与 LLM 标注者之间的标注者间一致性加以验证——可靠性是跨标注者建立的，不是跨骨干建立的，因此同一任务在不同骨干下重跑是否会被赋予相同失败类别未经检验；其分类学在本文中仅作为我们自己编码本的工具复用，而非作为记分板基线。

## 结论

本工作将悄然内建于每个 LLM 智能体自动失败归因工具中的一个假设——计划/工具/执行标签描述的是失败，而非恰好产生并评判它的骨干模型——重新表述为一个可测量、可证伪的问题，而非一个默认信任项。核心的方法论押注是：这个问题无法用单一一致性数字回答——删失、评审者身份、表面风格与编码本惯例必须各自被单独核算之后，残余不稳定性才能被归于真正的骨干行为分化，而本设计正是让每一个来源都被估计而非被假设掉。无论主发现落向哪边，它都与决策相关：若归因大体稳定，单骨干归因基准正在认证一种确实可迁移的东西，而该认证本身是新的；若归因是模型特异的，则建立在一个骨干上的诊断工具在骨干更换时需要重新验证，且这种不稳定性的结构（家族模式化或各自特有）决定重新验证能否摊销或必须逐骨干重复。四项局限从一开始就为该断言划界。其一，计划/工具/执行编码本是对失败可能真正跨类别的空间的规定性划分，虽然平局裁决敏感性检验会报告该惯例的影响大小，但它无法消解底层含糊性——更丰富的、可能是分级的失败分类学是自然的下一个方法论目标。其二，本设计的适用范围是可沙盒化基准上程序注入的单层故障；同样的稳定性（或不稳定性）模式是否适用于生产部署中有机产生的多因失败，仅由 Who&When 补充检验部分回应，其余仍然开放。其三，试点阶段刻意将故障载荷迭代至按设计不可恢复的致命度以确保失败重叠，这使受研究的故障总体偏向最大致命度故障，相对有机失败收窄了效度包络；载荷在主网格运行前冻结，故该偏移是预注册的而非依赖数据的，但 Who&When 补充只能部分抵消它。其四，所有数字都在一个固定的 ReAct 式智能体脚手架下产生，因此所有发现的适用范围限于该脚手架——归因不稳定性本身是否脚手架特异，留作开放问题。
