## 1. Introduction

Automated failure attribution for LLM agents — reading a failed trajectory and naming
whether the plan, a tool, or the execution layer is to blame — has become the control
layer of the agent stack. Manual attribution is prohibitively expensive and inconsistent
[Who&When], so the verdict is now produced by machines — LLM judges that read the log,
trained tracers that predict the decisive error [AgenTracer], and runtime monitors that
flag high-risk interactions online [SupervisorAgent] — and it is industrialized to drive
real interventions: retraining planners, patching tools, and curating training data. Each
diagnosis implies a different fix, so the *correctness* of the verdict, not merely its
availability, determines whether the repair lands on the component that was actually
broken. A wrong verdict does not just mislead a developer; it misspends the fix.

That correctness is now known to be at risk from one direction and untested from another.
A recent line of work establishes that *agents themselves* over-trust corrupted tool
output: TOOLMAZE reports recovery rates collapsing under implicit, semantically corrupted
returns that pass every surface check, and ToolGate finds that a wrong tool output can
overwrite an agent's already-correct belief. This settles that a **schema-valid lie** —
a tool return that is syntactically valid, parses cleanly, and passes every schema check,
but is simply the wrong number, the wrong entity, or a stale reading — can steer an agent
off course. It leaves open the question one level up, which is the question we ask: when
such a lie causes a failure, does the **diagnostic layer built to catch faults** inherit
the same lie and misroute the repair? Every attribution method proposed so far reads the
trajectory log as trustworthy evidence of what happened, and none contains a step that
asks whether the log's own tool observations might themselves be wrong. If the attribution
layer over-trusts the trace the way the agent did, the very tool that broke escapes blame,
an innocent plan or execution layer is retrained in its place, and the fix cements the
wrong lesson while the real defect recurs.

There is a principled reason to expect exactly this failure, inherent to the attribution
problem rather than to any one method, and we state it as an asymmetry rather than a gap
between literatures. Any method that localizes fault from a trajectory faces an
**evidential circularity**: the evidence it reasons over is generated by the component
whose guilt it is trying to establish — the trace is at once the crime scene and the only
witness, and when the witness lies, a diagnosis that trusts it blames the wrong suspect.
Structurally, **every check an attribution pipeline can run certifies the *form* of a tool
observation; the diagnosis then consumes its *content* as an unquestioned premise.**
Schema validation, parser acceptance, exception flags, and monitor triggers all inspect
grammar; none inspects truth. So when a schema-valid lie feeds a locally reasonable plan
step, the plan step *looks* defective on its face — separating "the plan was genuinely
broken" from "the plan was a sound response to false evidence" requires a counterfactual
(what would this step have looked like under the correct observation?) that no deployed
attribution method has access to. In long-horizon agents the difficulty compounds: a
single early corruption contaminates many later decisions, making downstream behavior
look progressively less rational while the original tool fault becomes ever harder to
see. This asymmetry is a property of the evidence channel itself; it would hold even if
prior work had already studied corrupted tool outputs, because it concerns what
trace-reading diagnosis structurally must do when its input is a well-formed falsehood.

The asymmetry yields two testable predictions that no prior work has measured. First, a
*rate* prediction: attribution methods should misattribute tool-caused failures away from
the tool layer **specifically when the corruption is schema-valid** — measurably more
often than when the same tool fault is overt (an exception, timeout, or empty return the
framework surfaces as a visible error). We call this per-method difference the
**Δ-trust gap** — the misattribution rate on silent semantic corruptions minus the rate
on matched overt errors. It is the unit of evidence in this paper: not "attribution is
imperfect" (it always is), but "attribution degrades *because the evidence is
well-formed*." Second, a *direction* prediction: when misattribution occurs, blame should
skew toward the **plan layer**, because plan critique sits immediately downstream of
reading the observation, while execution verdicts key on mechanical success/failure
signals that a schema-valid corruption deliberately never trips.

The nearest existing work approaches this from adjacent angles, but none measures whether
attribution correctly localizes a well-formed lie. On the attribution side, Who&When
formalizes the task as identifying the step whose correction flips a failed trajectory to
success, and a fast-growing benchmark line — TraceElephant on full-trace observability,
AgentRx and AgentHallu on step-level fault and hallucination attribution — extends it,
but all exercise their definitions on naturally occurring agent mistakes, never on a
corrupted-yet-well-formed observation whose ground truth is the tool. Causal Agent Replay
shares our counterfactual machinery but uses replay *as the attribution method* over
ordinary trajectories, not as an oracle for constructing verified corruption ground
truth. AgenTracer trains a tracer with replay and programmatic fault injection, but its
fault universe is agent *actions*, not tool *returns* — so a tracer supervised on it has,
by construction, never seen a trajectory whose decisive error is a lying observation. On
the tool-reliability side, Failing Tools and TOOLMAZE inject silent no-ops, staleness,
and corrupted state and measure whether the *agent recovers* — not whether any downstream
diagnosis localizes the fault. Security work on the tool channel (ChatInject,
MCP-SafetyBench) measures whether an instruction-bearing payload *succeeds as an attack*,
a different threat model from a plainly wrong value in an ordinary field. And runtime
supervisors trigger on explicit errors, repetition, or excessive observation length
[SupervisorAgent] — exactly the signals a schema-valid corruption is engineered not to
emit. Prior work has separately established that agents over-trust corrupted tools, that
attribution can localize agent mistakes, and that counterfactual replay can attribute
failures; no prior work joins them to measure whether attribution methods correctly
localize failures caused by schema-valid but semantically false tool observations. That
is the gap we occupy — and the claim survives even if someone has crossed these
literatures descriptively, because the object is the structural asymmetry, not
unoccupied territory.

The obstacle to measuring either prediction is that the ground truth does not exist in
nature: given only a naturally failed trajectory, a reasonable plan built on a bad
observation is causally indistinguishable from a bad plan built on a good one. **Our
enabling contribution is an instrument that manufactures this ground truth forward rather
than annotating it backward**, and its soundness rests on certifying two properties that
a naive injection would conflate. *First*, a corrupted observation must be provably
**invisible** — indistinguishable from a valid return by every surface check a method
could run — or the study only measures whether methods bother to validate input. We
enforce invisibility with three independent legality gates: schema re-validation, parser
acceptance, and a contextual-plausibility screen run by a model disjoint from every judge
and agent backbone. *Second*, and orthogonally, it must be provably **decisive** —
verifiably the cause of the failure, not merely correlated with it. We establish
decisiveness with a counterfactual twin-replay oracle: starting from a reproducibly
successful run, we inject exactly one schema-valid lie into a single tool observation
(numeric, entity, boolean, structural, and stale-value mutation families) and keep the
trajectory only if the corrupted run fails the task's programmatic checker *while its
identical twin with the original observation restored succeeds*, with a sham
identity-mutation control that must not shift attribution. Holding invisibility and
decisiveness apart — one certified by the legality gates, the other by twin replay — is
what makes any measured misattribution a property of the *method* rather than an artifact
of the *construction*. The standard is deliberately in the lineage of forward-injected,
test-certified defect suites from software engineering: Defects4J is trusted as ground
truth for automated program repair because a deterministic test certifies each defect,
not because a human annotated it after the fact. We bring that certification standard to
the agent observation channel.

On this verified testbed we run existing LLM-judge, trained-tracer, and runtime-monitor
attribution methods, **unmodified and blinded** to injection metadata, against two matched
controls: an *overt-tool-error* arm sharing the tool-layer root cause but emitting a
visible signal, and an *agent-side-fault* arm injecting the identical wrong value into the
agent's own action rather than the tool's return. Because an overt error typically
truncates a trajectory at the fault step while a silent corruption lets the agent run on,
we treat fault-to-manifestation distance as a named confound, report the Δ-trust gap
stratified by post-fault suffix length, and rest the channel-specificity claim on the
agent-side-fault contrast, which carries the identical wrong value at a different causal
locus and is immune to it. Because methods report verdicts in incompatible native
vocabularies, we fix a per-method mapping onto the shared {plan, tool, execution}
ontology before any result is seen and report its inter-annotator reliability as a
precondition for trusting any downstream number.

With this instrument we answer the paper's core question — *do existing attribution
methods systematically misattribute schema-valid tool corruptions, in which direction,
and why?* — and report three findings, each with a control that pre-empts its most
deflationary reading.

**(1) A systematic Δ-trust gap (H1).** [XX of M] attribution methods misattribute
schema-valid semantic corruptions **[+XX] percentage points** more than matched overt
errors (Holm-corrected *p* < .05), with the gap surviving suffix-length stratification
and the agent-side-fault arm staying within **[X]** points of the overt control — so the
inflation is specific to the tool-observation channel, not generic subtlety or trajectory
length. The gap is not symptom-reading: a trivial surface-heuristic attributor (blame the
layer nearest the visible error signal) recovers only **[XX]%** of certified tool-layer
labels and explains at most **[XX] pp** of any method's gap.

**(2) A directional skew toward the plan layer (H2).** Among misattributed cases, blame
lands on the plan layer **[YY]%** of the time — exceeding the plan base-rate on matched
controls by **[+XX] pp** (exact binomial against the control base-rate, not an assumed
even split) — confirming that silent corruption does not merely add noise but *channels*
blame to the component immediately downstream of the corrupted read, strengthening for
subtle, late-trajectory, numeric and stale-value corruptions (exploratory grid, H2b).

**(3) The mechanism is partly a removable trust default (H3).** A one-sentence
*trust-license* prompt — licensing each judge to distrust tool observations it already
had access to — reduces tool-corruption misattribution by **[ZZ] pp** for **[k of 3]**
judges (paired McNemar *p* < .05) while inflating false tool-blame on genuine plan
failures by only **[AA] pp** (non-inferiority bound ≤ [3] pp). A majority of the gap
remains — knowing that observations may lie does not tell a method *which* observation
lies — locating the residual in counterfactual reasoning rather than a missing
permission.

We stress what this paper is and is not. It is a measurement study: we propose no new
attribution method and claim no solution to the blind spot. Every hypothesis, estimand,
threshold, and fallback is pre-registered before data. If the Δ-trust gap is
indistinguishable from zero for a majority of methods, the attribution layer is
empirically *robust* to lying evidence and we release the suite as the certification of
that robustness; if the trust license fails to move misattribution, the blind spot is a
deeper counterfactual-reasoning deficit and cheap prompt fixes are ruled out. The finding
is designed to be informative in either direction.

- **C2 — The Δ-trust gap: the first measurement that the diagnostic layer inherits the

## 2. Motivation

**Why the target matters: attribution is a controller, and a biased controller misroutes
every fix it triggers.** A failure attribution system exists to answer one practical
engineering question: *what should we fix?* If the planner chose an impossible route, it
needs better decomposition or training data; if execution skipped a required step, the
controller needs stronger state tracking; if a tool returned wrong information, the fix
is different again — validate the tool, patch the wrapper, add a cross-check. Attribution
is being industrialized precisely because it is load-bearing for this routing [Who&When;
AgenTracer]. That makes it a *controller*: its output selects the intervention. A
controller with a systematic bias is worse than a noisy one — noise averages out, but a
bias that chronically relabels tool-caused failures as plan failures aims every
downstream fix at the wrong component. The planner gets retrained for a mistake it did
not make; the tool that lied stays unmonitored; and each misrouted fix appears to
"resolve" a case whose true cause is untouched, so the corrective loop silently optimizes
the wrong part of the system.

**Why the cases are indistinguishable in the trace.** Suppose an agent books the wrong
flight because the travel tool returned a valid JSON response carrying the wrong fare.
The downstream plan now looks irrational — it selected a flight that does not match the
request — and a judge reading the trace blames the planner. But from the agent's local
perspective the plan was the correct response to the evidence it was handed; the fault
lies upstream, in an observation that read `412.00` when the truth was `1,412.00`. Every
value on the trace is well-formed; the only visible anomaly is the plan's choice, so the
plan takes the blame, and a team retrains a planner that was never broken while the
stale-reading defect recurs on the next task. This is not a contrived edge case. Silent
value corruption — stale caches, unit mismatches, truncated lists, off-by-one entity
resolution — is the ordinary failure mode of real tool ecosystems: the security line
shows the tool-return channel is an actively exploited attack surface [ChatInject;
MCP-SafetyBench], and the robustness line shows tools are unreliable even with no
adversary [ResiliBench; Failing Tools]. Both score attack success or task completion
under stress; neither asks whether post-hoc diagnosis localizes the corrupted return as
root cause. The fault mode lands in the blind spot *between* what the security
literature measures and what the attribution literature assumes.

**Why existing methods are structurally, not incidentally, exposed.** The exposure
follows from how each class of method is built. LLM judges read the trajectory as
testimony; when the testimony is well-formed they have no signal that distinguishes a lie
from the truth, so they inherit the corruption into their own premises. Trained tracers
learn from fault distributions over perturbed *agent actions* [AgenTracer]; a lying
*observation* is outside their training support by construction. Runtime monitors trigger
on overt signals — explicit errors, repetition, excessive observation length
[SupervisorAgent] — precisely what a schema-valid corruption never emits. Three design
philosophies, one shared premise, one shared blind spot: the trajectory's grammar is
checkable, its truth is not. Being fooled at *run time* and at *diagnosis time* are
different failures with different consequences: an agent fooled once produces one bad
trajectory; an attribution layer fooled systematically produces a bias that feeds
automated repair loops — and it does so silently, because its verdicts remain well-formed
too.

**Why measuring it is hard, and what makes it possible now.** To score a verdict you must
know the true responsible layer; but for a schema-valid corruption the trajectory offers
no surface marker, the diagnosis consumes the corrupted evidence circularly, and
separating "reasonable plan given bad input" from "bad plan given good input" demands a
counterfactual the trace does not hold. Our instrument gives the *experimenter* — not the
methods under test — that counterfactual: the uncorrupted twin. The move is to stop
annotating blame backward from natural failures and manufacture it forward from
known-good runs, so the causal source is fixed by construction. Replay verification
converts an unobservable ("was the tool the decisive cause?") into a binary check ("does
restoring the original observation flip the outcome?") — the certification standard that
lets Defects4J serve as trusted ground truth for program repair, transplanted to the
agent observation channel. The measurement was never impossible in principle; it was
missing an instrument. That instrument is what makes the core question — *does the
evidence channel's trust asymmetry bias real attribution methods, and can it be cheaply
repaired?* — answerable now. The insight the study turns into a measurable question is
simple to state: **the trace is not always the truth; in tool-using agents, the trace may
contain the very fault that attribution is meant to diagnose.**

## Scope-guard (retained from B2.1)

Forward-injection labeling is restricted to the **observation slot only** — plan/tool-binding
injection is kept as a *control* (the agent-side-fault arm), not promoted to a co-equal
arm, because the contribution is the evidential-circularity asymmetry unique to the
observation channel. Expanding to a general three-slot "certified attribution benchmark"
would flatten that asymmetry into a resource paper and collide with sibling projects
B2.2/B2.3/B2.4. Archetype stays empirical/measurement.

## Anticipated reviewer attacks (merged, defensive)

1. **"TOOLMAZE/ToolGate already showed over-trust in corrupted tool output."** — They
   show the *agent* is fooled at run time; we measure whether the *attribution layer* is
   fooled at diagnosis time and where it redirects blame. Different subject, different
   consequence. (Pre-empted in ¶2.)
2. **"This is TraceElephant/AgenTracer/Causal Agent Replay with a different injection
   target."** — Replay machinery is shared and conceded; the delta is (a) schema-valid
   semantic corruption of a *tool observation* rather than an agent action, (b) the
   decisiveness ⊥ undetectability separation used to *construct* ground truth rather
   than assign blame, and (c) the direction-of-blame estimand their designs cannot make
   identifiable.
3. **"The plan-skew is just the corpus base rate."** — C3 is scored against the plan
   base-rate on matched controls; the always-predict-plan floor (B0) is required in
   every table.
4. **"The misattribution is symptom-reading, not a trust asymmetry."** — The
   surface-heuristic control caps how much of the gap symptom-reading can explain; the
   trust-license intervention plus agent-side-fault control jointly localize the cause.
5. **"If Δ-trust collapses within suffix-length strata, the headline is an artifact."**
   — Conceded up front; channel-specificity rests on the agent-side-fault arm, immune to
   the confound.
6. **Decay risk.** — ≥5 neighbors published in the last ~4 months. The delta is real
   today; at this velocity its half-life is short. Target the nearest deadline.
