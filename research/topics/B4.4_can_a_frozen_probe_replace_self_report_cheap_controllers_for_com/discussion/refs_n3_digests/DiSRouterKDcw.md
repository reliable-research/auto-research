## N2 Motivation (verbatim from proposal.motivation)

Large-model routing is fundamentally a utility optimization problem: for each query, the system should select the cheapest model that can still answer reliably. Prior work has shown that this objective is practically important. @chen2023frugalgpt demonstrated that multi-model cascades can recover much of the accuracy of expensive LLMs at far lower cost, while @ong2024routellm formalized routing as learning a query-dependent choice between weaker and stronger models. However, these approaches rely on a centralized external router that predicts difficulty or model performance before execution. This creates a mismatch between the decision-maker and the model being evaluated: the router must infer another model's competence boundary indirectly from training data.

That mismatch exposes two concrete limitations. First, centralized routers are structurally inflexible. Even when more sophisticated, as in @feng2024graphrouter, the routing mechanism remains a separate component whose behavior depends on the current model pool and routing objective, making adaptation to added, removed, or updated models cumbersome. Second, external routers may be intrinsically worse judges of model capability than the models themselves. @aggarwal2024automix suggests this by showing that self-verification signals from the serving model can guide escalation effectively, and @yin2023selfknowledge indicates that LLMs possess measurable awareness of their own limitations. At the same time, @xu2024selfawareness shows that refusal behavior can be trained explicitly, which opens the possibility of converting uncertainty into a reliable action rather than a post hoc score.

These observations define the core opportunity: instead of training a separate router to predict whether a model can answer, we can train each model to decide this for itself. This would eliminate the external-router bottleneck and turn routing into a distributed policy composed of local answer-or-forward decisions. The decentralization motivation is consistent with @yang2025agentnet, but the key unresolved question is how to realize decentralized routing without introducing another dedicated routing module per agent. Our problem is therefore to design a modular routing framework in which each LLM acts as both solver and router, using self-assessment to determine whether to answer or delegate under different cost-performance preferences.

## N6 Methodology (verbatim from proposal.method)

We propose a distributed self-routing framework in which each LLM agent directly evaluates whether a query falls within its own competence boundary. Rather than using a centralized router to predict model utility, we organize models in a cost-ordered cascade and let each agent choose between answering and rejecting; rejection deterministically forwards the query to the next stronger model. This formulation addresses the central gap because the routing decision is made by the model whose ability is being assessed, while preserving the low-cost cascade structure motivated by @chen2023frugalgpt.

1. **Distributed Cascade Routing Policy**: We instantiate routing as a sequence of local decisions over an ordered pool of models, where each agent either answers the query itself or forwards it to the next higher-cost agent. This preserves the cost-efficient cascade intuition of @chen2023frugalgpt but removes the centralized predictor used in @ong2024routellm and @feng2024graphrouter. The component is needed to make the overall policy modular: adding or removing an agent does not require retraining a global router.

2. **Self-Awareness via Rejection-Based Supervision**: We train each model to map a query to either a normal answer or an explicit refusal such as "I don't know," using the model's own empirical success frequency on repeated reasoning trials to label answerable versus unanswerable cases. This extends the refusal-alignment idea of @xu2024selfawareness from safety refusal to competence-aware refusal, and operationalizes the self-knowledge hypothesis suggested by @yin2023selfknowledge. The component is needed because intrinsic self-awareness is present but not sufficiently calibrated in open models for routing-quality decisions.

3. **Scenario-Conditioned Reward Alignment**: After supervised training, we further optimize each agent with reinforcement learning using a localized reward: correct answer receives positive reward, incorrect answer receives zero, and rejection receives a scenario-dependent value controlled by a preference factor over cost versus performance. This is needed to make local answer/reject behavior align with global utility under different deployment settings, and it extends the escalation intuition in @aggarwal2024automix by replacing fixed or externally managed thresholds with directly trained, scenario-aware policies. The reward is localized so each agent can be trained independently without joint system optimization.

4. **Instruction-Based Preference Adaptation**: We expose the cost-performance preference to each agent through prompt-level scenario instructions, enabling a single trained system to behave conservatively in performance-first settings and more aggressively in cost-first settings. This addresses a limitation of scenario-specific centralized routers such as @feng2024graphrouter, which typically require separate optimization for different trade-offs. The component is needed so that distributed local policies can synchronize around the same system objective without explicit inter-agent communication.

Together, these components form a coherent system: supervised refusal teaches each model to recognize its boundary, reinforcement learning calibrates that boundary against utility, and the cascade turns local refusals into global routing decisions. The result is a plug-and-play distributed router whose control logic is embedded inside the participating LLMs rather than imposed by an external selector.
