# 合规的代价：测量设计感知编码智能体的效用—约束前沿

## 摘要（Abstract）

将生产代码委托给 LLM 编码智能体（coding agent）的组织，越来越希望这些智能体在功能正确性之外还遵守设计层面的约束——架构分层（architectural layering）、依赖方向（dependency direction）、复杂度上限。我们指出这并非可以先验假定为免费的：设计合规与功能正确性由同一个有界的生成过程产出，因此强制执行约束不可能以固定汇率兑换效用，而一个只测量平均每约束成本的团队，无法区分一条平缓退化的前沿与一条恰好在其试点范围之外隐藏拐点（knee）的前沿。我们构建一个经 κ 审计（κ-audited）、约束力筛查（bindingness-screened）的机器可检设计规则目录，以广度（breadth）与严格度（strictness）参数化，并在可执行编码基准上于仅提示（prompt-only）、检查器在环重试（checker-in-the-loop retry）与二元全开（binary all-on）三种执行方式下扫描，在每个强度级别记录通过率、残余违规率与生成成本。一个双重统计判据分别独立检验通过率曲线与成本曲线是否存在可检测的拐点，并将两者的不一致作为一种独特的、信息量丰富的结果予以报告，而非以武断方式消解；一个交互模型将测得成本分解为机制归因（mechanism-attributable）与约束归因（constraint-attributable）两部分；一个 token 数匹配的安慰剂对照（placebo control）将真正的约束内容效应与"提示中指令变多"这一混淆因素隔离开。由此得到的前沿，把"设计感知编码智能体在工程上是否可行"从一场赌博变成一次测量。

## 引言（Introduction）

在 LLM 编码智能体中，设计合规与功能正确性并不是两个独立的旋钮——它们是同一个有界生成过程的两个输出，共享同一份提示预算、同一批采样尝试，以及单元测试通过所依赖的同一份解空间余量。当团队决定对编码智能体强制执行架构规则时，这一点很容易被遗忘：添加一条分层契约、一条复杂度上限或一份禁用 API 清单，看上去就像在一个已经能工作的系统上拴一个便宜的检查器，正如 linter 拴在人类开发者的工作流上一样。这种直觉恰恰说明它值得被测量而不是被假定。

然而，关于这一实践的核心问题仍未被测量——而如今悬而未决的部分已不再是"约束是否可能干扰任务求解"本身。近期工作已表明，即使插入不言自明（self-evident）的指令约束，也会可测地压低任务表现，包括在代码生成上（arXiv:2601.22047）；仍未被测量的是这一代价的*价目表（schedule）*：设计合规是否真的便宜，其价格是否随着规则数量增加或严格度提高而以可预测的、近线性的速率扩展。一个只测量其恰好试点过的范围内平均成本的团队，无法区分一条平缓退化的前沿与一条在该范围之外隐藏拐点的前沿——两者在试点区间内可以呈现完全相同的平均斜率，却在区间之外蕴含截然相反的部署决策。平缓的前沿意味着成本随规则累积而可预测地扩展；拐点则意味着在上一个试点级别看起来便宜的规则，到下一个级别会变得不成比例地昂贵。从平均值线性外推、而不是直接检验曲线形状，恰恰是会让"设计感知编码智能体负担得起"这一断言在真实部署越过试点强度的那一刻悄然失效的错误。

与该问题最接近的已发表工作研究的是单一的、语义中性的约束维度：移除代码格式化要求可大幅削减输入 token 而通过率几乎不变，这表明并非所有约束都昂贵——但它留下了一个悬而未决的问题：同样的结论是否适用于那些真正可能与正确解冲突的约束，例如架构分层或依赖方向，而非纯粹装饰性的约束。

其他几条相邻研究线也各因不同的原因而未能覆盖这一特定的联合测量。指令遵循基准（instruction-following benchmarks）记录了随着约束不断累积、自然语言约束的满足率显著退化，而建立在此类基准之上的训练流水线则优化同时满足多条约束——其中通用指令一系测量满足率时没有独立的功能正确性判定器（functional-correctness oracle），而较新的代码特定一系虽然确实联合评分约束遵循与可执行正确性，但两系都没有把约束强度参数化为一条可扫描的轴，生成成本在两系中也从未作为评估轴出现。对齐（alignment）文献将训练期安全目标的类似现象命名为一种"税"（alignment tax），解码期多目标方法则在各目标奖励模型已存在的前提下刻画帕累托（Pareto）权衡——但两者都没有为编码智能体参数化约束强度，也没有测量平缓的权衡在何处变成悬崖。一个基于序贯蒙特卡洛（sequential Monte Carlo）的推理期约束机制表明执行本身就可能在计算上昂贵（用其自己的话说，"既非 token 局部的、也不便宜"）——这提醒我们：任何测得的合规代价都有可能是执行机制的属性而非约束本身的属性，除非把两者刻意拆开。

把这一空白变成可测量的问题，本身会浮现出一系列困难。设计意图通常以定性方式陈述——"保持层间解耦"——把它转换为确定性的、可扫描的规则目录，有可能让目录悄悄偏离它本应代表的意图，尤其是为了可检查性而选择的规则往往过度代表机械性约束（命名、复杂度阈值），而牺牲那些抗拒确定性检查的更微妙的架构约束。约束强度本身不是一维的：激活多少条规则与每条规则执行得多严格，是逻辑上独立的两条轴，单一的序数阶梯（ordinal ladder）会把它们混为一谈，因此在这种阶梯上发现的拐点可能是任一轴上的拐点，或两者某种未定义的混合。由于执行（尤其是基于重试的执行）可能触发同时压低通过率、推高成本的重试循环，所得曲线的形状不能被先验假定，必须以足够的扫描分辨率检验，才能探测到真正的断点（breakpoint）而不是从噪声中制造或漏掉一个。在单一执行机制下测得的成本与该机制自身的开销纠缠在一起，因此单臂前沿有描述工具实现选择、而非约束本身的风险。并且，由于每个把激活规则渲染为提示文本的执行臂都必然随强度增长而加长提示，任何观察到的行为变化都与"指令更多了"这一事实本身纠缠，独立于这些指令说了什么——这一混淆在"记忆"是固定参数模型、而非提示里能塞进多少文本的设定中没有对应物。

我们的方法把上述每个障碍都转化为一个具体的设计选择。机器可检的规则目录对照独立的人类判断进行审计，并筛查无约束生成是否根本接近违反它，从而把一个本不可验证的忠实性问题转化为可验证的评分者间一致性（inter-rater agreement）问题。强度沿广度与严格度两条独立、因子交叉（factorially crossed）的轴扫描，而非一条混淆的阶梯，使退化可以归因到正确的轴上。一个双重统计判据——要求两个独立的曲线形状检验一致才宣告拐点——分别应用于通过率曲线与成本曲线，使两者之间的一致或不一致本身成为被报告的、有信息量的结果，而非方法中内置的假定。完全相同的约束内容在机制上不同的执行臂下运行，并做分项成本记录，使可归因于执行机制的成本能与可归因于被执行约束的成本分离。最后，一个 token 数匹配但语义惰性的安慰剂条件，把由约束内容驱动的行为变化与仅由提示长度驱动的变化隔离开。

我们在函数级与仓库级两个尺度的可执行真实编码基准上评估该设计，将受约束条件与无约束对照、朴素的全有全无执行策略以及长度匹配安慰剂进行比较，覆盖多个模型与多种执行机制。

总结起来，我们的贡献是：
- 对编码智能体设计约束治理底层不对称性的识别与形式化：合规与正确性取用同一个有界生成过程，因此合规的代价是一个需要测量的形状，而非一个可以假定的平均值；平缓前沿与拐点前沿在被直接检验之前可以看起来一模一样。
- 一个经 κ 审计、约束力筛查的规则目录，以及一个因子式的广度×严格度强度参数化，把单一序数阶梯会混为一谈的两种逻辑上不同的退化来源分离开。
- 一个分别独立应用于通过率曲线与成本曲线的双判据形状检验，把跨轴不一致作为一等的、有信息量的结果报告而非以任意平局规则消解，并配以机制—约束成本分解和以安慰剂对照把约束内容效应与一般指令负载效应隔离的手段。
- 一份关于当前 LLM 编码智能体的合规—效用前沿是平缓还是拐点形状的实证刻画，以及该形状对部署设计感知编码智能体的工程可行性意味着什么。

通篇而言，测得的形状裁决是本文的首要框架；经审计的规则目录、扫描工具链与带约束标注的任务套件是次要的、可单独发布的资源贡献——并且只有在核心形状假设全部失败的情况下才是预先承诺的后备标题——因此读者永远不必猜测本文站在两种框架中的哪一种上。

## 问题定义（Problem Definition）

**形式化设定。** 考虑任务集 T，划分为函数级任务 T_f（每个带有可执行单元测试判定器）与仓库级任务 T_r（每个带有针对真实仓库的 fail-to-pass 测试）。给定设计规则目录 R = {r_1, ..., r_K}，每条 r 是对候选解 y 的静态分析之上的确定性判定程序。约束强度是一个二元组 σ = (b, s)——广度 b（激活多少个规则包）与严格度 s（每条激活规则的阈值档位）——它决定激活规则集 R(σ) ⊆ R。一次生成尝试由（任务, σ, 执行臂 a, 模型 m, 样本）索引，其中 a ∈ {仅提示, 检查器在环重试, 二元全开}。每次尝试产生来自该任务可执行判定器的 pass(y, task) ∈ {0, 1}、违规计数 V(y, σ) = |{r ∈ R(σ) : r(y) = 违规}| / |R(σ)|，以及记录在案的生成成本 c(attempt)（输入/输出 token、重试次数、墙钟时间、美元）。研究对象是：对每个（模型, 执行臂），pass(·) 与 cost(·) 各自如何随 σ 变化，以及这两条关系各自是平缓的（可由单一光滑趋势良好近似）还是包含一个统计上可检测的拐点——即某个强度区域，越过它之后趋势陡然改变。

**为什么困难。** 一个可以被扫描的规则目录必须是确定性且机器可检的，但没有任何东西保证这样的目录忠实代表它意在形式化的设计意图——一个只对照自身检查器输出审计的目录，测量的是与检查器的一致性，而非与设计意图的一致性。强度参数 σ 天然是二维的，把广度与严格度压缩成单一序数位置会混淆两种可能不同的退化来源。由于执行（尤其是基于重试的执行）可能同时压低 pass(·)、推高 cost(·)，两条曲线的形状都不能事先假定，而且即使两者都测得很好，也不保证彼此形状一致。测得的成本与执行臂 a 的选择混淆，因为同一规则集在不同执行方式下产生不同的成本剖面。并且，由于每个把 R(σ) 渲染为提示文本的执行臂都随 σ 增大而加长提示，pass(·) 或 cost(·) 的任何变化都与提示长度本身纠缠，独立于 R(σ) 的内容——这一混淆在"记忆"不是上下文窗口中的文本、而是固定参数模型的设定中没有类似物。

## 方法概览（Method Overview）

在概念层面，本研究是一条由六个协作部件组成的单一测量流水线。规则目录与强度参数化进入流水线；忠实性与约束力审计把目录变成可信赖的测量仪器；任务级统计模型把逐次尝试的原始结果变成能在通常的 LLM 采样噪声下存活的条件级趋势；双判据形状检验把该趋势变成通过率曲线与成本曲线各自的"平缓或拐点"裁决；因子式强度设计把退化归因于广度或严格度；跨臂成本模型把成本归因于执行机制或约束内容；安慰剂对照比较把行为变化归因于约束内容或提示长度。

**目录忠实性与约束力审计**接收初始规则目录，返回其检查器裁决与独立人类判断的一致性高于预注册阈值、且被证明在所研究任务上确实起约束作用的规则子集，未通过任一检验的规则被剔除或替换。**任务级趋势模型**接收每个条件下大量采样尝试的原始通过/失败与成本结果，把真正的强度驱动效应与普通的任务间、样本间噪声分离，并在任何规模化投入之前先运行功效检验（power check）。**双判据形状检验**接收所得的条件级通过率与成本趋势，分别独立地把每条曲线归类为平缓或拐点形状，并显式报告两条曲线的一致或不一致。**因子式强度设计**规定广度与严格度如何独立变化，使两者对退化的各自贡献可以被直接读出而非混为一谈。**跨臂成本分解**接收在机制不同的执行臂下运行的完全相同的约束内容，把测得成本归因于执行机制或约束本身。**长度匹配安慰剂对照**把激活规则集重新渲染为 token 数匹配但语义惰性的文本，隔离观察到的行为是跟随约束内容还是仅仅跟随提示长度。

## 方法论（Methodology）

### 目录忠实性与约束力审计（Catalog Fidelity and Bindingness Audit）

**挑战。** 设计意图通常是定性的（"保持层间解耦"），把它转换为确定性、可扫描的规则目录，有目录悄悄偏离其声称形式化的意图的风险——除了人类判断之外没有可对照的真值，而检查器的存在恰恰是为了替代人类判断。

**洞察。** 忠实性无法在解析层面证明，但可以在经验层面加以约束：要求规则的检查器裁决与独立人类判断的一致性高于预注册阈值，把一个本不可验证的问题转化为可验证的评分者间一致性问题；一个独立的约束力筛查则捕捉那些名义上激活、但无约束生成从不接近违反的规则。

**方法。** 一个约二十条确定性静态分析规则的初始目录——导入分层与依赖方向契约、复杂度与长度上限、命名与可见性约定、禁用 API 清单、依赖注入（dependency injection）强制——由两名人类标注者对每个被标记实例进行"真实设计违规 vs. 检查器伪影"标注；标注采用按规则分层的样本，并预先规定每条规则至少二十个被标记实例的配额（不足则追加无约束生成直至达到配额——若把固定的 100 样本池摊到约 20 条规则上，每条规则只剩约五个实例，远不足以让任何按规则的一致性估计支撑一个剔除决定）；任何对照人类判断的 Cohen's κ 低于 0.8 的规则被从目录中剔除。另外，任何在无约束（无激活规则）生成中违规率低于 5% 的规则被视为不起约束作用并在约束强度扫描开始前替换，以免名义上"激活"但实际上惰性的规则人为压平测得的前沿。

### 任务级趋势模型（Task-Level Trend Model）

**挑战。** 单次尝试的通过/失败结果本身噪声过大，无法把变化归因于约束强度而非普通的 LLM 采样变异——而且在不检查设计是否有足够功效探测趋势的情况下报告趋势，有把功效不足的零结果误当作"合规是免费的"这一真实发现的风险。

**洞察。** 显式建模任务级方差、并在每个条件下独立采样足够多的尝试，才能让真正的强度驱动趋势在个别任务与样本的噪声行为中存活——并且在投入更大规模扫描之前（而非只在其后）运行功效检验，可以防止功效不足的试点伪装成真实结果。

**方法。** 在每个（强度级别, 模型, 执行臂）单元中运行大量尝试；一个混合效应逻辑回归（mixed-effects logistic regression）以任务级随机截距把逐次尝试的通过建模为强度级别的函数，并对 log 成本建立并行模型，两者均在模型与执行臂间做 Holm 校正。在任何规模化投入之前，基于观测方差运行试点后功效分析，检查设计对预先指定的通过率边际是否有足够功效；若不足，则按预先承诺的规则扩大每单元样本量，而非把功效不足的结果报告为零发现；一次性扩大后仍功效不足的单元被预先声明为不可判定（INCONCLUSIVE）——完全排除在通过/失败汇总之外，而非计为零结果。

### 双判据形状检验（Dual-Criterion Shape Test）

**挑战。** 通过率—强度与成本—强度关系是光滑的还是包含断点，无法事先假定；依赖单一统计判据的检验既可能被噪声愚弄（制造出虚假拐点），也可能被曲线拟合的灵活性愚弄（过拟合出并不存在的拐点）——而且两条曲线不保证在哪种情形成立上达成一致。

**洞察。** 要求两个独立统计判据一致才宣告拐点，可分别防范这两种失效模式；把同一双判据程序在通过率曲线与成本曲线上各跑一次、而不是假定两者必然同步，才能把跨轴一致或不一致变成被报告的发现而非沉默的假定。

**方法。** 对每个（模型, 执行臂）单元，需同时满足断点存在性检验与偏向分段拟合而非线性拟合的模型选择判据，才宣告通过率曲线或成本曲线存在拐点，并附加一个预注册的效应下限：分段拟合的断点后斜率其量级须至少为断点前斜率的两倍，从而把统计上可检测但实践上可忽略的弯折报告为"带拐点迹象的平缓"（graceful-with-inflection）而非计为拐点；任何被检测到的拐点位置以任务级重采样的自助法置信区间（bootstrap confidence interval）报告。随后直接比较基于通过率与基于成本的裁决：两者一致时，单元相应归类为平缓或拐点形状；不一致时，单元报告为**形状不一致（shape-discordant）**——一个独立的、有信息量的分类，绝不通过把一条曲线视为自动优先于另一条来消解。

### 因子式强度设计（Factorial Strength Design）

**挑战。** 约束强度至少有两条逻辑上独立的轴——激活多少条规则（广度）与每条执行多严格（严格度）——单一序数阶梯把它们混成一个数，因此在这种阶梯上发现的拐点无法具体归因于任一轴。

**洞察。** 序数阶梯能探测到"有东西在退化"；只有让广度与严格度独立变化的设计，才能归因该退化各有多少属于哪条轴。

**方法。** 试点阶段使用至少七个级别的累积序数阶梯，从无激活规则到固定严格度下全部规则包——这是分段拟合与线性拟合的比较具有实质功效而非流于空洞的最低分辨率——以确认强度确实产生可测分离。后续阶段以独立交叉广度与严格度的因子网格取代阶梯，使每条轴对通过率与成本的主效应及其交互可以直接从拟合的趋势模型中读出，而非从单一混淆的序数位置推断。

### 跨臂成本分解（Cross-Arm Cost Decomposition）

**挑战。** 同样的设计约束内容，仅因执行方式不同——仅提示注入、检查器在环重试、单次二元全开尝试——成本就可能不同，因此只在一种执行机制下测量成本，有报告该机制属性而非约束本身属性的风险。

**洞察。** 固定约束内容、只变化执行机制，是把测得成本的一部分归于机制而非约束的唯一途径——并且正式检验执行臂与强度之间的交互、而非只做描述性的臂间比较，才能让该归因成为统计断言而非目测断言。

**方法。** 完全相同的约束网格在全部三个执行臂下运行，成本按组成部分分项记录（提示开销 token、重试循环 token、输出膨胀 token）。一个以执行臂与强度为交叉因子的双因素混合效应模型分别作用于通过与 log 成本，检验其交互是否显著；一个机制份额（mechanism share）统计量估计重试臂与仅提示臂之间成本差中可归因于执行机制本身、而非底层约束内容的比例。由于该比率只有在其分母——重试臂相对无约束基线的成本溢价——不可忽略时才有意义，机制份额只在该溢价超过预先指定下限的单元中计算与报告；低于下限的单元报告为**机制份额未定义（mechanism-share undefined）**，呼应上文的形状不一致约定，而非把不稳定或符号翻转的比率当作普通有界比例喂进假设检验。

### 长度匹配安慰剂对照（Length-Matched Placebo Control）

**挑战。** 由于每个把激活规则渲染为提示文本的执行臂都必然随强度增长而加长提示，观察到的通过率或成本变化都与"指令更多了"这一事实纠缠，独立于指令内容——这一混淆不同于、也不被上文的跨臂分解解决，因为固定的执行臂仍可能只是对提示长度本身起反应。

**洞察。** 把"模型在指令更多时表现更差"与"模型恰恰因为这些指令是设计约束而表现更差"分开的唯一途径，是一个固定指令长度、清空其语义内容的对照。

**方法。** 在每个强度级别，安慰剂条件渲染语义惰性、在位置与格式上与真实激活规则集 token 数匹配的指令来替代实际约束文本。经由交互检验比较真实约束臂与安慰剂臂的强度效应对通过率的影响；只有当真实臂的效应超出安慰剂臂达到预先指定的边际时，观察到的前沿才归因于约束内容，否则重新界定为一般性的指令负载效应。

## 实验（Experiments）

### 实验设置（Experimental Setup）

**数据集。** 一个约 150 个任务、带可执行单元测试的函数级套件（BigCodeBench-Hard 风格）为试点阶梯扫描提供廉价、高样本量的基底。一个 50 任务的仓库级子集（SWE-bench Verified 风格，附每仓库适用目录规则的映射）是必需而非仅仅出于逼真性：导入分层、依赖方向与依赖注入规则在函数级任务上没有多文件结构可供约束，因此没有仓库级套件，约束力筛查将悄悄豁免整个架构规则子集不受检验；同一套件也让广度—严格度与机制份额的发现能在函数级尺度之外检验其泛化性。**污染检查（Contamination check）。** 由于两个套件都取自可能与模型预训练语料重叠的公开基准，任务级通过率额外按每个任务的公开发布日期相对每个被测模型的已记录训练截止日期（如可得）分层，并在排除任何被标记为疑似记忆化（在零约束强度下所有被测模型均近天花板通过率）的任务子集后重跑双判据形状检验；若合并分析与排除污染分析的形状裁决有实质差异，则两者都报告，而非只报告合并结果。

**扫描分辨率与预算**（预注册设计目标，非结果）。试点阶梯包含至少七个强度级别（含无约束级别），规模化网格至少交叉四个广度级别与三个严格度档位，因为双判据形状检验的功效直接取决于分段拟合可用的强度级别数。以生成次数计，试点约为 150 任务 × 7 级别 × 5 样本 ≈ 5×10³ 次生成（一个中档模型）；规模化——十二个网格单元 × 三个执行臂 × 至少三个模型 × 5 样本，覆盖两个套件——在重试开销之前约为 10⁵ 量级的生成；重试开销本身是研究的记录结果而非假定输入，跨臂分解所需的分项成本记录同时兼作本研究自身的预算核算。

**基线**（作为健全性对照与混淆控制，而非要被击败的竞争者——这是一项测量研究，没有任何研究问题被表述为"我们的程序击败基线 X"）。无约束臂（无激活规则）锚定效用上限，并兼作约束力筛查对照。二元全有全无执行臂——所有规则在单次尝试中全部激活——是分级多层扫描所对照的朴素部署策略，用以表明分级设计能提供单次全开运行无法提供的信息。长度匹配安慰剂臂（见方法论）把指令负载效应与约束内容效应隔离。约束遵循基准的仅满足率退化曲线作为外部锚点做定性比较，因为其已发表结果缺少通过率/成本轴，且并非在本文条件下运行。

**指标。** 每（强度, 执行臂, 模型）单元的 Pass@1；残余违规率；合规通过率（通过测试且零违规）；每次尝试成本（token、重试、墙钟、美元）与每合规解决任务成本；检测到拐点时的拐点位置及其自助法置信区间；有定义时的机制份额。

**研究问题（Research Questions）：**

#### RQ1：经审计后，规则目录是否保有其忠实性与约束力？若否，剔除集中在哪里？

**设置。** 初始约 20 条规则的目录由两名人类标注者（真实违规 vs. 检查器伪影）在按规则分层、每规则至少二十个被标记实例的样本上审计；Cohen's κ 低于 0.8 的规则被剔除，在无约束生成中违规率低于 5% 的规则被另行替换。被剔除/替换的规则按机械类（命名、复杂度阈值）或架构类（分层、内聚相关的判断题）归类。

**预期结果。** 初始目录被剔除或替换的比例总体不超过 40%，且发生的剔除集中于架构意图类别，而非在规则类型间均匀分布。

**证伪条件。** 若超过 40% 的目录被剔除或替换（触发预注册的中止并重划范围门槛），或剔除在机械与架构类别间大致均匀分布而非集中于架构类——两者任一都意味着目录的忠实性风险不在本设计预测的位置——则被驳倒。

**假设（通俗表述）。** 目录忠实性风险是真实的，但集中且有界，不是机器可检性的全面失败。

**指标。** 目录被剔除/替换的比例；剔除的类别分布。

#### RQ2：在试点强度范围内，强制设计约束使通过率降低多少、成本升高多少？

**设置。** 试点阶段：一个中档模型、约 150 个函数级任务、序数强度阶梯（从无约束到固定严格度下全部累积规则包）、仅提示执行、每（任务, 级别）若干次采样生成。规模化：多个模型（含至少一个前沿模型与一个开放权重模型）覆盖两个任务套件，以因子式广度×严格度网格取代阶梯，并加入重试与二元全开臂。以混合效应逻辑回归（任务随机截距）把通过对强度级别建模，跨级别做趋势检验，跨模型与执行臂做 Holm 校正。

**预期结果。** 最大试点强度下的通过率至少比无约束基线低 5 个百分点，强度系数显著为负；最大强度下每合规解决任务成本至少比无约束基线高 25%，对多数被测模型成立。

**证伪条件。** 若通过率上的强度系数不显著，或每合规解决任务成本在扫描范围内持平——即合规原来近乎免费，这本身就是一个可发表的发现，它移除了"合规有实质代价"这一前提——则被驳倒。

**假设（通俗表述）。** 在被测范围内，强制设计约束会可测地降低通过率并抬高成本，而非免费。

**指标。** 混合效应强度系数及其置信区间；最大强度对零强度的每合规解决任务成本比。

#### RQ3：试点设计是否有足够功效探测该效应？若否，预先承诺的扩样规则是否触发而非报告零结果？

**设置。** 基于 RQ2 拟合模型的观测单元方差做试点后功效分析，在敲定任何规模化样本量之前对照预先指定的 5 个百分点通过率边际检查。

**预期结果。** 若对 5pp 边际的观测功效低于 80%，则对规模化应用预先承诺的扩样规则，而非把试点结果报告为"平缓"或"免费"合规的零发现；一次性扩样后功效仍低于 80% 的单元被预先声明为不可判定并排除在通过/失败汇总之外，绝不计为零结果。

**证伪条件。** 若一个功效低于 80% 的试点结果在未应用扩样规则的情况下被报告为平缓或免费前沿的证据——这将把功效不足的零结果与真实零结果混为一谈——则（在设计失败而非科学发现的意义上）被驳倒。

**假设（通俗表述）。** 表面上"免费"的试点结果只有在其统计功效经过检查、而非被假定之后才可信。

**指标。** 观测效应量与对预定边际的相应功效；扩样规则是否触发。

#### RQ4：合规—效用前沿是否呈现统计上可检测的拐点？

**设置。** 在规模化数据的检查器在环重试臂下，按模型同时要求断点存在性检验与分段对线性的模型选择判据，并附预注册的斜率陡增效应下限（分段拟合的断点后斜率至少为断点前斜率的两倍；低于该下限的断点报告为"带拐点迹象的平缓"，不计为拐点），才宣告通过率曲线存在拐点；拐点位置以任务级自助法置信区间估计。

**预期结果。** 多数被测模型在重试臂下存在拐点（两判据同时满足），且存在拐点的各模型的拐点位置置信区间彼此重叠。

**证伪条件。** 若没有任何被测模型的任一判据拒绝线性拟合，或所有检测到的断点都低于斜率陡增效应下限（全程为带拐点迹象的平缓），或两判据在多数单元中彼此矛盾以致无法形成联合裁决，则被驳倒（前沿是平缓的，非拐点形状）。

**假设（通俗表述）。** 合规的通过率代价不只是与强度成比例——它有可能在某个强度级别之后不成比例地恶化。

**指标。** 每模型拐点存在性裁决；拐点位置与自助法置信区间；跨模型区间重叠。

#### RQ5：基于通过率与基于成本的形状裁决是否一致？

**设置。** 把 RQ4 的同一双判据程序应用于 log 成本—强度曲线（按模型与执行臂），并把其裁决（平缓或拐点）与同一单元基于通过率的裁决比较。

**预期结果。** 两裁决在多数被测单元一致（同为平缓或同为拐点）；不一致处报告为形状不一致。

**证伪条件。** 若两裁决在多数单元不一致——这意味着"前沿的形状"无法按单元以单一裁决报告、必须通篇按轴报告——则（作为一个干净的单前沿断言）被驳倒。

#### RQ6：约束广度还是约束严格度驱动更多的测得退化？

**设置。** 在规模化的因子式广度×严格度网格上，从混合效应模型中在匹配阶梯位置估计每条轴对通过率比值比（odds ratio）的主效应，固定另一条轴。

**预期结果。** 对多数被测模型，广度主效应的量级超过严格度主效应——增加更多不同规则比收紧已激活规则的阈值消耗更多通过率。

**证伪条件。** 若严格度主效应在多数被测模型中等于或超过广度主效应，或两轴效应在统计上不可区分——这意味着试点的一维阶梯并没有混淆有实质差异的退化来源——则被驳倒。

**假设（通俗表述）。** 对通过率而言，激活更多规则比让既有规则更严格更要紧。

**指标。** 每轴主效应估计及置信区间；轴间效应量比较。

#### RQ7：测得成本中有多少可归因于执行机制而非约束本身？

**设置。** 完全相同的约束网格在仅提示与检查器在环重试臂下运行，成本分项记录；一个双因素（执行臂 × 强度）混合效应模型作用于 log 成本以检验交互项，机制份额只在重试臂相对无约束基线的成本溢价超过预先指定下限的单元中计算（低于下限的单元报告为机制份额未定义）。

**预期结果。** 在最高强度档，重试臂的 log 成本斜率超过仅提示臂斜率的 1.5 倍，臂×强度交互显著，且合格单元中的机制份额至少为 0.30，对多数被测模型成立。

**证伪条件。** 若交互项不显著，或合格单元中的机制份额低于 0.30——意味着从业者可以选择最便宜的执行机制而不实质移动前沿——则被驳倒（前沿对机制不变）。

**假设（通俗表述）。** 测得的合规代价中有相当份额可归因于执行如何实现，而非仅仅归因于所执行的内容。

**指标。** 臂×强度交互估计；合格单元中的机制份额统计量；log 成本斜率比（重试/仅提示）。

#### RQ8：观察到的前沿反映的是约束内容，还是仅仅提示中指令更多？

## 相关工作（Related Work）

与本文最接近的单篇已有工作研究单一约束维度——代码格式化——的成本与通过率影响，表明移除它可大幅削减输入 token 而通过率几乎不变；在纵览更广图景之前，值得把差异说清楚。该结果表明并非所有约束都昂贵，但格式化在语义上中性、移除它完全不改变程序行为，且该研究没有扫描任何强度轴，也没有触及任何真正可能与正确解冲突的约束。本文的空白恰是该结果留下的：同样的近乎免费的发现是否适用于语义上有约束力的设计约束——分层、依赖方向、复杂度上限——它们可能直接与任务正确性此消彼长；以及这一关系是否在扫描的强度范围内平滑成立，而非只在单一固定级别上成立。效用一侧此后又出现了第二个近邻：一项干扰研究表明，即使插入不言自明的约束——模型自己的成功输出本已满足的约束——也会在包括代码生成在内的多个领域可测地压低任务表现（SUSTAINSCORE, arXiv:2601.22047）。该结果确立了本文的不对称性所预言的干扰在单一隐含强度级别上是真实的，但它没有扫描强度轴，没有以 token 或美元计价任何东西，也没有检验任何曲线形状——它证明了代价的存在，而本文测量代价的价目表。

**没有效用轴的约束遵循测量。** 定义程序可验证指令约束并测量满足率的基准，以及逐级添加约束并测量累积退化的多级基准，都确立了自然语言约束的满足率随约束堆积而可测退化。建立在此类基准之上的训练流水线合成大规模可验证多约束指令，并通过约束级验证奖励训练模型同时满足多条约束；自博弈（self-play）框架生成可验证指令及可执行检查，以规模化监督受约束指令遵循。这条线的通用指令一系在没有独立功能正确性判定器的情况下测量满足率，因此合规从未与底层任务是否真正解决相权衡。一个代码特定的系列此后弥合了这一特定缺口：受控代码生成基准如今把指令遵循与可执行正确性解耦（IFEvalCode, arXiv:2507.22462），以多轮反馈评估层级化约束类型（MultiCodeIF, arXiv:2507.00699），通过复合指标联合评分正确性与多约束合规（CIFE, arXiv:2512.17387），并在正确性之外同时评分可读性、可维护性与效率要求（RACE, arXiv:2407.11470）。两系的每一项仍然缺少的，正是本文的前沿要联合测量的东西：作为参数化可扫描轴（而非固定的每任务约束集）的约束强度、作为一等结果的生成成本，以及对所得曲线形状的统计检验。

**相邻领域中的效用—合规权衡。** 安全对齐工作把训练期安全目标表述为效用代价具有结构性的约束优化，将该现象命名为"对齐税"（alignment tax），并投影策略更新以在改进安全的同时保持通用能力。解码期多目标方法在各目标奖励模型已存在的前提下刻画最坏情形权衡；对分类式、凹效用设定，帕累托前沿的精确计算有闭式解。这些工作都没有为编码智能体专门参数化设计约束强度，而闭式帕累托结果明确无法推广到开放式代码生成——那里的前沿必须经验测量而非推导——这些结果确立的方法论先例（值得刻画的是整条前沿而非单一工作点）正是本文形状检验直接延伸到无闭式解领域的东西。

**执行机制与可执行编码智能体基底。** 一个建立在序贯蒙特卡洛之上的推理期受约束解码机制把受控生成视为约束势函数乘积下的后验采样，其自身动机就指出昂贵的语义约束"既非 token 局部的、也不便宜"——这是本文为何通过跨臂分解把执行机制成本与约束内容成本隔离、而非假定单一机制的成本剖面可以泛化的直接先例。把真实仓库 issue 与对应修复 pull request 配对的大规模执行验证基准，是评估编码智能体功能效用的事实基底，但其正确性纯由测试解决定义，没有设计约束维度也没有成本轴——本文的仓库级套件建立在该基底之上，并扩展了它本身不提供的每仓库适用设计规则映射。另有两项相邻测量从两侧夹住本设计：一项在资源约束下对软件工程智能体的效能重评估以 token 与时间为准绳为准确率计价，但完全没有设计约束轴（SWE-Effi, arXiv:2509.09853）；一项对 LLM 生成微服务在固定六边形架构（hexagonal architecture）强制下的试点研究测量架构违规率，但没有扫描强度轴、也没有报告通过率或成本前沿（arXiv:2512.04273）——一个有成本轴而无约束，另一个有约束而无前沿。

**关于覆盖面的说明。** 支撑本综述的语料检索（digest N3，对 11,683 篇论文的八个检索角度）没有返回软件架构一致性检查（software-architecture conformance checking）工具与文献的在题命中——这个存在数十年的子领域涵盖依赖结构矩阵（dependency-structure-matrix）分析与自动化架构规则执行（import-linter 风格依赖契约等工具正源自这一传统），而本文自身的规则目录正是直接以其为原型。这是一个坦承的真实缺口，而非被悄悄省略的线索：此处不声称任何未经独立验证的具体引文，故这条工作线被标记为**[citation needed——架构一致性检查工具与文献，在检索语料中未找到]**而非杜撰，应在运行针对性的语料外文献检索后补齐。

## 结论（Conclusion）

本工作把一个治理假定——对编码智能体强制设计约束是廉价的、线性成本的附加项——重新表述为关于一条可测前沿之形状（而不仅是其平均价格）的经验问题。核心的方法论赌注是：平缓前沿与拐点前沿从有限试点范围上算出的平均成本上可以无法区分，因此只有直接检验的形状裁决——在通过率曲线与成本曲线上独立检查、并把两者的不一致报告出来而非以武断方式消解——才能告诉团队它实际处于哪个情形。无论当前编码智能体由哪种情形主导，该发现都与决策相关：平缓前沿意味着合规可以按规则线性编列预算；拐点则意味着在较低强度下看似负担得起的同一规则集，刚越过该强度就变得不成比例地昂贵，这对设计感知智能体应以多激进的方式部署有直接影响。两项局限从一开始就为该断言划界，并且是自然的后续步骤而非事后附注：本研究的范围限于可给出确定性、机器可检定义的约束类型，把抗拒此类检查的定性设计属性（以及本目录所借鉴、但尚未直接引用的软件架构一致性检查文献）留给未来的方法论工作；目录忠实性检查（RQ1）本身可能揭示集中于架构规则类别的不小剔除率，本设计对此予以报告和约束而非消除，指向更丰富的、半自动化的设计意图获取作为下一件要造的仪器。
