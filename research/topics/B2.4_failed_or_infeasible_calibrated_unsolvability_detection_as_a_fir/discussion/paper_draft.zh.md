# 未被解决，还是不可解：度量智能体失败归因系统能否识别不可行任务

> 由 `pipeline.md` 中六个已确认的阶段产出组装而成，经审计（`taste_audit.md`：🟢）。状态：**规格说明 / 论文草稿——尚未运行任何实验。** 下文所有数字均为预注册（pre-registered）的设计目标，而非实验结果。本文为 `paper_draft.md` 修订后（2026-08-21 评审修订）的中文译本；参考文献条目保留英文。

## 摘要

面向 LLM 智能体的失败归因（failure attribution）系统把"责任"定义为：最早的、若被纠正就能把失败翻转为成功的那一步——这一定义预设了这样的纠正必然存在。当任务根本不存在任何解时，这一预设会悄然失效：归因流水线仍然会提名一个"元凶"，系统性地把没有任何人能够完成的结果归咎于智能体，并使下游消费该判定的重试、升级或放弃策略发生误校准（miscalibration）。我们在文本转 SQL、工具调用、客户服务与命令行智能体四个领域上构造可解/不可解任务实例的匹配对（matched pairs），通过类型化的机械突变（mutation）注入不可解性，使得真值由脚本而非人工判断来认证。我们在这些配对上运行一组现有归因策略——LLM 评审（LLM-judge）、训练得到的追踪器（tracer）、以及智能体自身的第一方自报告——度量真正不可解的实例被误归因为智能体失败的比率，辨析观测到的差距反映的是可修复的归因系统设计缺陷、还是执行轨迹（trace）所能揭示信息的信息论上限，并刻画在何种置信度下宣告任务不可行才是有依据的校准边界（calibration boundary）。我们把不可解性作为现有系统无法表达的一等归因结果来报告，而不是继续把它当作可以被度量假设掉的边缘情形。

## 引言

当一个自主 LLM 智能体接到一项任务——写一条 SQL 查询、通过工具 API 订机票、解决客户的账户问题、运行构建脚本——而任务未能完成时，随之而来的自然问题是：智能体做错了什么。调试流水线、自动失败归因系统、乃至简单的重试逻辑，都建立在回答这个问题之上：智能体的规划、工具使用或执行中必有某处应负其责，而找到它正是归因的全部意义。这个假设几乎总是合理的。但就其自身的表述而言，它也是不可检验的——因为它没有任何方式来表达"智能体无论怎么做都不可能成功"的情形。

然而，对于 LLM 智能体领域实际部署的归因系统而言，关于这一假设的一个核心问题仍未被度量：归因系统（或智能体自身）能否把"智能体失败了"与"任务本来就不可解"区分开？这一二分本身此前已被提出——对黑盒自主智能体的差分测试（differential testing）已经能把系统性的智能体错误与"即使对理想智能体也内在不可行"的环境区分开（AIProbe）——但为 LLM 智能体构建的、读取轨迹的归因表述从未被拿来对照这一二分进行度量。当前最强的失败归因表述不仅没有回答这个问题——它们把它排除在了词汇表之外。归因被定义为找出最早的、纠正后本可把失败翻转为成功的智能体决策，这一定义预设了纠正性决策的存在。当所需的数据库列已被删除、所需的工具已被移除、或所述目标与所述约束相互矛盾时，不存在任何单步纠正，而归因流水线仍然必须输出点什么。它输出一个元凶。对一个没有第二种类别的系统来说，持续而无声的过度归咎与一个真正不可能完成的任务，在这一精确意义上是不可区分的。

最接近的已有工作从紧邻的角度逼近这一空白，却未将其闭合。AgenTracer 重放失败的多智能体轨迹，在每一步代入纠正后的动作以找出最早的、纠正后能产生成功的那一步，并在由此产生的监督上训练追踪器；Who&When 基准形式化了同样的反事实纠正目标，并据此评测 LLM 评审归因策略。二者都是本文最接近的先行工作，值得把差异说清楚：二者都继承了本文所质疑的那个预设——翻转成功的纠正总是存在——因此都无法把不可解实例表示为"被误归因的失败"之外的任何东西。在 LLM 智能体设定之外，AIProbe 通过与一个不依赖于智能体的规划器（planner）做差分测试，把自主智能体的失败归为智能体能力缺陷或环境不可行——这是对该二分本身最接近的先行陈述——但其研究对象是执行任务的强化学习/规划智能体而非读取轨迹的归因系统，其真值来自规划器对比（是证据，不是证书），且既不构造匹配对也不度量校准边界。MAST 分类法从人工标注的轨迹出发，归类多智能体系统如何失败（规格错误、智能体间失配、验证缺口），但没有任务级不可行性的类别——虽然其标注语料现已增长到 1,600 条以上轨迹、规模不再是短板，缺失不可行性类别这一点依然如故。另一条关于拒答与校准的工作线确立了：模型的弃答（abstention）决策可以、也应该对照真实目标来检验，而非仅按其频率给予奖励；置信度可以被直接训练而非事后估计——但在所有这些工作中，被校准的目标都是模型自身的知识边界或可验证的单轮答案，从来不是关于任务本身是否存在解的、经外部认证的事实。智能体自我评估与交互式歧义消解的工作在操作层面最为接近——询问智能体能否预测自己的成功，或通过澄清问题恢复缺失的约束——但其测试床在原则上全部可解，因此低成功预测永远意味着"对我太难"，而非"对任何人都不可能"。

把这一空白变成可度量的对象会浮现四个不同的障碍。任务是否可解的真值必须在任何智能体行动之前、仅凭任务与环境规格以机械方式确立——仅有的替代方案（人工判断或智能体自身的失败）分别是难以规模化的和构造上循环的。即便握有机械真值，执行轨迹中可得的证据也可能根本无法区分"胜任的智能体正确穷尽了一个不可能的任务"与"不胜任的智能体搞砸了一个可解的任务"，因为二者都会产生看起来相似的死胡同与工具报错。归因系统产生的任何置信信号都必须以完整的权衡曲线而非单一阈值来报告，因为过度标记与标记不足对不同的下游消费者代价不同。而被注入的不可解性本身不能留下任何其构造过程的文本痕迹，否则系统可能学会检测突变而非推理可行性，使研究报告的每一个比率失效。

我们的方法把这些障碍逐一转化为具体的设计决策。不可解性由脚本认证，脚本在任务规格本身上检查两个条件——被改动的元素为参考解所必需，且不存在任何替代——因此真值从不依赖于观察智能体的运行。一个固定的运行框架（harness）在每个匹配对的两个成员上运行一组归因策略，其中包括一个被限制在现有表述实际使用的标签空间内的版本，从而把每个策略从轨迹中读出什么与轨迹如何产生相互隔离。为了把可修复的设计缺口与硬信息上限区分开，另一个读取器直接在真值上校准，并在留出实例上与从未见过真值的归因策略对比——如果连特权校准（privileged calibration）都无法把判别力提升到随机之上，那么再好的提示或标签空间重设计也无济于事。所得置信分数被扫描成完整的风险–覆盖（risk–coverage）曲线而非压缩为单一阈值，并且每个突变都要先通过泄漏审计（leakage audit）——纯文本探针、表层统计匹配与人工抽查——其上构建的任何比率才被允许计数。

我们在由现有带验证器基准构建的文本转 SQL、工具调用、客户服务与命令行智能体领域上评估这一设计，将标签受限对照与特权校准对照同已部署的 LLM 评审、训练追踪器与第一方自报告策略进行比较。

概括起来，我们的贡献是：
- 对当前 LLM 智能体失败归因表述内部预设——翻转成功的纠正总是存在——的识别与形式化，并论证它在结构上强迫任何真正不可解的实例被归咎于智能体。
- 一个跨四个智能体领域、机械认证、可解/不可解匹配的基准，由预注册的泄漏审计把关，使真值从不依赖人工判断或智能体自身行为。
- 一个特权校准对照，用以辨析所测得的误归因差距反映的是可修复的归因系统设计，还是执行轨迹所能揭示信息的信息论上限。
- 对恰当弃答的校准边界刻画，以完整的风险–覆盖曲线而非单一工作点报告，覆盖各领域与各归因策略。

## 问题定义

**形式化设定。** 一个任务实例是二元组 t=(q,E)：指令 q 加上环境 E（数据库模式、工具列表、文件系统或策略集合）。智能体 π 在固定的步数/词元预算下产生执行轨迹 x = π(t)，以给出答案、显式宣告不可行、或预算耗尽而终止。归因系统是函数 A(q,x) → (ŷ, c)，其中 ŷ ∈ {success, agent_failure, unsolvable}，c ∈ [0,1] 是附着在 unsolvable 判定上的置信分数；A 可以是为已完成轨迹打分的第三方读取器，也可以是执行智能体自身的终局自报告，但无论哪种情形，A 都观察不到真值神谕（oracle）O(t) ∈ {solvable, unsolvable}。研究对象是 ŷ 能否恢复 O(t)，以及在 c 的哪些工作点上宣告 ŷ=unsolvable 是有依据的。

**为何困难。** O(t) 必须在任何智能体作用于 t 之前、仅由 t 的规格确立——人工判断与智能体自身的失败都不能充当真值，前者无法规模化，后者构造上循环（那会把"不可解"定义为"智能体没解出来的"）。即便 O(t) 已定，轨迹 x 也可能不携带足够证据来区分"胜任的智能体正确穷尽了不可解的 t"与"不胜任的智能体失败于可解的 t"，因为二者都产生表面相似的死胡同、工具报错与未决探索——所以 A 能否仅凭 x 恢复 O(t) 本身就是开放的经验问题，而非设计给定。c 上的正确工作点也不是单一取值：过度标记 ŷ=unsolvable 让智能体得以对只是困难的任务宣称不可行，把真实的无能包装成有原则的拒绝；标记不足则把没有人能解决的任务归咎于智能体——并且由于 ŷ 的不同消费者（自动重试循环、人工升级队列、放弃策略）对这两种错误的容忍度不同，没有任何单一的 c 阈值能服务所有消费者。最后，用于构造不可解 t 的突变除了决定可解性的那个事实之外，不得改变 q 或 E 的任何其他方面，否则 A（或 π）可能从 q 的表面线索学会检测突变，而非推理 t 是否真的可解。

## 方法概览

在概念层面，本研究是一条由五个协作部分组成的单一度量流水线。生成器与脚本级神谕把一个带验证器的源任务变成匹配的、经认证的可解/不可解对；固定运行框架在每对的两个成员上运行一组归因策略；特权校准读取器把所得轨迹级证据转化为上限估计，辨析可修复的设计缺口与硬信息上限；阈值扫描把同一证据转化为完整的校准刻画；泄漏审计在上述每一读数被允许计数之前对其把关。

**突变认证神谕**对任务的环境或指令施加恰好一个类型化改动，并用静态脚本检查认证所得实例的可解性，产生从不依赖任何智能体行为的真值。**匹配归因组**在配对两成员上运行固定框架，并同时用多个归因策略打分，其中包括一个镜像现有表述可表达范围的标签受限对照。**神谕校准上限探针**直接在其他策略从未见过的真值上训练，确立任何读取器能从同一轨迹中提取的最佳判别力。**校准扫描**把每个策略的置信分数转化为完整的风险–覆盖刻画，而非单一准确率数字。**泄漏审计**在上述任何数字被报告之前，检查突变是否留下了其构造过程的可检测表面痕迹。

## 方法论

### 突变认证神谕

**挑战。** 真值可解性必须独立于任何被观察到的智能体行为来确立——仅有的其他来源（人工判断或智能体自身的失败）分别是难以规模化的和构造上循环的。

**洞见。** 可解性是任务规格的属性而非智能体行为的属性，因此可以仅在规格上检查两个条件来认证：被改动元素是否为已知参考解所必需，以及是否存在任何替代。

**方法。** 对一个带验证器的源任务施加恰好一个类型化突变——缺失必需资源、相互矛盾的约束、或指向不存在实体的引用——同时保持指令措辞与环境规模不变。静态脚本仅当被改动元素为参考解所必需且不存在替代推导路径时（数据库任务用模式图可达性检查、函数调用用工具签名覆盖检查、有状态智能体任务用环境状态断言），才把突变实例认证为不可解；未突变成员则通过确认其参考解仍能通过原验证器来认证为可解。

### 匹配归因组

**挑战。** 执行轨迹中的证据可能不足以让任何读取器区分"胜任的智能体正确穷尽不可解任务"与"不胜任的智能体失败于可解任务"，因为二者产生相似的死胡同与错误。

**洞见。** 在匹配对的两个成员间保持运行框架——预算、日志与提示脚手架——固定，能把归因策略从轨迹中读出什么与轨迹如何产生相互隔离；在完整策略组之外并行运行一个标签受限对照，能把现有表述在原则上可表达什么与已部署评审在实践中达到什么区分开。

**方法。** 每个实例都在相同的步数/词元预算下运行，并对每个动作、工具结果与终局事件做标准化日志。一组归因策略为每条所得轨迹打分：一次性与逐步两种模式的 LLM 评审、标签空间扩展至包含 unsolvable 结果的训练追踪器、执行智能体自身的第一方终局自报告、关键词/终局错误启发式下限、以及一个只能输出 success 或 agent_failure 的标签受限对照——精确镜像当前归因表述的词汇表。

### 神谕校准上限探针

**挑战。** 测得的高误归因率可能反映归因策略构建方式中可修复的缺陷，也可能反映信息论上限——轨迹本身对任何观察者（无论多么强大）都不携带可恢复的可行性信号。

**洞见。** 直接在真值上校准一个读取器只约束它在训练实例上学到什么，不约束该信号是否泛化到留出轨迹；如果连这个特权读取器都无法在留出实例上判别高于随机，那么任何归因系统的重设计也不可能做到，因为限制因素是轨迹的信息含量而非读取器的构造。

**方法。** 在匹配对的留入（held-in）划分上训练一个可直接访问神谕标签的探针，采用与最强已部署归因策略相同的骨干模型与计算预算，然后在已部署策略同样被打分的留出（held-out）划分上评估其对不可解轨迹与可解但失败轨迹的判别力。留出实例上超过预设判别阈值被视为轨迹级信号存在、只是已部署策略未能提取的证据；未超过则被视为信息上限的证据——任何下游归因系统的改动都无法解除。

### 校准扫描

**挑战。** 对 unsolvable 标签的过度标记与标记不足对不同下游消费者代价不同，因此没有任何单一置信阈值能作为每个任务族、每个消费者的校准边界。

**洞见。** 报告完整的风险–覆盖刻画而非单一准确率数字，正是让每个下游消费者按自身成本结构选择工作点的方式。

**方法。** 对每个归因策略与任务领域，把附着在 unsolvable 判定上的置信分数在其全范围内扫描，产生风险–覆盖曲线及其面积（AURC）、该置信分数的免阈值判别力（对神谕标签的 AUROC）、10 桶期望校准误差（ECE）、以及置信度与神谕认证不可解性之间的 Spearman 相关，按领域分别报告而不合并。

### 泄漏审计

**挑战。** 如果用于构造不可解实例的突变留下任何可检测的表面痕迹，系统就可能学会检测该痕迹而非推理可行性，使下游每一个比率失效。

**洞见。** 隔离这一失效模式的唯一办法是剥离除原始任务文本之外的一切，检查可解性能否仅凭文本预测。

**方法。** 在某领域的任何头条比率被报告之前，其突变算子须对照预注册的门槛检查：一个只拿到任务文本（无轨迹、无环境访问）的探针尝试预测可解性，其判别力必须在至多一轮算子修复迭代后降到预设阈值以下；配对成员还须检查在表面长度、词元重叠与指令困惑度上的统计不可分性；并对 10% 随机抽样的配对做人工审计，确认突变是配对成员之间唯一的语义差异。

## 实验

### 实验设置

**数据集。** Spider 1.0（Yu et al., 2018）——单数据库文本转 SQL 场景，对缺失资源突变有闭式的模式可达性检查；先导阶段领域，神谕构建成本最低。Berkeley Function Calling Leaderboard v3（BFCL v3）——已有无关性检测划分，是移除工具突变最近的自然先例；与 Spider 同为先导阶段领域。BIRD（Li et al., 2023）——多表模式，参考查询远比 Spider 复杂；用于检验方向性偏差与"设计对上限"发现在更接近真实部署的模式复杂度下是否成立，而非 Spider 相对简单设定的产物。τ-bench 零售/航空——在有状态、多轮的工具智能体环境中支持删除记录与策略矛盾突变；规模化阶段领域。Terminal-Bench——在命令行设定中支持不存在资源突变；规模化阶段领域。在已纳入领域内扩展规模只是配置变更，但每个新领域都需要自己的神谕后端与突变算子库；因此每个规模化领域都必须先通过按领域的神谕启用里程碑——在该领域 20 对规模上通过 PG-1、PG-2、PG-5——其配对才能进入任何头条表格。

**基线与对照组**（作为健全性检查的比较对象，而非要击败的竞争者——这是一项度量研究，这里没有任何研究问题被表述为"我们的流程胜过基线 X"）。受测的已部署策略是一次性与逐步两种模式的 LLM 评审归因（按 Who&When）、标签空间扩展至包含 unsolvable 的 AgenTracer 式训练追踪器、第一方自报告（协议改编自能力自评工作）、以及关键词/终局错误启发式下限。训练追踪器带有预先承诺的可用性条款：其 unsolvable 标注监督只能取自 B-alt1 使用的同一 30% 留入校准划分（绝不取自留出的 70%），若追踪器无法在预注册预算内复现，策略组缩减为 4 个基线并说明原因，所有"5 中至少 3"的投票规则变为"4 中至少 3"，RQ1b 的选择校正变为 4 选最优。围绕该策略组预注册了五个对照组，每个针对一个不同的对立解释，而非作为要击败的竞争者。**B0-p**，构造即空（null-by-construction）的安慰剂，是 goal.md 判定程序最先检查的组：用语义惰性突变构造的假配对（两成员构造上均可解）加上神谕标签洗牌检查，都用与头条比率相同的估计器打分；此处出现非空结果（在本不应携带信号的人工制品上出现真实差距或高于随机的 AUROC）意味着流水线度量的不是可行性判别，在任何假设被评分之前就使所有其他组失效。**B0-a**，标签受限归因器（只能输出 success 或 agent_failure），是现状组：其 FBR 预期构造性地接近 1.0，这不是流水线有效的证据，而是问题存在的论据本身——若 B0-a 的 FBR 不接近 1.0，"现有表述在结构上强迫归咎智能体"这一前提本身就错了。**B-alt1**，神谕校准上限探针，是能力/预算匹配的对照，针对"不可解任务的轨迹对任何观察者都不携带可恢复可行性信号"这一对立解释；它在从不进入任何头条表格的 30% 对级划分（按领域与算子类型分层）上训练与校准，只在留出的 70% 上评估。**B-alt2** 在每个领域 20% 的表面匿名化配对子集上（模式、工具、实体与文件名一致重命名，语义不变，重命名后神谕标签重新验证）重跑最强 LLM 评审基线，针对"测得的误归因反映的是对知名源基准的记忆差异检测而非可行性推理"这一对立解释——这是纯文本泄漏探针在结构上看不到的通道。**B-alt3** 在提示中加入一句披露基准 50/50 不可解先验的话重跑同一基线，针对"方向性偏差是对部署先验失配的理性反应，而非标签空间或提示设计局限"这一对立解释。

**指标。** 误怪率（false-blame rate, FBR：不可解实例被标为 agent_failure 的概率）与推诿率（cop-out rate, CoR：失败但可解的实例被标为 unsolvable 的概率）及其差；{success, agent_failure, unsolvable} 上的三类宏 F1；unsolvable 置信分数对神谕标签的 AUROC 与 10 桶期望校准误差；风险–覆盖曲线及其面积（AURC）；Refusal-Index 式的置信度与神谕认证不可解性的 Spearman 相关；泄漏审计所用纯文本探针的 AUROC；以及专属对照组的：假配对 FBR−CoR 类比差距与洗牌标签 AUROC（B0-p）、上限探针与最佳已部署策略的留出 AUROC 差距（B-alt1）、表面匿名化（B-alt2）与先验披露（B-alt3）下 FBR/AUROC 的移动。

**研究问题：**
1. RQ_INF_1（先导规模，H1）——现象是否以可观的量级存在：默认 LLM 评审归因器是否以值得进一步研究的比率误归因经认证的不可解实例？
2. RQ1a（规模化，H2）——一旦 unsolvable 标签在技术上可用，方向性的过度归咎偏差（FBR 超过 CoR）是否在已部署归因组中持续存在？
3. RQ1b（规模化，H3）——unsolvable 置信分数是否在每个领域都承载可用的校准边界——真实的风险–覆盖拐点，而非事后贴的标签？
4. RQ_INF_2（工具效度，H4）——构造的配对是否只在真实可解性上有差异，在每个进入头条数字的领域都没有可检测的表面泄漏？

另有两个效度问题作为前置条件而非头条假设来检查：神谕的机械检查认证的是真正的不可解性而非单纯的困难（假设 A1，门 PG-1，在上述四个 RQ 使用任何构造不可解实例之前，对每个实例做有界穷举/工具搜索检查）；以及 B0-p 的安慰剂返回空结果（goal.md 判定程序运行的第一项检查，先于任何 RQ 评分）。

#### RQ_INF_1（H1）：现象是否以可观量级存在？

**设置。** 第一阶段先导：100 对（Spider + BFCL v3）、2 个智能体骨干、默认 LLM 评审归因器（一次性模式）、未调阈值。

**预期结果。** FBR ≥ 0.20，且 95% 对级聚类自助（bootstrap）置信区间下界超过 0.05。

**证伪条件。** 若 FBR < 0.20 或置信区间与 0.05 重叠则被驳倒——此时头条改为"现成 LLM 评审归因未经调优已能以比率 X 分离不可解与智能体失败；开放问题是残余尾部/更难的领域或基线"，按领域、按基线分别报告而不合并。

**假设（白话）。** 现有归因流水线在先导规模、无调优的条件下，误归因经认证不可解任务的频率足够高，值得在完整规模上刻画，而非舍入误差。

**指标。** FBR 及 95% 对级聚类自助置信区间（10,000 次重采样），单一主量，无多重比较校正（先导规模下单一预注册基线，不构成比较族）。

#### RQ1a（H2）：方向性过度归咎偏差是否在已部署策略组中持续？

**设置。** 规模化：600 对（4 个领域各 150）× 3 个智能体骨干 × 完整 5 策略归因组。按策略做双比例聚类自助检验（FBR 对 CoR，对级重采样，10,000 次），5 个策略间做 Holm–Bonferroni 校正，族错误率 α=0.05。由于 CoR 类只条件于失败但可解的实例——该计数随智能体能力上升而缩小——在预注册的智能体成功率范围内（假设 A3，t⁺ 成功率 ∈ [0.15, 0.90]），实际失败可解 n 约在 180 到 1,530 之间；对 10 个百分点下限的单侧功效仅当失败可解 n ≳ 400 时才超过 0.9，在该范围低端未校正时降至约 0.8（Holm 校正下更低）。任何校正后实际功效低于 0.8 的基线被预先宣告对 H2 **不确定（inconclusive）**，从下述投票分母中排除，并连同其实际 n 与置信区间一起报告，绝不悄悄折入零结果。同一规则适用于每个领域×智能体族×算子类型单元：对同一下限功效不足的单元仅对该单元不确定，绝不作为零结果并入领域汇总。

**预期结果。** 在至少 3/5 个（非不确定的）归因策略上，校正后 FBR 超出 CoR 至少 10 个百分点。

**证伪条件。** 若少于 3/5 个非不确定策略显示校正后 10 点的过度归咎方向差距，则（偏差不存在）被驳倒。若反而有 ≥3/5 个策略显示校正后 CoR 超出 FBR 10 点，则在**相反方向**被驳倒——以完整显著度报告，不降格为脚注：头条变为"归因系统过度拒绝而非过度归咎；校准边界结果（RQ1b）成为记录在案的发现，推荐阈值调整反号"。

**假设（白话）。** 即使归因系统有说"不可解"的空间，过度归咎偏差仍然存在——它不仅仅是缺失标签的产物——若它不存在，则同样醒目地报告更有信息量的反向发现。

**指标。** 每策略的 FBR、CoR 及其差，附聚类自助 95%（在 H3 选择校正适用处为 99%）置信区间；每策略、每单元的实际功效与实际 n；CoR 除合并比率外按源任务难度层分层报告，因为 FBR 与 CoR 条件于不对称的总体（全部不可解成员对比仅*失败的*可解成员，后者的构成随智能体能力上升而偏向最难的可解任务）——不分层的合并会让智能体能力的变化伪装成方向性偏差本身的变化。一个次要的逻辑回归（误归因对领域、算子类型与智能体族固定效应）定位偏差集中于这三个因素中的哪一个，本身不构成头条断言。

**结果。** *[占位——实验运行后填写]*

#### RQ1b（H3）：每个领域是否存在可用的校准边界？

**设置。** 与 RQ1a 相同的规模化总体。由于"每个领域至少一个基线"是在每个领域内对 5 个基线做选择，按基线的置信区间采用 Bonferroni 校正的 99% 水平（在选择下保持每领域 α=0.05）；AURC 对对角线的分离检验采用同一校正水平。

**预期结果。** 在 4 个领域的每一个中，至少有一个策略满足 AUROC(c, 𝟙[y=unsolvable]) ≥ 0.65 且 99% 水平自助置信区间下界超过 0.50，同时风险–覆盖曲线的 AURC 在同一校正水平下严格低于覆盖率成比例的对角线。

**证伪条件。** 若某领域没有策略越过校正后的 AUROC/AURC 门槛，则该领域被驳倒——95% 水平未校正通过而 99% 选择校正水平未通过不算数。失败领域的拼接结论以下述 B-alt1 三分支规则为条件，绝不独立断言。

**假设（白话）。** 置信分数不是固定标签上的装饰——它承载真实可用的校准信号；在它不承载之处，原因（信息上限还是设计缺口）从 B-alt1 读出而非猜测。

**指标。** 置信分数对神谕标签的 AUROC 与 AURC、10 桶期望校准误差、Refusal-Index 式 Spearman 相关，全部按领域、按校正置信水平报告。作为预先承诺的次要分析（非头条断言），留出领域阈值迁移检查：在每三个领域上选出的工作阈值原样应用到第四个领域，报告迁移下实现的风险与覆盖率——即使结果为负也照报。

#### RQ_INF_2（H4）：进入头条数字的每个领域，构造配对是否无泄漏？

**设置。** 每个领域一个双读取器泄漏门：以纯文本方式提示的最强归因组骨干，与在 B-alt1 同一 30% 校准划分上拟合、在留出配对上评估的训练判别器；二者都必须先通过阳性对照功效检查（在刻意泄漏的配对上 AUROC ≥ 0.90），其对真实配对的 <0.60 判定才算数。对配对成员做表面长度、词元重叠与指令困惑度的双样本检验；对 10% 抽样做 ≥2 名独立评审的人工审计（κ ≥ 0.70）。

**预期结果。** 每个领域的纯文本探针 AUROC 在至多一轮算子修复迭代后降到 0.60 以下，且配对成员在表面统计上于 α=0.05 不可分。

**证伪条件。** 若某领域纯文本探针 AUROC 在一轮修复后仍 ≥0.60，或配对成员在表面统计上可分，则该领域被驳倒——其头条比率从 RQ1a/RQ1b 中扣下，转而作为该领域突变算子的负面构念效度（construct validity）发现报告（全局后备 F-G1）。若**每个**领域在允许的一轮修复后都未通过此门，论文整体转向关于泄漏本身的构念效度发现（全局后备 F-G2），其正当性仅来自探针已通过自身的阳性对照功效检查。

**假设（白话）。** 构造配对只在真实可解性上有差异，而非某个偶然的文本破绽——若某领域未过此门，就诚实报告"无泄漏注入比设想更难"这一发现，而不是悄悄丢弃该领域。

**指标。** 每领域纯文本探针 AUROC（双读取器）；表面统计检验 p 值；10% 抽样上的人工审计 κ。

### 对照组详述

**B0-p（构造即空安慰剂，Phase-D 门）。** 用与每个头条数字相同的估计器为两种假构造打分：假配对——生成器施加语义惰性突变（重命名未使用的别名、重排环境列表），两成员构造上均保持可解；洗牌神谕标签检查——在领域内置换神谕标签后重算每个估计器。预先承诺的空判据是：每个领域中，假配对 FBR−CoR 类比差距的 95% 置信区间包含 0，**且**洗牌标签 AUROC 的 95% 置信区间包含 0.5。任一非空即在上述四个研究问题被评分之前使本轮运行失效——最先检查的是它，不是 B0-a。

**B0-a（现状组，预期非空）。** 标签受限归因器（只能输出 success 或 agent_failure）在不可解实例上的 FBR 预期构造性地接近 1.0。这不是令人意外的空结果，而是问题存在的论据本身。若 FBR 显著低于 1.0（95% 置信区间排除 0.95），则"现有归因表述在结构上（而非偶然地）强迫归咎智能体"的前提是错的，在报告其他任何内容之前先重审框架。

**B-alt1（信息上限对立解释）。** 在从不进入任何头条表格的留入 30% 对级划分（按领域与算子类型分层）上训练/校准，只在所有已部署策略同样被打分的留出 70% 上评估。三个预先承诺的分支，无缝衔接：留出 AUROC < 0.60 意味着对立解释获胜——差距是信息受限而非设计受限，RQ1b 的各领域短板读作信息上限；留出 AUROC ≥ 0.65 而没有已部署策略达到 0.65，意味着对立解释被排除，差距是归因设计受限；探针 AUROC 落在 [0.60, 0.65) 或置信区间横跨两个门槛，则机制判定预先宣告为**不确定**，两种措辞都不得拼入摘要。

**B-alt2（记忆/污染对立解释）。** 用相同骨干/提示/预算，在每领域 20% 的表面匿名化配对子集上（模式、工具、实体与文件名一致重命名，语义不变，重命名后神谕标签重新验证）重跑最强 LLM 评审基线——这是纯文本泄漏探针看不到的通道，因为匿名化能挫败记忆差异检测而不改变探针能捕捉的表面统计。若某领域匿名化变体的 FBR 移动 ≥10 点或 AUROC 移动 ≥0.10（移动量的 95% 置信区间排除 0），则记忆对立解释在该领域获胜，匿名化变体比率取代该领域的头条比率。

**B-alt3（基率先验失配对立解释）。** 同一基线加一句披露基准 50/50 不可解先验的话重跑，其余相同。若披露使该基线 FBR−CoR 差距缩小 ≥50%，过度归咎发现降格为可行性先验误校准而非结构性标签空间局限，实践建议从增设一等标签转为披露或校准先验。若差距在披露后仍存，结构性解读成立。

### 全局后备

**F-G1（原型转向）。** 若中心假设族整体失败——RQ_INF_1/H1 失败（无可观现象）**且** RQ1a/H2 失败（无方向性偏差）——只要 RQ_INF_2/H4 通过、工具本身依然有效，论文就从度量/经验原型转向基准/数据集原型：头条变为所发布的匹配对套件本身，报告当今归因系统已能处理注入的情形，并把残余困难部分标记为开放目标。

**F-G2（构念效度转向）。** 若 RQ_INF_2/H4 在允许的一轮修复迭代后于每个领域都失败，则 F-G1 被禁止（没有有效工具可发布），每个 FBR/CoR/AUROC 数字都不可报告。论文转而给出关于泄漏本身的构念效度发现——其正当性仅来自泄漏探针已通过自身的阳性对照功效检查，因此"有泄漏"是可信的工具读数而非弱探针伪影——刻画哪些算子族经由哪些表面通道泄漏，覆盖全部四个领域。

**进一步评估。** 若有更多时间，一个自然的扩展是检验自然发生（非注入）的不可解性——部署中出现的含糊、部分或有争议的不可行性——本文明确将其排除在范围之外，因为它以更混乱的、需人工裁决的真值换掉了本设计所依赖的机械可验证真值，需要自己的效度论证而非上述泄漏审计的延伸。

## 相关工作

与本文最接近的先行工作是 AgenTracer 与 Who&When 基准，在综述更广的图景之前值得把差异说清楚：二者都已经形式化了 LLM 智能体系统的自动失败归因并做了规模化评测，但都把归因定义为找出最早的、纠正后本可把失败翻转为成功的智能体决策——这一目标预设了此类纠正的存在，无法把真正不可解的实例表示为"被误归因的失败"之外的任何东西，而这正是本文要闭合的空白。

**LLM 智能体系统的自动失败归因。** AgenTracer 重放失败的多智能体轨迹，在每一步代入纠正后的动作以找出最早的、纠正后能产生成功的那一步，并在由此产生的监督（经程序化故障注入扩充到成功轨迹）上训练专用追踪器。Who&When 基准形式化同一目标——识别哪个智能体、哪一步导致失败——并针对标注的失败轨迹评测 LLM 评审归因策略（一次性、逐步、二分搜索），发现即使强评审在步级定位上也很弱。二者都确立了步级归因是真实、可评测的目标，但都没有为"不存在任何步级纠正"的情形设置结果——两篇论文自身的标签空间与形式化决定性错误定义都构造在纠正动作按假设存在的轨迹之上，从未构造在被认证不存在任何纠正的实例之上。一波快速增长的 2025–2026 后继工作——谱分析归因（FAMAS）、AgentDebug/AgentErrorBench 分类法、层次因果图归因（CHIEF）、依赖引导的轨迹搜索（FALAT）、时序语义步骤定位（StepFinder）、多视角的 MP-Bench、以及注入规模化的 Who&When Pro——对同一反事实纠正目标做了规模化、结构化或重新基准化，而其每一个成员都预设存在可归咎的一步：Who&When Pro 在其 12,326 条注入轨迹上按构造保证这一步存在；MP-Bench 把"恰好一个根因"放宽为"可能多个"，从不放宽为"零个"；CUADebug 的计算机使用失败分类法在被迫面对 OSWorld 中按设计不可行的任务时，只能把它们归入"其他"。这波工作非但没有闭合本文瞄准的空白，反而是"该预设在整个当前表述族中承重"的正面证据。MAST 分类法从主流框架的人工标注轨迹出发，归类多智能体系统*如何*失败——规格错误、智能体间失配、验证失效——与这条线互补；其标注语料现已增长到 1,600 条以上轨迹，因此尚存的局限不是规模，而是缺失任何任务级不可行性类别。最后，最接近的框架先行者位于 LLM 智能体设定之外：AIProbe 通过与不依赖智能体的基于搜索的规划器做差分测试，把自主智能体失败归为系统性智能体错误或环境不可行（"即使对理想智能体也内在不可行"）。我们承认 AIProbe 在本稿之前一年就确立了智能体对环境的归因二分；它没有做、而本文要度量的是：检验 LLM 智能体领域实际部署的读取轨迹的归因系统，用规格级证书而非规划器对比（证据，而非证明）认证不可解性，用泄漏审计把关的匹配对控制表面混杂，以及刻画校准边界。

**拒答校准与选择性预测。** Refusal Index 用两遍协议度量模型的拒答概率是否追踪其自身在事实性问题上的错误概率，把追踪知识的拒答与刷拒答频率区分开——本文借用其 Spearman 相关的度量构造（置信度对某个真值列），以神谕认证的任务不可行性替换模型自身错误作为该列，构成不可解性拒答指数（Unsolvability Refusal Index），但它不是"击败数字"意义上的基线，因为其设定（单轮事实问答）不可迁移。RLCR 训练推理模型在答案旁输出置信度，优化正确性与校准的联合奖励，使谨慎的不确定与自信的幻觉不再获得相同奖励，其奖励设计所在的可验证单轮问题没有不可解实例类。级联 LLM 评审框架（Trust or Escalate）以可证明的、基于固定序列检验的保证，把升级阈值对照*人类评审一致性*来校准，把不确定情形升级给更强评审而非宣告不可行——其动作空间（升级）与真值目标（人类偏好，而非认证的任务可行性）都不同于本文的神谕。相关的承认无知与校准工作把同一主题延伸到检索增强问答、预训练语言模型的一般校准、以及单轮问答中的可疑假设检测——全部是单轮、纯文本设定，没有多步智能体轨迹或环境认证的可行性神谕。以上工作都确立了置信或弃答信号可以对照真实目标而非其原始频率来校准，但在每一处，该目标都是模型自身的知识边界、可验证的单轮答案、或人类评审一致性——从来不是关于一个多步智能体任务是否存在任何解的、经外部认证的事实，而这正是本文神谕提供的真值。

**智能体自我评估与交互式歧义消解。** 能力自评工作评估模型能否在可执行编码任务（BigCodeBench、SWE-bench）上提前预测自己的成功，从上下文经验更新置信度以在失败代价高昂时指导接受/拒绝决策——其测试床全部在原则上可解，因此低成功预测总是把"对这个模型难"与"对任何人都不可能"混为一谈。弃答训练工作（When Silence Is Golden）通过思维链监督后接强化学习的流水线与弃答感知奖励，教生成器在基准标注的不可回答时序问答问题上输出"无答案"——这是本文在*训练机制*上承认并区分的方法孪生：其奖励设计与 CoT+RL 配方是直接相关的先例，但其不可回答性继承自源基准中自然出现的时序矛盾，从未像本文设计所要求的那样被独立突变注入或机械神谕认证。一个面向临床数据库智能体的交互式基准评测用户请求含糊或欠规格时完整的澄清提问循环，把歧义当作可通过澄清*消解*的对象，而非要求智能体认证真正的不可行性并停下。三者在操作层面都最接近本文设定，但没有一个按构造把"对任何人不可解"与"未被这个智能体解决"分离开来，而这正是本文配对设计提供的分离。另一个先例族位于智能体基准内部：包含不可行、无关或不可能任务的评测划分，按执行模型是否在任务时拒绝（或钻空子）来打分。BFCL v3 的无关性检测划分（本研究将其复用为源领域）是最早的此类先例，此后该族已变得拥挤：AbstentionBench 覆盖单轮弃答的不可回答推理问题；ImpossibleBench 通过规格–测试矛盾把编码基准变为不可能——按构造认证——并度量执行智能体的作弊倾向；APB 增设不可解任务鲁棒性划分，在十二个模型上为规划时的校准拒绝打分；FeasiGen——本文最直接承认的构造方法孪生——从成功轨迹中识别关键工具并将其屏蔽，自动构建不可行的工具智能体任务，带人工验证的不可行性标签（约 94%）与第一方检测指标。FeasiGen 的屏蔽操作与本文的缺失资源突变是同一个构造动作，我们对该动作本身不主张任何新颖性；差异在于证书（由脚本而非人工验证检查的"必需且无替代"条件）、由预注册泄漏审计把关的匹配对表面控制、以及估计量（estimand）。这个族，坦率承认，度量的是第一方、任务时、非匹配单实例上的拒绝；本文的估计量在每条轴上都不同——对已完成轨迹的第三方事后归因、带机械认证真值的可解/不可解匹配对、以及完整的校准边界刻画而非拒绝准确率——没有任何先行工作覆盖的是这一组合，而非"不可行任务评测"本身。

## 结论

本工作把埋在 LLM 智能体失败归因方式内部的一个假设——失败的运行总包含一个应受归咎的决策——重新表述为一个带有精确可识别性结构的经验问题，而不是把"总有人有错"当作不证自明。核心的方法论押注是：只有当不可解性独立于智能体行为被认证、在同一固定框架下对照一组归因策略被检验、并针对观测差距最强的对立解释被压力测试之后，误归因、校准与"设计对上限"问题才是可分离的。无论度量结果指向哪个方向，发现都与决策相关：可修复的设计缺口支持把今天的标签空间与提示扩展出真正的可行性类别；真实的信息上限则支持把干预上移——移到如何让智能体自己识别并宣告不可行，而非事后如何读取其轨迹。三条局限从一开始就框定这一主张，它们是自然的后续而非事后补充：本研究的范围限于机械注入的不可解性，而非真实部署中出现的更混乱、有争议的不可解性；此处刻画的校准边界未必能迁移到下游消费者对两个错误方向权重不同的任务族；上限探针界定的是训练出的机器读取器能从轨迹中提取什么，而非调试实践最终消费的人类分析师判别上限——把报告的判别数字对照人类在轨迹样本上的表现做锚定，仍是开放的扩展。
