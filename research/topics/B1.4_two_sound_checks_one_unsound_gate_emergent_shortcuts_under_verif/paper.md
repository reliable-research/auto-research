## Step 0 — Core Asymmetry (升维)

**Invariant sentence:** A verifier's soundness certificate is valid only relative to the facet it checks and the candidate distribution its own gate induces, while Boolean composition of gates shifts exactly that distribution — so the act of adding a second certified-sound check silently destroys the precondition under which the first check's certificate was issued.

**判据 test (delete the domain nouns):** "A ___'s ___ is valid only relative to the ___ it checks and the ___ its own ___ induces, while composition of ___ shifts exactly that ___ — so adding a second certified ___ destroys the precondition of the first." Stripped of *verifier / soundness certificate / facet / candidate distribution / gate*, the residue is not merely empty — the generic reading is **provably false**: the conjunction of two extensionally sound acceptors on a fixed set is trivially sound (intersection of supersets of the truth set), and the disjunction of two total-correctness acceptors likewise. The sentence only becomes true (and interesting) once "sound" means *facet-relative, distribution-relative, budget-stamped certification* — the domain nouns carry the entire claim. Not a bridge: it names a violated closure property (soundness is not closed under Boolean composition in the facet-relative regime, per C1), not a connection between two fields.

## Step 5 — Formal Problem Definition

**Estimand (R1, guidance.md §3.4).** The per-(task, verifier-pair-type, composition-rule) emergent-gap indicator: whether a budget-matched adversary produces a candidate accepted by the composed gate (A∧B or A∨B) while failing held-out differential ground truth, with both single-verifier variants independently certified sound at the identical budget. Unit of analysis: one (task, verifier-pair-type, composition-rule) cell (5 exhaustive pilot families × 2 rules for existence; ~200 tasks × 6 pair types × 2 rules for prevalence). Reference population: the pre-registered bounded-DSL pilot suite (Stage 0) plus the EvalPlus/BigCodeBench benchmark-and-verifier-pair grid (Stage 1). Decision it feeds: whether Boolean composition of facet-certified verifiers is safe to deploy without a dedicated composed-gate audit (CO2's audit procedure is the artifact this estimand licenses).

**Notation.** Task T = (spec, reference solution r, differential corpus D, |D| ≥ 10⁴, EvalPlus-style amplified; for BigCodeBench and LiveCodeBench tasks, which ship no amplified corpus, D is generated by applying the same EvalPlus-style amplification to each task's reference tests, and any task whose corpus cannot reach the 10⁴-input floor is excluded and counted toward E2's thin-cell accounting rather than silently retained — design_review.md S-5 residual, "state the protocol or drop the dataset"). Ground truth GT(c) = 1 iff c(x) = r(x) ∀x ∈ D. A verifier V maps candidates to {accept, reject}. A gate G is a verifier or a Boolean composition A∧B / A∨B. Task variants per M1: tuple ⟨T, t_A, t_B, t_∧, t_∨⟩ sharing spec and full-task GT, where each variant v carries its **own pre-registered certification space** S_v ⊆ S_∘: the composed variants' space S_∘ extends each single variant's space S_A / S_B by exactly the constructs the added gate makes reachable (e.g., B's resource constraint admits lookup-table forms absent from t_A's DSL), per an extension rule fixed in M1's manifest before any certification runs. This operationalizes Step 0's "candidate distribution its own gate induces": each verifier is certified over the space its own gate's variant induces, never over the composed space. Constraint (per-variant spaces with a pre-registered extension rule) removes confound (an "emergent" shortcut that is really a post-hoc-chosen region no single certificate ever claimed to cover) — R3. The **degenerate same-space configuration** (S_A = S_B = S_∘, certificates against the shared GT) is provably incapable of emergent shortcuts — (A∧B)(c)=accept ⇒ A(c)=accept, and (A∨B)(c)=accept ⇒ A(c)=accept ∨ B(c)=accept, so any GT-failing composed accept contradicts one same-space single-gate certificate — and is therefore reserved as the null-by-construction placebo arm B0-P (Mandatory baselines). Attacker 𝒜 (M3) with budget N is applied identically to every gate.

Load-bearing adjectives from the Claims section, each with a computable definition:

| **sound** (facet-relative, per C1) | Sound(V, t, Π) = 1 iff certification procedure Π finds no shortcut against V on t. Pilot: Π = exhaustive enumeration of the variant's own certification space S_v (\|S_v\| ≤ 10⁷). Scale-up: Π = (mutant pool ≥10³ + certification attacker 𝒜_cert at budget B_cert), zero unsound acceptances — **𝒜_cert is a different model, prompt scaffold, and seed family from the comparison attacker 𝒜**; constraint (certifier/attacker separation) removes confound (winner's-curse selection: gates certified against 𝒜 itself would show FAR(single)≈0 in 𝒜's comparison by construction, baking in H2's headline) — R3 | machine-checkable certificate stamped with (facet, variant, space S_v, Π, budget) per M2 |

## Assumptions (A1–A6)

> Each entry below fills all five guidance.md §3.2 slots (assumption, failure_mode, detection, gate, consequence); *Gate* and *Consequence* were added in the Phase A re-run (`discussion/stage_review.md`, "Phase A (re-run)", item 5) because the prior draft stated detection mechanisms without naming which phase checks them or what happens to which H* on failure.

- **A1 (oracle validity).** The differential corpus D operationalizes task intent; GT=0 means genuine failure. *Failure mode:* D incomplete → "shortcut" measures the instrument (t1). *Detection:* pilot uses exhaustive enumeration + human adjudication of a 100-shortcut sample under a pre-registered rater protocol (added per design_review.md S-8.2 — R2 treats asserted validation without a protocol as absent): 2 independent raters, a written rubric (the task spec plus the differential corpus's intent statement; a sampled candidate is a genuine intent violation iff it is gate-accepted yet fails behavior the spec explicitly requires), Cohen's κ ≥ 0.7 on the binary intent-violation judgment, disagreements resolved by a third rater; ≥90% of the sample must be adjudicated as genuine intent violations, else D is re-amplified and affected cells re-run. *Gate:* PG-A1, run inside the walking skeleton (Step 9) and repeated on the Stage-1 100-shortcut adjudication sample before any H is scored. *Consequence:* below the 90% threshold, D is re-amplified and every affected cell is re-run before scoring; H1–H4 all depend on GT, so an unresolved failure here blocks all hypothesis scoring, not just one.
- **A2 (constructibility).** A bounded DSL exists that is enumerable ≤10⁷ candidates/task and contains both genuine solutions and shortcut-shaped candidates. *Failure:* space too poor or too big. *Detection:* walking-skeleton gate S-1 (below). *Gate:* PG-A2 = Step 9's Gate S-1, checked before any pilot or scale-up spend. *Consequence:* failure blocks Phase B entirely (construction restarts per Step 9); no H* can be scored until A2 passes, since E1–E4 all instantiate tasks through the same DSL generator.
- **A3 (certificate meaningfulness at scale).** Budget-stamped certification (B_cert) is a usable soundness proxy outside the pilot. *Failure:* latent single-gate shortcut voids an "emergent" label (N6 feasibility risk). *Detection:* mandatory 10× single-gate re-attack of every emergent-labeled shortcut before counting; headline existence claims anchored exclusively in the exhaustive pilot. *Gate:* PG-A3, applied continuously during E2/E3 (Stage-1) as each candidate "emergent" shortcut is discovered, not as a single upfront checkpoint. *Consequence:* a shortcut that fails the 10× re-attack is reclassified shared-blind-spot and dropped from the emergent-gap counts that feed H2 and H3a/H3b (degrades those hypotheses' evidence for the affected cell only); H1 is unaffected because it is scored only on the exhaustively enumerated pilot, where this assumption does not apply.
- **A4 (verifier determinism).** LLM verifier verdicts are stable enough under 3-of-3 to define a gate. *Failure:* flip rate high → gate is a coin. *Detection:* cells with verdict-flip rate >5% are excluded and reported (t5). *Gate:* PG-A4, monitored per-cell throughout E2 (Stage-1 sweep). *Consequence:* cells exceeding the 5% flip-rate threshold are excluded from the H2/H3a/H3b/H4 comparisons that use that cell and reported separately (restricts scope of those hypotheses' evidence base); does not block H1, which uses no LLM-based verifiers in the pilot.
- **A5 (attack symmetry).** The attacker has no structural per-gate advantage beyond the gate's own feedback. *Failure:* feedback-richness asymmetry manufactures "emergence" (t2/C3). *Detection:* identical prompts/budgets; publish per-gate discovery-vs-attempts curves; asymmetric curves at equal success trigger budget audit. *Gate:* PG-A5, checked continuously during E2/E3 via the published discovery-vs-attempts curves. *Consequence:* a triggered budget audit that confirms asymmetry degrades the affected verifier-pair comparison to INCONCLUSIVE for H2/H3a/H3b (per guidance.md Part 4 situation 5) rather than being scored as a positive finding.
- **A6 (grid feasibility).** ≥6 verifier-pair types can be instantiated on ~200 benchmark tasks (HumanEval+/MBPP+/LiveCodeBench post-cutoff/BigCodeBench, per N8 datasets) with certifiable single-gate behavior. *Failure mode:* pair types fail to instantiate at scale — single gates that cannot reach zero unsound acceptances at B_cert on enough tasks, or verifier types unavailable without training (e.g., the execution-free RM if no released checkpoint exists, per E4's instantiation rule) — leaving fewer than the 12 pre-registered primary comparisons, or cells below E2's thin-cell power floor. *Detection:* Stage-1 pilot gate — 10 tasks × full grid must certify before the sweep launches. *Gate:* PG-A6, the Stage-1 pilot gate itself (10 tasks × full grid), run once before the ~200-task sweep launches. *Consequence:* failure blocks E2–E4 (all of Stage-1: H2, H3a/H3b, H4) until the grid is shrunk along pre-declared axes (guidance.md Part 4 situation 10, fewer verifier-pair types rather than fewer tasks per cell, to protect power); H1 (Stage-0 pilot) is unaffected.

## Step 6 — Pre-Registered Experiments

### E1 (RQ1 — existence; pilot, exhaustive)
- **Assumption:** A1, A2.
- **Hypothesis H1:** H1 holds iff, for **each** composition rule (AND and OR separately), **≥3 of 5** exhaustively certified pilot task families contain ≥1 emergent shortcut — composed gate accepts a GT-failing candidate over the fully enumerated composed space S_∘ while both single-verifier variants are certified shortcut-free over their own exhaustively enumerated certification spaces S_A, S_B (Step 5 notation — the per-variant spaces and their pre-registered extension rule are what make this criterion satisfiable; over one shared space the outcome is provably impossible and that configuration serves as the B0-P placebo instead). Decision is exact (enumeration), no statistics. Partial outcome pre-registered: H1-OR and H1-AND are scored independently.
- **Metric:** binary per (family, rule): ∃c ∈ S_∘: G_composed(c)=accept ∧ GT(c)=0, with Sound(A,t_A,exhaustive over S_A)=Sound(B,t_B,exhaustive over S_B)=1.
- **Verification:** exhaustive enumeration certificate, machine-checkable; independent re-execution from released artifacts (CO2).
- **Fallback (full combination lattice, pre-committed):**
  - *H1 fails for AND only:* the paper's claim becomes: "Disjunctive verifier composition opens emergent shortcuts in the facet-relative regime; conjunctive composition resisted construction in a bounded space — the warning is scoped to OR-style gates (fallback branches, either-check-passes policies)."
  - *H1 fails for OR only:* the mirrored claim: "Conjunctive verifier composition opens emergent shortcuts in the facet-relative regime — the second gate's constraint displaces solutions off the space the first gate's certificate covers — while disjunctive composition resisted construction in a bounded space; the warning is scoped to AND-style gates (must-pass-all policies)."
  - *H1 fails for both rules AND H2 also fails:* → F-G1 (whose trigger requires exactly this conjunction).
  - *H1 fails for both rules BUT H2 passes:* F-G1 must **not** fire (its pivoted abstract would then be false). Pre-committed claim for this cell: "Emergent shortcuts resisted construction in the bounded pilot DSL, yet a budget-matched adversary finds them at significantly higher rates on composed than on strictest-single gates across realistic benchmark stacks — composition-induced unsoundness is a deployment-scale phenomenon whose existence evidence is the Stage-1 discovered shortcuts themselves (each machine-checked against held-out ground truth), not pilot certificates; the bounded-DSL negative is reported alongside as a limit of the construction method, not of the phenomenon."

### E2 (RQ_INF_2 — prevalence; Stage-1 sweep)
- **Assumption:** A1, A3, A4, A5, A6.
- **Hypothesis H2:** H2 holds iff in **≥4 of the 12** primary comparisons (6 verifier-pair types × 2 rules), FAR(composed) exceeds FAR(strictest single gate) with McNemar exact test p<0.05 after Holm–Bonferroni over the 12, **and** discordant-pair asymmetry ≥7 percentage points (the effect size the N8 plan powers at 0.8 with 200 tasks/cell), **and** at least one of the ≥4 is an AND-gate comparison.
- **Metric:** paired unsound-acceptance indicators per task; FAR and AttackSuccess@500 per gate (N8 formulas); odds ratios with 95% CIs.
- **Verification:** 200 tasks × 6 pair types; identical comparison attacker 𝒜 (fixed model, fixed scaffold, N=500/gate); single-gate certification uses the **independent certifier 𝒜_cert** (Step 5 "sound" row — different model, prompt scaffold, and seed family from 𝒜), so the comparison attacks draw randomness never used for certification selection; McNemar exact, Holm-corrected, α=0.05; every emergent-labeled shortcut passes the 10× single-gate re-attack before counting (A3).
- **Thin-cell policy (guidance.md Part 6 item 9 / Part 4 situation 5/10; added in the Phase A re-run).** The 200-tasks/cell target is what the N8 power note's 7pp/0.8-power detection floor assumes; if compute (situation 10) or A4/A5 exclusions (verdict-flip or budget-asymmetry cells) leave any of the 12 primary (verifier-pair-type × rule) cells below 150 tasks (the smallest n at which the same McNemar design still has ≥0.8 power to detect a 7pp discordant-pair asymmetry), that cell is **pre-declared INCONCLUSIVE** rather than scored as PASS, FAIL, or silently dropped or pooled with an adjacent cell; H2's "≥4 of 12" count is then evaluated only over the non-INCONCLUSIVE cells, and the number of INCONCLUSIVE cells is reported alongside the headline count. *Scorable-cell arithmetic (design_review.md S-8.4, pre-committed so the threshold is never improvised at verdict time):* with k < 12 scorable (non-INCONCLUSIVE) cells, the pass threshold scales proportionally to **≥⌈k/3⌉ of the k scorable cells** (preserving the pre-registered 4-of-12 ratio); the requirement that ≥1 qualifying comparison is an AND-gate comparison is unchanged; and a minimum of **k ≥ 6** scorable cells is required — below 6, H2 itself is declared INCONCLUSIVE rather than scored in either direction.
- **Fallback:** If H2 fails but H1 holds, the paper's claim becomes: "Composition-induced unsoundness is constructible and exhaustively certifiable, but a budget-matched adversary rarely finds it on realistic benchmark stacks — the risk is a tail event conditioned on verifier-pair structure, not an ambient property of two-check pipelines."

### E3 (RQ_INF_1 — structural conditions)
- **Assumption:** A3, A5 (uses E2's discovered shortcuts).
- **Hypothesis H3a (complementarity):** holds iff the logistic-regression coefficient of κ on per-cell emergent-gap incidence (controlling task difficulty and gate type, per N8) is positive with Wald p<0.05 (Holm-corrected within the secondary family) and odds ratio ≥1.5 per 1-SD increase in κ.
  **Hypothesis H3b (taxonomy concentration):** holds iff ≥60% of OR-gate emergent shortcuts fall in M4's weak-branch class and ≥50% of AND-gate emergent shortcuts in the constraint-displacement class (exact binomial CI excluding the uniform-over-4-classes rate of 25%, p<0.05).
- **Metric:** κ = 1 − Jaccard(kill_A, kill_B); M4 taxonomy labels from the ablation triple.
- **Verification:** regression pre-specified in N8 analysis_plan, with **cluster-robust (task-level) standard errors** for the Wald test — the same ~200 tasks recur across the six verifier-pair types, so per-cell observations are not independent and naive SEs would overstate precision (design_review.md S-8.5; the Holm-corrected McNemar family in E2 is unaffected, being valid under dependence); taxonomy labels double-annotated on the human-adjudicated 100-shortcut sample, Cohen's κ ≥0.7 required for the labeler.
- **Instrument validation for M4's taxonomy classifier (R2, guidance.md §3.4; added in the Phase A re-run — the prior draft stated only step ③ of R2's five steps).** The four-class taxonomy {OR-weak-branch, AND-constraint-displacement, facet-split, threshold-interaction} is itself a classification instrument and must clear all five R2 steps before Stage-1 scale-up, not only inter-rater agreement: ① *ground* the four classes in the composition-rule case analysis of Step 0/C1–C4 (OR-weak-branch and AND-constraint-displacement are the two mechanisms named in the paper's own closure-property argument; facet-split and threshold-interaction are added to cover shortcuts that fit neither, per C4's emergent-vs-shared-blind-spot distinction) — no class is invented post hoc from the data; ② *draft wide, refine on a held-out calibration set*: the first 20 pilot-family shortcuts (disjoint from the 100-shortcut adjudication sample) are labeled by the taxonomy's author and used to merge/split classes with named operations if two classes are never distinguishable or one absorbs >80% of cases — and because the pilot's pass criterion requires only ≥1 shortcut per family in ≥3 of 5 families, the pilot may yield fewer than 20 shortcuts in total, so the fallback calibration source is pre-committed (design_review.md S-8.3): the set is completed from a Stage-1 burn-in sample, the first scale-up-discovered shortcuts, kept disjoint from the 100-shortcut adjudication sample, before any scale-up labeling proceeds; ③ *validate* against 2 independent human raters on the 100-shortcut adjudication sample, Cohen's κ ≥0.7 required (already specified); ④ *inspect the confusion structure*: disagreements must fall between adjacent mechanism pairs (e.g., AND-constraint-displacement vs. facet-split, which share the "certified-on-a-different-distribution" root cause) rather than a systematic collapse onto one class, reported as a confusion matrix in the results; ⑤ *freeze* the taxonomy (hash the class definitions and the calibration-set labels) before the Stage-1 sweep launches, per the same freeze discipline as B_cert. Failure at step ③ or ④ triggers guidance.md Part 4 situation 7 (refine or simplify the construct) before H3b is scored; H3a's continuous κ-complementarity regression does not depend on the taxonomy and is unaffected.
- **Fallback:** If H3a and H3b both fail, the paper's claim becomes: "Emergent shortcuts exist (H1) and occur at measurable rates (H2), but are not predicted by mutant-kill-set complementarity nor concentrated by gate type — no cheap pre-deployment warning signal was found, strengthening the case that composed gates must be attacked directly to be audited." **Mixed outcome (pre-committed):** if exactly one of H3a/H3b holds, only the surviving half is claimed — H3a-only: "mutant-kill-set complementarity predicts where emergent gaps arise, but discovered shortcuts do not sort into gate-type-specific mechanism classes"; H3b-only: "shortcut mechanisms sort by gate type, but kill-set overlap does not predict incidence ex ante" — never both by implication. **Wrong direction (pre-committed, guidance.md Part 4 situation 4):** if the complementarity coefficient is significantly *negative* (odds ratio ≤ 1/1.5 per 1-SD increase in κ), this is reported at full prominence as a finding in its own right, not filed under the null wording: *overlapping* — not complementary — blind spots predict emergent gaps, the ex-ante warning signal inverts, and the C4 mechanism account is re-derived before any pre-deployment-screening claim is made.

### E4 (Claim-4 check — hardening vs. adding)
- **Assumption:** A3, A5, A6.
- **Hypothesis H4:** holds iff for ≥1 verifier-pair type, FAR(UTRL-style hardened single gate [UTRL, OpenReview:VqjNYF9nbP]) is lower than FAR(naive AND gate of the unhardened pair) by ≥5 pp, McNemar exact p<0.05, Holm-corrected within the secondary family — at equal total attack budget.
- **Metric / Verification:** same paired protocol as E2, hardened-gate arm from the N8 baselines grid. **Instantiation (training-free, so digest N6's "no training runs required" stays true):** the hardened arm imitates UTRL's *objective* (maximize the suite's discrimination against the current solver's failure modes) without its RL training — iterative adversarial test augmentation: run 𝒜_cert against gate A, add a killing test for every discovered unsound acceptance, repeat to a fixed iteration budget cost-matched to the naive-AND arm; the fidelity loss vs. trained UTRL is conceded in Limitations. Likewise, the execution-free-RM verifier type instantiates with a released off-the-shelf checkpoint if one exists at run time, else a prompted trajectory-judge proxy — never a new training run; if neither is workable, that pair type is dropped under A6's pre-declared grid-shrink rule.
- **Fallback:** If H4 fails, the paper's claim becomes: "Within the studied grid, adding a second facet-certified check never underperformed adversarially hardening the first — the composition warning (H1/H2) concerns silent certificate invalidation, not a prescription to prefer single hardened gates."

### Mandatory baselines
- **B0 — two jobs (guidance.md §3.3), split into two arms:**
  - **B0-C (current-practice / "why do this at all"):** the **no-composition arms** — verifier A alone and verifier B alone, each attacked on its own variant at the identical budget (N=500). If composed gates are statistically indistinguishable from the strictest single gate everywhere, no problem exists and the pipeline-audit motivation collapses (→ the F-G1 route); every H2 comparison is *against* B0-C by construction.
  - **B0-P (null-by-construction placebo — evaluated FIRST, before any H\* is scored, per goal.md §5 step 1):** the **degenerate same-space composition**. Pilot: certify A and B exhaustively over the full composed space S_∘ itself, then run the identical composed-gate attack. Stage 1: self-composition A∧A′ of two independently seeded instantiations of the same check, certified and attacked under the standard protocol. By the Step-5 impossibility argument (a GT-failing composed accept contradicts a same-space single-gate certificate; A∧A′ is extensionally A), the emergent-shortcut count in this arm **must be exactly 0**. Any nonzero count means the pipeline is measuring an artifact (GT incompleteness, certificate bug, attacker bookkeeping error): the run is recorded `{"run_valid": false}`, no hypothesis is scored, and diagnosis restarts from the walking skeleton (guidance.md Part 4 situation 1). This arm fills guidance.md §3.3 job (b), which the previous revision left unfilled.
- **B-alt — strongest-alternative-explanation control:** the rival explanation is **"the 'emergent' shortcut is an unequal-search artifact or a latent single-gate bug, not a product of composition"** (C3/C4, t2). Control: capability- and budget-matched **10× single-gate re-attack** of every emergent-labeled shortcut's task variants; any shortcut whose single-gate variant falls at 10× budget is reclassified shared-blind-spot and excluded from emergent counts. Secondary rival — "the culprit is *naive Boolean* aggregation, not composition per se" — is isolated by the R2-Guard-style rule-linked aggregation arm [R2-Guard, OpenReview:CkgKSqZbuC] run at equal budget.

### Global fallback F-G1
If the central family fails (H1 fails for both rules, and H2 shows no composed>single effect anywhere), the archetype pivots from empirical warning to **pre-registered negative result / refutation**. Pivoted abstract sentence: "Under a pre-registered, budget-matched adversarial audit with exhaustively certified components, Boolean composition of two facet-certified verifiers preserved soundness in every constructed and benchmark condition — bounding the composition risk that reward-hacking folklore attributes to multi-check gates, and shifting the burden of the '普适警告' claim to regimes (≥3 checks, thresholded aggregation) that our released audit suite now makes testable."

**Credibility preconditions for the pivot (guidance.md S9 negative-result bar; added per design_review.md S-4 — "an underpowered non-detection is nothing"):** the pivoted abstract may be asserted only if all three of the following accompany it, pre-registered here so they cannot be improvised at verdict time: (i) *family-grid coverage* — the pilot's construction failure is reported against a parameterized task-family grid (which family parameters were swept and over what ranges), not only exhaustive candidate-space enumeration within each hand-picked family, since exhaustiveness over candidates says nothing about representativeness over families; (ii) *search saturation* — the per-gate discovery-vs-attempts curves (A5) show saturation at N=500, and the emergent-gap-rate-vs-B_cert curve already committed in N6's mitigation is reported, so "found nothing" is evidenced as "stopped finding," not "stopped looking"; (iii) *attacker-scope restriction* — absent the attacker-generality ablation (a second, structurally different attacker at matched budget; currently unbudgeted, logged in design_review.md's Missing-RQs as future work), the null is claimed only for the attacker class actually run, never as attacker-general. If any of (i)–(iii) is unmet, the negative result is reported as INCONCLUSIVE-scoped rather than as the pivoted bounding claim.

## Step 9 — Walking Skeleton

**One binary question:** does one hand-constructed bounded-DSL task admit an OR-gate emergent shortcut, with all certificates machine-checked end-to-end and the placebo arm null?

- **Arms (4):** (1) enumerate certification space S_A for variant t_A, certify Sound(A) by exhaustion; (2) same for S_B / t_B / Sound(B); (3) enumerate the composed space S_∨ ⊇ S_A ∪ S_B (extension rule from the M1 manifest), search for c with (A∨B)(c)=accept ∧ GT(c)=0; (4) **placebo B0-P:** re-run arm 3 with certificates recomputed over S_∨ itself (S_A = S_B = S_∨) — by the Step-5 impossibility argument this arm **must** find nothing; any hit fails the skeleton (the pipeline is measuring an artifact).
- **Task set:** exactly 1 task (a small Python function per N6 Stage 0; A = unit-test suite, B = resource/style static check), |S_∨| ≤ 10⁶ for the skeleton, D fixed-seed with 10⁴ inputs.
- **Metrics:** deterministic only — exhaustive certificates + the binary existence bit + the placebo null bit. No LLM calls, no statistics.
- **Cost:** CPU-only, ≤8 wall-clock hours (≤10⁶ candidates × ~10 ms differential eval per arm, parallel; arm 4 re-certifies over S_∨), ~0 API cost, ~2 person-days construction.
- **Pass criterion:** the pipeline emits the per-arm machine-checkable certificate files, one binary answer, and a null placebo result, and re-running with a different task/verifier-pair/rule requires **only a config change** (task spec + per-variant DSL bounds + extension rule + gate wiring in a manifest), zero code changes. Skeleton passed → the 5-family pilot (E1) and the Stage-1 grid (E2–E4) are scaling, not engineering. Gate S-1: if no |S|≤10⁷ DSL yields both a genuine solution and any GT-failing accepted candidate for *any* single gate, A2 fails and construction restarts before any scale-up spend.

## Abstract v0 (draft, mechanism-first — DRAFT BEFORE RESULTS; numbers are pre-registered targets, not findings)

A verifier's soundness certificate is valid only for the facet it checks and the candidate distribution its own gate induces; Boolean composition shifts exactly that distribution, so stacking certified checks can void the certificates being stacked. We formalize facet-relative soundness, then isolate composition as a cause: matched task variants whose single-verifier gates are certified shortcut-free by exhaustive enumeration, attacked under strictly budget-matched search alongside their AND/OR compositions. We pre-register binary criteria for whether composed gates admit emergent shortcuts neither component admits (existence, exhaustive), how often a matched adversary finds them across 200 benchmark tasks and six verifier-pair types (McNemar, Holm-corrected), and whether mutant-kill-set complementarity predicts the gap. Rival explanations — latent single-gate bugs, unequal search effort, naive aggregation — are controlled by 10×-budget re-attacks, an independent certification attacker, and rule-linked aggregation arms; a same-space placebo composition, provably incapable of emergent shortcuts, is attacked identically and must return zero for the run to count. The audit suite is released for gating pipelines to run against their own stacks.
