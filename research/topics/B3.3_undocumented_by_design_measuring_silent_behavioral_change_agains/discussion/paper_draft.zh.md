# 变更日志不等于变更本身：测量已部署 LLM API 中的静默行为漂移

> 由 `pipeline.md` 中六个已确认阶段输出组装而成，已通过品味审计（`taste_audit.md`：🟢），并经 2026-08-21 复审修订（见 `review_2026-08.md`）。状态：**规格说明 / 论文草稿——尚未运行任何实验。** 下文所有数字均为预注册的设计目标，而非实验结果。

## 摘要

已部署 AI 系统的厂商按其独自掌控的节奏更新 API，而描述"改了什么"的变更日志（changelog）又是厂商独自撰写的文档——因此该记录的完整性无法从其内部得到验证。我们指出这并非假想的缺口：现有黑盒审计（black-box audit）工具能够检测到所服务模型的行为发生了偏移——最接近的工作甚至已在规模化部署中报告了疑似未披露的变更，其依据是"版本锁定（version-pinned）端点上的任何变化都推定为未公告"——但没有任何一个工具将检测到的变更与厂商自己的披露文本对齐，以判定哪些被记录、哪些没有。我们构建了一条流水线：对成对的更新前/后 API 快照运行按类别分层的行为探针（probe）电池；用校准过的同版本零假设分布（same-version null）与效应量下限（effect-size floor），把真实的跨版本变化与普通采样噪声区分开；再通过语义蕴含（semantic entailment）——以人工标注和字符串匹配下限校准——将每个检测到的变更与厂商变更日志中的声明对齐。探针类别锚定于独立发表的基准（benchmark）而非事后发明，因此任何"集中分布"模式都不可能是分类法人为构造的产物；版本边界用数据驱动的指纹不连续性（fingerprint discontinuity）归因，而非假定于公告日期；最终得到的静默变更率（silent-change rate）被诚实地报告为覆盖率条件下的下界（coverage-conditioned lower bound），只验证其稳定性而不宣称是点估计。我们在真实厂商 API 版本迁移上评估该设计，与同版本对照和朴素字符串匹配对齐器比较，报告被测行为变化中有多大比例静默逃逸于厂商披露之外，以及集中在哪里。

## 引言

大语言模型（LLM）API 按厂商独自掌控的节奏变化，而"改了什么"的记录又是厂商独自撰写的文档。集成商基于一个自己从未选择冻结的版本构建产品；审计者评估的系统，其行为可能已不同于上次测试时；而为 AI 系统起草"持续监测"条款的监管者，实际上是在要求当事方自我监督。变更日志是所有人都当作"版本间变更记录"的那份唯一文件——这使得一个问题值得被直接提出：这份记录到底有多完整？

然而关于这一安排的一个基本问题至今没有答案：实际发生的变化中，有多少从未出现在那份记录里？一个交付了行为变更并披露的厂商，与一个交付了同样变更却只字不提的厂商，都会发布变更日志——而仅凭变更日志文本本身，外部观察者无从分辨谁是谁。这不是一个次要的文档问题。如果真实行为变化中有相当份额是静默的，那么任何把变更日志当作完整记录的问责流程——把事故、回归或安全相关的偏移归因于"厂商说改了的那些东西"——就静默地继承了一个它既看不见、更无法界定的缺口。

最接近的已有工作只触及了这一问题的相邻部分而未将其闭合。最近的是 Chen、Zaharia 和 Zou 的研究：GPT-3.5 与 GPT-4 在两个带日期的快照之间、在固定任务电池上发生了显著的行为漂移——这是未披露漂移确实存在的直接证据，但该研究从未与 OpenAI 自己的发布说明交叉比对，以判定观察到的变化哪些被记录、哪些是静默的——而这正是本文要补上的缺失一步。其他黑盒审计工具解决的是相邻但不同的问题：连续对数概率追踪（logprob tracking）方法能检测到端点输出分布发生了偏移——并且已在数月的实地部署中标记出数十个疑似未披露的变更，但那里的"未披露"是从版本锁定继承来的推定，而非通过阅读任何披露文本作出的判定——基于秩的均匀性检验（rank-based uniformity test）则能检测到所服务的模型被悄悄替换成了另一个；但两者都止步于变更信号本身，既不将偏移归因到某个行为类别，也不与厂商实际发布的变更日志对齐。公平性专项审计测量微调后的发布版是否偏离其基座模型，但只限于刻板印象/偏见构念，从不对照变更日志文本。治理综述把由此产生的监测缺口编目为政策问题，却不自己构建或运行测量。本文问题所需的每一种原料都散落在这一版图的某处；但没有任何先前工作把它们组合起来对准厂商自己的披露文本。

把这一缺口转化为可测量的断言会浮现四个不同的困难。单条 LLM 输出即使在同一固定版本内也是随机的，因此真正的跨版本变化必须先与普通采样噪声、负载相关路由和提示敏感性区分开——而同版本噪声底线本身也是移动靶，不是固定常数。厂商变更日志是非结构化、粒度不一的散文体（"改进了推理""安全性更新"），因此判定一个检测到的行为偏移是否确实被某条变更日志声明蕴含，是一个开放的语义匹配问题，而非查表。任何关于*哪些行为类别*集中出现静默变更的断言，只有在类别边界并非"看到哪些探针发生了偏移之后"才划定的前提下才可信——否则"集中"发现就是循环论证。而且由于 API 所服务的模型通过滚动部署、未注明日期的变更和 A/B 路由更新，而不是干净的离散发布，把检测到的差异（diff）归因到变更日志条目所描述的具体发布窗口，本身就是不确定性下的推断，而非给定事实。

我们的方法把上述每个困难都转化为一个具体、可检验的设计选择，而非假设。校准差异检测器（calibrated diff detector）同时要求校正后的统计检验和最小效应量才判定探针发生变化，并直接在不存在真实变化的同版本对照上检查其行为。用语义蕴含对齐器而非关键词匹配器判定某条变更日志声明是否覆盖了检测到的差异，以人工裁决校准，并与朴素字符串匹配基线对比，以确证语义匹配的复杂度物有所值。行为类别锚定在为无关目的设计并发表的基准上，使集中分布的发现不可能是类别划定方式的产物。版本边界由持续记录的、数据驱动的指纹不连续性归因，而非厂商公告日期。并且由于"一次发布中实际改变的全部内容"永远不存在独立的真值，最终的静默变更率被明确报告为下界，并在独立探针子集下验证稳定性，而不是呈现为超出证据精度的数字。

我们在多家 LLM API 厂商的真实版本迁移上评估该设计，将跨版本流水线与同版本零对照、朴素字符串匹配变更日志对齐器比较，并按行为类别报告"已记录 vs 静默"的比率及自助法（bootstrap）置信区间。

综上，我们的贡献是：
- 将厂商变更日志完整性显式地表述为"无法从撰写它的系统内部验证"的结构性命题，并给出"已记录 vs 静默"行为变更的形式化定义——作为覆盖率条件下的下界，而非宣称的精确比率。
- 一个校准差异检测器，通过校正显著性检验与效应量下限，把真实跨版本行为变化与普通采样随机性分离，其假阳性行为直接在同版本对照上得到检查。
- 一个语义蕴含变更日志对齐器——用人工标注和朴素字符串匹配下限验证——为检测到的行为差异产出首个"已记录或静默"标签，而非仅有的变更信号。
- 一个锚定于独立发表基准的行为类别分类法，消除"看过数据后才发明类别方案"的循环性风险；并附带一个数据驱动的指纹检查，用于把差异归因到厂商未明确注明日期的发布窗口。
- 一份跨多厂商、多版本迁移的实证记录：被测行为变化中有多大比例是静默的、集中在哪里，诚实地报告为经过稳定性检查的下界。

## 问题定义

**形式化设定。** 考虑目标系统的相邻版本 v_t、v_{t+1}。探针套件 P = {p_1, …, p_M} 由固定的（提示，解码配置）对组成，每个探针属于类别 c(p_i) ∈ 𝒞（事实问答、拒答/安全、指令遵循/格式、推理/数学、工具调用、延迟/成本）。对探针 p 与版本 v，抽取 N 个重复样本 S_{p,v} = {y_{p,v}^(1), …, y_{p,v}^(N)}。厂商针对该迁移的变更日志为文本 L_{t→t+1}，解析为离散声明集 𝒦 = {k_1, …, k_R}。若 S_{p,t} 与 S_{p,t+1} 上经同版本零分布校正的双样本统计量在多重比较校正后仍显著、且越过最小效应量下限，则该探针被标记为**检测到的差异**（detected diff），D(p)=1。若存在某个 k ∈ 𝒦 在语义上蕴含该差异，则该差异为**已记录**（documented），Doc(p)=1；否则为**静默**（silent）：Silent(p) = D(p) ∧ ¬Doc(p)。研究对象是由此得到的按类别与总体的静默变更率 ρ_c 与 ρ，报告为相对于所测探针套件 P 的**覆盖率条件下界**，而非对"实际改变的全部内容"的绝对比率。

**难点所在。** 固定 P 并不能固定 D(p) 的干净定义：由于同版本 LLM 采样本身就有变异（负载相关路由、提示敏感性），用于判定 S_{p,t} 与 S_{p,t+1} 的跨版本差异是否"真实"的零分布必须被估计而非假定，否则任意增大探针数量就能制造出显著但微不足道的差异。计算 Doc(p) 需要把探针的检测差异与 𝒦 匹配，但 𝒦 提取自非结构化、粒度不一的散文，其声明可能同时蕴含许多探针、也可能没有一条精确对应——这是多对多的语义关系，不是查表。使 ρ_c 有意义的类别映射 c(·)，只有当 𝒞 的边界独立于哪些探针最终满足 D(p)=1 而事先固定时才有信息量；为解释已观察到的模式而构造的类别方案，会使任何关于 ρ_c 非均匀性的断言沦为循环论证。而且由于 API 所服务的 v_t、v_{t+1} 并不总是由干净的、注明日期的发布分隔，把 S_{p,v} 的样本归到某次具体迁移的正确一侧——以使 L_{t→t+1} 恰好是应当对齐的那份变更日志——本身就是不确定的。最后，由于没有外部方能观察到"一次发布实际交付的每一处变更"，ρ 与 ρ_c 永远只能被部分识别（partially identified）：可以在 P 的变化下验证其**稳定性**，但永远无法被认证为真实比率。

## 方法总览

在概念层面，本研究是一条由五个协作部件组成的单一测量流水线，每个部件闭合上述一个困难。成对快照与探针套件进入流水线；校准检测器把所得样本转化为真实差异标记，并在同版本对照上得到检查；语义对齐器把每个被标记的差异与厂商自己的变更日志声明比较，转化为"已记录或静默"标签；基准锚定的类别方案把所得标签转化为在构造上不可能循环的分类法；基于指纹的边界检查裁定哪些迁移足够干净、可用于归因；稳定性检查则把所得比率从不可验证的点断言转化为经过验证的下界。

**校准差异检测器**对探针的两个快照各取重复样本，用重采样估计同版本零分布，只有当校正显著性检验与效应量下限同时通过时才标记真实差异——并直接在不应存在真实差异的同版本对照上检查。**基于蕴含的变更日志对齐器**对每个被标记的差异与该迁移解析出的变更日志声明，用语义蕴含而非字符串重叠判定其是否已被记录。**类别锚定分类法**把每个探针指派到由独立发表基准定义的类别，使按类别比率的集中模式不可能是类别划定方式的产物。**边界指纹**模块持续记录 API 的轻量分布签名，只在该签名出现真实不连续处才宣布迁移"干净"，把主结论限制在能可信归因的迁移上。**覆盖稳定性检查**从探针套件的独立随机子集重算所得比率，报告一致性而非断言比率绝对正确。

## 方法论

### 校准差异检测器

**挑战。** 同版本 LLM 采样本身就有变异——负载相关路由、提示敏感性与普通随机解码意味着从*同一*版本抽取的两组样本已然不同，因此仅凭固定显著性阈值可被探针数量与微小效应量钻空子。

**洞见。** 同版本零分布不是可以假设掉的固定常数，而是要直接估计并检验的分布；同时要求校正显著性检验与最小效应量、并在不存在真实变化的同版本对照上验证，把"这是不是真实差异"变成可证伪的条件而非假定。

**方法。** 对每个探针，每个快照抽取 N 个样本；用版本内重采样估计同版本零分布；施加置换/自助双样本检验，固定显著性水平并在迁移内跨探针做 Holm 校正；只有再越过最小标准化效应量下限，探针才被标记 D(p)=1。相同流程另在同版本（A/A）重采样对上作为零对照运行，使检测器自身的假阳性行为被直接测量而非假定。

### 基于蕴含的变更日志对齐

**挑战。** 厂商变更日志是非结构化、粒度不一的散文——一条声明可能同时蕴含多个探针类别，也可能没有一个精确对应——因此判定检测到的差异是否被变更日志覆盖是开放的语义匹配问题，不是关键词查表。

**洞见。** 只有语义的——而非词面的——匹配器才能泛化到各厂商不同的披露风格；把语义匹配器与朴素字符串匹配下限对比，才使"语义对齐配得上其复杂度"成为可检验的断言而非假设。

**方法。** 将每次迁移的变更日志与发布说明文本解析为离散声明集。对每个检测差异的描述与该集合中的每条声明打蕴含分；若其与任一声明的蕴含分越过在人工标注开发子集上调定的阈值，则标记为已记录，否则为静默。同样的对齐还用朴素关键词/字符串重叠匹配器计算一遍，作为下位基线，衡量这项标注任务中有多少是查表、多少是真正的推断。

### 类别锚定分类法

**挑战。** 在观察到哪些探针出现静默变更之后才发明的行为类别分类法，会使任何"集中"发现沦为循环论证——类别总可以被划得恰好吻合已经可见的模式。

**洞见。** 把每个类别锚定到一个为无关的原始目的设计并验证过的独立发表基准，就打破了这种循环性，因为类别边界在任何静默变更测量之前、且独立于其被固定。

**方法。** 每个探针类别由一个与本研究无关的基准定义：事实问答探针取自既有知识问答基准，推理/数学探针取自既有数学推理基准，幻觉探针取自真实性基准，过度拒答与拒答不足的安全探针取自互补的既有安全基准，格式/指令遵循探针取自既有指令合规基准，工具调用探针取自既有函数调用基准。各类别静默变更率经跨类别齐性检验比较，两两比较做 Holm 校正。

### 边界指纹

**挑战。** API 所服务的模型通过滚动部署、未注明日期的变更和 A/B 路由更新，而非干净的离散发布，因此把"之前""之后"的样本配对到变更日志条目所描述的具体发布窗口本身就不确定。

**洞见。** 当部署是滚动的或未注明日期时，公告的发布日期不是可靠的配对依据；廉价、持续记录的行为指纹中的不连续性是真实边界的数据驱动信号，可独立于厂商选择公告什么、何时公告来检验。

**方法。** 持续轮询 API，并随时间记录一个轻量分布指纹（首 token 的 top-k 对数概率剖面）。指纹工具本身继承自先前的对数概率追踪工作——首 token top-k 对数概率剖面正是该工作已为廉价变更检测验证过的信号——本文不对其宣称任何新颖性；本文的增量在于其*角色*：以指纹的不连续性作为迁移清洁度门控，裁定披露对齐断言可归因于哪些迁移。只有指纹不连续性超过版本内指纹方差处，迁移才被宣布"干净"；主静默率断言限于干净迁移，含糊或未注明日期的迁移被隔离并单独报告，而非静默混入。本模块还确定了一个资格约束：它要求端点暴露 token 对数概率，而生产端点中只有少数满足，因此在监测任何迁移之前，厂商选择先按对数概率可得性筛选。

### 覆盖稳定性检查

**挑战。** "一次发布中实际改变的全部内容"不存在独立记录，因此测得的静默变更率永远无法被认证为真实比率——只能是以所测探针套件覆盖率为条件的下界。

**洞见。** 既然比率的绝对正确性不可检查，可信度的最近似替代就是稳定性：从同一探针套件独立抽取的子集能否恢复出相同或相近的比率。

**方法。** 把某次迁移的探针套件切分为两个不相交的随机半集，在每个半集上独立重算静默变更率。两个半样本比率在预先设定的容差内的一致性，与全样本比率一并报告，作为该估计的稳定性证据，而非隐含宣称全样本数字精确正确。

## 实验

### 实验设置

**数据集与探针来源。** MMLU 锚定事实问答类别（既有的广覆盖知识基准）。GSM8K 锚定推理/数学。TruthfulQA 锚定幻觉/事实准确性失败模式。XSTest 锚定安全行为的过度拒答方向（安全提示被错误拒绝），AdvBench/HarmBench 锚定互补的拒答不足方向（本应拒绝的有害提示被回答）——两个方向都需要，因为厂商可能在版本间朝任一方向静默移动拒答行为，只用一个来源会让安全/拒答类别对未覆盖的方向失明。IFEval 锚定格式/指令遵循合规。BFCL 锚定工具/函数调用行为。自行抓取的、跨多家 API 厂商的变更日志/发布说明语料是流水线对齐的记录文本。

**快照获取与研究窗口门控。** 成对的前/后样本来自两个来源：存在时使用厂商注明日期的快照端点，以及一个前瞻性监测臂——持续轮询每个筛选后的端点，使未注明日期的迁移的两侧都在发生时被捕获——对早于监测开始的迁移做回溯测量是不可能的，因此厂商集合先行固定、监测先于任何迁移评分启动。由于干净迁移按厂商而非研究的时间表到来，设计预注册了研究窗口门控：只有当厂商集合中累计出现至少两次指纹干净迁移与两次被隔离迁移后才为 RQ5 评分；在此之前 RQ5 报告为待定，而不在功效不足的切分上作答。

**基线**（健全性检查比较对象，不是要击败的竞争者——这是测量研究，没有任何研究问题被表述为"我们的流程胜过基线 X"）。同版本（A/A）对照——在两个同版本重采样上运行完全相同的流水线——是每个跨版本断言的必要检查。朴素关键词/字符串匹配变更日志对齐器是为语义对齐器的额外复杂度提供正当性的弱下位基线。先前的黑盒变更检测工具（对数概率分布双样本追踪器；基于秩的模型替换检验）作为仅变更检测的比较对象运行：若某探针的差异两个先前检测器都未标记，那是对本流水线额外覆盖的健全性检查，不是优越性断言。

**指标。** 跨版本与同版本（A/A）条件下的检测差异率；总体与按类别静默变更率（ρ、ρ_c）及自助法 95% 置信区间；蕴含对齐器相对人工标注及字符串匹配下限的 F1；每次迁移的指纹不连续状态；对半切分比率一致性。

**研究问题：**
1. RQ1——差异检测器能否在同版本零分布下控制假阳性、同时仍检测到跨版本变化？
2. RQ2——检测到的行为差异中有多大比例没有匹配的变更日志声明？
3. RQ3——自动变更日志对齐能否复现人工"已记录/静默"标签，并优于朴素字符串匹配下限？
4. RQ4——静默变更是否集中于特定的、外部锚定的行为类别？
5. RQ5——把主结论限制在指纹干净的版本边界上，对报告的比率是否有影响？
6. RQ6——静默变更率在探针套件的独立随机子集间是否稳定？

**与预注册协议的编号对照**（`paper.md` 按 H1–H3 而非 RQ 编号假设）：RQ1 检验 H3(b)（A/A 假阳性界，门 PG-1）；RQ2 检验 H1（静默率多数断言，含跨厂商投票规则）；RQ3 检验 H3(a)（对齐 F1 效度断言，门 PG-3）；RQ4 检验 H2（类别集中断言）。RQ5 与 RQ6 无 H 编号：它们分别是边界归因（假设 A4，门 PG-4）与探针覆盖稳定性（假设 A5，门 PG-5）的预注册工具效度检查。

#### RQ1：差异检测器能否在同版本零分布下控制假阳性、同时仍检测到跨版本变化？

**设置。** 试点阶段：一家厂商、一次干净边界版本迁移，约 200 个探针覆盖 5–6 个类别，每快照 N=50 个样本；置换双样本检验取 α=0.05，跨探针 Holm 校正，效应量下限 |Cliff's δ| ≥ 0.33。相同流程另以等采样预算在同版本（A/A）重采样对上运行。规模化：≥3 家厂商 × 各多次迁移。

**预期结果。** A/A 对照标记检测差异（D=1）的比率不高于名义 α=0.05；跨版本臂的检测差异计数至少是 A/A 臂假差异计数的 3 倍。

**证伪条件。** 若 A/A 对照的假差异率超过 α（检测器在无真实变化时也制造发现），或跨版本臂的检测差异计数未达到预注册的 3 倍余量（跨版本"差异"在统计上与检测器自身噪声底线不可区分），则被驳倒——任一情形都意味着主静默变更率是检测器而非厂商真实行为的产物。按预注册后备方案，A/A 假差异率超过 α 不会终止研究：效应量下限上调至恢复 A/A 臂 FPR ≤ α 的最小值，所有比率在校正下限下重新推导，且校正下限与原始下限一并透明报告——绝不静默替换。

**假设（通俗表述）。** 流水线能把真实的跨版本行为变化与普通同版本采样噪声区分开，而不只是声称能。

**指标。** 跨版本 vs. A/A 的检测差异率与计数；两臂间的倍数比。

#### RQ2：检测到的行为差异中有多大比例没有匹配的变更日志声明？

**设置。** 对某次迁移中每个被标记 D(p)=1 的探针，用蕴含对齐器对照该迁移解析出的变更日志声明计算"已记录/静默"标签；聚合为总体比率 ρ 并给出自助法 95% 置信区间（≥1000 次重采样），按厂商分别报告而不合并。由于 ρ 按厂商计分，H1 由预注册的**跨厂商投票**裁决：PASS 要求在 ≥3 家受测厂商中至少 2 家满足 ρ>0.50 且置信区间下界也 >0.50（贡献少于 20 个检测差异的厂商因功效不足被排除出投票，不计为"否"）。在 Stage-0 试点规模、仅测一家厂商时，H1 完全不计 PASS/FAIL——报告为**待规模化后再定**，直至 ≥3 厂商投票可用。

**预期结果。** 跨厂商投票通过：在 ≥3 家受测厂商中至少 2 家，ρ 超过 0.50 且自助法 95% 置信区间下界也超过 0.50。

**证伪条件。** 若跨厂商投票失败（≥3 家受测厂商中不足 2 家满足 ρ>0.50 且置信区间下界 >0.50），则被驳倒——此时核心前提（静默是多数结局）在受测厂商集中不成立，论文断言按预先承诺的后备方案从"静默是默认"转为"静默是不可忽视的少数"，按厂商直接报告测得的 ρ 及其置信区间而非多数框架，主结论改为围绕 RQ4 的"存在性与类别结构"发现而非多数占比。

**假设（通俗表述）。** 对受测系统而言，统计上检测到的行为变化多数是未记录的，而非例外。

**指标。** 按厂商的总体静默变更率 ρ 及自助法置信区间。

#### RQ3：自动变更日志对齐能否复现人工"已记录/静默"标签，并优于朴素字符串匹配下限？

**设置。** 由两名标注者对 ≥200 个差异/声明对进行人工裁决并解决分歧，报告 Cohen's κ（标签效度要求 ≥0.6）。蕴含对齐器的"已记录/静默"标签与该人工标注子集比较得 F1，并与朴素字符串匹配对齐器在同一子集上的 F1 比较。

**预期结果。** 蕴含对齐器相对人工标注达到 F1 ≥ 0.70，并以预先设定的、非平凡的差距超过字符串匹配基线的 F1。

**证伪条件。** 若蕴含对齐器 F1 低于 0.70，则被驳倒（对齐不可靠）；若字符串匹配基线的 F1 与蕴含对齐器在统计上不可区分，则被驳倒（语义匹配是不必要的复杂度）——任一情形都会削弱"本文对齐步骤不止是查表"的断言。按预注册后备方案，F1 低于 0.70 不会撤回 M4：自动对齐器从主力工具降级为人机协同辅助（自动标记加强制人工裁决），静默变更率只在人工标注子集上报告，自动流水线断言明确改标为"辅助性"而非已验证。

**假设（通俗表述）。** 判定变更日志是否覆盖某个检测到的行为变化是真正的推断问题，关键词搜索无法替代。

**指标。** F1（蕴含 vs. 人工，字符串匹配 vs. 人工）、人工标注子集上的 Cohen's κ。

#### RQ4：静默变更是否集中于特定的、外部锚定的行为类别？

**设置。** 对每个拥有 ≥20 个检测差异的基准锚定类别计算按类别静默变更率 ρ_c（低于该阈值的类别合并报告为功效不足，不单独检验）。用卡方齐性检验检查 ρ_c 是否跨类别均匀；用 Holm 校正的两两比例检验检查预测的特定排序（安全/拒答、格式/指令遵循、延迟/成本各自高于事实准确性）。

**预期结果。** ρ_c 跨类别非均匀（卡方在 α=0.05 拒绝相等），且两两检验中安全/拒答、格式/指令遵循、延迟/成本各自显著超过事实准确性。

**证伪条件。** 若齐性检验未拒绝均匀性，则被驳倒（静默是普遍的、与类别无关的）；若 ρ_c 非均匀但预测排序不成立，则在方向上被驳倒（是另一种集中模式）——后一情形下，无论观察到何种集中，都作为发现报告，因为分类法的价值在于揭示真实结构，而非确认某个特定的预测顺序。

**假设（通俗表述）。** 厂商并非对每种行为变化都同等可能不予记录——某些行为类别被静默改动的频率远高于其他类别。

**指标。** 按类别 ρ_c 及自助法置信区间；卡方统计量；两两比例检验结果。

#### RQ5：把主结论限制在指纹干净的版本边界上，对报告的比率是否有影响？

**设置。** 连续指纹记录把每个候选迁移分类为干净（指纹不连续性超过版本内方差）或隔离（无清晰不连续，如未注明日期或滚动变更）。比较干净与隔离迁移之间的检测差异率，并把仅在干净迁移上计算的主静默变更率与合并所有迁移（含隔离）的朴素估计比较。

**预期结果。** 干净迁移的检测差异率显著高于隔离迁移，且仅干净的主比率与朴素合并估计有实质差别（不只是不确定性更宽）。

**证伪条件。** 若干净与隔离迁移的检测差异率在统计上不可区分，或仅干净与朴素合并的比率在噪声内一致，则被驳倒——任一情形都意味着基于指纹的边界检查没有承重，更简单的按日历配对本已足够。

**假设（通俗表述）。** 把差异归因到变更日志实际描述的发布窗口，需要数据驱动的边界检查，而不是仅仅相信厂商公告的发布日期。

**指标。** 按迁移清洁度状态的检测差异率；仅干净 vs. 合并静默变更率比较。

#### RQ6：静默变更率在探针套件的独立随机子集间是否稳定？

**设置。** 对每个拥有足够检测差异的（厂商 × 迁移）单元，把探针套件切分为两个不相交的随机半集，在每个半集上独立重算静默变更率；两个半样本比率的一致性与预先设定的容差比较。

**预期结果。** 在多数受测单元中，两个半样本比率在预设容差内一致。

**证伪条件。** 若一致性在受测单元间低于多数阈值，则被驳倒——那意味着报告的比率对恰好纳入哪些探针敏感，动摇其作为"厂商披露实践的属性"而非"任意选定探针清单的属性"的解读。

**假设（通俗表述）。** 报告的静默变更率描述的是厂商如何记录变更的真实属性，而非用哪些具体探针测量它的产物。

**指标。** 受测单元间的对半切分比率一致率。

## 相关工作

与本文最接近的先前工作是 Chen、Zaharia 和 Zou 对 ChatGPT 行为随时间漂移的研究，值得在综述更广版图前先把增量说清楚：该工作已证明两个带日期的 GPT-3.5/GPT-4 快照之间、在固定任务电池上存在显著可测的行为漂移，但它从未与厂商自己的发布说明交叉比对，以判定观察到的变化哪些被披露、哪些是静默的——这正是本文要补上的对齐步骤，也是"已记录 vs 静默"比率从未为任何已部署系统（包括该最接近工作已测量的那个）被报告过的原因。

**黑盒 API 变更与模型等同性检测。** 连续对数概率追踪方法用固定的极简提示反复查询端点，并对所得 top-k token 对数概率施加非参数双样本检验，给出所服务分布已偏移的廉价通用信号。该方向的实地部署是与本文核心问题最接近的已发表证据：对十家提供商的 189 个生产端点监测四个多月，报告了 37 个疑似未披露的变更——但那里的"未披露"是从版本锁定继承的推定（锁定端点本不应有任何变化），而非通过解析厂商披露文本作出的判定，该工作自己也将后者列为范围之外；同一方向的一个 token 高效后继工作（arXiv:2602.11083）降低了同一检测信号的查询成本，但未增加任何披露环节。基于秩的均匀性检验则提出更窄的二元问题——所服务模型是否与可信本地参考相同——通过在该参考下为补全打百分位秩并检验均匀性，标记静默的模型替换。相关的另一条线把微调模型的黑盒输出溯源回其预训练基座，属同一类关切（API 背后未记录的替换），但经由谱系归因而非披露对齐解决。这些工作确立了已部署 API 中的行为变更或替换是可检测的，但没有一个把检测到的偏移归因到行为类别、或与厂商实际披露对齐；仅有的变更信号——即便被推定为未披露——不是"已记录或静默"标签，也从未有"已记录 vs 静默"比率被报告。

**关系型与公平性专项行为审计。** 一条工作线通过在共享公平性提示上把每个模型的行为表示为多视角签名并计算两两相似度，测量微调发布版是否偏离其基座模型，专门在偏见/刻板印象构念内检测继承与漂移。相关工作表明此类构念下的单次审计易受平台伪装——向审计方提供合规的审计面模型、与用户面模型不同——并提出用审计者的私有标注先验使此类操纵在统计上可检测。两者都局限于公平性专项构念与一次性审计设计，既不覆盖本文分类法锚定的一般行为类别，也不跨发布序列纵向追踪文档忠实度。

**治理立场与问责基础设施。** 一份技术 AI 治理综述把监管条款——注册、评估、审计、尤其是持续监测——分解为具体技术需求，并编目当前工具在何处无法满足；一篇姊妹立场论文指出独立第三方评估是这一切的结构性前提，鉴于服务条款（ToS）限制使此类评估在法律上处于敌意环境，提出配套的法律与技术安全港。一个面向 AI 原生工程团队的组织风险框架从部署方一侧独立指出了同一问责缺口——"提供商更新权重、第三方工具契约漂移……却没有对应的变更事件"——而一份针对 LLM 评审器/评估器漂移的标准化协议提案在栈的上一层提出了同一结构性关切（针对评估器而非被评估系统），以社区版本化而非变更日志文本对齐来解决。这四者都没有构建或运行实证工具——它们为审计提供了动机，却未将其操作化。

**纵向漂移测量与序贯统计机制。** 基于鞅的下注框架给出对群体公平性零假设的任意时刻有效（anytime-valid）序贯检验，在持续监测与可选停止下仍正确——是纵向审计可复用的统计机制，但没有解析散文变更日志或构建行为类别分类法的机制。一个跨十年的恶意软件基准展示了严格时间切分下的纵向概念漂移评估，但针对的是第一方分类器自身的精度退化，而非黑盒厂商行为与该厂商自身文档之间的缺口。连同上文讨论的直接先例，这些工作确立了本文所需的每一种统计与方法学原料都散落在文献某处——但没有一种被对准过厂商自己的披露文本。

## 结论

本工作把厂商变更日志完整性——通常被理所当然地当作 API 版本间变更的记录——重新表述为可实证测量的量而非假设，因为掌控系统何时变化的一方，在结构上正是撰写该变化记录的同一方。核心方法学承诺是：只有当工具自身的性质被检查而非假定时，这一测量才可信——差异检测器会不会被同版本噪声愚弄、变更日志对齐器是不是不止关键词搜索、类别分类法会不会自制集中模式、版本边界归因是否重要、主比率是稳定的还是特定探针清单的产物。无论测得的静默变更率是多少，该发现都具有决策相关性：高比率意味着基于变更日志的问责当前不可靠，需要一个恰如本研究的外部周期性检查；低比率本身也是关于受测厂商披露实践的重要发现——且任一结果都报告为覆盖率条件下界而非精确绝对数字。两条局限从一开始就界定了该断言。第一，测得的比率永远无法被认证为真实比率，因为"一次发布中实际改变的全部内容"永远不存在独立记录——本设计报告并稳定性检查一个下界，而不宣称其无法拥有的精度。第二，受测厂商的发现未必推广到文档文化、发布节奏或服务基础设施不同的厂商——且受测集合本身按对数概率可得性筛选过，并非市场的随机样本——这正是按厂商分别报告而不合并为单一数字的原因；扩展受审计厂商集合是自然的下一步，而非事后补充。若核心假设族整体失败——RQ2 的跨厂商投票未通过且 RQ4 的类别比率均匀——贡献并不消失：按预先承诺的方案,它从测量-发现论文转向工具论文,以经过验证、误差已刻画的文档忠实度流水线本身为主要贡献,并把零结果报告为与问责相关的校准发现（受测系统的厂商变更日志基本忠实），而非失败的研究。
