# 通道不等于内容：对 LLM 版本对之间能力、策略与格式漂移的校准分解

## 摘要

当 LLM 提供商发布新模型版本时，下游用户能观察到行为变化，却很少被告知底层究竟是什么发生了移动：是模型的能力（capability）、其对齐或安全策略（policy），还是仅仅其默认的输出格式（format）。标准的纵向审计只报告一个混合的前后差值（blended before/after delta），无法区分这三种原因——而对 ChatGPT 行为随时间变化的经典审计发现，一次表面上的能力退化实际上部分源于格式变化（新增的 markdown 代码围栏）破坏了可执行性检查，把表面漂移误归因为能力损失。我们把 LLM 版本对（version pair）之间的行为漂移分解为能力、策略与格式三个分量，采用三套探针题库（probe battery），每套都通过构造使另外两个轴保持固定，并辅以显式的跨轴泄漏估计（cross-axis leakage estimate）与版本内噪声底（within-version noise floor），把普通采样波动与真实漂移分离开。由于没有任何真实版本对带有经过验证的真实原因，我们在解释任何真实版本对的分解之前，先在已知主导轴的构造对照对（constructed control pairs）上盲测其恢复能力，以此校准整套流程。将该方法应用于多家供应商的版本对后，我们检验所得的轴主导结构是跨提供商复现的行业共性还是供应商特有的，并检验对混合审计不可见的格式漂移是否在当前实践报告为能力变化的部分中占据不可忽略的份额。

## 引言

大型语言模型提供商如今频繁发布新模型版本，往往彼此相隔仅数周；基于固定 API 端点或已下载检查点进行构建的做法已如此常规，以至于版本升级被当作背景噪声，而非值得单独审视的事件。用户与集成方确实会在这类更新后注意到行为变化——原本能成功的任务现在失败了、原本会配合的回复现在拒绝了、原本能干净解析的输出现在解析不了——但报告这种变化的标准方式，即单一的混合前后分数，把这三类截然不同的事件同等对待。

然而，关于每次此类更新的一个核心问题是这个数字本身无法回答的：模型是真的变聪明了，还是其对齐或安全策略发生了偏移，抑或除了默认格式习惯之外什么都没变？这三者的下游后果完全不同、完全不可互换。能力变化要求重新做任务性能基准测试；策略变化要求重新审计安全与合规姿态；格式变化只需要修一个脆弱的解析器。把它们混为一谈并非假想的风险。对 ChatGPT 行为随时间变化的经典纵向审计发现，代码生成上一次表面的能力退化实际上部分由新增的 markdown 围栏破坏了可执行性检查所致——一个纯格式变化被打分并报告为能力损失。而且这种"聚合数字掩盖可分离原因"的结构并非版本审计特有：一项对 LLM 在 SFT 与 RL 后训练下泛化方式的细粒度分析表明，单一的混合准确率差值掩盖了底层推理技能构成的可分解变化——同样的混淆，只是发生在训练方法轴而非版本轴上。如果今天的标准审计无法可靠地排除这一点，那么每一条"模型能力在快照之间退化"的头条结论，都可能恰恰被本文要分离出的这种表面伪影所混淆。

这一问题的直接前身是最早记录它的纵向审计：ChatGPT 行为随时间变化研究报告了快照之间单一的混合逐任务差值，没有任何机制把该差值归因于能力、策略或格式，而其自身报告的代码生成下降正是本文所针对混淆的直接证据——这一点值得在综述更广阔的图景之前直白说出，因为其核心局限催生本文的那篇论文，恰也是该现象首次被记录之处。然而，*当代*最近邻是 2026 年一个快速推进的、围绕模型更新治理（update governance）与变化检测（change detection）的工作簇，它们包围了这一问题却并未占据它：部署方更新治理按风险类别——其中包括功能、格式与安全——测试新版本，并明确把在提供商透明度有限条件下检测并解释模型漂移列为开放挑战（arXiv:2604.27789）；黑盒变化检测以极少 token 确认被服务的模型*发生了*变化，但不回答为什么（arXiv:2602.11083）；条目级可靠变化分析（reliable-change analysis）对照模型内采样波动底线检测*哪些*条目真正移动了——它预示了本文所用的噪声底，这笔"债"我们明确承认——但止步于二元变化而不涉及原因（arXiv:2604.27405）；而评测流水线中的随时有效（anytime-valid）漂移归因把指标偏移在服务系统与评审器（judge）之间分摊，这是由人工标注锚定的另一对原因（arXiv:2606.15474）。检测、逐类别把关与双向的"系统对评审器"归因由此均已被占据；对版本对漂移在能力、策略或格式之间进行黑盒、校准门控的三路归因则没有。在这一簇之外，相关工作从相邻但不同的角度接近该问题。对分阶段对齐影响的研究用基于影响函数的数据归因把行为变化归到特定训练阶段，但这需要商业版本对从不暴露的检查点与训练数据的白盒访问，且只测量可信性维度，没有能力或格式轴。基于逐 token 散度或两模型间权重差的工具能以细粒度隔离单一轴，但都需要 API 商用版本对不可得的 logit 或全权重访问，且都不把观测到的总差异在竞争性原因之间分摊。一个把拒绝倾向与知识局限分开的秩相关度量证明策略与能力是不同的、可分别测量的构念——但只在单一模型的单一时间点上，完全没有版本对或漂移的框架。而基于评审器的评测框架记录了表面长度与风格会系统性扭曲自动打分，却把这当作要在排名指标中惩罚掉的干扰偏差，而不是一个一等的、单独报告的行为变化轴。

把这一空白变成可测量的问题会浮现四个独立的障碍。真实版本对的行为差异由哪个原因产生并无真值（ground truth），因此任何归因主张除非能在原因恰好已知的对上间接检验，否则有不可证伪之虞。旨在隔离一个轴的探针仍可能被另一个轴以探针自身输出不可见的方式污染——策略变化可以以看似格式漂移的方式改变回复长度，能力变化可以以看似策略漂移的方式翻转一次拒绝决策。普通的逐次采样波动，以及研究中途静默基础设施变更的可能性，除非被测量并扣除而非假设不存在，否则会伪装成真实漂移。并且由于各供应商可能通过完全不同的底层机制实现概念上相似的变化——比如收紧的拒绝规则可以来自策略层、系统提示编辑或输出过滤器——任何"归因结构跨供应商共享"的主张都有可能只反映工具恰好如何构建，而非行业的真实事实。

我们的方法把每个障碍都变成一个具体的、可检查的设计选择，而非一句托辞。由于输出文本既是黑盒测量唯一可用的通道、本身又是供应商变更的目标，而内容变化不会像格式变化那样改变表面特征分数，三套探针题库各自通过构造把另外两个轴固定——冻结通道以还原内容。由于没有真实对带有已知原因，整条流水线在主导轴由设计确定的构造对照对上盲式校准，且除非该校准门（calibration gate）先通过，否则不对任何真实对做出任何主张。跨轴污染不是被假设不存在，而是被显式估计并作为独立的泄漏份额（leakage share）报告；版本内噪声底——并经交错查询窗口的稳定性验证——决定一个轴的贡献必须多大才算漂移而非采样噪声。最后，跨供应商可通约性（commensurability）通过实证检验：对每家供应商施加同一工具，并检查所得轴主导排序跨供应商的一致程度是否超过随机预期。

我们在多家商业与开放权重供应商的版本对上评估该设计，并同时运行一个复现当前标准实践的混合差值基线（blended-delta baseline），以及一个必须完全检测不到"漂移"的同模型空对安慰剂（null-pair placebo）。

综上，我们的贡献是：
- 一个校准协议：在对真实、黑盒、真实原因不可验证的版本对做出任何主张之前，先在已知原因的构造对照对上验证行为漂移归因程序。
- 显式的跨轴泄漏估计与版本内噪声底模型：把"探针题库彼此正交"与"这个差值真的是漂移"从沉默假设变为被报告的、可证伪的量。
- 一个跨供应商结构检验：检验能力/策略/格式的轴主导是行业共享模式还是供应商特有模式，以行为方式评估，而非从并不存在的供应商文档中假设。
- 一份实证记录：对混合前后分数不可见的格式漂移，是否在标准纵向审计当前报告为能力或策略变化的部分中占据不可忽略的份额。

## 问题定义

**形式化设定。** 考虑来自同一提供商的版本对 P = (v_old, v_new)，二者都只能通过普通文本输入/输出访问——流水线中任何环节都没有 logits、权重或训练数据。一个"对"定义为两个直接可比、相邻发布、在研究窗口内可同时查询的快照，而非跨越多个中间版本的链条。行为变化沿三个候选来源 a ∈ {capability, policy, format} 测量，探针题库的条目以固定解码设置、每条目每版本 k = 5 次重复采样，对两个版本做完全相同的查询。对每个来源 a，轴份额（axis share）η²_a(P) 是观测到的版本间差异中可归于该来源的比例，其估计须超出由重复采样计算的版本内噪声底 σ²_w(P)。泄漏份额 λ(P) 刻画一个轴的测得信号中由另一轴独立测得特征所解释的比例；它作为独立量报告，绝不静默并入 {η²_a}。一个对的主导轴为 dom(P) = argmax_a η²_a(P)。对一组构造得使真实主导轴事先已知的对，恢复准确率（recovery accuracy）Acc 是 dom(P) 与已知原因相符的比例。跨供应商一致性由对三个轴份额的逐对排序计算的 Kendall's W 概括——m ≥ 6 个对中每个对贡献一个对三轴的排序，作为一个排序单元（ranking unit）——并对置换零假设（permutation null）检验；供应商层面的结构经由轴份额单纯形上的聚类做描述性报告，因为若仅以三家供应商作排序单元，精确置换零假设除完全一致外无法达到 p < 0.05。

**为什么这很难。** 没有任何真实版本对带有其行为差异的经过验证的真实原因，因此关于 η²_a(P) 的归因主张是不可证伪的，除非底层程序的可靠性能以其他方式检验——具体而言，在真实原因已知的构造对上检验，这正是许可（或否证）在原因未知的真实对上信任同一程序的依据。三个来源在原始行为上并不正交：策略变化可以以看似格式漂移的方式改变回复长度，能力变化可以以看似策略变化的方式翻转拒绝决策，因此任何报告的 η²_a(P) 都有静默吸收另一轴效应之虞，除非轴间泄漏被估计并报告，而非假设为零。由于 LLM 输出是随机的、服务基础设施可能在研究中途无告知地变动，真实的版本间差异必须先与普通的版本内采样波动区分开，否则 σ²_w(P) 本身就成了不可靠的参照，所有下游 η²_a(P) 估计随之被污染。最后，由于供应商内部机制从不可直接观察，"能力""策略""格式"是否为跨提供商可通约的构念无法从文档或源代码访问中验证——只能行为化地检验：检查同一工具应用于每家供应商的对时，产生的轴主导排序跨供应商的一致程度是否超过置换零假设。另有两条可辨识性（identifiability）上的限制内在于校准策略本身，须作为一等限制报告而非隐藏：构造对照对是在其所要验证的同一套能力/策略/格式分类法（taxonomy）之下定义的，因此通过校准只确立了"分类法对齐的干预是可恢复的"——而非该分类法穷尽地覆盖了真实漂移；且对照对必然由开放权重模型构建，而被审计目标包括商业规模的服务栈，因此校准跨规模与栈的迁移（calibration transfer）是一个待压力测试的假设（经由下文的混合轴对照与规模阶梯），而非既定事实。

## 方法概览

在概念层面，本研究是一条包含四个协作部分的单一测量流水线。探针题库与构造对照对进入流水线；校准步骤先确定所得分解是否可信，然后才解释任何真实对；泄漏与噪声核算模型把原始的逐条目行为差值转化为附带自身不确定度与污染界的可报告轴份额；跨供应商一致性检验把逐对分解转化为"同一结构是否跨提供商复现"的主张。

**轴隔离探针题库与对照对校准**模块构建三套探针题库，每套都通过构造使另外两个轴对其测量量影响最小，并另行构造已知主导轴的对照对，盲式运行完整流水线以检查其能否恢复真实原因。**跨轴泄漏估计**模块把每个轴的测得信号回归到其他轴独立测得的特征上，把被解释的比例作为显式泄漏份额报告，而非任其静默偏置所报告的轴份额。**噪声底方差模型**由重复采样估计版本内的逐次方差，并拟合混合效应模型（mixed-effects model），使一个轴对观测漂移的贡献只计超出该底线的部分，同时检查底线本身在研究窗口内是否稳定。**跨供应商结构一致性检验**把每个对概括为轴份额单纯形（simplex）上的一个点，并检验逐对的轴主导排序在对之间——以及描述性地在供应商之间——的一致程度是否超过置换零假设的预期。

## 方法

### 轴隔离探针题库与对照对校准

**挑战。** 没有任何真实版本对为其行为差异带有已知、可验证的原因，因此任何归因主张都有不可证伪之虞——没有可以直接对照检验的东西。

**洞见。** 纠缠无法在真实对上解析地解决，因为没有真实对提供真值——但分解程序的*可靠性*仍可间接检验：构造原因由设计确定的对，在其上盲式运行完全相同的题库与模型，然后才把程序应用于原因未知的真实对。

**方法。** 三套探针题库各自通过构造使另外两个轴对其测量量影响最小：能力题库使用格式鲁棒的抽取（执行代码、规范化数值匹配、受限多选抽取），使其分数对表面格式不变；格式题库仅限于两个版本都已接近天花板正确的提示，使能力差异无法泄入格式测量；策略题库按独立已知的真值有害性分层提示，使拒绝率变化能对照固定参照解读，而不与正确性混淆。另行构造每次只修改一个轴的对照对——基础模型对同一模型在领域数据上微调的版本作为能力对照，基础模型对安全微调变体（遵循 Related Work 所引过度拒绝对比精炼工作的安全对齐微调配方）作为策略对照，相同权重在改动的系统模板下作为格式对照——从而与任何真实供应商对不同，真实主导轴是已知的。随后在分析代码不知道对身份的情况下运行完整、未修改的流水线，并把预测的主导轴与真实主导轴比较。

有两个设计要素划定了这套校准能许可与不能许可的范围，二者都被当作协议的一部分而非事后补充。第一，单轴对照对是在其所要验证的同一套三轴分类法之下构造的，因此对它们的盲恢复只表明工具能检测分类法对齐的干预——并不表明真实漂移被该分类法所覆盖——而真实供应商对很可能是原因的混合，而非纯粹个案。因此对照集还包含混合轴对（mixed-axis pairs）：以已知相对剂量施加两种干预构造的对（例如一次安全微调更新叠加一次系统模板变更），其已知主导轴必须在同一盲协议下被恢复，使校准覆盖本文头条真实对主张实际所处的混合情形。第二，对照对由小型开放权重模型构建，而被审计对包括商业规模服务栈，因此校准迁移本身是一个假设而非设计的推论：一个规模阶梯（scale ladder）在两个或更多开放权重规模上重复仅格式对照与空对安慰剂，检查恢复准确率与泄漏份额是否随规模稳定。强烈的规模趋势将警示校准数字不能被搬到前沿对上；无论结果如何，迁移这一步都作为显式限制报告，绝不静默假设。

### 跨轴泄漏估计

**挑战。** 名义上隔离一个轴的探针题库仍可能被另一轴污染，且这种污染从该题库自身输出中不可见。

**洞见。** 由于泄漏的轴在其自身测量内部与不泄漏的轴看起来完全一样，泄漏只能通过显式地把一个轴的信号回归到另一轴独立测得的特征上来暴露——把"题库彼此正交"从沉默假设变成被报告的、可证伪的数字。

**方法。** 把每个条目的能力题库差值回归到该条目的格式特征差值上，把每个条目的策略题库差值回归到词法与表面线索上，以估计名义上的能力或策略信号中有多大比例实际由表面形式协变量解释。这一被解释比例作为附加于该对的显式泄漏份额报告，而非被静默吸收进能力或策略轴份额。

### 噪声底方差模型

**挑战。** 版本到版本的行为差异只有超出同一版本自身在重复查询中会产生的波动，才是漂移的证据——否则普通采样波动或研究中途的静默基础设施变更会伪装成真实效应。

**洞见。** 把原始观测差值直接当作噪声底，恰恰会让随机采样波动被误读为漂移；底线必须直接从版本内重复采样估计，其在研究窗口内的稳定性也必须检查而非假设。

**方法。** 每个探针条目在固定解码设置下对每个版本采样五次，以估计该版本、该条目的版本内逐次方差。在所得逐条目差值上拟合以轴为固定效应、条目为随机效应的混合效应模型，使一个轴对观测漂移的估计贡献只计超出合并版本内方差底线的部分。一个对的两个版本在交错时间窗口中查询，并把研究窗口前半段的噪声底估计与后半段比较，以检测否则会污染底线本身的静默基础设施漂移。

### 跨供应商结构一致性检验

**挑战。** "能力""策略""格式"在不同供应商间是否为可比构念，无法从供应商内部文档验证，因为根本没有文档——同一标签的变化在不同提供商那里可能经由完全不同的底层机制实现。

**洞见。** 跨供应商可通约性即使无法结构性验证，也可以行为化检验：如果同一工具以同样方式应用于每家供应商的对，产生的轴主导排序跨供应商的一致程度超过随机置换的预期，这就是三个轴作为共享构念而非工具构建方式的三个供应商特定伪影在起作用的证据。

**方法。** 每个版本对的分解概括为轴份额三元单纯形上的一个点。跨供应商结构以两种方式检验：一个以对为排序单元计算的秩一致统计量（Kendall's W）——m ≥ 6 个对各贡献一个三轴排序，给出可达的置换零假设（m = 6、n = 3 时 χ² ≈ m(n−1)W ≈ 7.2 于 W = 0.60，p ≈ 0.027），而只以三家供应商为排序单元的供应商层检验除完全一致（P(W=1) = 1/36 ≈ 0.028）外无法达到 p < 0.05——以及对单纯形点的聚类分析，描述性地检查对是按供应商身份成组还是跨供应商混合超出置换零假设的预期。

## 实验

### 实验设置

**数据集。** GSM8K、MMLU-Pro 与 HumanEval 以客观可验证、按执行或精确匹配打分的条目锚定能力题库。纳入 LiveCodeBench 专门是因其滚动发布设计，可防止能力题库条目在一个对的两个版本之间有差异化的训练数据暴露——否则该混淆会使测得的能力轴变化与污染伪影无法区分。XSTest、OR-Bench-Hard-1K 与 SORRY-Bench 把策略题库分层为"安全但看似不安全""伪有害"与"真正有害"的提示，使拒绝率变化能对照固定的真值有害性参照解读，而不与正确性混淆。IFEval 锚定格式题库的指令格式遵循度测量，并辅以一个单独预验证的、两个版本都已接近天花板正确的提示池。由于 2026 年前沿对在 GSM8K、HumanEval 与 MMLU-Pro 的大部分条目上处于或接近天花板——而天花板条目不携带能力漂移信号，这会机械地压低能力轴份额、抬高格式与策略的相对份额，是一种*偏向*本文自身偏好结论的偏倚——能力题库应用一个与格式题库近天花板筛选方向相反的镜像步骤，即去天花板预验证（off-ceiling pre-verification）：能力条目按对预筛为至少一个版本可测地低于天花板的条目池，使题库构成内生于该对，而非内生于某个固定基准的原始难度。条目级可靠变化分析报告 MMLU-Pro 的多数条目对现代模型对处于地板或天花板饱和（arXiv:2604.27405），这是该筛选步骤的实证基础；且凡是格式份额被作为头条结论之处，残余偏倚的方向都被明确说明。

**基线**（健全性检查 / 误归因演示的比较对象，不是要击败的竞争者——这是一项测量研究，没有任何研究问题被表述为"我们的程序击败基线 X"）。混合差值审计复现经典 ChatGPT 行为随时间变化研究的设计——每任务一个聚合差值，无格式鲁棒打分、无噪声底、无分解——在仅格式的构造对照对上运行，以检验标准实践是否确实把纯格式漂移误归因为能力或策略变化。空对安慰剂在不相交的交错时间窗口内对同一快照查询两次并走完整流水线；因为它按构造是同一模型对自身，其上任何轴"检出"都是流水线伪影而非真实现象的证据。一个双路消融完全去掉格式轴（仅能力与策略），在仅格式对照对上运行，以检验第三个轴是承重的而非装饰性的。

**指标。** 带自助法（bootstrap）置信区间的轴份额 η²_a(P)；泄漏份额 λ(P)；版本内噪声底 σ²_w(P) 及其前半段对后半段稳定性；对照对上的主导轴恢复准确率 Acc；跨供应商秩一致的 Kendall's W 及置换零假设 p 值。

**研究问题：**
1. RQ1 —— 以仅格式对照对评判，探针题库是否按构造正交？
2. RQ2 —— 完整流水线能否在已知原因的构造对照对上盲式恢复真实主导轴？
3. RQ3 —— 题库与校准就位后，残余跨轴泄漏有多大？
4. RQ4 —— 估计的版本内噪声底在研究窗口内是否足够稳定，可作参照？
5. RQ5 —— 在真实版本对中，是否有多个轴超出噪声底？格式是否占据不可忽略的份额？
6. RQ6 —— 轴主导的排序跨供应商的一致程度是否超过随机预期？

#### RQ1：以仅格式对照对评判，探针题库是否按构造正交？

**设置。** 在仅格式构造对照对（权重相同，仅系统模板改动）上，测量能力题库的逐条目正确性差值与策略题库的拒绝率差值，并各自经置换检验对照其自身版本内噪声底。

**预期结果。** 在这些仅格式对上，能力题库的正确性差值与策略题库的拒绝率差值均与各自版本内噪声底无显著差异。

**证伪条件。** 若在按构造只有格式轴变化的对上，能力或策略题库中任一显示出显著超出其噪声底的差值，则被否证——那意味着该题库并非按设计对格式正交，任何真实对解读都必须依赖泄漏回归估计（RQ3）而非正交性假设。

**假设（通俗表述）。** 能力与策略题库如其设计的那样，对纯格式变化没有反应。

**指标。** 仅格式对照对上，各题库对版本内噪声底的置换检验 p 值。

#### RQ2：完整流水线能否在已知原因的构造对照对上盲式恢复真实主导轴？

**设置。** 在至少九个单轴构造对照对（每轴三个）加上至少三个已知主导轴的混合轴对照对（以已知相对剂量施加两种干预）上，在分析代码不知道对身份的情况下运行完整流水线，把预测的主导轴与真实主导轴比较，并同时报告同批对上的平均估计泄漏份额。规模阶梯迁移检查（见"方法"）在两个或更多开放权重规模上重复仅格式对照与空对安慰剂。

**预期结果。** 流水线在至少九分之八的单轴对照对以及至少三分之二的混合轴对上恢复真实主导轴，平均泄漏份额低于 0.15，且恢复准确率与泄漏份额在规模阶梯上稳定。

**证伪条件。** 若恢复准确率不显著高于三分之一的随机水平（精确二项检验，如九对中五对或更少正确），或平均泄漏份额达到或超过所报告的最大轴份额，则被否证——二者任一都意味着该工具的可靠性不足以许可对真实的、不可校准的对做任何主张，本文的核心主张（RQ5、RQ6）必须报告为未获校准门支持，而非按字面解读。若流水线能恢复纯单轴原因却在混合轴对上失败，则*专就混合情形*——独立于单轴结果——被否证，此时真实对的分解须报告为仅对纯粹情形完成校准，这是一个明显更弱的许可，必须与每一条下游主张并列陈述；若规模阶梯显示恢复准确率或泄漏份额存在强规模趋势，则*就校准迁移*被否证，此时任何校准数字都不得在无显式迁移警示的情况下搬到商业规模的对上。评分受预注册功效规则（假设 A8、门 PG-7）约束：若某轴三个对照对上检测泄漏低于 0.15 的试点重算功效低于 0.9，该轴对恢复准确率的贡献报告为 INCONCLUSIVE（不确定）而非按通过/失败评分，"九分之八"的门槛只在有功效的轴上评估，并明确说明缩减后的分母。

**假设（通俗表述）。** 分解程序是经过校准的：当真实原因已知时，程序能找到它。

**指标。** 恢复准确率（对 1/3 随机水平的精确二项检验）；带自助法置信区间的平均泄漏份额。

#### RQ3：题库与校准就位后，残余跨轴泄漏有多大？

**设置。** 把每个对照对的能力题库与策略题库差值回归到其他轴独立测得的特征上（能力对格式特征；策略对词法/表面线索），把被解释方差比例报告为该对的泄漏份额。

**预期结果。** 估计泄漏份额在构造对照对上平均低于 0.15——与校准门（RQ2）认定分解有效所要求的阈值相同。

**证伪条件。** 若平均泄漏份额达到或超过 0.15，或任一单轴的泄漏大到去掉该轴估计会翻转某个真实原因已知的对照对的主导轴判定，则被否证——二者任一都意味着所报告的轴份额无法彼此独立地解读。

**假设（通俗表述）。** 题库间的跨轴污染真实存在，但小到不足以破坏所报告的份额。

**指标。** 平均及逐对泄漏份额，带自助法置信区间。

#### RQ4：估计的版本内噪声底在研究窗口内是否足够稳定，可作参照？

**设置。** 对每个被测版本对，比较由研究窗口前半段计算的版本内噪声底估计与后半段的估计。

**预期结果。** 每个被测对的前半段与后半段噪声底估计一致在 20% 以内。

**证伪条件。** 若某对的前半段与后半段估计相差超过 20%，则被否证——那将表明研究中途存在静默基础设施变更污染了噪声底，该对的任何轴份额估计都必须报告为不可靠，而非对照一个漂移中的参照。

**假设（通俗表述）。** 在研究期间，噪声底是一个足够稳定、可供真实漂移对照的参照。

**指标。** 前半段对后半段噪声底估计之比，按对、按题库。

#### RQ5：在真实版本对中，是否有多个轴超出噪声底？格式是否占据不可忽略的份额？

**设置。** 以 RQ2 通过为门槛。在至少六个真实版本对上，对每个轴的贡献相对其对的噪声底做置换检验（对"对×轴"族做 Holm–Bonferroni 校正），并报告每个对中格式轴占已解释漂移的份额。

**预期结果。** 至少六分之四的真实版本对中，三个轴中至少两个的贡献显著超出噪声底；且至少六分之三的对中格式轴份额至少占已解释漂移的 10%。

**证伪条件。** 若在打分改为格式鲁棒之后，每个被测对的格式轴份额都低于已解释漂移的 10%，则朝"格式可忽略"方向否证——此时结论变为：混合审计表面上的格式敏感性是可用格式鲁棒抽取器修复的打分伪影，而非真实第三行为轴的证据，本文的主张 3 被反转而非确认。若泄漏加噪声在多数对中吸收了观测差异的大部分、没有轴明显高于其底线，则朝"分解不成立"方向否证。预期结果与两种否证都按预注册功效规则（假设 A8、门 PG-7）评分：十八个"对×轴"单元中任何试点重算功效低于 0.9 的单元，同时从"至少六分之四"与"至少六分之三"计数的分子与分母中剔除并单独报告为 INCONCLUSIVE——绝不作为通过、失败或静默丢弃处理。

**假设（通俗表述）。** 版本更新通常同时移动不止一个轴，而对混合分数不可见的格式漂移，在被报告为行为变化的部分中不是可忽略的贡献者。

**指标。** 逐对、逐轴对噪声底的置换检验 p 值；带自助法置信区间的逐对格式轴份额。

#### RQ6：轴主导的排序跨供应商的一致程度是否超过随机预期？

**设置。** 以 RQ2 通过且 RQ5 成立为门槛。在来自至少三家供应商的至少六个真实版本对上，对三个轴份额的逐对排序计算 Kendall's W——每个对作为一个排序单元贡献一个排序——对 10,000 次抽取的置换零假设检验；另外，描述性地检查这些对在轴份额单纯形上按供应商身份聚类的程度是否超出同一置换零假设的产出。排序单元是对而非供应商，因为否则下述显著性阈值在最小设计下不可达：以三家供应商为排序单元、三个轴排序时，精确置换零假设给出 P(W=1) = 1/36 ≈ 0.028，且所有 W < 1 都有 p > 0.05；而 m = 6 个对时，χ² ≈ m(n−1)W = 7.2 于 W = 0.60，p ≈ 0.027——该设计下的最小可达 p 与结果并列报告。

**预期结果。** 逐对排序上的 Kendall's W 至少为 0.60 且置换 p < 0.05，并且各对不按供应商身份紧密聚类超出置换零假设预期（描述性聚类检查）。

**证伪条件。** 若 Kendall's W 与置换零假设统计上不可区分（p ≥ 0.05），或各对按供应商身份紧密聚类超出零假设，则被否证——二者任一都表明轴主导结构是供应商特有而非共享的，意味着纵向审计实践不能假设一家供应商的配方可迁移到另一家，必须为每家供应商预算一套定制工具。由于底层问题按构造是双向的，无论哪种答案都完全可发表。进入 Kendall's W 的主导排序继承同一预注册功效规则（假设 A8、门 PG-7）：主导轴判定依赖某个被报告为 INCONCLUSIVE 单元的对，其自身在本检验中也报告为 INCONCLUSIVE——从一致性统计量及其否证中同时剔除，绝不静默丢弃。

**假设（通俗表述）。** 支配一家供应商版本更新的三轴结构同样支配另一家，而不是每家供应商都有自己特有的"版本升级通常改变什么"的模式。

**指标。** Kendall's W（以对为排序单元）及置换零假设 p 值，并报告实际 m 下的最小可达 p；供应商标签聚类相对置换标签零假设的轮廓系数（silhouette score）（描述性）。

## 相关工作

本文的动机性前身是 ChatGPT 行为随时间变化研究，在综述更广阔图景之前值得直白说明差异：该研究已记录了本文要以工具刻画的确切现象——快照之间单一的混合逐任务差值，其自身报告的代码生成下降后来部分可归于一次被打分为能力损失的格式变化——但它没有提供任何机制把检测到的差值归因于能力、策略或格式，只审计一家供应商，也无法回答其发现是否跨提供商泛化。本文的贡献恰是一个经校准的工具，完成该研究自身设计无法执行的归因。然而，*当代*最近的先行工作已不再是那份 2023 年审计，而是接下来综述的 2026 年更新治理与变化检测簇；下文的定位对每一处重叠都明确让步（concede），而非宣称一片空场。

**检测与治理模型更新但不做归因。** 2026 年的一条工作线是本文最近的当代邻域。部署方更新治理（arXiv:2604.27789）按风险类别测试更新后的模型——其中包括功能、格式与安全，正是本文所测量的三分法——但形式是逐类别的通过/失败验收门，且它明确把在提供商透明度有限条件下检测并解释模型漂移列为开放挑战而非已解决问题；本文正是针对该归因步骤的工具。黑盒变化检测（arXiv:2602.11083）以极少查询标记被服务模型与参照不同；条目级可靠变化分析（arXiv:2604.27405）对照模型内采样波动底线识别哪些基准条目真正变化了——后者预示了本文所用的版本内噪声底，因此本文在该组件上的存留增量是噪声底在三路归因内部的角色，连同单独报告的跨轴泄漏份额，而非二元变化检测。经由消融拒绝方向（abliteration）的拒绝—能力分离（arXiv:2606.05396）干净地解开了本文三轴中的两个，但用的是 API 服务对不可得的白盒权重空间干预，且没有版本对框架。评测流水线漂移的随时有效归因（arXiv:2606.15474）用一个经校准的序贯检验把指标偏移在服务系统与评审器之间分摊——是本文"校准优先"立场在方法上最近的亲属——但它在另一对原因之间归因、依赖人工标注锚集，且没有能力/策略/格式分解。纵观该簇：更新被检测、被把关、或被双向归因；没有一项对版本对漂移执行黑盒三路归因，也没有一项在解释真实对之前先在已知原因的构造对上盲式验证其归因。

**纵向 LLM 行为审计。** ChatGPT 行为随时间变化研究是"已部署模型行为在发布快照之间发生可测变化"的经典证明，评估了涵盖数学、敏感问题、观点调查、代码生成与推理的固定任务套件。关于适配器（adapter）在演化基础模型检查点之间鲁棒性的工作记录了同一现象的下游后果：针对一个快照训练的适配器随底层模型更新而静默退化，被迫完全重训。二者都确立了版本漂移真实且有后果，但都把它当作未分化的前后（或训练前后）扰动，而非要在竞争性原因间分摊的对象——前者每任务报告一个混合数字，后者把漂移当作要鲁棒对抗的干扰而非要诊断的现象。

**借助模型内部访问归因行为变化。** 分阶段对齐影响分析用基于影响函数的数据归因把训练检查点之间的行为差异归到训练流水线的特定阶段，但需要受控白盒流水线的检查点与训练数据——黑盒商业版本对从不暴露这些——且其测量维度全部是可信性侧面，没有能力或格式轴。经由对齐模型与其基座之间逐 token KL 散度诊断浅层对齐，能精确定位回复中安全效应集中之处，但需要对被比较的两个模型都有 logit 访问。学习把两模型间的权重差翻译为其所致行为变化的自然语言描述，同样需要对两个模型的全权重访问。三者都证明当内部可得时细粒度归因是可能的，而没有一个适用于审计者最需要答案的那类对——商业 API 快照。

**在单一时间点分离策略与能力、格式。** 一个把模型在事实性问题上的拒绝概率与错误概率分开的秩相关度量证明，在单一模型内部，拒绝行为（策略）与知识局限（能力）是不同的、可分别测量的构念——但它是单时间点的校准度量，没有版本对或漂移框架，也没有格式轴。关于减少过度拒绝的工作表明安全微调会把真正有害与仅表面有风险的提示在模型内部表征空间中耦合起来，为把"良性但表面有风险"的提示作为策略探针的判别性分层提供了实证依据——其安全微调配方也正是本文自身策略对照对构造（见"方法"）所采纳的——但其诊断需要表征空间访问，其目标是修复一个模型，而非测量两个已部署版本之间的漂移。基于评审器的评测框架记录了自动打分被回复长度与风格系统性偏置，并在单时间点排行榜内用长度惩罚指标校正——这证明表面形式混淆是真实的、先前已被记录的测量问题，但在那里被当作要控制掉的干扰，而非一等的、单独报告的行为轴（并且值得注意的是，那是一个长度特定的校正，而非覆盖本文格式题库所针对的 markdown/列表/措辞回避等轴的通用格式鲁棒打分理论）。

## 结论

本工作把纵向 LLM 审计中一个普遍但少受检视的假设——混合前后分数足以描述两个模型版本之间发生了什么变化——重新表述为一个带有精确可辨识性结构的测量问题，而非把混合数字当作自明可解读。核心的方法论押注是：只有当跨轴泄漏与版本内噪声作为一等量被估计并报告、且整个程序在已知原因的对上先完成校准之后，能力、策略与格式漂移才是可分离的；更弱的设计有风险报告出一个看似精确、却恰恰静默混淆本文要分开的那些来源的数字。无论校准门与真实对分解最终产出哪种结果，该发现都具有决策相关性：一个经验证的、不可忽略的格式份额意味着当前审计实践在系统性地为有时只是格式变化的东西过度归功或归咎于能力与策略；而一个否定性的校准结果本身也将是关于黑盒行为测量所能区分之极限的重要发现。三条限制从一开始就划定这一主张的边界，且是自然的后续步骤而非事后补充：对商业黑盒版本对的归因始终是一个经校准的行为推断，从未对照供应商内部得到验证，因为这里没有任何方法消解这种不透明性，只是为其造成的不确定性划界；跨供应商结构主张建立在少量对与供应商之上，因此其结果作为带有明示置换零假设比较的分级统计证据报告，而非对整个行业的二元断言；并且校准门自身也被其构造方式所限——其对照对是在其所要验证的分类法之下、在比工具目标商业栈更小的开放权重模型上构建的，因此混合轴对照与规模阶梯迁移检查能为"在构造对上的校准成功高估了在真实对上的可靠性"这一残余风险划界，却不能消除它。
