## Step 0 — Core Asymmetry (升维)

**Asymmetry sentence.** Whether a task admits any solution is fixed by its specification *before any agent acts* and is certifiable by a mechanical check over the environment, whereas failure-attribution reads only the *post-hoc trace*, in which the counterfactual that defines blame — the earliest step whose correction would flip failure to success — provably does not exist on an unsolvable instance.

Without the nouns the sentence has no referent for "the counterfactual that defines blame" or for the pre-vs-post-hoc split — it degrades to the empty generic "some property is fixed before some process and something else only sees the aftermath." Not a bridge — the sentence states an invariant of the attribution counterfactual, not "A and B were never connected."

## Step 5 — Formal Problem Definition

**Estimand (R1, guidance.md §3.4).** The false-blame rate `FBR` — the probability that a deployed failure-attribution system labels a script-certified-unsolvable agent-task instance as `agent_failure` — and its directional gap against the reverse error `CoR`, estimated per task-family/domain over the released matched-pair population, feeding the decision of whether "unsolvable" must become a first-class, calibratable attribution outcome (a threshold choice per downstream consumer) rather than an unmodeled edge case.

**Notation.** A task instance `t = (q, E)` is instruction `q` in environment `E` (schema / tool list / file system / policy set). A generator `μ` (M1) maps a source task with passing reference solution `r` to a matched pair `(t⁺, t⁻)`, `t⁺` solvable, `t⁻` unsolvable, differing only in one typed mutated element `e`. Oracle `O(t) ∈ {solvable, unsolvable}` (M2) is a script. Agent `π` produces trace `x = π(t)` under fixed budget `B` (steps/tokens), terminating in answer / infeasibility-declaration / budget-exhaustion. Attribution system `A` maps `x` (and `q`, never `O`) to label `ŷ ∈ {success, agent_failure, unsolvable}` with confidence `c ∈ [0,1]` on the `unsolvable` decision. `𝟙[·]` indicator; `y = O(t)` is ground truth.

Adjective/verb → definition → measurement:

| term (from digest Claims / N8) | definition (computable) | measured by |
|---|---|---|
| **unsolvable** (Claim 3) | `O(t⁻)=unsolvable`: mutated element `e` is (a) required by `r` and (b) has no substitute — schema-graph unreachability (SQL) / no tool-signature coverage (function-call) / env-state assertion (τ-bench, Terminal-Bench) | M2 static check; `t⁺`'s `r` must still pass its original verifier |
| **misattributed / false-blame** (Claim 1, CO2) | `FBR = P(ŷ=agent_failure \| y=unsolvable)` | count over unsolvable members |
| **cop-out** (N8 metrics) | `CoR = P(ŷ=unsolvable \| y=solvable ∧ π did not succeed)` | count over failed-solvable members |
| **directional bias** (Claim 1) | `FBR − CoR > 0` | two-proportion cluster-bootstrap test |
| **calibration boundary** (Claim 2, CO3) | operating point on risk–coverage curve from threshold `τ` on `c`; `AURC = ∫ risk(coverage) d(coverage)` | M5 threshold sweep |
| **discrimination signal** (Claim 2) | `AUROC(c, 𝟙[y=unsolvable])` | threshold-free ROC over `c` |
| **leak-free / valid pair** (Claim 3, CO1) | text-only probe `AUROC_txt < 0.60` per domain; pair members matched on length/token-overlap/perplexity | M6 audit |
| **calibrated refusal boundary** (RQ1) | Spearman `ρ(c, 𝟙[y=unsolvable])` (Unsolvability Refusal Index) + 10-bin ECE of `c` | M5 |

Any adjective without a row is deleted from the claims.

## Assumptions (A1..A6)

Each entry below fills guidance.md §3.2's five slots (assumption, failure_mode, detection, gate, consequence); gate ids `PG-1`..`PG-6` are the pilot/walking-skeleton checks goal.md §4 requires ("Instrument validation ... runs inside B as PG-* gates") and are cross-referenced from Step 9's pass criterion.

- **A1 — Oracle soundness (M2).** `O` never labels a genuinely solvable instance `unsolvable`. *Failure mode:* a substitute derivation path exists that the no-substitute check misses, so `O` mislabels a solvable instance. *Detected:* run the strongest available agent + a bounded exhaustive/tool-search on every `t⁻`; any success ⇒ oracle unsound. *Gate:* **PG-1** (walking skeleton, 0 successes on `t⁻` required). *Consequence:* any `t⁻` on which the search succeeds is dropped from all H1–H4 scoring immediately (not merely flagged); if a domain accumulates any A1 failures after one repair pass, that domain's oracle is rebuilt before it may contribute to headline FBR/CoR.
- **A2 — No surface leakage (C4).** The mutation changes only the solvability-determining fact, not detectable surface statistics. *Failure mode:* `AUROC_txt ≥ 0.60` — a text-only reader detects unsolvability without feasibility reasoning. *Detected:* M6 text-only probe (hard gate, pilot + per domain). *Gate:* **PG-2** (walking skeleton at pilot scale; re-checked every scale-up batch per domain). *Consequence:* a domain failing A2 has its FBR/CoR/AUROC numbers withheld from every headline table until operators are repaired and the domain re-clears the gate (guidance §3.4 R2 step⑤ freeze-before-scale); H1–H3 are restricted to passing domains, never silently pooled with failing ones.
- **A3 — Agents genuinely attempt.** `π` does not trivially refuse (or trivially answer) everything, else FBR/CoR degenerate. *Failure mode:* solvable-member success rate ≈ 0 or ≈ 1. *Detected:* pilot check — success rate on `t⁺` must lie in [0.15, 0.90]. *Gate:* **PG-3** (walking skeleton, per agent backbone × domain cell). *Consequence:* a cell failing A3 is excluded from headline H1–H3 aggregation and reported separately as a floor/ceiling artifact of that backbone, never counted as evidence for or against the directional-bias or discrimination hypotheses.
- **A4 — Attribution label space admits `unsolvable`.** Each baseline `A` can emit `unsolvable`+`c`. *Failure mode:* a baseline structurally cannot (this is the B0-a condition, kept as a control, not a bug). *Detected:* harness schema check on `A`'s output type before any run. *Gate:* **PG-4** (harness integration check, pre-pilot, one-time per baseline). *Consequence:* a baseline failing A4 is retained only as the B0-a current-practice control (expected `FBR≈1.0` by construction) and is excluded from the H2/H3 baseline-battery denominator — never silently dropped without appearing anywhere.
- **A5 — Matched design integrity.** Pair members share environment size and instruction template; only `e` differs. *Failure mode:* mutation changes env size / wording as a side effect. *Detected:* surface-statistics matching test (M6a: length, token-overlap, instruction perplexity, two-sample test at α=0.05) **plus** a human audit of the mutated-vs-source pair by **≥2 independent raters** on a 10% random sample, requiring inter-rater agreement **κ ≥ 0.70** that the mutation is the only semantic difference (guidance §3.4 R2 step③; disagreements must be adjacent, not a systematic split, per R2 step④). *Gate:* **PG-5** (walking skeleton, then every scale-up batch per operator). *Consequence:* a pair failing either the statistical match or the κ≥0.70 rater-agreement bar is removed from the matched-pair pool before any H1–H4 scoring; an operator whose pairs fail systematically (not just isolated pairs) is repaired or retired, not down-weighted.
- **A6 — Verifier-equipped sources exist.** Each domain has script-checkable reference solutions (Spider/BIRD, BFCL v3, τ-bench, Terminal-Bench). *Failure mode:* a domain lacks a deterministic verifier. *Detected:* domain-selection-time audit of each candidate source benchmark's verifier. *Gate:* **PG-6** (domain-selection time, before the pilot; not re-checked per batch since it is a one-time source-benchmark property). *Consequence:* a domain failing A6 is excluded from the pre-registered domain set entirely (not down-weighted or substituted ad hoc), and every headline claim is scoped to the remaining domains.

**Design constraints and their confounds (R3, guidance.md §3.4).** Every fixed design choice above removes a specific rival explanation, not decoration:
- Fixed harness/budget/logging identical across both members of a matched pair (M3) → removes the confound that a difference in FBR/CoR reflects a difference in how the trace was *produced* rather than in what the attributor *reads out of it* (isolates A5/A2's target).
- Held-out mutated element is the *only* difference between `t⁺`/`t⁻` (M1, guarded by A5/A2) → removes the confound that measured misattribution reflects surface-artifact detection rather than feasibility reasoning (C4).
- Oracle `O` computed from the task/environment specification alone, never from agent behavior (M2, A1) → removes the circularity confound of defining "unsolvable" as "whatever the agent failed to solve."
- B-alt1's oracle-calibrated probe uses the *same backbone/compute budget* as the strongest deployed LLM-judge (Step 6 Mandatory control arms) → removes the confound that a ceiling-vs-design gap reflects unequal compute rather than unequal access to the oracle signal.
- Surface-anonymized control variants (B-alt2: schema/tool/entity names consistently renamed, semantics unchanged) → removes the confound that "unsolvability detection" is mutation-detection-by-diff against a memorized famous source benchmark rather than feasibility reasoning — a channel the text-only probe cannot see (its blindness is stated in the R2 subsection below).
- Base-rate-disclosure control variant (B-alt3: identical judge prompt + one sentence stating the 50/50 unsolvability prior) → removes the confound that the directional bias reflects an uninformed deployment prior over unsolvability prevalence rather than the label-space/prompt design itself.
- CoR reported stratified by `t⁺` difficulty (source-benchmark difficulty tier) alongside the pooled rate → names and controls the confound that FBR and CoR condition on asymmetric populations (all unsolvable members vs. *failed* solvable members, whose composition skews toward the hardest solvable tasks as agent competence rises).

**Instrument validation (R2, guidance.md §3.4) — the leakage probe and the oracle.** The two instruments every headline number depends on each get the full 5-step plan with acceptance thresholds; asserted numbers without this protocol are treated as absent (goal.md §8).

- **Leakage probe (M6b), named.** The probe is **two readers, gate = max of the two**: (i) the strongest backbone family used in the attributor battery (frozen at pilot time), prompted text-only; (ii) a **trained discriminator** (same backbone, lightweight classification head or few-shot-tuned) fit on the same 30% pair-level calibration split used by B-alt1 and evaluated only on held-out pairs. R2 steps: ① *ground* — leakage-cue categories grounded in C4's named channels (length, telltale phrasing, conspicuous absence) plus the surface statistics M6a already tests; ② *draft-wide, refine* — both probe variants run on the calibration split; operator families producing detectable cues get named repair operations (re-template, length-match, distractor insertion); ③ *validate the instrument's power* — before its `< 0.60` verdict on real pairs counts, the trained probe must reach `AUROC ≥ 0.90` on a **positive-control set** of deliberately leaky pairs (one intentionally injected surface cue per pair) — a probe that cannot detect planted leaks cannot certify absence of leaks; ④ *confusion structure* — probe false positives on the calibration split are inspected and must concentrate in the named cue families, not spread systematically; ⑤ *freeze* — probe prompt + weights + threshold hashed before scale-up (PG-2 then re-checks per batch). **Stated blindness, honestly:** a text-only probe cannot detect memorization-based cues available only to backbones that have memorized the *original* source benchmark — that channel is covered by B-alt2 (surface anonymization), not by M6.
- **Oracle (M2).** R2 steps: ① *ground* — each domain's required/no-substitute conditions are grounded in the source benchmark's own verifier semantics (Spider/BIRD execution match, BFCL signature match, τ-bench/Terminal-Bench state assertions), not invented; ② *draft-wide, refine* — operators implemented per domain and run on a calibration sample before any pair enters the pool; for open-action domains (Terminal-Bench) operators are restricted to a closed sub-language where no-substitute is decidable (resources whose absence is provably unrecoverable inside the sandbox: no network, no generator, no cached copy — asserted over the environment state); instances not certifiable this way are excluded, never guessed; ③ *validate* — on a 10% random sample of `t⁻`, **≥2 independent raters** attempt to construct a substitute derivation, with agreement **κ ≥ 0.70** against the oracle's no-substitute verdict, in addition to PG-1's strongest-agent + bounded-search falsification; ④ *confusion structure* — every rater- or search-found substitute is traced to the specific no-substitute condition it defeated, and that condition (not the instance) is repaired; ⑤ *freeze* — oracle code hash recorded before scale-up (PG-1 re-checks per batch).

## Step 6 — Pre-Registered Experiments

### RQ_INF_1 — Does the phenomenon exist at material magnitude? (digest N8 RQ_INF_1; CO1, CO2)
- **Assumption:** A1, A2, A3, A4, A6.
- **Hypothesis H1 (binary):** On the Stage-1 pilot (100 pairs, Spider + BFCL v3, 2 agents), the default LLM-judge attributor's `FBR ≥ 0.20` (effect floor) **and** the 95% pair-clustered bootstrap CI lower bound `> 0.05`.
- **Metric:** `FBR = P(ŷ=agent_failure | y=unsolvable)`, untuned default threshold.
- **Alpha:** α = 0.05 (one-sided, via the 95%-CI-lower-bound-> 0.05 criterion above); no multiple-comparison correction because H1 evaluates a single primary baseline/pilot quantity, not a family (contrast with H2's Holm–Bonferroni across 5 baselines).
- **Aggregation:** N/A at this stage — the Stage-1 pilot pre-registers exactly one baseline (default LLM-judge, all-at-once) on exactly one metric; there is no vote to aggregate. (Aggregation across baselines/domains is deferred to H2/H3, which is why those hypotheses carry explicit "≥3 of 5" / "≥1 per domain, each of ≥4 domains" vote rules.)
- **Verification:** cluster bootstrap over pairs, 10,000 resamples; report point estimate + 95% CI. No correction (single primary pilot quantity).
- **Fallback:** If `FBR < 0.20` or CI overlaps 0.05 — claim instead "Off-the-shelf LLM-judge attribution already separates unsolvable from agent-failure at rate X untuned; the open problem is the *residual* tail / the harder domains," and re-target the headline to the worst-performing baseline/domain (per-domain reporting makes this publishable).

### RQ1 — Directional bias and the calibration boundary (digest N8 RQ1; CO2, CO3)
- **Assumption:** A1–A5.
- **Hypothesis H2 (binary, directional bias):** For **≥3 of the 5** attribution baselines, `FBR − CoR ≥ 0.10` (10 pp), Holm–Bonferroni-corrected across the 5 baselines at family-wise α = 0.05, two-proportion cluster-bootstrap test (resample at pair level).
- **Hypothesis H3 (binary, discrimination/knee):** For **≥1** baseline in **each** of the ≥4 domains, `AUROC(c, 𝟙[y=unsolvable]) ≥ 0.65` with bootstrap CI lower bound `> 0.50`, and the risk–coverage curve is non-1:1 (AURC strictly below the coverage-proportional diagonal, CI-separated). **Alpha / multiplicity (correcting the best-of-5 selection):** because "≥1 baseline per domain" selects the best of 5 baselines within each domain, the per-baseline CIs use the Bonferroni-corrected level `1 − 0.05/5 = 99%` (per-domain α = 0.05 preserved under selection); the AURC-vs-diagonal separation uses the same corrected level. An H3 pass at the uncorrected 95% level that fails at 99% does not count.
- **Metric:** `FBR`, `CoR`, `AUROC` of `c`, `AURC`, 10-bin ECE, Unsolvability Refusal Index `ρ` (N8 metrics).
- **Verification:** Stage-2 run, 600 pairs (150/domain, 1,200 instances) × 3 agents ⇒ ≥1,800 unsolvable decisions/baseline for the FBR class. **Honest CoR-denominator arithmetic (corrects the earlier "n ≈ 1,800 per class" statement):** the CoR class conditions on *failed-solvable* instances, whose count is agent-competence-dependent — under A3's allowed `t⁺` success range [0.15, 0.90], pooled failed-solvable n per baseline ranges from ≈180 (success = 0.90) to ≈1,530 (success = 0.15). Under the conservative p≈0.5 variance bound, one-sided power for the 10-pp FBR−CoR gap at α = 0.05 exceeds 0.9 only when failed-solvable n ≳ 400 (`t⁺` success ≲ 0.78); at the A3 worst case (n ≈ 180) power falls to ≈0.8 uncorrected and lower under Holm. **Pre-declared rule:** realized failed-solvable n and realized power are reported per baseline; any baseline whose realized power for the 10-pp floor is < 0.8 after Holm correction has its H2 verdict pre-declared **INCONCLUSIVE** (never a null) and is excluded from the "≥3 of 5" vote denominator, with the exclusion stated. Secondary: logistic regression of misattribution on {domain, operator-type, agent-family} fixed effects to localize the bias. All rates reported with per-domain 95% bootstrap CIs. **Power/thin-cell rule (guidance §3.4 R8, situation 5):** the 150-pairs/domain, 3-agent design is powered for the pre-registered 10-pp floor at the domain level; any domain × agent-family × operator-type cell whose realized n falls below the count needed for 0.8 power at the same floor is pre-declared **INCONCLUSIVE** for that cell alone (never silently pooled into the domain aggregate, never reported as a null) — it is excluded from the H2/H3 vote count for that cell but is still listed in the per-cell table with its n and CI.
- **Fallback:** If H2 fails with both rates non-trivial (gap indistinguishable from 0 for the majority) — claim "attribution systems are *symmetrically* miscalibrated on the feasibility axis (both directions non-trivial), so the design lever is a bidirectional feasibility category, not de-biasing." **If H2 fails in the WRONG direction** (`CoR − FBR ≥ 0.10`, Holm-corrected, for ≥3 of 5 baselines — guidance situation 4, reported at full prominence, never buried): claim "attribution systems *over-refuse* rather than over-blame: the dominant miscalibration is copping out of solvable-but-hard tasks, so the deployment risk is unearned unsolvability amnesty, not unfair blame; the calibration-boundary analysis (H3) becomes the headline with the recommended threshold adjustment reversed in sign, and the first-class-outcome recommendation is retained but re-argued from the cop-out direction." If H3 fails, the spliced wording is **conditional on B-alt1's three-branch rule** (Mandatory control arms): probe `< 0.60` → "trace-level evidence is provably insufficient to recover feasibility (information-theoretic ceiling reached); the fix must move upstream to first-party in-run declaration, not post-hoc attribution," reporting the ceiling; probe `≥ 0.65` → "the feasibility signal exists in the trace but deployed attribution designs fail to extract it — the gap is design-limited and fixable, bounded by the ceiling probe's operating characteristics"; probe in `[0.60, 0.65)` or CI straddling → mechanism verdict INCONCLUSIVE, Claim 7 reported unresolved. Never combine H3-failure wording with a B-alt1 branch it contradicts.

### RQ_INF_2 — Is the instrument valid? (digest N8 RQ_INF_2; CO1)
- **Assumption:** A2, A5.
- **Hypothesis H4 (binary, hard gate):** For **every** domain used in headline results, text-only probe `AUROC_txt < 0.60` after at most one operator-repair iteration, and pair members are not separable on length/token-overlap/perplexity at α=0.05.
- **Metric:** `AUROC_txt` (LLM prompted on task text only, no trace, no env); surface-statistics two-sample tests; human-audit agreement on a 10% sample.
- **Verification:** run before any RQ1/RQ_INF_1 headline number; a domain failing the gate after repair is *withheld* from headline (reported as a negative construct-validity result).
- **Fallback:** If a domain fails the gate irreparably — report it as a finding: "mechanically leak-free unsolvability injection is infeasible for domain D under operators {…}," narrowing the headline to passing domains and characterizing which operator families leak.

### Mandatory control arms

- **B0-p — null-by-construction placebo (guidance §3.3 job (b); the Phase D step-1 gate):** two sham constructions, both scored with the identical M5 estimators: (i) **sham pairs** — the generator `μ` applies a *semantically inert* mutation (rename an unused alias, reorder an environment listing) so both members are solvable (verified: each member's reference solution still passes its original verifier and `O` labels both `solvable`); the full battery runs over both members and the FBR−CoR-analog gap between sham members plus `AUROC(c, 𝟙[sham member])` are computed. (ii) **shuffled-label check** — permute oracle labels within domain and recompute every headline estimator. **Pre-committed null criterion:** sham-pair gap's 95% pair-clustered bootstrap CI contains 0 **and** shuffled-label AUROC's 95% CI contains 0.5, per domain. Non-null ⇒ the pipeline measures an artifact ⇒ the run is invalid (goal.md §5 step 1 / guidance situation 1); no H1–H4 is scored. B0-p, not B0-a, is what Phase D checks first.
- **B0-a — "why do this at all" current-practice arm (guidance §3.3 job (a); no-mechanism arm, expected non-null):** the **label-space-restricted attributor** that can only output {success, agent_failure} — i.e., the current-formulation attribution pipeline with no feasibility category (N4.limitation 1). Expected `FBR ≈ 1.0` on unsolvable members by construction. Justifies the problem's existence: without a first-class unsolvable outcome, every unsolvable task is definitionally misattributed. If B0-a's `FBR` is *not* near 1.0, the premise that current formulations force agent-blame is wrong and the whole framing is revisited. (Explicitly *not* the Phase D placebo gate — its expected result is maximal, not null; the gate is B0-p.)
- **B-alt1 — information-limit rival (capability/budget-matched):** The first rival to "attribution systems over-blame because of *label-space/prompt design*" is "**the traces on unsolvable tasks simply contain no recoverable feasibility signal — any observer, however capable, is at chance**" (an information problem, not an attribution-design problem). Control: an **oracle-supervised trace probe** — same backbone/compute as the strongest LLM-judge, but *directly trained/calibrated on the oracle label* from the trace (the ceiling of trace-extractable signal). **Split protocol (pre-registered):** the probe is trained/calibrated on a pair-level calibration split (30% of pairs, stratified by domain × operator type) and evaluated only on the held-out 70% on which all headline numbers are computed; calibration pairs never enter any headline table. **Pre-committed decision rule (three branches, no gap):** held-out probe `AUROC < 0.60` ⇒ information-limited, rival wins (→ H3's information-ceiling fallback wording); probe `AUROC ≥ 0.65` while deployed attributors do not clear 0.65 ⇒ rival ruled out, gap attributable to attribution design (supports H2/H3); probe `AUROC ∈ [0.60, 0.65)` **or** its 95% CI straddling both gates ⇒ the mechanism verdict for Claim 7 is pre-declared **INCONCLUSIVE** — neither the information-limit nor the design-gap wording may be spliced, and Claim 7 is reported as unresolved with the probe's point estimate and CI.
- **B-alt2 — memorization/contamination rival (budget-matched):** The second rival: "**the attributor recognizes the famous source benchmark and detects the mutation by diffing against a memorized original**" — mutation-detection-by-memorized-diff, not feasibility reasoning; the M6 text-only probe is structurally blind to this channel (blindness stated in the R2 subsection above). Control: rerun the strongest LLM-judge baseline (same backbone, prompt, budget) on a **surface-anonymized variant** of a random 20% subset of pairs per domain (schema/tool/entity/file names consistently renamed; semantics unchanged; `O` labels re-verified after renaming). **Pre-committed interpretation:** if the anonymized-variant `FBR` shifts by ≥ 10 pp or unsolvable-score `AUROC` shifts by ≥ 0.10 (95% CI of the shift excluding 0) for a domain, the memorization rival wins there — downgrade wording: "measured detection on domain D partially reflects memorized-source diffing; anonymized-variant rates replace famous-source rates as that domain's headline." No material shift ⇒ rival ruled out for that domain.
- **B-alt3 — base-rate prior-mismatch rival (budget-matched):** The third rival: "**the directional bias is rational prior mismatch, not label-space design** — a judge calibrated to deployment (where nearly all tasks are solvable) *should* rarely emit `unsolvable` under a 50/50 benchmark prior; one disclosure sentence would fix it." Control: the strongest LLM-judge baseline rerun with a single added prompt sentence disclosing the base rate ("approximately half of the tasks in this evaluation are unsolvable by construction") — identical otherwise. **Pre-committed downgrade wording:** if disclosure closes ≥ 50% of that baseline's FBR−CoR gap, "the observed over-blame is substantially a feasibility-prior miscalibration rather than a structural label-space limitation: Claims 4 and 7 are downgraded accordingly, Claims 1–3 and 5 stand, and the practical recommendation shifts from adding a first-class label to disclosing/calibrating the feasibility prior." If the gap survives disclosure, the structural-design reading stands and the rival is ruled out.

### Reporting protocol (R7, guidance.md §3.4)
No hyperparameter search is performed on the pre-registered thresholds (FBR/CoR floors, AUROC gates, α levels) — these are frozen before Stage-2 execution per the Assumptions section's PG-gates. The one exception, stated explicitly rather than left implicit: each LLM-judge baseline's *prompt wording* is not search-free — per digest.md N10 t5's pre-committed protocol, the two established strategies (all-at-once, step-by-step) are each run with ≥3 paraphrased variants, variance across variants is reported, and the best variant per baseline is used for headline comparisons. This is a declared search protocol over prompt wording only (never over the statistical thresholds), reported alongside the variance it produced so a reader can judge how much of the headline number is prompt-selection-sensitive.

### Global fallback F-G1 (archetype pivot)
If the central hypothesis family fails — H1 fails (no material phenomenon) **and** H2 fails (no directional bias) — pivot from **empirical/measurement** to **benchmark/dataset** archetype. ### Global fallback F-G2 (construct-validity pivot — the H4-all-fail corner)

## Abstract v0 (draft, mechanism-first) — DRAFT BEFORE RESULTS

Failure-attribution for LLM agents defines blame as the earliest step whose correction would flip failure to success — a counterfactual that provably does not exist when the task admits no solution, forcing these systems to nominate a culprit for impossible tasks. We isolate this regime by constructing matched solvable/unsolvable task pairs across text-to-SQL, tool-calling, customer-service, and command-line domains, injecting unsolvability with typed mechanical mutation operators (remove a required schema element, tool, record, or resource; contradict a stated constraint) so ground truth is certified by script, not judgment, and gating every pair through a leakage audit. We measure the rate at which existing attribution pipelines misattribute certified-unsolvable tasks as agent failures, quantify its directional asymmetry against the reverse error, and map the risk–coverage boundary of calibrated refusal per domain. We report unsolvability as a first-class attribution outcome and release the construction-certified instrument. (≤150 words)
