# 验证税：测量编码 agent 推理服务中验证诱发的成本与可避免开销

> 由 `discussion_trace.md` 中六个已确认的阶段产出组装而成，已通过品味审计（`taste_audit.md`：🟢）与阶段评审（`stage_review.md`：三项阶段级 REVISE 修复外加两项写作阶段修复已并入）。状态：**规格说明 / 论文草稿 —— 尚未运行任何实验。** 下文所有数字均为预注册（pre-registered）的设计目标并附有理由说明，而非实验结果。

## 摘要（Abstract）

编码 agent 将代码生成与验证（verification）交错进行 —— lint 检查、类型检查、单元测试、构建、全量测试套件 —— 并把结果回喂进上下文。承载它们的推理服务栈（serving stack）对生成精确计价，却把验证当作不透明的工具时间（opaque tool time）：其执行成本不计入同一预算，其输出对前缀缓存（prefix cache）复用的影响不被统计，其失败触发的重试环与正常推进无法区分。目前已存在两项编码 agent 服务负载刻画研究，但都不携带验证步语义；美元计价的投机执行（speculative execution）已被提出，但既无真实 trace 落地，也不把验证决策本身作为其调度对象。我们预注册一项基于公开编码 agent trace 的"验证税"（verification tax）测量：一个区间值账本（interval-valued ledger），用偏差方向已知的归因规则给会话美元中验证诱发的份额定界；一个缓存反事实重放（cache-counterfactual replay），把前缀缓存失效具体归因到验证内容；一个覆盖 lint、类型检查、单元测试、构建与全套件的逐类成本–价值画像；以及一个双层余量评估（two-tier headroom evaluation）—— 对 agent 不可观察的重调度用精确重放，对 agent 可观察的用带非劣性（non-inferiority）门控的实测运行 —— 度量在解决率持平的条件下，已记录账单中有多少是可避免的。每个估计都带有预注册的证伪门槛，包括"验证根本不是一等成本对象"这一门槛本身。

## 引言（Introduction）

编码 agent 已经成为一类独立的推理服务负载。单次 issue 解决会话会让 LLM 经历数十个生成步骤并与工具调用交错，平台级部署如今以万亿 token 的规模计量这类流量 —— 企业推理经济学分析与一项覆盖 320 万用户的生产级刻画之所以存在，正是因为运营方在为这些账单付费（arXiv:2608.00101；arXiv:2607.13080）。在服务侧，同样成熟的一条系统工作线 —— 分页 KV 内存（paged KV memory，Kwon et al., 2023）、基数树前缀缓存（radix-tree prefix caching，Zheng et al., 2023）、prefill/decode 解耦（Zhong et al., 2024；Qin et al., 2024）、分块 prefill 调度（chunked-prefill scheduling，Agrawal et al., 2024）—— 在优化服务这些 token 流的成本，其共同前提是：复用缓存前缀并良好调度 prefill 工作正是省钱之所在。

然而编码 agent 负载的一个结构性特征对这两个社区的成本模型都不可见：它的一大类步骤是验证。一次 lint、一次类型检查、一个单元测试、一次构建、一轮全套件运行 —— 每一个都在模型之外执行，返回的输出被注入回 prompt，且在失败时触发修复环，该环的生成成本在因果上是验证事件的下游。服务栈对每个生成 token 计价，却把这些步骤当作不透明工具时间：它们的执行不计入其所引发 token 的同一预算，其输出对前缀缓存复用的影响不被统计，重试环与前向推进无法区分。agent 侧文献也没有站得更好：测试时计算（test-time compute）分析用 FLOPs 或 token 计量思考与采样，把检查当作事后附注（Brown et al., 2024；Snell et al., 2024）；而反馈环本身 —— 跑测试、读失败、再尝试 —— 自 Reflexion（Shinn et al., 2023）以来就是标准做法，基于执行的检查自 pass@k（Chen et al., 2021）以来亦然，却从没有人为这个环给服务层带来的成本定价。没有任何已发表的数字说明：编码 agent 会话的美元中有多大比例是验证诱发的，验证输出摧毁了多少前缀缓存复用，其中又有多少是可避免的。

最接近的既有工作围住了这个缺口却没有闭合它。TraceLab（arXiv:2606.30560）发布了首个公开的编码 agent 负载 trace 语料 —— 约 4,300 个会话与 430,000 次工具调用，test/build/edit 步骤可区分 —— 但只做聚合刻画，没有验证归因的成本份额、没有重试归因、没有缓存交互分析；一项 Copilot 流量的生产级研究（arXiv:2608.00101）同样沉默且不发布 trace。Cost-Aware Speculative Execution for LLM-Agent Workflows: An Integrated Five-Dimension Method（arXiv:2606.07846）是方法上最近的邻居：它像我们一样用美元为投机定价，但不落地于真实 trace，不把验证决策作为其调度对象，也不建模验证对缓存的破坏。LLM 推理与 agent 的排队论调度（Dai et al., 2025）已把 Generate 与 Verify 建模为不同的服务类别 —— 这是"该区分很重要"的理论先声 —— 但恰恰预设了从未被测量过的逐类成本、价值与扰动参数。而 agent 感知的缓存工作簇（KVFlow，Pan et al., 2025；Irminsul: MLA-Native Position-Independent Caching for Agentic LLM Serving，arXiv:2605.05696，三个月内至少五个系统）为 agent 负载改进复用，却对"究竟哪种步骤语义在摧毁复用"保持盲视。

从观测 trace 测量验证税比数标注步骤更难，而这些困难正是塑造我们设计的因素。重试环的 token 在因果上是失败验证的下游，却与真实进展交错，且 trace 中不存在无验证的反事实会话 —— 所以任何诱发成本的点估计都是武断的。缓存失效是内容扰动（churn）、位置与体量在特定缓存策略下的联合效应 —— 所以原始命中率差异无法说明是验证*内容*的错。验证类别的信息价值无法从结果直接读出，因为 agent 在编辑后跑便宜的检查、在终点跑昂贵的套件 —— 这一调度习惯混杂把朴素的类别比较变成伪影。而重调度反事实的有效性取决于其评估方式：在一个会改变 agent 所见内容的调度下重放已记录会话什么也回答不了 —— 这正是最近邻工作在 trace 落地上的弱点。

本文的设计围绕一个单一断言构建：验证步被服务栈当作不透明工具时间计价，但它是该负载中成本异质性最强、对缓存最有敌意、且最可重调度的步骤类别 —— 且该断言的两半都可从公开 trace 测量。上述每个困难都变成一个设计选择。归因在构造上就是区间值的：保守规则（只计直接执行与反馈 token）与自由规则（外加完整重试段）在各自一侧的偏差方向已知，因此无需反事实即可将真值夹在区间内。缓存损害通过反事实重渲染归因：与 agent 行为不同，在固定策略下缓存行为是 token 序列的确定性函数，所以重放体量匹配的惰性内容与规范化后的验证输出，能把扰动从体量、位置与格式中分离出来 —— 这一干预对缓存是精确的，尽管对 agent 是无效的。类别价值只在前置上下文分层内估计，且置于预注册的正性门（positivity gate）之后：若 agent 的习惯过于锁相而不支持比较，前沿就降级为描述性。余量评估按不变性谓词（invariance predicate）分为两层：逐字节保持 agent 可见 token 序列的重调度用精确重放评估，结果在构造上完全一致；会改变 agent 所见内容的重调度 —— 对预测会通过的验证做投机续跑、失败时回滚 —— 只用实测重执行评估，并施加预注册的解决率单侧非劣性边际。

我们在 TraceLab 公开语料与自测 SWE-bench Verified 会话（Jimenez et al., 2024）上、在两个开源脚手架（scaffold；Yang et al., 2024；Wang et al., 2024）下评估该设计，用打乱标签的安慰剂（placebo）门控归因流水线，并在三个价格向量、两种缓存策略与两个语料上重算每个头条判定。

综上，我们的贡献是：

- 把验证诱发的服务成本形式化为区间值估计量（estimand）—— 由偏差方向已知的归因规则定界 —— 并给出从公开 trace 计算它的会话级账本，以美元（及描述性的延迟）计。
- 一个缓存反事实重放方法，把前缀缓存失效具体归因到验证内容，将扰动与体量、位置、格式分离，并度量通过规范化易变输出片段可消除多少损害。
- 一个覆盖 lint、类型检查、单元测试、构建与套件的逐类成本–价值画像 —— 即现有 Generate/Verify 调度理论所预设的经验参数 —— 在显式正性门之后估计，当 agent 的调度习惯使比较不可识别时如实报告而非掩盖。
- 一个按 agent 可见性不变性谓词切分的双层余量评估，预注册"已记录服务账单中有多少在解决率持平下可避免"：对 agent 不可观察的重调度精确计算；对预测通过的投机续跑，则在实测非劣性证书下计算。

## 问题定义（Problem Definition）

**形式化设定。** 一个会话 s = (x₁, …, xₙ) 交错包含生成步、非验证工具步与验证步；每个验证步携带类别 k ∈ K —— lint、类型检查、单元测试、构建或套件 —— 一个作用域（被检查的文件或模块）与一个结果（通过/失败/出错）。验证*目标*是二元组（类别，作用域）；*重试段*（retry segment）是从目标 f 的一次失败验证到同一目标下一次验证尝试之间的连续步骤区间。服务成本模型 C_{p,Θ}(s) 在给定价格向量 p（按输入 token、输出 token、缓存输入 token 与验证执行秒计价）与前缀缓存策略 Θ 下，把会话的请求序列映射为美元，统计 prefill（缓存未命中）token、decode token 与执行时间。研究对象有四个：(i) C_{p,Θ}(s) 中验证诱发的份额 ρ(s) = [ρ_cons(s), ρ_lib(s)]，即两条固定归因规则下的区间；(ii) 被失效（重新 prefill）的缓存 token 中可归因于验证的份额；(iii) K 上的逐类成本与信息价值画像；(iv) 在可行重调度 π 上的余量 Δ(π) = C_{p,Θ}(s) − C_{p,Θ}(π(s))，按不变性谓词 ι(π) —— "agent 可见 token 序列逐字节保持" —— 划分，且只在解决率持平下报告：ι 成立时由构造完全持平，不成立时由实测运行上预注册的单侧非劣性边际认证。

**为何困难。** trace 中不存在无验证的反事实会话，所以 ρ 逐点不可识别：任何单一归因规则都内嵌了"验证'导致'了哪些重试 token"的武断因果判断。上述两条规则的选取使各侧偏差方向由构造可知 —— 保守规则只会少计（完全忽略诱发的修复），自由规则只会多计（吸收段内全部进展）—— 因此诚实的估计量是区间而非任一端点。缓存失效使问题更复杂：在前缀缓存下，一个 token 的成本取决于其之前的 token 是否变化，所以会扰动的验证输出 —— 易变路径、时间戳、时长、轮间重渲染的截断边界 —— 的代价可达其自身长度的数倍，但只有在同一策略 Θ 下的反事实重渲染才能把这种扰动与任何等长内容都会占据的体量和位置分开。逐类画像被调度习惯混杂 —— agent 在编辑后跑 lint、在终点跑套件，类别与上下文纠缠 —— 只有层内对比（且重叠经过验证）才配得上一个排序断言。最后，Δ(π) 只在其评估有效之处可测：重放恰好在保持 ι 的子类上精确，超出者需要实测重执行 —— 这一划分正是最近邻工作没有画出的，也是其美元计价投机结果不落地于 trace 的原因。

## 方法总览（Method Overview）

本研究是带四个协作仪器的单一测量流水线。类型化会话进入后，**验证成本账本（verification cost ledger）**把每个会话变成区间值的验证诱发美元份额，分解为执行、反馈 token、重试生成与缓存重 prefill 四个组分，并在价格向量、缓存策略与语料上重算每个判定。**缓存反事实重放（cache-counterfactual replay）**把同一批会话跑过两个前缀缓存模拟器并对照重渲染变体 —— 体量匹配的惰性填充与规范化的验证输出 —— 以把失效归因到验证内容，并度量其中多少只是格式。**逐类价值画像器（per-class value profiler）**把每类的账本成本与其信息价值的分层估计配对（结果是否改变 agent 的下一动作；是否推动最终解决），置于正性门之后。**双层余量评估（two-tier headroom evaluation）**消费上述三者：按 agent 可见性不变性谓词划分候选重调度，对不变层依账本成本模型精确重放，把可见层 —— 对预测通过的验证投机续跑 —— 送入非劣性证书下的实测运行，并以一个 oracle 预测器臂给投机所能收回的上限定界、以一个冻结的 trace 训练预测器测量其现实收回量。

## 方法（Methodology）

### 验证成本账本

**挑战。** 重试环生成在因果上是失败验证的下游，却与真实进展交错，且 trace 中不存在无验证的反事实会话 —— 点归因将是武断的，领域有理由无视它。

**洞察。** 该估计量所服务的决策 —— 验证是不是一等成本对象？—— 不需要点值；它需要一个端点偏差方向已知的区间。定界替代了不存在的反事实。

**方法。** 每个会话被解析为类型化步骤（步骤类型标注对照两名独立人工标注员审计，Cohen's κ ≥ 0.8，只允许相邻混淆，然后才扩大规模）。直接成本 —— 验证执行秒数与注入上下文的反馈 token —— 精确计算。重试段由（类别，作用域）目标同一性在结构上定界。保守份额 ρ_cons 只计直接成本；自由份额 ρ_lib 加上重试段内全部生成与工具成本；两者在三个预注册价格向量（API 计价；自托管 GPU 时；延迟加权）与两种缓存策略下美元化，用相同代码在 TraceLab 与自测 SWE-bench 会话上运行。延迟份额并行计算并作描述性报告；头条判定限定在美元计价内。打乱步骤类型的安慰剂门控流水线：把标签在会话内随机重指派后，"验证归因"份额必须坍缩到其 token 份额，否则在给任何假设打分之前判定运行无效。

### 缓存反事实重放

**挑战。** 前缀缓存失效是内容扰动、位置与体量在特定缓存策略下的联合效应；原始命中率缺口无法说明是验证内容的错。

**洞察。** 与 agent 行为不同，给定策略后缓存行为是 token 序列的确定性函数 —— 因此反事实重渲染作为对 agent 的干预无效，作为对缓存的干预却是精确的。

**方法。** 每个会话的请求序列在一个基数树前缀缓存模拟器（SGLang 风格）与一个块哈希模拟器（vLLM 风格）中重放，两者都在会话子样本上对照真实引擎运行校准（模拟 prefill 计数与实测相差 ±10% 以内，随每个缓存结果一并报告）。重放三种渲染：已记录会话；体量匹配的惰性填充变体（同长度、同位置 —— 零假设参照，其比值必须 ≈ 1）；以及把易变片段（路径、时间戳、时长、截断边界）改写为稳定形式的规范化变体。第一个差值把失效归因到验证内容；第二个度量该损害中多少由格式驱动 —— 无需改变 agent 所学即可消除 —— 多少在语义上必要。

### 逐类价值画像器

**挑战。** agent 在编辑后跑便宜检查、在会话终点跑昂贵套件，验证类别与步骤上下文纠缠；朴素类别比较测的是调度习惯，不是信息价值。

**洞察。** 调度只需要各类别每美元价值的*排序*，而排序断言由层内对比授权 —— 前提是重叠确实成立，这是可检查且必须检查的。

**方法。** 对每个类别，账本提供成本画像；在会话阶段、触及文件与自上次同类检查以来 diff 大小的预定义分层内估计两个价值代理：动作分歧（action-divergence，通过与失败结果下 agent 下一动作不同的概率）与终局相关性（terminal relevance，结果所关联的最终解决概率移动）。预注册正性门只接纳含至少两个类别、至少 30 步的层；若通过的层不足一半，前沿只作描述性报告、其假设记为不确定（inconclusive）—— 重叠的失败本身就是关于 agent 验证习惯锁相程度的发现。

### 双层余量评估

**挑战。** 重调度反事实的有效性取决于其评估：在会改变 agent 所见内容的调度下重放会话是离策略（off-policy）的，什么也回答不了 —— 这正是最近邻工作在 trace 落地上的弱点。

**洞察。** agent 可见性边界把一个不适定的离策略问题变成两个适定问题：对 agent 不可观察的重调度做精确模拟，对可观察的做小规模实测实验 —— 而使每个余量断言有效的是这条边界，不是模拟器保真度。

**方法。** 一个重调度属于 Tier A 当且仅当它逐字节保持 agent 可见 token 序列：批量化验证执行、沙箱放置与预热、缓存感知的重 prefill 调度、把验证执行与同轮 decode 重叠。Tier-A 余量在冻结成本模型下精确重放计算；已记录结果由构造复用。其精确性被显式限定作用域：它对已记录会话在所述成本模型下成立，其部署解读还额外假设 agent 行为不依赖墙钟时间（步骤超时、延迟条件化 prompt），该类构造在语料中的出现率作描述性报告。Tier B 打破不变性 —— 其代表是对预测会通过的验证投机续跑，误判时回滚（并支付）被丢弃的 token —— 只通过实测 SWE-bench 重执行评估，按实例与种子配对，施加解决率上单侧 5 个百分点的非劣性边际。一个基于前置步骤可观测量的通过/失败预测器只在 TraceLab 上训练并在任何实测运行前冻结（哈希）；一个 oracle 臂 —— 可通过对原生实测运行日志的重放计算，因为 oracle 从不误判 —— 从上方给可达的投机余量定界，使冻结预测器臂读作已测天花板的一个分数而非孤立数字。

## 实验（Experiments）

### 实验设置

**数据集。** TraceLab 公开 trace（arXiv:2606.30560）—— 约 4,300 个会话与 430,000 次工具调用，test/build/edit 步骤可区分；唯一具有类型化工具调用的会话粒度公开语料；承载账本、缓存、前沿与 Tier-A 分析及预测器的训练划分。其语料事实以及其论文中验证归因分析的缺席，作为阻塞性的预测量门槛需第一手确认 —— 若确认失败则执行预先承诺的重新定位。自测 SWE-bench Verified 会话（Jimenez et al., 2024），在两个开源脚手架 —— OpenHands（Wang et al., 2024）与 SWE-agent（Yang et al., 2024）—— 下，每臂 300 实例 × 2 脚手架 × 3 种子：agent 可见重调度的唯一有效场域，也是判定稳定性的第二语料。

**成本模型。** 两种缓存策略（基数树、块哈希）、三个价格向量（API 计价；自托管 GPU 时摊销；延迟加权），全部在测量前冻结并哈希；模拟器校准误差随每个缓存结果一并报告。

**运行溯源与研究成本。** 每个实测臂按脚手架锁定单一骨干模型（backbone model）检查点与固定解码配置（温度、top-p、最大步数），在任何运行前与成本模型一起冻结并哈希；脚手架版本按 commit 锁定。实测臂是本研究的主要开销 —— 至少两个臂、每臂 1,800 次配对 SWE-bench 运行，外加校准子样本 —— 因此每臂实际美元支出与其所定价的节省估计一起、以相同价格向量报告：一项关于服务美元的研究若不披露自己的服务账单，就过不了自己的标准。

**基线**（健全性比较对象 —— 这是测量研究；没有任何东西被框定为要击败的竞争者）。原生 agent 调度是被测对象，也是所有余量的参照。打乱步骤类型的安慰剂在任何假设打分前门控归因流水线。体量匹配的惰性填充重渲染是缓存侧的零假设对照。

**指标。** 区间美元份额及其分解；延迟份额（描述性）；失效比与规范化回收率；带层计数的逐类成本与价值画像；Tier-A 按机制分解的回收份额；oracle 与实际投机节省及预测器 AUC 与回滚成本；配对解决率差及置信界。

**研究问题（RQ）：**
1. RQ1 —— 会话服务成本中有多大份额是验证诱发的？
2. RQ2 —— 头条判定是否是某个单一核算选择的伪影？
3. RQ3 —— 验证输出是否不成比例地摧毁前缀缓存复用？
4. RQ4 —— 缓存损害由格式驱动还是语义必要？
5. RQ5 —— 逐类成本–价值前沿是异质的还是退化的？
6. RQ6 —— 仅靠 agent 透明的重调度能避免已记录账单的多少？
7. RQ7 —— 在现实预测器质量下投机续跑是否可行？

#### RQ1：会话服务成本中有多大份额是验证诱发的？

**设置。** 对全部通过完整性过滤的 TraceLab 会话跑完整账本；在头条价格向量/缓存策略单元下计算每会话的保守/自由区间及组分分解。样本量：全语料（约 4,300 会话）；中位份额的 95% bootstrap 置信区间（10,000 次重采样）预期半宽远小于 0.02，故约束在语料规模而非统计功效。

**预期结果。** 保守份额中位数至少 0.15、自由份额中位数至少 0.30 —— 验证越过预注册的一等成本门槛。

**证伪条件。** 若自由份额中位数的置信上界低于 0.10 则被驳斥 —— 那时验证就不是一等成本对象，被认证的小份额将按预先承诺的转向、以完整显著度作为研究发现报告。

**假设（白话）。** 会话中验证诱发的开销大到：把它误标为不透明工具时间的服务栈正在为一个一阶成本驱动因素错误定价。

**指标。** 美元份额区间（头条）；执行/反馈 token/重试生成/缓存重 prefill 分解；延迟份额作描述性报告，头条判定限定于美元。

#### RQ2：头条判定是否是某个单一核算选择的伪影？

**设置。** 在三个价格向量 × 两种缓存策略的完整网格上、并在使用相同账本代码的自测 SWE-bench 语料（1,800 个原生会话）上重算 RQ1、RQ3、RQ6 的判定。

**预期结果。** 点估计会移动；判定类别不会 —— 每个头条判定在网格与两个语料上不变。

**证伪条件。** 若任何头条判定在任一网格单元或第二语料上翻转则被驳斥；受影响的断言随即按预先承诺的措辞降级为其成立的核算包络。

**假设（白话）。** 本文结论是负载的性质，不是某张价目表、某种缓存策略或某个 trace 语料的伪影。

**指标。** 网格上的判定矩阵；每单元估计及置信区间。

#### RQ3：验证输出是否不成比例地摧毁前缀缓存复用？

**设置。** 在两种缓存策略下对每个会话做确定性重放；把可归因于验证输出片段的重 prefill token 与这些片段占上下文 token 的份额比较；体量匹配的惰性填充渲染提供零假设参照并兼任缓存侧安慰剂。

**预期结果。** 在两种策略下，验证输出占失效 token 的份额至少是其上下文 token 份额的 1.5 倍，而填充对照接近 1。

**证伪条件。** 若在任一策略下该比值至多 1.1 则被驳斥 —— 那时验证内容对缓存的伤害不比等体量等位置的惰性内容更大；若填充对照实质偏离 1，则该 RQ 无效（归因伪影）。

**假设（白话）。** 验证输出对缓存的敌意超出其长度：它会扰动，而前缀缓存下的扰动正是花钱之处。

**指标。** 每策略失效比；绝对重 prefill 美元；填充对照比值；模拟器校准误差。

#### RQ4：缓存损害由格式驱动还是语义必要？

**设置。** 在两种策略下重放规范化渲染（易变片段 —— 路径、时间戳、时长、截断边界 —— 改写为稳定形式）；将验证可归因的重 prefill 与 RQ3 的结果比较。

**预期结果。** 规范化至少收回验证可归因失效的一半 —— 损害大部分是格式性的，无需改变 agent 所学即可消除。

**证伪条件。** 若回收率低于四分之一则被驳斥 —— 那时损害在语义上必要，"稳定渲染器"的推论被放弃、代之以诚实的否定结果。

**假设（白话）。** 缓存损害主要是验证输出如何渲染的伪影，而非其内容本身。

**指标。** 每策略回收分数；残余（语义性）失效份额。

#### RQ5：逐类成本–价值前沿是异质的还是退化的？

**设置。** 逐类：账本成本画像；在会话阶段、触及文件与自上次同类检查以来 diff 大小的预定义分层内估计动作分歧与终局相关性，采用簇稳健（按会话）bootstrap 区间。先应用正性门（每个被接纳层含至少两个类别的至少 30 步）；其通过率本身也报告。

**预期结果。** 从 lint 到全套件的执行成本中位数跨度至少 10 倍，而分层动作分歧跨度至多 3 倍 —— 各类别每美元价值差异至少三倍，粒度感知调度确有可利用的真实结构。

**证伪条件。** 若各类别成本与分层价值在 1.5 倍以内成比例则被驳斥（退化前沿）；若通过正性门的层不足一半，则记为不确定，前沿只作描述性报告。

**假设（白话）。** 便宜的检查用每美元买到不成比例的信息；把所有验证合并成一个数字恰恰掩盖了调度器要用的结构。

**指标。** 带层计数的逐类成本与价值画像；正性门通过率。

#### RQ6：仅靠 agent 透明的重调度能避免已记录账单的多少？

**设置。** 对 agent 透明的重调度 —— 批量化验证执行、沙箱放置与预热、缓存感知的重 prefill 调度、验证执行与同轮 decode 重叠 —— 在冻结成本模型下精确重放，在不变层内自由搜索（探针可以尽可能强：估计量是负载的可避免份额，不是某个策略的优劣）。墙钟作用域条件适用，语料中超时或延迟条件化 agent 构造的出现率随之报告。

**预期结果。** 中位会话总服务美元中至少 10% 在结果逐字节一致的条件下被收回。

**证伪条件。** 若收回份额低于 5% 则被驳斥；且若 RQ1 本身在 0.10 水平被驳斥，此底线重定为实测自由份额的一半并明示重定 —— 使一个坏常数不能以同一理由让两个问题双双失败。

#### RQ7：在现实预测器质量下投机续跑是否可行？

**设置。** 以实测臂为条件：oracle 节省通过对原生实测运行日志的重放计算（oracle 从不误判，故其续跑在构造上结果一致）；实际节省来自使用冻结的、TraceLab 训练预测器的实测运行，回滚 token 计入该臂。解决率非劣性：按实例与种子配对，单侧 5 个百分点边际，α = 0.05，采用不一致对（discordant-pair）构造 —— 当真实差为零且不一致率至多 0.15 时功效至少 0.8（2 个百分点的边际在此样本量下不可判定，已在设计评审中否决）。样本量：300 实例 × 2 脚手架 × 3 种子 = 每臂 1,800 次配对运行。

**预期结果。** oracle 节省至少达会话服务美元的 15%；冻结预测器保留 oracle 节省的至少一半；解决率非劣。

**证伪条件。** 若 oracle 节省低于 5%（无论预测器质量如何投机余量都不存在）或冻结预测器保留不足 oracle 节省的四分之一（余量存在但受预测器限制、超出实际可及范围）则被驳斥；解决率非劣性不达标则无论节省多少都封顶该断言，置信界跨界则报告为不确定。

**假设（白话）。** 越过将会通过的检查继续推进只有在通过/失败足够可预测时才值真金白银 —— 天花板与可实现分数都被测量而非假设。

**指标。** oracle 与实际美元节省；预测器留出集 AUC；误判与回滚成本份额；配对解决率差及置信界。

### 效度威胁（Threats to Validity）

**构念效度（construct validity）。** 验证诱发份额在构造上依赖归因规则；设计的回答是两端偏差方向已知的区间、任何归因伪影都必然不过的打乱标签安慰剂、以及捕捉核算选择伪影的网格重算。价值代理（动作分歧、终局相关性）是行为相关量而非因果效应；排序断言只在通过门控的层内被授权，重叠失败时触发预先承诺的降级（描述性前沿、不确定判定）。

**内部效度（internal validity）。** 步骤类型标签是仪器，在扩大规模前经过审计（两名标注员，κ ≥ 0.8，只允许相邻混淆）。缓存模拟器对照真实引擎校准，接受门槛 ±10%，误差如实报告。Tier-A 精确性对已记录会话在冻结成本模型下成立；其部署解读假设 agent 行为不依赖墙钟时间，该类构造的语料出现率如实报告而非假设不存在。

**外部效度（external validity）。** 发现限定于所测语料与脚手架：TraceLab 的会话构成与两个开源 SWE-bench 脚手架。以其规模作为问题动机的生产研究不发布 trace，因此向专有部署的迁移只经由判定稳定性网格论证、不作断言。若干承重的邻居刻画在设计期只以语料扫描深度接触；其文献元数据此后已对照 arXiv export API 核实，但元数据不等于全文，因此预测量门槛仍要求第一手确认 TraceLab 论文确实缺少验证归因分析，若确认失败则执行预先承诺的重新定位 —— 新颖性立场是被检验的，不是被假定的。冻结的通过/失败预测器还在 TraceLab 上训练、部署于实测 SWE-bench 会话，这一跨语料迁移的退化本身被测量（两个语料上的留出集 AUC）而非假定无害；受预测器限制的结局是 RQ7 的预注册结果，不是设计的失败。

**结论效度（conclusion validity）。** 每个假设都带预注册底线与证伪方向；功效不足或未过门控的单元报告为不确定，从不为零、从不静默丢弃；安慰剂在任何假设之前打分；非劣性边际在设计评审中从不可判定的 2 个百分点放宽为有功效的 5 个百分点，而非放任其悄然失败。

## 相关工作（Related Work）

最接近的先行工作是 Cost-Aware Speculative Execution for LLM-Agent Workflows: An Integrated Five-Dimension Method（arXiv:2606.07846），在综述全景之前值得把差量说清楚：它与本文共享面向 agent 服务决策的美元计价目标，但不落地于真实 trace、不把验证决策本身作为调度对象、也不建模验证对前缀缓存复用的破坏 —— 而这三点正是本设计的骨架。我们承认共享的目标，主张测量本身：trace 落地的归因、缓存交互、以及按有效性划分的余量估计。

**编码 agent 负载刻画。** TraceLab（arXiv:2606.30560）发布了首个带类型化工具调用的公开编码 agent trace 语料并面向服务系统设计刻画负载；一项 Copilot 流量的生产级研究（arXiv:2608.00101）在 320 万用户规模上做了同样的事但不发布 trace；企业推理经济学分析（arXiv:2607.13080）证明运营方确在计量这笔开销。按本项目在立项前所做的占据度分析，第三篇聚合刻画已无空间 —— 且三者都不携带验证步语义：没有验证归因成本份额、没有重试归因、没有缓存交互分析。这一缺席维度经第一手确认作为预测量门槛后，正是本文的估计量。

**agent 感知的服务与缓存。** 服务经典 —— PagedAttention（Kwon et al., 2023）、SGLang 的基数树复用（Zheng et al., 2023）、prefill/decode 解耦（Zhong et al., 2024）、以 KV 缓存为中心的生产服务（Qin et al., 2024）、分块 prefill 调度（Agrawal et al., 2024）—— 确立了前缀复用与 prefill 调度是服务资金集中之处，这正是失效在我们账本中是一阶项的原因。其上的 agent 感知簇（KVFlow，Pan et al., 2025；Irminsul: MLA-Native Position-Independent Caching for Agentic LLM Serving，arXiv:2605.05696；三个月内至少还有三个系统）利用工作流结构优化缓存行为 —— 但对步骤内容一视同仁，因此谁也说不出哪种步骤语义在摧毁复用。本文测量的正是这些系统所需的通道：验证输出作为扰动源，以及规范化能消除其中多少损害。

**测试时计算与 agent 环中的验证。** 基于执行的检查自 pass@k（Chen et al., 2021）以来锚定代码生成；Reflexion（Shinn et al., 2023）使"把失败回喂"成为标准 agent 环；重复采样（Brown et al., 2024）与计算最优的测试时扩展（Snell et al., 2024）在把验证当作免费或事后附注的前提下分配生成计算，预算以 FLOPs 或 token 而非服务美元计。SWE-bench（Jimenez et al., 2024）及攻克它的开源脚手架（SWE-agent，Yang et al., 2024；OpenHands，Wang et al., 2024）固定了任务底座并恰好产生本文所研究的会话形态。这条线没有人为验证环的服务侧成本定价 —— 即我们账本所定界的量。

**调度理论与投机。** LLM 推理与 AI agent 的排队论调度（Dai et al., 2025）把 Generate 与 Verify 建模为不同服务类别并推导吞吐最优策略 —— 该区分对调度重要的理论先声 —— 但预设了本文所估计的逐类成本、价值与扰动参数；我们的画像是该模型的经验侧。token 级投机解码（Leviathan et al., 2023）是步骤级投机续跑的请求内祖先，SpecBox: Speculative Sandbox Scheduling for Efficient LLM Agent Serving（arXiv:2607.23933）提供了投机会用到的沙箱预热机制 —— 一个没有策略也没有经济目标函数的机制，而这正是本研究带实测非劣性门控的投机臂所处的位置。

## 结论（Conclusion）

本工作把一个服务栈盲点重构为带证伪门槛的可测量对象：验证 —— 被服务系统当作不透明工具时间计价的步骤类别 —— 要么是带可测缓存损害与可退还余量的一等成本对象，要么不是，而设计预先承诺无论哪个答案都如实报告。方法论上的赌注是：无法支撑逐点因果归因的观测 trace，只要给每个估计量以其识别条件真正授权的最强证据 —— 无反事实处用偏差方向已知的区间、系统（缓存）确定之处用精确反事实、混杂可检查之处用门控排序断言、以及把每个重调度反事实送往唯一能诚实评估它的场域（重放或实测）的有效性划分 —— 就仍能支撑决策级断言。无论头条数字落向何方，本研究预注册的画像正是现有 Generate/Verify 调度理论所预设、agent 感知缓存系统要成为语义感知所必需的参数。设计中最弱的识别被点名而非隐藏：逐类价值排序依赖正性门之后的分层观测对比，把它升级为因果断言需要随机化验证节奏的插桩脚手架 —— 那是自然的下一个实验，连同将在生产中消费这些测量的在线调度器，也就是本测量研究刻意拒绝成为的那篇论文。
