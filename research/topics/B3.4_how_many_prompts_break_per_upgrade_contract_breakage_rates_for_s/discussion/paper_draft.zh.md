# 今天通过，明天失效：测量结构化输出 LLM 流水线的逐次升级契约破坏率

> 由 `pipeline.md` 中六个已确认阶段输出汇编而成，已通过品味审计（`taste_audit.md`：🟢）。状态：**规格说明 / 论文草稿——尚未运行任何实验。** 下文所有数字均为预注册的设计目标，而非结果。本文档为 2026-08-21 复审修订后版本的中文翻译。

## 摘要

生产系统日益将大语言模型（large language model, LLM）包裹在结构化输出契约（structured-output contract）之后——JSON 模式（JSON schema）、格式约定、少样本模板（few-shot template）——下游代码直接解析这些输出，却从不重新审视其底层模型。供应商侧的模型升级频繁发生、文档往往粗略，而它们改变的恰恰是这些契约默默依赖的东西；然而，这些受契约约束的行为在一次版本跳变后能存活多少，从未被直接测量过：目前团队只能被动地从自己的生产事故中得知破坏的发生。我们构建了一个分层的生产风格契约库，涵盖 JSON 模式符合性、机器可校验的格式约定、以及从真实对话中挖掘的少样本模板，每一项都由一个针对人工标注校准过的三层确定性校验器（three-tier deterministic checker）验证。我们在开放权重（open-weight）与闭源 API 模型谱系的连续版本上测量破坏率，且仅将其报告为超出由同一流程计算的版本内重采样噪声底线（noise floor）的超额部分；拟合一个将契约结构与脆弱性关联起来的多变量模型；将其预测能力与一个廉价的分布偏移检测器（distribution-shift detector）正面对比，以排除通用混杂因素；并界定两种现有缓解手段——语法约束解码（grammar-constrained decoding）与逐版本提示重编译（per-version prompt recompilation）——能消除多少已测得的破坏。我们报告按契约类型划分的噪声校正破坏率、经验证的结构性脆弱性预测因子、以及升级诱发破坏中可避免的份额，为工程团队在采用新模型版本前排定回归测试优先级提供依据。

## 引言

大语言模型如今被例行地包裹在结构化输出契约之后：下游解析器期望的 JSON 模式、渲染管线依赖的格式约定、将模型锚定到特定输出形态的少样本模板。契约的编写者固定了"合格输出应当是什么样子"，却无法固定"实际产出它的是什么"——必须满足契约的行为属于今天恰好响应请求的那个模型版本。这种安排在出问题之前是不可见的：供应商侧的模型升级按契约拥有者无法控制的节奏发生，文档往往只是粗略描述，而它们改变的恰恰是每一份契约默默假设不变的东西。

然而，这些受契约约束的行为在一次版本跳变后究竟能存活多少，从未被直接测量过。一份在上个月的模型上干净通过验证的契约，与一份在本月的模型上失败的契约，并不是不同的对象——它们是同一个接受谓词（acceptance predicate）作用于两个不同的输出来源——但今天这些系统的构建方式中，没有任何环节会报告一次给定升级中真实契约库有多大比例越过了这条线，或哪些契约是最该预警的。团队目前是被动发现的——来自生产事故，而不是来自一个在采用新版本之前就能查验的数字。

最接近的现有工作从一个相邻但不同的角度触及这一空白。Chen、Zaharia 与 Zou 对 ChatGPT 行为随时间变化的研究是最近的先行工作：它记录了两个 GPT 快照之间在通用任务集上巨大的、任务相关的行为与格式符合性偏移，确立了"同一个"已部署服务在不同发布之间可以发生实质性变化。LogProbTracking 紧随其侧，将检测一个端点（endpoint）的响应分布*是否*发生了任何变化本身当作一个开放的黑盒监控问题。这两项工作合起来确立了模型行为会漂移、且漂移可被检测——但它们都没有构建生产风格契约库、没有针对验证器计算逐次升级的破坏率、也没有追问哪些契约特征预测脆弱性；本文要弥合的增量正是这两项工作所记录的漂移在下游契约层面的后果。在这一对工作之外，其他研究方向更为疏远：输入侧提示鲁棒性（prompt robustness）研究固定模型、扰动措辞，恰是升级场景的对偶；指令验证与约束解码工作构建了真实的验证器与保证，却只在单一模型快照内部使用，从不跨越版本谱系；纵向基准（longitudinal benchmark）方法学存在于另一类工件（恶意软件概念漂移）中，尚无 LLM 契约行为的对应物。

将这一空白转化为可测量的问题会引出它自己的障碍。"契约破坏"没有任何来源可提供现成的真值（ground truth）——JSON 模式符合性可机械判定，但格式约定遵守与少样本模板跟随存在分级符合的情形，故通过/失败边界本身就是一个设计选择，必须针对真实解析器的行为进行校准，而非直接假定。供应商控制的端点事后不可靠重查：一个具名快照可能被静默更改或彻底下线，这会使观测到的变化被归因于一个日后无人能独立核验的版本。即便是真实的、非噪声的通过/失败行为变化，也不自动构成任何具体结论的证据——单个契约的结果是通过随机的生成过程实现的，因此真正的升级诱发破坏必须先与普通的版本内采样变异区分开，然后再单独与通用的、契约无关的分布偏移区分开——后者是一个廉价监控信号可能同样预测得到的混杂。而识别哪些结构特征使契约脆弱，需要足够多的独立版本跳变与契约多样性以获得统计功效（statistical power），同时契约的自然特征——嵌套深度、约束数量、字段数量——彼此相关，故朴素的逐特征相关分析会错误归因，需要多变量模型来解缠。

我们的方法将上述每个障碍转化为一个连贯的测量设计，而非一组对冲说明，其核心是一个统一的动作：将同一个通过/失败流程应用于同一输出池的两种不同划分——一次按版本切分，一次按版本内重采样切分——从而使"这是不是真实的破坏"变成一个可查验的、同类对同类的比较，而非一个假设。一个针对人工标注输出校准、并对其严格/宽松边界做扫描的三层验证器，为这一比较的真值一侧提供可辩护的基础。一个版本配对执行框架（version-paired execution harness）将主要论断锚定在可永久重查的开放权重模型谱系上，并在每个批次旁运行首 token 对数概率哨兵探针（logprob canary），捕获并标记闭源端点的可寻址性（addressability）失效——这正是该锚定选择所防范的对象。一个由同一流程计算的版本内对半切分噪声底线，是每个破坏论断都要对照检验的零假设。一个在预注册、去相关特征向量上以分组交叉验证拟合的多变量脆弱性模型，将契约结构变成经验证的预测因子而非边际相关。一个与廉价分布偏移检测器的正面对比，检验所测脆弱性反映的是契约自身结构，还是任何通用监控器都能捕获的混杂。最后，一个按层分解的对比，将两种现有缓解手段与未缓解组对照，界定已测破坏中有多少是部署选择而非升级的固有代价。

我们在一个分层的契约库上评估该设计——真实世界 JSON 模式、可验证格式规则、从生产风格对话中挖掘的少样本模板——针对作为主要可复现锚的开放权重模型谱系的连续版本，以及作为次要臂的带日期闭源 API 快照运行，并以一个廉价的基于对数概率的检测器与两种现有缓解技术作为对照。

综上，我们的贡献是：
- 一个测量设计：升级诱发的契约破坏仅报告为超出由同一验证流程计算的版本内噪声底线的超额部分，而非原始跨版本翻转计数——对半切分零假设构造本身是标准的配对重采样实践；新的是它所服务的被估量（estimand）：在一个精心设计的契约库上的逐次升级破坏率。
- 一个经校准的三层契约验证器与一个版本配对执行框架——锚定于可永久重查的开放权重谱系，并配有针对闭源端点可寻址性失效的哨兵——二者共同为破坏估计提供可辩护的真值与可引用的版本身份。
- 一个经验证的多变量脆弱性模型，将契约级结构特征与破坏几率关联起来，并配以与廉价分布偏移检测器的正面对比，将契约特异的脆弱性从通用混杂中分离出来。
- 一个按层分解的测量：两种现有缓解手段能消除多少升级诱发的破坏，从而界定原本看似升级固有代价中的可避免份额。

## 问题定义

**形式化设置。** 一份契约是三元组 c = (T, D, A)：提示模板 T、输入分布 D、以及将输出映射到 {0,1} 的确定性接受谓词 A。版本谱系 L = (v₀, v₁, …, v_k) 是一列可单独寻址的模型版本。对契约-版本对 (c, v)，在固定解码设置下抽取 n = 20 个独立同分布样本并由 A 评分，得到通过概率 p̂(c, v)。契约在 v 处*通过*当且仅当 p̂(c, v) ≥ 0.9，*失败*当且仅当 p̂(c, v) ≤ 0.5（中间带被排除在主统计量之外，由敏感性分析单独覆盖）。契约在跳变 v → v′ 上*破坏*当且仅当它在 v 通过且在 v′ 失败。破坏率为 B(v→v′) = |{c : 在 v 通过 ∧ 在 v′ 失败}| / |{c : 在 v 通过}|；对称地定义修复率 F(v→v′)，净回归为 B − F。噪声底线 B_null(v) 的计算方法是：将每份契约在版本 v 的 20 个样本切分为两个不相交的 10 样本半组，并把与跨版本完全相同的破坏计算应用于两半之间，如同它们是两个版本。由于每个半组只含 10 个样本而跨版本比较每侧使用全部 20 个——且 n = 10 时的 p̂ 方差约为 n = 20 时的两倍、阈值粒度也更粗——跨版本统计量会另行在每个版本的不相交 10 样本子集上重新计算，使 B(v→v′) 与 B_null 共享同一估计量粒度；这一子样本匹配的比较是主检验，全样本跨版本率一并报告。研究对象是超额量 ΔB = B(v→v′) − B_null，以及在契约库的预注册特征向量上哪些分量预测逐契约破坏。

**为何困难。** 在格式约定与少样本模板遵守的层面上，"破坏"的含义没有外部提供的真值——只有 JSON 模式符合性在严格意义上可机械判定，故接受谓词 A 本身内嵌了一个严格度选择，必须针对真实下游解析器行为校准，而不能靠构造直接假定其正确。版本谱系 L 的可信度取决于其可寻址性：闭源 API 的版本标识符可能在其名字不变的情况下被静默更改或整体下线，故一次观测到的通过→失败翻转有被归因于一个日后无法独立复核的版本跳变的风险。即便承认一次真实的非噪声翻转，{o_t} 经由随机采样过程实现这一事实意味着，真正的跨版本效应必须先越过版本内噪声底线 B_null 才能被归因于该跳变——而越过这一门槛仍不充分，因为一次超出 B_null 的翻转仍可能反映端点输出分布的通用、契约无关的偏移，而非 c 自身结构的任何特异性——这是噪声底线比较本身无法排除的另一类混杂。最后，可能解释脆弱性的特征向量——模式嵌套深度、约束密度、少样本示例数量及相关量——天然共线（更深的模式往往携带更多字段与更多约束），故可信的特征级论断需要具有足够独立跳变与契约多样性以保证功效的多变量设计，而非在手头恰好有的契约上做边际相关。

## 方法概览

在概念层面，本研究是一条由六个协作部分组成的单一测量流水线，围绕一个统领性动作组织：将同一个通过/失败流程应用于同一输出池的两种不同划分——版本内重采样切分与跨版本切分——从而升级诱发的破坏只报告为跨版本比较超出版本内比较的部分。

**契约验证器**将每个输出转化为确定性的通过/失败裁决，经过校准，使后续每次比较的真值一侧是可辩护的而非假定的。**版本配对执行框架**收集该裁决所依据的原始样本，锚定在每个版本在研究全程保持可单独寻址的谱系上，并配有哨兵，标记该假设会静默失效的闭源端点情形。**噪声底线估计器**取这些已收集样本，通过在单一版本内部（而非跨两个版本）运行同一基于验证器的计算，产出每个破坏论断所对照的零假设。**脆弱性预测模型**取跨多契约多版本的破坏事件，将其与每份契约的结构特征相关联，并控制特征间的自然相关。**廉价信号特异性检验**取同一批破坏事件，追问一个便宜得多的、契约无关的分布偏移检测器是否已能同样好地预测它们，从而排除（或不能排除）脆弱性模型自身无法处理的通用混杂。**缓解上限界定**取两种降低提示级脆弱性的现有技术，逐层测量每一种实际消除了多少已量化的破坏。

## 方法论

### 契约验证器构建

**挑战。** JSON 模式符合性可机械校验，但格式约定遵守与少样本模板跟随存在分级符合（例如字段正确但键序重排，或列表正确但项目符号不同），因此任何接受谓词都有沦为任意严格度选择的风险——要么误报良性变异，要么漏掉真实的下游失败。

**洞察。** 这种歧义无法通过在抽象层面挑一个"正确"的严格度来解决，但可以将其转化为一次针对真实解析器行为的显式校准练习加一次敏感性扫描，而非一个默默烘焙进流水线的隐藏设计决定。

**方法。** 每个输出由一个三层确定性校验器评分：解析层（parse tier，输出是否解析为期望的封套——合法 JSON、期望的代码围栏？）、模式层（schema tier，依据契约的模式做 JSON Schema Draft 2020-12 验证）、约定层（convention tier，风格上类似可执行指令验证函数的正则/规则校验器）。一个契约实例通过当且仅当所有适用层通过。在任何测量运行之前，验证器针对一组保留的人工构造正负示例输出做单元测试，且严格/宽松边界（例如 JSON 块周围容忍多少环绕文本）是一个预注册常数，由专门的敏感性分析扫描，而非由单一任意选择固定。

### 版本配对执行框架

**挑战。** 供应商控制的模型版本并非总能干净枚举或事后独立重查——闭源端点可能在具名快照内静默变化，旧快照会被下线——这使得难以将观测到的行为变化归因于一个具体的、可引用、可复现的版本跳变。

**洞察。** 闭源端点上的可寻址性失效一旦发生便无法追溯修复，但它可以被实时检测，并且设计可以做到让首要论断从一开始就不依赖任何可能发生此类失效的端点。

**方法。** 契约库针对锁定的、可单独寻址的版本执行——带日期的闭源 API 快照与永久归档的开放权重检查点（checkpoint）——在固定解码设置下，每个（契约, 版本）对抽取 n = 20 个样本。每个收集批次旁并行运行一个首 token top-k 对数概率哨兵探针，探测同一端点；若检测到收集中途的分布偏移，受影响批次被标记并重新收集。首要论断锚定在开放权重谱系上（永久可下载的检查点，天然可单独寻址），带日期的闭源 API 快照链被作为次要的、受可寻址性约束的臂对待，而非等强度的论断。

### 版本内噪声底线估计器

**挑战。** 契约的通过/失败结果是经由随机的生成与服务过程实现的——即使在温度为 0 时，服务栈的非确定性（serving-stack nondeterminism）也会扰动输出——因此跨版本跳变的通过转失败原始翻转计数本身无法区分真正的升级效应与普通的重采样变异。

**洞察。** 同一破坏计算流程，应用于版本内切分而非跨版本切分，恰好产出跨版本论断所需对照的零分布——将"这是真实的还是噪声"变成同类对同类的统计比较，而非假定的基线。

**方法。** 对每个版本，将每份契约收集的 20 个样本切分为两个不相交的 10 样本半组，并在两半之间完全按照跨版本方式运行破坏计算，得到充当噪声底线的伪破坏率。为使比较两侧处于同一估计量粒度，跨版本破坏统计量另行在每个版本的不相交 10 样本子集上计算——与半组的 n = 10 匹配——该子样本匹配的超额量是主检验统计量，全样本（n = 20）跨版本率一并报告。在温度 0 主臂下，该底线捕获的版本内变异是服务栈非确定性——批处理、内核与路由效应——而非采样温度；由于此类非确定性未必在时间上可交换，两个半组按收集顺序交错抽取，并在对半切分底线之外同步计算一个时间半组底线（前 10 个对后 10 个样本）；若两者显著背离，则所有破坏论断降级为以较大的时间半组底线作为保守零假设。版本跳变的破坏仅报告为跨版本率超出该版本内底线的部分，并以配对的、多重比较校正的流程跨跳变与契约类型检验。

### 脆弱性预测模型

**挑战。** 可能解释脆弱性的契约级结构特征彼此相关——嵌套更深的模式往往也携带更多字段与约束——故朴素的逐特征相关分析有把效应完全归错特征的风险。

**洞察。** 一个联合考虑所有候选特征的多变量模型，配以从不让近重复契约跨折泄漏的交叉验证评估，才能让特征级论断同时经受住这种共线性与多特征检验带来的膨胀。

**方法。** 一个混合效应逻辑回归（mixed-effects logistic regression）将逐契约破坏事件与预注册的结构特征向量关联——模式嵌套深度、字段数、必填字段比例、约束数、少样本示例数、指令 token 长度、以及分隔符/大小写规则数——外加契约类型，并对版本跳变与模型家族设随机截距。该拟合模型的预测效用另行在分组交叉验证下评估，契约按家族分组使近重复者从不跨折，另在留一模型家族（leave-one-model-family-out）切分下检验拟合出的预测因子是否泛化到未参与拟合的家族。契约库的分层抽样设计刻意覆盖联合特征网格，使深度与约束数不会因构造而完全相关。

### 廉价信号特异性检验

**挑战。** 即便一个破坏效应越过了版本内噪声底线，也不自动证明契约自身结构起作用——它同样可能反映端点的通用、契约无关的分布偏移，而一个便宜得多的信号也许同样能预测，这将使精心构建的契约库相对现有廉价监控成为冗余。

**洞察。** 两种信号回答的确实是不同的问题——一个契约无关、近乎零成本，另一个契约特异、构建昂贵——因此只有在同一数据上做直接的正面预测比较，才能表明昂贵信号携带了廉价信号遗漏的信息，而不是靠断言维持这一区分。

**方法。** 在用于拟合脆弱性模型的同一批（契约, 版本）对上运行首 token top-k 对数概率双样本检测器，计算其对逐契约破坏的预测 AUC。将该 AUC 与结构脆弱性模型在同一保留数据上的 AUC 直接比较；仅当结构模型的 AUC 超出廉价检测器达到预注册的差距时，契约特异脆弱性才被视为已从通用混杂中分离。

### 缓解上限界定

**挑战。** 现有的提示级脆弱性缓解手段只保证契约要求的一部分——例如语法约束解码从构造上保证模式层，却对约定层与语义封套失效无能为力，且格式限制（format restriction）本身已被证明会改变任务表现（Tam et al., arXiv:2408.02442），因此约束解码臂的逐层差值捆绑了结构性保证与任何此类表现偏移——故单一的聚合缓解数字会混淆对同一修复响应截然不同的各层。

**洞察。** 由于两种候选缓解是回答同一底层问题（已测破坏中有多少是部署选择而非固有代价）的不同技术，有信息量的比较是针对同一未缓解臂运行的、共享的按层分解协议，而非两次独立且不可比的评估。

**方法。** 在开放权重锚谱系上，契约库额外在语法约束解码臂（从构造上保证模式层、约定层仍可失败）与逐版本提示重编译臂下执行，各自与未缓解臂在同一批契约上逐层比较，采用配对统计检验。

## 实验

### 实验设置

**数据集。** SchemaStore（schemastore.org）——真实世界 JSON 模式，按嵌套深度与约束数分层抽样，为模式契约类型提供自然出现的特征分布。JSONSchemaBench——约 10,000 个真实世界 JSON 模式，将模式契约类型的覆盖扩展到 SchemaStore 之外，以满足脆弱性模型的功效要求。IFEval——程序可验证的指令约束，为格式约定契约类型提供成熟的机器可校验规则集。FollowBench——按约束数分层的多约束指令，为约束密度高端提供契约来源，使该特征在库中有足够方差以估计其几率比（odds ratio），因为 SchemaStore 与 JSONSchemaBench 的模式偏向中等约束数。WildChat-1M——真实用户-LLM 对话，从中挖掘生产风格的少样本与结构化输出模板，使少样本模板类型来自真正的野生用法而非人工编写示例。Berkeley Function Calling Leaderboard v3——函数调用结构化动作契约，将覆盖扩展到函数调用类型。模型版本链：横跨 gpt-4o → gpt-4.1 → gpt-5 谱系的带日期 OpenAI 快照作为次要的、受可寻址性约束的臂；Llama 2 → 3 → 3.1 → 3.3 与 Qwen2 → Qwen2.5 → Qwen3 作为主要的、可永久重查的开放权重锚谱系。

**预算（设计目标，非结果）。** 试点阶段意味着 300 份契约 × 3 个版本 × 20 个样本 ≈ 18,000 次生成——单节点 vLLM 级推理，在生产风格提示长度下约一个 GPU 日的量级。规模化阶段意味着约 3,000 份契约 × 约 13 个版本 × 20 个样本 ≈ 780,000 次开放权重生成，外加两个缓解臂在其开放权重子集上的重跑，以及一个闭源 API 次要臂——其金钱成本通过为该臂预注册固定契约子样本来界定，而非将全库对付费端点执行。任何收集成本将超出该预算包络的（跳变 × 契约类型）单元被预先声明为"因预算不可判定"（INCONCLUSIVE-by-budget）——与预注册的功效/不可判定规则一致——而非被静默丢弃或部分收集。

**基线**（健全性对照，而非要击败的竞争者——这是一项测量研究，没有任何研究问题被表述为"我们的流程胜过基线 X"）。版本内对半切分噪声底线是每个破坏论断必须对照检验的零假设。风格上沿袭既有端点变化监控工作的首 token top-k 对数概率检测器是廉价信号对照：若它预测破坏的能力与结构脆弱性模型相当，则契约库相对现有廉价监控毫无增益。语法约束解码臂，在开放权重链上以兼容自回归的约束解码工具实现（借用既有扩散模型约束解码工作的解码期保证概念而非其实现，因为此处锚谱系是自回归的），是模式层缓解上界。风格上沿袭既有逐版本提示编译工作的声明式提示重编译臂，是重编译缓解基线。

**指标。** 噪声校正破坏率 ΔB 及其统计检验结果（按契约类型）；脆弱性模型的混合效应几率比及 95% 置信区间、分组/留一家族预测 AUC；廉价信号检测器的 AUC；验证器对人工标注的一致率；按谱系类型统计的哨兵触发重收集次数；以及按层分解的缓解组对未缓解组破坏率。

**研究问题：**
1. RQ1 —— 契约验证器的通过/失败裁决与人工标注的一致程度是否足以充当真值？
2. RQ2 —— 版本可寻址性是否确实是闭源 API 与开放权重谱系之间有差异的风险？
3. RQ3 —— 已测破坏是否超出版本内噪声底线？是否随契约类型而异？
4. RQ4 —— 哪些契约级结构特征预测脆弱性？
5. RQ5 —— 已测脆弱性反映契约特异结构，还是廉价检测器已能预测的通用分布偏移？
6. RQ6 —— 语法约束解码能消除多少模式层破坏？
7. RQ7 —— 逐版本提示重编译能消除多少总破坏？

*编号说明。* 预注册协议（`paper.md`）以三个研究问题 H-RQ1–H-RQ3 为主线；它们在此对应 RQ3（H-RQ1：超出噪声底线的破坏）、RQ4（H-RQ2：脆弱性预测因子）与 RQ6–RQ7（H-RQ3：可避免破坏，每个缓解臂一个编号问题）。RQ1、RQ2 与 RQ5 将协议中预注册的工具有效性检查——验证器校准（A1）、版本可寻址性（A3）与廉价信号对立解释（B-alt）——提升为独立编号的问题，而非留作无编号的假设检查。

#### RQ1：契约验证器的通过/失败裁决与人工标注的一致程度是否足以充当真值？

**设置。** 在任何测量运行之前，一组保留的人工构造正负示例输出由全部三个验证层（解析、模式、约定）评分，并与人工标注比较。

**预期结果。** 验证器对人工标注的一致率在全部三层上不低于 0.95。

**证伪条件。** 若校准集上任何一层的一致率低于 0.95，则被驳斥——意味着接受谓词对真实下游解析器裁决的追踪不够紧密，下游破坏数字不可信，且在任何其他 RQ 的结果有意义之前必须重新校准严格/宽松边界。

**假设（通俗表述）。** 验证器的通过/失败判定是真实下游解析器行为的可信替身，而非任意严格度选择。

**指标。** 逐层及总体的验证器对人工标注一致率。

#### RQ2：版本可寻址性是否确实是闭源 API 与开放权重谱系之间有差异的风险？

**设置。** 在整个收集窗口内，首 token 对数概率哨兵探针在开放权重锚谱系与闭源 API 带日期快照链上都伴随每个收集批次运行；按谱系类型统计哨兵触发的重收集事件数。

**预期结果。** 开放权重锚谱系在收集窗口内触发零次哨兵重收集事件，而至少一条闭源 API 带日期快照链触发至少一次。

**证伪条件。** 若哨兵事件在开放权重谱系上发生得与闭源链相当（或更多），则被驳斥——意味着本设计将首要论断锚定在开放权重谱系上所防范的可寻址性风险实际上不具区分性，将闭源 API 结果作为次要臂的选择需要重新论证。

**假设（通俗表述）。** 闭源 API 端点携带真实可检测的可寻址性风险，而永久归档的开放权重检查点没有。

**指标。** 按谱系类型的哨兵触发重收集事件数。

#### RQ3：已测破坏是否超出版本内噪声底线？是否随契约类型而异？

**设置。** 试点阶段：300 份契约（模式、格式约定、少样本模板各 100），一条至少含三个锁定连续版本的开放权重谱系，每（契约, 版本）对 n = 20 个样本，温度 0 主臂。规模化阶段：约 3,000 份契约，横跨至少十次版本跳变与三个模型家族。每次跳变：对 B(v→v′) 相对 B_null 在契约上做双侧配对置换检验，跨全部（跳变 × 契约类型）单元做 Benjamini–Hochberg 校正，α = 0.05。

**样本量论证。** 试点阶段每次跳变 300 个配对通过/失败观测，使双侧精确配对检验在 α = 0.05 下区分 B = 5% 与 B_null = 1% 的功效超过 0.9；规模化阶段约 3,000 份契约横跨十余次跳变，是按 RQ4 脆弱性模型的功效需求而非仅本 RQ 定的规模。

**预期结果。** 在至少一半被检验的版本跳变上，B(v→v′) 显著超出 B_null；合并点估计 ΔB 至少 3 个百分点；严格封套契约类型（模式、约定）的 ΔB 大于少样本模板契约——后者的演示样例冗余地锚定了输出格式。

**证伪条件。** 若在所有被检验跳变与契约类型上，校正后 B(v→v′) 与 B_null 统计上不可区分，则被驳斥——即若表观跨版本破坏不大于同版本重采样方差，"升级会在噪声之外可测量地破坏契约"这一中心论断为假，本文的发现将转为破坏率的噪声校正上界，而非已证实的效应。

**假设（通俗表述）。** 每次升级都有真实的、非噪声比例的契约新失效，且随契约格式受约束的紧密程度而异。

**指标。** B(v→v′)、B_null、ΔB 及其配对检验 p 值，按契约类型。

#### RQ4：哪些契约级结构特征预测脆弱性？

**设置。** 对逐契约破坏事件做混合效应逻辑回归，自变量为预注册七特征向量加契约类型，对版本跳变与模型家族设随机截距，在全部规模化破坏事件上拟合；对每个特征做 Wald 检验并 Benjamini–Hochberg 校正；预测 AUC 在分组 5 折交叉验证（按契约家族分组）与留一模型家族切分下评估。

**样本量论证。** 约 3,000 份契约横跨至少十次版本跳变，依预注册分析计划，对每特征几率比 1.3 的检测功效至少 0.8。

**预期结果。** {模式嵌套深度, 约束密度} 中至少一个的几率比不低于 1.3 且校正后 95% 置信区间不含 1；少样本示例数的几率比低于 1；留一家族预测 AUC 至少 0.65。

**证伪条件。** 若校正后没有任何预注册特征取得显著几率比，或分组交叉验证或留一家族 AUC 与 0.5 不可区分，则被驳斥——意味着脆弱性无法由所提结构特征预测、无法据此导出契约设计指引，而这本身是可行动的负结果（回归测试无法按契约结构排序，必须视为穷举式）。

**假设（通俗表述）。** 契约对版本升级的脆弱程度至少可部分地由查询任何模型之前即可知的契约属性预测。

**指标。** 各特征几率比及 95% 置信区间；分组 5 折与留一模型家族预测 AUC。

#### RQ5：已测脆弱性反映契约特异结构，还是廉价检测器已能预测的通用分布偏移？

**设置。** 在用于拟合 RQ4 脆弱性模型的同一批（契约, 版本）对上运行首 token 对数概率双样本检测器；在同一保留切分上计算其破坏预测 AUC，与结构模型的 AUC 直接比较。

**预期结果。** 结构脆弱性模型的破坏预测 AUC 超出廉价对数概率检测器至少 0.10（预注册差距）。

**证伪条件。** 若 AUC 差距低于 0.10 或为负，则被驳斥——意味着破坏不携带超出近零成本、契约无关分布偏移信号已能预测的可检测结构，这将从根本上削弱构建并维护昂贵契约库的实用理由。

**假设（通俗表述）。** 了解契约自身的结构，在仅仅知道端点变了之外，增加真实的预测能力。

**指标。** 结构模型与廉价检测器在同一保留数据上的 AUC 差距。

#### RQ6：语法约束解码能消除多少模式层破坏？

**设置。** 在开放权重锚谱系上，模式契约子集在语法约束解码臂下重跑，与未缓解臂在同一批契约上逐层比较，采用配对置换检验。

**预期结果。** 语法约束解码消除至少 90% 的模式层破坏——反映它从构造上基本保证模式符合性——而同批契约的约定层破坏基本不受影响。

**证伪条件。** 若模式层破坏降幅低于 90% 或不显著，则被驳斥——意味着模式层破坏实际上并非由解码期保证可消除的失效主导，削弱将该缓解视为该层近乎完全修复手段的理由。

**假设（通俗表述）。** 大多数模式层破坏可由解码期保证避免，而非模型行为的固有属性。

**指标。** 模式层 B_缓解 对 B_未缓解，在同一批契约上配对。

#### RQ7：逐版本提示重编译能消除多少总破坏？

**设置。** 在开放权重锚谱系上，全契约库以逐版本声明式重编译的提示重跑，与冻结提示的未缓解臂在同一批契约上比较，对总 B(v→v′) 做配对置换检验。

**预期结果。** 逐版本提示重编译使总 B(v→v′) 相对降低至少 25%，在 α = 0.05 下显著。

**证伪条件。** 若相对降幅低于 25% 或不显著，则被驳斥——意味着逐版本重新优化提示并不能有意义地抵消升级诱发的破坏，残余破坏须归因于解码期保证与提示重优化都触及不到的失效模式。

**假设（通俗表述）。** 为每个新模型版本重新推导提示能有意义地、但仅部分地降低破坏，相比跨版本冻结同一提示。

**指标。** 重编译下总 B_缓解 对 B_未缓解，在同一批契约上配对。

## 相关工作

与本文最接近的先行工作是 Chen、Zaharia 与 Zou 对 ChatGPT 行为随时间变化的研究 [ChatGPTDrift2307]，其次是 LogProbTracking 端点监控工作 [LogProbTracking]；在综述更广图景之前值得把增量说清楚：ChatGPT 行为研究已记录了两个模型快照之间巨大的、任务相关的行为与格式符合性偏移，LogProbTracking 已把"端点响应分布是否变了"本身当作开放监控问题——但两者都没有构建生产风格契约库、没有针对验证器计算逐次升级破坏率、也没有追问哪些契约特征预测脆弱性，而这正是本文要完成的下游契约级测量。

**端点行为漂移与监控。** ChatGPT 行为研究 [ChatGPTDrift2307] 在固定任务集上评估"同一个"已部署服务的连续快照，记录了显著的任务相关偏移；LogProbTracking [LogProbTracking] 则把变化检测本身作为研究对象，用固定的极简提示反复查询端点，并对首 token 对数概率做非参数双样本检验，以标记底层服务栈何时变化。两者都确立了模型行为会漂移且漂移可检测，但都没有产出在设计好的契约库上的逐次升级破坏*率*、按契约类型的分解、或脆弱性预测因子——两者所记录漂移的下游后果在各自工作中均未被测量；LogProbTracking 仍排在更近的第二位（高于下述 EPC），因为它针对的宽泛工件类别与本文相同——原始 LLM API 响应——而非更窄的下游工件。一个密切相关的版本化协议设计 EPC [EPCEvaluatorPreference0297] 为另一类更窄的工件——锚定到模型版本标识符与失效日期的 LLM 裁判评估器偏好——标准化了静默逐版本漂移的测量，而非结构化输出契约通过率；其版本化协议纪律仍是端点监控文献之外与本文版本配对框架在机制层面最接近的类比。一个更广的组织风险框架 [RiskArchitectureAI1421] 从部署侧独立论证了这一空白：常规的阈值告警对"行为静默漂移、无流程检测"这一失效模式恰恰是盲的，而这正是本文直接测量的对象。

**输入侧提示鲁棒性。** 内在提示噪声抗性与锐度感知提示演化的工作 [CoIPO, TARE] 研究的都是本文场景的对偶方向：固定模型、扰动提示措辞、按该扰动评分鲁棒性。此处研究的升级场景是精确的反向——固定提示、底层模型变化——因此两者的鲁棒性得分都不能解读为对升级存活率的预测；这一对偶性给因果归因带来的混杂正是本文廉价信号特异性检验要分离的对象。同一对偶性的结构化输出特例出现在列类型标注提示鲁棒性工作 [RobustLLMBased2742] 中——它表明即使在固定模型上微调后提示模板敏感性仍存在；作为补充，LLM 生成中少样本示例数的工作 [EnhancingLLMBased4120] 报告了少样本数量与生成稳定性之间非单调、偶尔灾难性的关系（示例数量的小幅增加可使成功率崩塌），这直接启发并复杂化了本文将少样本示例数作为脆弱性预测特征而非简单单调协变量的处理。

**约束验证与约束解码。** 为指令跟随构建可执行程序化约束校验器的工作 [RECAST, AutoIF]，以及将约束解码扩展到在解码器层面保证结构符合性的工作 [DiffusionCFG]，都提供了本文验证器与缓解臂所依托的真实机制。但约束验证工作只在单一固定模型快照上将其校验器用作训练期奖励或过滤信号，从未纵向跨越同一模型的连续版本；而约束解码工作发表的保证限于其针对的模型家族，故其在此的角色是解码期保证缓解臂的概念谱系而非直接复用的实现。一个相关的多智能体工具使用数据合成方法 [CloseLoopSynthesizing3611] 与本文共享模式符合性关切（严格的 JSON/MCP 遵守），但作为训练数据目标而非纵向测量对象。二者都未将其机制应用于本文测量的纵向破坏问题。

**提示编译与权重空间版本脆弱性。** 声明式提示编译工作 [DSPy] 在其自述动机中论证手写提示模板脆弱、无法干净地跨模型迁移，并提供重编译作为缓解——但它从未量化破坏现象本身，使逐版本重编译的成本与收益停留在断言而非测量，而这正是本文缓解上限臂直接检验的对象。另外，面向演化基座模型的压缩感知鲁棒适配器工作 [CARLoRA] 确立了*权重空间*的下游工件（训练好的适配器）在基座检查点变化时退化——与本文测量的提示与契约空间脆弱性属不同工件类别，而后者才是多数生产 LLM 集成的实际所在。

**纵向测量方法学。** 恶意软件概念漂移的纵向基准 [LAMDA] 提供了本文版本配对协议借用的方法学模板——一致的表示与跨多时间点的时序结构化评估——但针对不同工件类别（Android 恶意软件），LLM 契约行为跨模型版本尚无对应物；本文的版本配对框架与噪声底线设计是该模板向本场景的改编。另有两个范例专门支撑噪声底线设计：比较两个随机系统变体的配对种子方差缩减分析 [WhenDoesPairing4145] 提供了从组内采样噪声中分离真实效应的可直接迁移的统计方法；开源 LLM 复合可靠性评分研究 [BeyondHallucinationsComposite4058] 通过自助法（bootstrap）置信区间示范了与本文噪声底线同样的纪律——微小的分数差异不自动等于有意义的差异。把定位说白：对半切分版本内零假设被承认为这一谱系中的标准配对重采样实践，不作为新机制主张——贡献在于该零假设所服务的被估量：上述任何一条研究线都未曾计算的逐次升级契约破坏率。

## 效度威胁

**构念效度。** 破坏/通过/失败构念依赖三层验证器的严格度边界，而对约定层与少样本层而言该边界本身是经校准的设计选择而非机械给定的事实；缓解手段是 RQ1 的 ≥0.95 人工标注一致率门槛（在解读任何其他 RQ 之前检查），且严格度边界的敏感性扫描已预注册为配套检查而非单一未检验的截断。

**内部效度。** 中心混杂——把普通版本内采样变异误当作真实升级效应——由构造解决：每个破坏论断仅报告为超出 B_null 的部分，后者由对版本内对半切分应用同一验证器计算，而非假定为固定基线。第二个不同的混杂——真实但通用、契约无关而非契约特异的跨版本效应——由 RQ5 与廉价对数概率检测器的正面对比解决，而非留作未审视的替代解释。

**外部效度。** 首要论断锚定在开放权重模型谱系上，恰因闭源 API 版本标识符事后不可靠重查；这意味着头条破坏估计未必原样迁移到许多生产团队实际运行的以闭源 API 为主的部署——在那里本设计绕开的可寻址性问题不可回避。闭源 API 结果仅作为次要的、受可寻址性约束的臂报告，而非并入主估计，故该局限是被披露而非隐藏的，但它确实限制了头条数字向最常见生产环境的直接泛化程度。另外，脆弱性模型的七特征向量必然是固定有限清单；一个实践中重要但未预注册的特征无法被本设计检测。

**结论效度。** 每个逐跳变、逐契约类型、逐特征的检验都做 Benjamini–Hochberg 多重比较校正；任何未达到预先声明功效目标的（跳变 × 契约类型）单元按预注册的功效/不可判定规则报告为"不可判定"（INCONCLUSIVE），而非并入零结论或阳性结论——功效不足的单元从不被静默当作无效应的证据。

## 结论

本工作将一个静默的工程假设——结构化输出契约的行为能在供应商对底层模型的任何操作中存活——重构为一个具有精确可识别性结构的可直接测量量，而非只能在生产中失效后才被发现的东西。核心方法论押注是："升级是否破坏了这份契约"与"这份契约是否在普通重采样中翻转"是同一测量应用于同一输出池的两种划分，故可信的破坏数字只能是超出该版本内比较的超额量，绝非原始翻转计数；跳过这一步的设计有把采样噪声误当升级效应的风险。无论最终测得的噪声校正率是多少，该发现都具有决策相关性：与噪声不可区分的率意味着结构化输出契约比端点漂移文献所暗示的更耐升级；而越过噪声底线的率——连同经验证的结构预测因子与被界定的可避免份额——为工程团队在采用新模型版本前决定重测哪些契约提供具体依据，而非把回归测试当作要么不必要、要么穷举式的二选一。两个局限从一开始就框定该论断，且是自然的下一步而非事后附注：闭源 API 版本链可能中途下线或静默变化，故首要论断锚定于开放权重谱系、闭源结果仅作次要臂报告；脆弱性模型的特征集虽经预注册并由库的抽样设计去相关，但必然是固定有限清单——若预注册七特征预测力不足，更丰富或可学习的特征表示是自然的下一个方法学目标。
