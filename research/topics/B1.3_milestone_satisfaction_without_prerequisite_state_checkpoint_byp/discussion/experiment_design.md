## Datasets

| Dataset | Role | Justification |
|---|---|---|
| Constructed prerequisite-DAG task suite — **pilot** (~20–40 hand-authored coding/filesystem tasks, ~5–12 milestones each) | Primary evaluation object for RQ1, RQ4, RQ5, RQ6 | A canonical, independently computable terminal state is required by assumption A1; the pilot's coding/filesystem domain (filesystem hash-set + deterministic program output) satisfies this cheaply, which is why it is the walking-skeleton and pilot domain. |
| Constructed prerequisite-DAG task suite — **scale-up** (~200–500 procedurally generated coding + tool-use + web-action tasks) | Primary evaluation object for RQ3 (topology modulation) | RQ3's mixed-effects logistic regression on prerequisite-chain depth and node in-degree needs enough distinct tasks/topology strata to estimate two fixed effects with a task random intercept — the pilot's 20–40 tasks is undersized for this, hence the ≥200-task scale-up requirement. |
| Real-world task substrates used as grading-practice references: SWE-bench-style repository tasks, τ-bench/τ²-bench, BFCL v3, ToolSandbox | Justifies A3 (verifier mirroring), not directly sampled for RQ scoring | These substrates' actual grading mechanisms (file/DB-state checks, unit sub-tests, tool-signature checks) are what this suite's per-milestone verifiers are built to mirror, so that `ρ` estimates generalize to standard, not idealized, agent-benchmark grading. |
| Web-action tasks (WebArena-style) | Feeds RQ3's generalization check | Included specifically to test whether `rq_topology_modulation`'s (RQ3) depth/in-degree finding generalizes to a domain whose per-milestone verifiers are DOM/page-state checks rather than the file/DB/tool-signature checks used in the coding and tool-use domains — stress-testing the stratified design against a structurally different verifier population, not re-observing the same domain twice (Stage 6 refiner-pass fix). |
| Real LLM-agent rollouts (3–5 agents × ≥3 seeds, on the scale-up suite) | Primary evaluation object for RQ2 (natural incidence, headline) | The only source that can answer whether checkpoint bypass already occurs unprompted, as opposed to whether it can be constructed — the reference population for RQ2 is rollouts a working milestone-verification pipeline would already score complete. |

## Baselines (sanity-check / attribution comparators — never outcome-tier competitors)

- **B0 — Honest-trajectory control.** Topologically-valid trajectories that genuinely execute every prerequisite, for every task. Expectation: `A(τ)=1 ∧ Ω(τ)=1` for all, i.e., bypass rate ≈0 (pre-registered check: honest-trajectory bypass rate must be `<1%`). *Justification:* proves the verifier suite and the oracle agree on legitimate completions, so any positive rate on constructed adversarial trajectories is attributable to the bypass mechanism, not to baseline verifier/oracle disagreement or oracle strictness. Feeds RQ6.
- **B-alt — Strongest-local-checker control.** Each per-milestone verifier `φ_k` replaced by the richest realistic local check per checker type (fullest DB-state comparison, strictest exact-match, deepest unit sub-test) — still milestone-scoped, still no cross-milestone provenance, capability/compute-matched to the standard suite. *Justification:* isolates whether observed bypass is caused by the structural fact that per-milestone verification is locality-scoped (`sp_verifier_locality`) versus an artifact of this study's own checkers being weak/lazy (`sp_structural_vs_weak_checker`) — the rival-explanation control the paper's central claim depends on. Feeds RQ5 (formalized there as Hypothesis H5).

## RQ1 — Can checkpoint bypass be constructed at all? (constructibility gate)

- **Tier:** Mechanism (`rq_bypass_exists`, targets `sp_verifier_locality`).
- **Target hypothesis (verbatim, Stage 5 `m_locality_scoped_verifiers`, first hypothesis):** "The measured aggregate checkpoint-bypass rate ρ̂ will be significantly greater than zero — ρ̂ ≥ 0.10 with Wilson 95% lower bound > 0.05 — over at least 300 constructed reorder/skip/inject trajectories on the pilot DAG suite (one-sided exact binomial test, p<0.05), demonstrating that independent per-milestone verification is not a sufficient proxy for true multi-step task success on this suite."
- **Role note:** RQ1 is a manipulation check, not a headline claim — because the injection strategy is defined to write the exact surface signature the milestone verifiers check, a pass is expected by construction. A pass licenses RQ3–RQ5; a failure is the more informative, surprising outcome.
- **Setup.** On the pilot DAG suite, construct at least 300 trajectories (20–40 tasks × reorder/skip/inject × ~5 variants each) and compute the constructed-suite bypass rate `ρ̂_c` as the fraction passing every milestone verifier while failing the terminal oracle.
- **Sample-size rationale.** ≥300 trajectories over 20–40 pilot tasks gives the topology-stratified sampler (Stage 5 `m_topology_stratified_sampling`) enough coverage across the 3 strategy families × topology strata to support a stratified — not exhaustive — characterization; this reuses digest N8's sample-size choice, hardened with binary decision thresholds (paper.md Step 6 preamble). *Power note (stage_review.md item 9 follow-up):* these figures are coverage targets, not power-derived — RQ1 is a constructibility gate expected to pass by construction, so the binding inferential power requirements live in RQ2 (A6's corrected power statement) and RQ3 (the per-cell simulation gate below), not here.
- **Statistical test.** *As originally specified (Stage 5):* one-sided exact binomial test against ρ=0.10, p<0.05. *As corrected post-design-review (paper.md/`paper_draft.md`, since trajectories are nested within tasks and not i.i.d.):* task-level cluster bootstrap (10,000 resamples of tasks with replacement, percentile CI) on `ρ̂_c`, decision rule `ρ̂_c ≥ 0.10` **and** cluster-bootstrap 95% lower bound `> 0.05`. Holm slot 1 of the H1–H4 family.
- **Expected outcome.** `ρ̂_c ≥ 0.10` with the cluster-bootstrap 95% lower bound above 0.05, gating the strategy/topology/attribution analyses below.
- **Metrics.** Constructed-suite bypass rate `ρ̂_c` with task-level cluster-bootstrap 95% CI and `n_tasks`; per-checker-type breakdown. *Scope note (design_review.md §Missing-RQs 2):* per-checker-type breakdowns are descriptive only — A3 is a continuous reporting discipline, not a hypothesis, so the design pre-registers no inferential claim about which checker types are vulnerable; this is an acknowledged scope restriction, not an oversight.

## RQ2 — Do real agents produce checkpoint-complete-but-inconsistent rollouts without adversarial intent? (headline)

- **Tier:** Mechanism (`rq_natural_incidence`, targets `sp_verifier_locality`).
- **Target hypothesis (verbatim, Stage 5 `m_locality_scoped_verifiers`, second hypothesis):** "Real LLM agents will naturally (non-adversarially) produce rollouts scored complete by every per-milestone verifier yet failing the terminal oracle at a non-zero but lower incidence than the constructed rate — natural incidence ρ̂_nat ≥ 0.02 with Wilson 95% lower bound > 0, over at least 200 verifier-complete real-agent rollouts, with a two-proportion test confirming ρ_nat < ρ_constructed."
- **Setup.** Among rollouts of 3–5 real LLM agents (≥3 seeds each, spanning ≥20 distinct tasks) on the scale-up suite that are scored complete by the milestone verifier suite, measure the fraction that fail the terminal oracle, net of the audited oracle false-inconsistency rate (RQ6).
- **Sample-size rationale.** ≥200 M2-complete rollouts spanning ≥20 distinct tasks (A6). Power-corrected decision rule: `H4` holds iff `ρ̂_nat ≥ 0.01` (≥2 bypass events at n=200) — the decision threshold (0.01) is deliberately set *below* the pre-registered effect floor (`ρ_nat ≥ 0.02`) because setting threshold = floor caps power at ≈0.57 regardless of n; decoupling them gives power `P(X≥2 | Bin(200,0.02)) ≈ 0.91` at the floor (A6, corrected 2026-07-04). The ≥20-distinct-task requirement exists so the task-level cluster bootstrap is estimable. *Completion-yield assumption (design_review.md §Missing-RQs 4):* the ≥200 floor counts *verifier-complete* rollouts, not rollouts attempted, so the total rollout budget scales as 200 divided by the M2-completion yield of the chosen agents on the scale-up tasks; the design pre-registers no assumed yield value — the walking-skeleton/pilot must measure the observed yield, PG-3 (A6) blocks H4 scoring until the 200-complete/≥20-task floor is met, and if the measured yield implies an infeasible total budget the task mix is re-selected under PG-0 rather than the floor being lowered.
- **Statistical test.** Task-level cluster-bootstrap 95% CI on `ρ̂_nat`; cluster-robust two-proportion test vs. `ρ̂_c` (expected direction `ρ_nat < ρ_c`, descriptive). Pre-declared edge cases: `ρ̂_nat = 0` → FAIL (invoke fallback); `0 < ρ̂_nat < 0.01` → INCONCLUSIVE-at-n, never reported as null. Holm slot 4 of the H1–H4 family.
- **Expected outcome.** Natural incidence clears the decision rule and is significantly lower than the constructed-suite rate.
- **Metrics.** Natural bypass incidence `ρ̂_nat` with task-level cluster-bootstrap 95% CI and `n_tasks`; cluster-robust two-proportion comparison against `ρ̂_c`.

## RQ3 — Does dependency-graph topology modulate the bypass rate?

- **Tier:** Mechanism (`rq_topology_modulation`, targets `sp_combinatorial_coverage`).
- **Target hypothesis (verbatim, Stage 5 `m_topology_stratified_sampling`):** "In a logistic regression of the bypass outcome on prerequisite-chain depth and node in-degree over the scale-up suite (≥200 tasks), at least one predictor will show an odds ratio > 1.2 per unit with Wald p<0.05 (Holm-corrected across the two predictors), indicating deeper or higher-fan-in prerequisite structure raises bypass odds."
- **Setup.** Over the scale-up suite (≥200 tasks), fit a mixed-effects logistic regression of the per-trajectory bypass outcome on prerequisite-chain depth and node in-degree, with a task-level random intercept (trajectories are nested in tasks).
- **Sample-size rationale.** ≥200 tasks is the scale-up floor stated directly in the target hypothesis — needed to estimate two fixed-effect coefficients plus a task random intercept with adequate power across topology strata; the pilot's 20–40 tasks is reserved for RQ1/RQ4/RQ5/RQ6 instead. *Per-cell power gate (design_review.md §Missing-RQs 3 / stage_review.md item 9 follow-up):* before RQ3 is scored, a simulation-based power analysis of the mixed-effects model — using the intra-task correlation and per-task trajectory counts observed in the pilot — must confirm power ≥0.9 (matching A6's power target) to detect an odds ratio of 1.2 per unit at the realized depth × in-degree cell counts; topology cells whose simulated power falls short are pre-declared INCONCLUSIVE under the thin-cell rule (A5) rather than scored as null.
- **Statistical test.** Mixed-effects logistic regression (task random intercept), Wald tests on fixed effects, Holm-corrected across {depth, in-degree}. Holm slot 3 of the H1–H4 family.
- **Expected outcome.** At least one fixed-effect coefficient shows odds ratio >1.2 per unit with a significant Wald test.
- **Metrics.** Odds ratio per unit depth and per unit in-degree (mixed-effects logistic regression, task random intercept) with CIs and Wald statistics; `n_tasks` and per-cell trajectory counts.

## RQ4 — Which bypass strategy is most effective at defeating milestone verification?

- **Tier:** Mechanism (`rq_strategy_dominance`, targets `sp_provenance_authentication`).
- **Target hypothesis (verbatim, Stage 5 `m_injection_provenance_probe`):** "The state-injection strategy's bypass rate will exceed both the reordering and step-skipping strategies' rates by at least 10 percentage points (pairwise two-proportion z-tests, Holm-corrected p<0.05 across the three pairs), because injection forges the milestone's local success signal directly without requiring an executable control-flow path."
- **Setup.** Compare per-strategy bypass rates (reorder, skip, inject) computed on the same constructed-suite trajectories used for RQ1 (the injection probe holds each milestone's surface signature fixed while varying only whether the true prerequisite was executed).
- **Sample-size rationale.** Reuses RQ1's ≥300-trajectory constructed suite (20–40 tasks × reorder/skip/inject × ~5 variants) split by strategy family — no separate trace generation is required; the same pool that establishes constructibility (RQ1) is partitioned to compare strategies.
- **Statistical test.** Three pairwise two-proportion z-tests with cluster-robust (task-level) standard errors (equivalently, GEE binomial with strategy as predictor, exchangeable working correlation), Holm-corrected across the 3 pairs. Holm slot 2 of the H1–H4 family.
- **Expected outcome.** Injection's bypass rate exceeds both reordering and step-skipping by ≥10 percentage points.
- **Metrics.** Per-strategy bypass rate with cluster-robust pairwise contrasts, Holm-corrected p-values, and `n_tasks` per strategy cell.

## RQ5 — Is any observed bypass attributable to structural locality rather than weak checker implementations?

- **Tier:** Mechanism (`rq_structural_attribution`, targets `sp_structural_vs_weak_checker`). Formalized in `paper.md` as Hypothesis H5, the B-alt control's isolation test. Conditional: only meaningful once RQ1 (H1) is non-null.
- **Target hypothesis (verbatim, Stage 5 `m_strongest_checker_control`):** "Against the strongest-local-checker control (the richest realistic, still milestone-scoped, capability/compute-matched local check per checker type), the injection-strategy checkpoint-bypass rate remains at least half its value under the standard-strength checker suite — demonstrating that the measured bypass is attributable to structural locality rather than to lazy or weak checker implementations."
- **Setup.** Recompute the injection-strategy bypass rate under the B-alt strongest-local-checker control and compare it to the rate under the standard verifier suite, run only over tasks where the standard-suite injection rate is itself non-zero (undefined ratio otherwise).
- **Sample-size rationale.** Paired by task with RQ1/RQ4's injection-strategy subsample (the strong- and weak-checker rates are computed on the *same* tasks), restricted to the subset with non-zero standard-suite injection bypass — no independent sample-size target beyond that subsample, since this is an attribution ratio, not a fresh incidence estimate.
- **Statistical test.** One-sided two-proportion non-inferiority test with cluster-robust (task-level) standard errors — pairing/clustering by task is mandatory since strong- and weak-checker rates share tasks. Retained (H5 holds) iff the ratio's cluster-robust lower bound clears 0.5. Own Holm family (n=1, single comparison), separate from the H1–H4 family.
- **Expected outcome.** The strongest-checker bypass rate retains ≥0.5× its standard-suite value (cluster-robust lower bound clears 0.5).
- **Metrics.** Bypass-rate ratio (strongest-checker control / standard suite) with a cluster-robust (task-paired) confidence interval.

## RQ6 — Is the terminal oracle itself valid ground truth?

- **Tier:** Mechanism (`rq_oracle_validity`, targets `sp_oracle_validity`). Pre-registered audit gate (A4/PG-1), not part of the Holm-corrected hypothesis family.
- **Target hypothesis (verbatim, Stage 5 `m_disjoint_oracle_with_audit`):** "A manual stratified audit of 50–100 oracle verdicts on honest (topologically-valid) trajectories will find a false-inconsistency rate of at most 5%, and the honest-trajectory bypass rate itself will be below 1% — establishing that the terminal oracle is disjoint-code-validated ground truth rather than a source of inflated bypass counts."
- **Setup.** Manually audit a stratified sample of 50–100 oracle verdicts on honest, topologically-valid (B0) trajectories, which should uniformly pass both the verifier suite and the oracle; separately confirm the honest-trajectory bypass rate is near zero.
- **Sample-size rationale.** 50–100 manually audited verdicts is the pre-registered audit-sample size (A4) — large enough to bound a ≤5% false-inconsistency rate at reasonable audit cost, small enough to be a manual (not automated) review, consistent with this being a gate checked once before any bypass rate is trusted, not a per-RQ statistical test.
- **Statistical test.** No formal significance test — a descriptive pre-registered threshold gate: false-inconsistency rate ≤5% AND honest-trajectory bypass rate <1%. Both must hold (PG-1, walking-skeleton exit criterion ii) before H1–H5 are scored on a domain.
- **Expected outcome.** False-inconsistency rate ≤5%; honest-trajectory bypass rate <1%.
- **Metrics.** Oracle false-inconsistency rate from manual audit; honest-trajectory bypass rate.
