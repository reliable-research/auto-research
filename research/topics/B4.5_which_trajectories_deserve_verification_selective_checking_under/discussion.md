# Discussion: B4.5 校验调用的选择性分配 — Which Trajectories Deserve Verification?

**Topic:** Selective Checking under a Verifier-Call Budget — with the verifier trusted and scarce, which of N candidate trajectories should receive the B < N verification calls to maximize accuracy-per-verifier-call?
**Label:** [资源] · **Parent:** B4. 预算分配 / 推理经济学 · **Audit status:** KEEP (Tier-2, support). Distinctive precisely because it *complements* rather than collides with the incoming stopping-rule wave; a cheap re-ranking study over pre-collected rollouts.
**Boundary (stated up front):** B1.5 (校验预算的对抗性分配, on HOLD) is the adversarial sibling — there the agent optimizes *against* the checker and the question is which spending pattern minimizes undetected shortcuts. B4.5 is the **non-adversarial** allocation problem: the generator is not strategic, the verifier is trusted (可信), and the only scarcity is the number of calls (问怎么省着用).
**Format:** 6 stages, each with an internal critic → refine pass.

---

## Stage 1 — Problem Definition

**The allocation problem.** A test-time scaling pipeline samples N candidate reasoning trajectories per task instance (self-consistency samples, best-of-N candidates, or agent rollouts) across a batch of M instances. A **trusted verifier** — unit-test execution, a ground-truth grader, or a strong judge whose verdicts we accept as correct — is available, but each call is costly, and the pipeline is granted a **global budget of B calls**, with B < N·M. The problem:

> Choose which ≤ B trajectories (across all instances) to submit for verification, and how to combine verified and unverified evidence into one final answer per instance, so as to maximize batch accuracy — equivalently, to maximize **accuracy-per-verifier-call** relative to (a) uniform-random allocation at matched B and (b) full verification (B = N·M).

Components of a solution: (1) a **pre-verification score** per trajectory, computed from verifier-free signals only (self-consistency mode share, normalized sequence log-likelihood, verbalized confidence); (2) an **allocation policy** mapping scores + budget to a verified subset — static ranking or sequential (spend one call, observe, reallocate); (3) an **aggregator** producing the final answer from the mix of verified outcomes (sparse, ground-truth-grade) and unverified signals (dense, noisy). The core question (seed, near-verbatim): verifier 调用受限时，验证哪些轨迹能最大化 accuracy-per-verifier-call？

The evaluated object is the **budget–accuracy curve**: accuracy as a function of budget fraction b = B/(N·M), for each (signal, policy, aggregator) triple, with uniform allocation and full verification as anchors.

**Critic:** (1) "Trusted verifier" is doing double duty: in the pilot the verifier *is* the ground-truth label that also defines the accuracy metric — a circularity that must be architecturally contained (scores frozen before any call; verifier outcomes touch only selection/aggregation), and eventually broken by realistic verifiers that are trusted without being the evaluation oracle (held-out unit tests vs. full EvalPlus suites). (2) The objective "accuracy-per-verifier-call" is ill-defined at B = 0 and non-monotone as a ratio; the primary object should be accuracy@B with the ratio and the budget-recovery fraction as derived summaries. (3) The problem statement hides a design choice with real consequences: allocation granularity — ranking all N·M trajectories jointly vs. ranking instances then trajectories within an instance — changes both the policy space and the information per call (verifying one representative of each distinct answer dominates verifying near-duplicates). (4) A verified-*incorrect* outcome is not wasted budget — it eliminates an answer — and the definition must count that information, else the problem silently reduces to "find one verified-correct trajectory." (5) What does a *call* verify — a trajectory or an answer? If several trajectories share a final answer and the verifier checks answers (math), one call resolves the whole equivalence class; if it checks trajectories (process-level judge), it doesn't. The unit of verification must be part of the formal statement.

**Refined:** The formal statement gains: (i) **unit of verification** — the pilot's verifier checks *final answers*, so a call resolves an answer-equivalence class within an instance; the trajectory-level variant (process verification) is scoped out of the pilot and flagged for Stage 2 discussion; consequently the effective decision is *which distinct candidate answers of which instances* to check. (ii) **Primary metric** — accuracy@B curves; derived: budget-recovery fraction (accuracy@B − accuracy@0)/(accuracy@full − accuracy@0), AUBC (area under the budget curve), and accuracy-per-call as a secondary ratio. (iii) **Two policy granularities as part of the problem**, not implementation trivia: trajectory-joint vs. instance-then-answer-class ranking. (iv) **Aggregation as a first-class output**: elimination-aware rule (drop verified-incorrect answer classes, confidence-weighted vote over the remainder; output any verified-correct answer immediately) vs. the naive rule, ablated at matched B. (v) The pilot circularity contained by pipeline separation (signals computed and frozen pre-verification) and broken in Stage 2 by execution/PRM verifiers distinct from the evaluation oracle.

## Stage 2 — Motivation

1. **Verification is becoming the metered resource.** Test-time scaling multiplies candidates; every candidate then wants a check. Execution sandboxes, PRM scoring over all N candidates, and strong-judge review of rollouts are all linear-in-N costs, and in judge-based pipelines the judge is often a *larger* model than the generator — making verification, not generation, the marginal-dollar line item. [VERIFY: any concrete vendor pricing or internal cost split quoted here is channel-relayed; do not cite specific numbers without a primary source. The safe citable form is structural: PRM/judge inference cost scales with N while the budget does not.]
2. **The literature budgets the wrong side.** Generation-side allocation is well studied — difficulty-conditioned compute allocation (Compute-Optimal-TTS / Snell et al.), calibrated adaptive sampling (CaTS) — and verifier *imperfection* is well studied (ROC-n-reroll, OT-Verify, both assuming the verifier scores *every* candidate). The corner where the verifier is *trustworthy but call-limited over a trajectory pool* has, to our knowledge, no direct account: which of N already-sampled trajectories deserve the B calls is answered nowhere, though it is the first question a deployer with a sandbox quota actually faces.
3. **Complement, not collision, with the stopping wave.** The vendor-chart-driven wave now forming around when-to-stop-thinking (B4.1's territory; the overthinking literature) concerns the *generation* budget. B4.5 sits on the orthogonal axis: after generation, under a *checking* budget. Even if stopping-rule papers saturate the venue, this remains unclaimed ground — and the two compose: a pipeline first stops sampling (their problem), then allocates verification over what it kept (ours).
4. **Self-consistency's known failure is exactly the target.** Majority voting verifies nothing and is defeated by consensus-wrong answers; a small, well-aimed verification budget is the cheapest mechanism that can catch what voting structurally cannot. Whether cheap signals can *aim* it — given that the highest-value checks sit where those same signals say "confident" — is the empirical heart of the paper.

**Critic:** (1) Point 1's cost claim is the motivation's anchor and is currently uncitable; the structural form (linear-in-N verification vs. fixed budget) is safe, but the paper would be stronger with one real, primary-sourced cost figure — assign a [VERIFY] task to find one (e.g., published PRM parameter counts vs. generator counts, or judge-model pricing pages) rather than leaning on relayed numbers. (2) Point 2's "no direct account" is an absence claim over active-learning-adjacent territory — label-efficient evaluation, active testing, and bandit best-arm identification all allocate scarce ground-truth queries by informativeness; the novelty is the *deployment object* (trajectory pools from one model on one instance batch, with aggregation) not the abstract allocation idea, and the paper must say this before a reviewer does. (3) Point 3 is honest strategy but must be phrased in the paper as composition-of-budgets, not as venue tactics. (4) Point 4 contains the paper's built-in tension — the signal's worst errors coincide with the highest-value targets — and stating it in the motivation risks pre-refuting the method; better: state it as the *reason the measurement is needed* (the answer is not knowable a priori).

**Refined:** Motivation rebuilt: (a) structural cost asymmetry, cited via primary-source verifier/judge cost data if found, else stated qualitatively [VERIFY before submission; never relay channel numbers]; (b) the two-axis map of verification-under-limits — trust axis (studied: ROC-n-reroll, OT-Verify; adversarial corner: B1.5, on HOLD) vs. scarcity axis (this paper) — with the active-learning/active-testing lineage explicitly acknowledged and the delta located in the object: budgeted checking of *competing trajectories for the same instances*, where calls resolve answer classes, aggregation must exploit eliminations, and the budget couples decisions across instances; (c) composition with stopping rules, framed as pipeline stages sharing one inference-economics account (parent topic B4); (d) the confident-but-wrong tension framed as the open empirical question the budget–accuracy curves settle: if signals cannot aim the budget, uniform is unbeatable, and that too is a finding with a pre-registered falsification condition.

## Stage 3 — Related Work

**Generation-budget allocation (adjacent, different resource).** Compute-Optimal-TTS (OpenReview:4FWAwZtd2n; Snell et al., arXiv:2408.03314): difficulty-conditioned allocation of *generation* strategies under FLOPs budgets — verifier scoring bundled into the strategy, never metered. CaTS (OpenReview:jrSc4RJXy1): calibrated confidence to decide *how many samples to draw*. Neither answers which sampled trajectories to verify under B < N·M.

**Verifier-imperfection theory (adjacent, opposite corner).** ROC-n-reroll (OpenReview:3Gy5mmyuxn) and OT-Verify (OpenReview:BBDhQJh6GB): closed-form accuracy–compute analysis under *noisy* verification of *every* candidate — call count is an outcome, never a constraint; trust, not scarcity, is the variable. B4.5 is the dual: perfect verdicts, hard call ceiling. (The Stage-2 verifier-noise sweep is the designed bridge between the two regimes.)

**Selective evaluation / routing (adjacent, different unit).** Trust-or-Escalate (OpenReview:UHPnqSTBPO): per-item escalation with risk guarantees — no competing-trajectory pools, no global budget coupling. TRIM (OpenReview:MoKrugWUfC): budgeted strong-model regeneration of *steps within one trajectory* — the intra-trajectory dual of our inter-trajectory problem. SAFER (OpenReview:kJmLmOvwLC): risk-calibrated sample-then-filter with *no* test-time verifier at all. Self-Capability (OpenReview:EO6WtJ0q6G): measures ex-ante confidence quality but builds no allocation policy on it.

**The base pipeline.** Self-consistency (Wang et al., ICLR 2023, arXiv:2203.11171): fixed sample count, equal weights, zero verification — supplies both our lower anchor and our cheapest signal (mode share).

**Formal ancestors [VERIFY exact citations before writing].** Active testing / label-efficient evaluation (allocating scarce ground-truth labels by informativeness), best-arm identification with fixed budget, and optimal experiment design. The delta from all three: their query resolves an i.i.d. item's label; our call resolves an answer-equivalence class inside a structured pool where the payoff is batch accuracy after aggregation — elimination effects and cross-instance budget coupling have no analogue in the standard active-testing setting.

**Boundaries.** (i) **B1.5 (on HOLD)** — the adversarial sibling: generator optimizes pass-rate against the checker; allocation strategies are spot-check/probe/hidden-test and the metric is undetected-shortcut rate. B4.5 holds the generator non-strategic and the verifier honest; if B1.5 is ever revived, B4.5's frontier is its non-adversarial baseline. (ii) **B4.1** — stopping rules meter *thinking*; B4.5 meters *checking*; the topics share the inference-economics frame (B4) and compose in a pipeline but share no experimental machinery beyond pre-collected rollouts. (iii) Not a verifier-training paper (no PRM is trained), not a verifier-reliability paper (trust is assumed, then relaxed only as a sensitivity sweep), not overthinking (arXiv:2604.10739, 2502.08235, 2503.16419, 2505.17813 are B4.1's positioning targets, cited here only for the two-axis map).

**Critic:** (1) All OpenReview entries are corpus-scraped proposals — acceptance status, final content, and even titles need verification before citation [VERIFY each]. (2) The active-testing paragraph names no papers; a reviewer from that community will supply them unflatteringly — do the search now (Kossen et al.-style active testing; fixed-budget BAI, Bubeck/Audibert lineage; [VERIFY]) and cite the two or three closest, plus any recent LLM-specific label-efficient-eval work, which is the likeliest hidden twin. (3) "To our knowledge no direct account" (Stage 2) must survive a targeted search for exactly this setting — "budgeted verification best-of-N", "selective verification LLM reasoning" — schedule it now and again at T-minus-2-weeks; a 2026 preprint doing uncertainty-ranked verification of best-of-N candidates would relegate B4.5 to a replication, and the design should pre-commit its response (differentiate on aggregation + sequential policy + cross-domain transfer, which a first paper is unlikely to have all of). (4) The B1.5 boundary is clean but under-used: one sentence on *why* the non-adversarial case must be solved first (it upper-bounds what any allocation can achieve once an adversary is added) earns the boundary its space.

**Refined:** Actions absorbed into the plan: a dedicated related-work sweep for (a) active testing / label-efficient evaluation, (b) fixed-budget best-arm identification, (c) any LLM-specific selective-verification preprints — run in week 1 and at T-minus-2-weeks, findings logged in `reference_candidates.jsonl` [VERIFY all corpus citations against OpenReview/arXiv at writing time]. The two-axis map (trust × scarcity) becomes the related-work organizing figure, with B1.5 and ROC-n-reroll/OT-Verify on the trust axis, Compute-Optimal-TTS/CaTS on the generation-budget axis, and B4.5 alone in the trusted-scarce cell; the caption states the upper-bound relation to the adversarial case. The hidden-twin contingency is pre-committed: if a direct prior emerges, reposition on the three components it lacks (elimination-aware aggregation as a measured axis, sequential reallocation vs. static ranking, math↔code policy transfer) and cite it as the anchor rather than competing on priority.

## Stage 4 — Sub-Problems

- **SP1 — Signal validity before truth. [THE HARD PART.]** Every allocation decision is made from verifier-free proxies, and the proxies' errors are *structured against the policy*: the highest-value calls are consensus-wrong cases (all N agree on a wrong answer) — exactly where mode share reads "certain, skip me." The sub-problem is measuring, per signal and per domain, the AUROC against verifier-labeled correctness *and* specifically the mass of verified-incorrect-with-high-mode-share cases — the quantity that upper-bounds what any signal-ranked static policy can ever recover. If this adversarially-structured proxy gap is total, selective checking cannot beat uniform, and the paper's finding flips sign. Everything else is conditional on this number.
- **SP2 — Allocation policy design under global coupling.** One budget across M instances: "second answer-class of a hard instance" competes with "first check of the next instance." Static granularities (trajectory-joint vs. instance-then-answer-class) and the sequential upgrade (observe outcome, stop probing resolved instances, reallocate) — with the hindsight-optimal allocation on the same logs as the policy ceiling.
- **SP3 — Aggregation of mixed evidence.** Sparse ground-truth verdicts + dense noisy signals → one answer per instance. Elimination-awareness (a verified-incorrect verdict removes an answer class from the vote) is the design axis; its value is measurable as accuracy at matched B vs. the naive rule.
- **SP4 — Verifier realism and cost accounting.** From oracle lookup (pilot: isolates allocation from verifier quality) to execution on held-out tests and thresholded PRM verdicts (Stage 2), each with measured per-call cost — enabling accuracy-per-dollar alongside accuracy-per-call, and a noise sweep connecting to the ROC-n-reroll regime.
- **SP5 — Transfer of the allocation policy.** Signals' informativeness differs across answer-space structure (small numeric answers vs. open-ended code); does a policy tuned on math beat uniform on code, and vice versa?

**Critic:** (1) SP1 is correctly the hard part, but as stated it is purely diagnostic; add the constructive corollary — if consensus-wrong mass is significant, the rational static policy is *not* pure most-uncertain-first but a mixed policy reserving a budget slice for spot-checking high-consensus instances; this "insurance slice" arm is cheap (another replay) and turns the diagnosis into design. (2) SP2's hindsight-optimal ceiling needs a definition careful about sequential information (hindsight-optimal *static* allocation vs. hindsight-optimal *adaptive* — the latter is the true ceiling for M5-style policies; compute both, they differ). (3) SP4's PRM-as-trusted-verifier stretches "trusted" — a thresholded PRM is exactly the noisy verifier the trust axis excludes; reframe PRM as the *first step of the noise sweep*, not as a trusted instantiation, keeping execution-on-held-out-tests as the only realistic trusted verifier. (4) SP5 lacks a mechanism hypothesis; predict *why* transfer might fail (mode share degrades on code because answer equivalence is behavioral, not string-level) so the transfer result is interpretable either way.
 
**Refined:** SP1 gains the mixed-policy corollary: an ε-insurance arm (spend (1−ε)·B most-uncertain-first, ε·B uniformly over high-consensus instances), swept over ε ∈ {0, 0.1, 0.25} — pure replay, no new generation. SP2 defines both ceilings: OPT-static (best fixed subset in hindsight) and OPT-adaptive (best sequential spend in hindsight); policies are scored against both, and the OPT-adaptive − OPT-static gap itself measures how much the online character of the problem is worth. SP4 reclassified: trusted verifiers = oracle lookup (pilot) and held-out-test execution (code, Stage 2); PRM verdicts open the verifier-noise sweep bridging toward ROC-n-reroll territory. SP5 adds the mechanism note (answer-class construction on code uses test-input output equivalence, and its imperfection is itself logged as a measured construct).

## Stage 5 — Methods

- **M1 — Trajectory-difficulty / uncertainty features (per trajectory, pre-verification, frozen before any call).** (a) *Mode share* — fraction of the instance's N final answers agreeing with this trajectory's (exact-match for math; test-input output-equivalence classes for code); (b) *normalized sequence log-likelihood* — mean token log-prob under the sampling model; (c) *verbalized confidence* — one fixed follow-up prompt eliciting 0–100; (d) derived instance-level features: answer-class entropy, top-2 vote margin, class count. Deliverable: per-signal AUROC (DeLong CIs) against verifier labels — SP1's measured object — plus the consensus-wrong mass table.
- **M2 — Allocation policies.** Static: uniform-random (control); most-uncertain-first at two granularities (trajectory-joint; instance-then-answer-class, checking the largest unresolved answer class first — most information per call); difficulty-conditioned instance-level (Compute-Optimal-TTS-style adaptation: rank instances by estimated difficulty); confidence-threshold escalation (Trust-or-Escalate-style adaptation, ignoring budget coupling — included to show what per-item thresholding loses); ε-insurance mixed policy. Sequential: greedy reallocation — spend one call on the current most-valuable target, mark resolved instances (any verified-correct answer), reallocate; compared to OPT-static and OPT-adaptive hindsight ceilings.
- **M3 — Verifier cost model.** Pilot: oracle lookup (unit cost 1/call; free to execute). Stage 2: sandboxed held-out unit-test execution (code; wall-clock + CPU logged) and PRM inference (math; GPU-seconds + tokens logged), thresholded verdicts entering the noise sweep. Reported: accuracy-per-call always; accuracy-per-dollar for realistic verifiers using measured costs — never relayed price sheets [VERIFY any external price figure against the provider's published pricing at writing time].
- **M4 — Aggregators.** Naive (verified-correct answer if any, else raw majority vote) vs. elimination-aware (drop verified-incorrect classes; confidence-weighted vote over survivors; flag instances with all classes eliminated). Ablated at matched B across all policies.
- **M5 — Accuracy-per-call frontier.** For every (signal, policy, aggregator, dataset, model): accuracy@B at b ∈ {5, 10, 25, 50, 100}%, budget-recovery fraction, AUBC; McNemar + 10k-resample paired bootstrap vs. uniform at each b, Holm–Bonferroni within declared families; all policies replayed on identical frozen pools.

**Critic:** (1) The verbalized-confidence elicitation is the only feature that costs extra generation (one short call per trajectory — 64K calls in the pilot); it is also, per the Self-Capability corpus finding, likely the weakest signal — pre-commit that if its dry-run AUROC is within noise of chance it is dropped from Stage 2 to halve elicitation cost. (2) Answer-equivalence for code via test-input output equivalence needs the probe-input suite defined *before* seeing verifier outcomes (else leakage); fix a canonical probe-input generator per task. (3) The difficulty-conditioned baseline conflates instance difficulty with trajectory uncertainty — good, that is exactly the comparison that shows *trajectory-level* signals matter beyond *instance-level* ones; make that contrast explicit in the frontier figure. (4) Frozen-pool replay means all policies share sampling noise — paired tests are valid, but generalization claims need the 5-seed dispersion on the primary configuration, which is budgeted but must cover at least one full policy grid, not just the winner. (5) PRM choice is unpinned — name the candidate (an open math PRM checkpoint) and its threshold-calibration split now, or the Stage-2 plan is vaporware [VERIFY available open PRM checkpoints at execution time].

**Refined:** Elicitation gate: verbalized confidence survives to Stage 2 only if pilot AUROC lower CI > 0.55. Code answer-classing uses a frozen canonical probe-input suite generated from task signatures before any verification. The frontier figure is organized around the instance-vs-trajectory contrast (difficulty-conditioned baseline vs. answer-class-aware policy) as the headline comparison after selective-vs-uniform. Seed budget: 5 seeds × full policy grid on GSM8K + MBPP+ (primary), 2 seeds elsewhere. Stage-2 PRM slot: one open process-reward model with threshold calibrated on a held-out split, named in `experiment_design.md` once checkpoints are verified [VERIFY]; if no adequate open PRM exists, the math noise-sweep is downgraded to synthetic verifier noise (flip verdicts at rate ρ), which serves the same bridge to ROC-n-reroll.

## Stage 6 — Experiment Design

**Design shape:** one generation pass, then everything is CPU replay. Sample once, allocate forever.

**Arms (all replayed on identical pools):**
- Signals: mode share; log-likelihood; verbalized confidence (gated); rank-combination.
- Policies: uniform-random; most-uncertain-first (trajectory-joint); most-uncertain-first (instance→answer-class); difficulty-conditioned; per-item threshold escalation; ε-insurance (ε ∈ {0.1, 0.25}); sequential-greedy; OPT-static and OPT-adaptive ceilings.
- Aggregators: naive; elimination-aware.
- Budgets: b ∈ {5, 10, 25, 50, 100}%.
- Anchors: no verification (self-consistency vote); full verification.

**Scale & compute.**
- *Pilot:* 2 datasets (GSM8K 500-instance fixed subsample; MATH-500) × 2 models (Qwen2.5-7B-Instruct; Llama-3.1-8B-Instruct) × N = 16 samples ≈ 64K generations (~40M tokens) + 64K short confidence elicitations. **~1–2 days on one A100/H100 with vLLM.** Oracle verification is a label lookup (free). All arms above are replays: the full policy × budget × aggregator grid costs CPU-minutes.
- *Stage 2 (post-pilot, likely post-deadline for parts):* + HumanEval+ (164) and MBPP+ (378) with held-out-test execution (CPU, negligible); N = 64 on the primary configuration (~10× pilot tokens ≈ 1–2 GPU-weeks or ~$1–3K API-class); PRM or synthetic noise sweep; math↔code policy transfer.
- Total pilot cost is the smallest in the B4 family — this is the "cheap re-ranking study" by construction.

**Go/no-go gates.**
- *Week 1 (50-instance dry run per model×dataset):* pre-screen pairs — keep only base accuracy ∈ [30%, 70%] and mode-share IQR > 0.2 (else the signal is degenerate and no allocation can differ from uniform; swap in MATH-500 levels 3–5 / MBPP+ as difficulty knobs). Also: hidden-twin literature sweep (Stage 3 critic) returns clean, or repositioning is invoked.
- *Week 2 (pilot pools complete):* (a) best signal AUROC lower CI > 0.55 on kept pairs — else NO-GO as a methods paper; pivot to the negative-result framing ("cheap signals cannot aim a verifier budget"), which the pre-registered falsification conditions make publishable at workshop/TMLR scale; (b) selective vs. uniform separation at b = 25% powered ≥80% for full-pilot n — else enlarge n (cheap) or NO-GO.
- *Week 3:* freeze analysis plan (families, tests, primary configuration); full replay grid + seed dispersion. *Weeks 4–5:* Stage-2 code-domain execution-verifier slice (HumanEval+/MBPP+ at N = 16 — small enough to pull forward) + writing. *Week 6:* polish, internal review.

**ICLR 2027 feasibility verdict (deadline Sep 25, 2026; today Aug 13 → ~6 weeks).** **GO.** The pilot + pulled-forward code slice fits comfortably: generation is 1–2 GPU-days, verification is free-to-cheap, and the entire scientific surface (policies × budgets × aggregators × signals) is post-hoc replay — the deadline risk is writing, not compute. The paper at deadline scope: problem formalization (trusted-scarce cell of the two-axis map), signal-AUROC + consensus-wrong diagnosis, budget–accuracy frontiers with static/sequential policies and both hindsight ceilings, aggregation ablation, oracle + execution verifiers, two model families, math + code. Deferred to camera-ready/journal extension: N = 64 scaling, PRM/noise sweep, full transfer matrix. Known vulnerabilities: single-scale models (7–8B) and the active-testing lineage question — both answerable in Limitations/Related Work, neither compute-bound. **Fallback venue:** ICML 2027 (abstract ~late Jan 2027; absorbs all Stage-2 deferrals) or TMLR (rolling; the [资源] framing — a replayable pool + policy-evaluation harness — fits TMLR's bar well). Unlike B4.1, there is no crowd-timing penalty to falling back: the complementary positioning holds regardless of when the stopping wave crests.

**Critic:** (1) The verdict's confidence rests on the frozen-pool trick, which is genuinely sound — but the week-1 pre-screen can fail on *all four* model×dataset pairs (models too strong for GSM8K is the known failure mode in 2026), and the mitigation ("difficulty knobs") is hand-waved; name the concrete fallback pairs now (MATH-500 L3–5 with the 7B models; MBPP+ full) and the decision rule if even those saturate (drop to a smaller/weaker model tier, which is scientifically fine — the problem statement is model-agnostic). (2) Pulling the code slice into week 4–5 doubles the surface just when writing starts; the deadline paper survives on math-only + oracle if needed — declare the code slice *droppable* and the math core *frozen*, so the scope decision under pressure is pre-made. (3) The negative-result pivot underestimates its own value: "uncertainty signals cannot aim a trusted verifier budget better than uniform" would contradict the working assumption of every escalation pipeline — if well-powered, that is a main-track finding, not a workshop note; the pivot framing should not concede venue prematurely. (4) Six weeks with zero slack for the hidden-twin repositioning path — if the week-1 sweep finds a direct prior, the differentiation experiments (sequential policy, transfer) move from optional to load-bearing, and *those* are the ones scheduled last; invert the replay order so sequential + ε-insurance run in week 3, not week 5. (5) No explicit artifact plan despite the [资源] label: the frozen pools + replay harness are the resource — releasing them must be a week-5 deliverable with the same priority as the paper text.

**Refined:** Pre-named difficulty ladder: {GSM8K, MATH-500 all, MATH-500 L3–5, MBPP+} × {Qwen2.5-7B, Llama-3.1-8B, and a weaker fallback tier (e.g., 3B-class) if all saturate} — the dry run walks the ladder until two pairs pass the pre-screen; model downgrade is documented as a design choice, not a concession.
