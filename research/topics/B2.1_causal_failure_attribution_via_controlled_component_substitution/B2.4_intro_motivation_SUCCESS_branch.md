## Motivation

LLM agents are deployed not to answer but to *act* — they call tools, query databases,
edit files, execute commands, and coordinate multi-step workflows. When such a run fails,
the operative question is **why**: a flawed plan, a wrong tool, a misread error, an early
stop. The answer is load-bearing because it drives what happens next — retry, repair,
escalate, fine-tune, or abandon.

Current failure-attribution pipelines answer it under a hidden assumption: **every failed
trace contains a culpable agent decision.** A single asymmetry breaks that assumption.
Whether a task admits *any* solution is fixed by its specification before any agent acts
and is certifiable by a mechanical check over the environment; attribution reads only the
post-hoc trace, in which the counterfactual that defines blame — the earliest step whose
correction would flip failure to success — **provably does not exist on an unsolvable
instance.** A required column may be dropped, a needed tool removed, a stated goal
contradicted by a stated constraint. Here the correct diagnosis is not "the agent failed"
but "the task was infeasible."

One might hope the fix is merely adding the missing word. **Our central result is that it
is not.** Even when the `unsolvable` outcome is made explicitly available, deployed
attribution pipelines falsely blame the agent on **[XX.X%]** of certified-unsolvable
instances — at or above our pre-registered 20% floor — and the error is *directional*:
false blame exceeds the reverse cop-out error by **[YY.Y pp]**. The bias is not a
vocabulary defect (the B0-a label-restricted control isolates that arithmetic separately,
at ≈ 1.0 by construction) but a *judgment* defect: given a trace full of repeated tool
errors, dead-end reasoning, and budget exhaustion, current attributors systematically
prefer a culprit to a verdict of impossibility. The consequence is operational and cuts
one way: impossible tasks burn retries, generate misleading debugging evidence, blame
components that behaved correctly, and — worst — feed *repair supervision*, teaching the
next generation of agents lessons extracted from failures no agent could have avoided.

The boundary is genuinely hard to observe from a failed trace alone: a competent agent
exhausting an impossible task and an incompetent agent botching a solvable one produce
superficially similar traces. Measuring the confusion therefore requires tasks whose
solvability is known *independently of agent behavior* — which motivates our central
design: matched solvable/unsolvable pairs in which infeasibility is injected by typed
mechanical mutation and certified by a script that checks the altered element is
*required* and admits *no substitute*, so that the measured false-blame rate is a
property of the attributor, never of the annotation.

## Introduction

When an autonomous LLM agent is handed a task — write a SQL query, book a flight through
a tool API, resolve a customer's account issue, run a build script — and the run ends
without success, automated debugging and monitoring systems ask one question: **what did
the agent do wrong?** Failure-attribution systems exist to answer it, localizing the
plan, tool call, or execution step responsible, and their verdicts increasingly drive
automated repair, retry, escalation, and the training data for the next agent. The
strongest current formulations make the target explicit: attribution identifies the
earliest agent step whose *counterfactual correction* would have flipped failure into
success \citep{who_when,agentracer}.

That definition presupposes a correcting step *exists*, and excludes a practically common
failure mode: the task may have been **infeasible before the agent ever acted** — a
required schema element absent, a necessary tool removed, a requested resource
nonexistent, a goal that contradicts the environment. The formulation-level arithmetic is
immediate and we confirm it as a control: an attributor with no `unsolvable` outcome
misattributes *every* certified-unsolvable instance by construction (B0-a, measured
[XX.X%] ≈ 1.0). The empirical question that arithmetic *cannot* answer — and the one this
paper measures — is whether the blind spot survives the obvious fix: **do attributors
falsely blame the agent even when "the task was infeasible" is an available verdict?** If
they do, the defect lives in how models read failure traces, not in the label space, and
no vocabulary patch will remove it.

Turning that question into a measured rate has been blocked by ground truth, not
modeling. A misattribution rate needs solvability labels independent of agent behavior,
and the two obvious sources disqualify: human labels do not scale to the pair counts a
rate estimate needs, and the agent's own failure is circular — it defines "unsolvable" as
"whatever the agent did not solve," the exact conflation under study. Ground truth must
come from the task specification alone; the soundness of that certification is the
load-bearing assumption of the study, and we defend it with a leakage audit and an
adversarial oracle-falsification gate before any rate is reported.

Prior work touches parts of this problem without isolating it. Attribution benchmarks
\citep{who_when,agentracer,elephant} assume the task is solvable and the trace holds a
decisive error; failure taxonomies \citep{mast} catalog *how* systems fail without
mechanically certified task-level infeasibility; refusal-and-calibration work treats
abstention as a property of *model knowledge*, not an external environment. Two recent
benchmarks come closest and are worth conceding precisely. APB \citep{apb} injects
broken-tool and unsolvable tasks but reports the *acting agent's* calibrated-refusal
rates, validated by LLM-judge plus human review — it never asks whether a *third-party
attributor* misdiagnoses an already-failed trace. Rigorous-benchmark guidance \citep{abc}
certifies each task *is solvable* as a quality gate — the mirror image of our move: we
certify *unsolvability* by script and keep it as a first-class measured condition. No
prior testbed dissociates *unsolvable-for-anyone* from *unsolved-by-this-agent* by
construction, which is the one dissociation the question requires.

We construct matched pairs differing only by a typed mechanical mutation — remove a
required schema element, delete a necessary tool, eliminate an environment resource,
contradict a task constraint. The solvable member retains a passing reference solution;
the unsolvable member is certified by an oracle script verifying the altered element is
*required* and admits *no substitute* (schema-graph unreachability for SQL,
tool-signature non-coverage for function calling, an environment-state assertion for
stateful tasks). Every pair passes a leakage audit — a text-only probe (AUROC **[EE]**,
below the pre-registered 0.60 gate), surface-statistic matching, and a two-rater human
check — so no measured rate is an artifact of detecting the mutation rather than
reasoning about feasibility.

Over this instrument we report three quantities, all on attributors **equipped with the
`unsolvable` outcome**. Across **[N]** matched pairs spanning **[D]** domains, **[K]**
backbones, and **[M]** attribution strategies, the **false-blame rate** on
certified-unsolvable instances is **[XX.X%]** (pair-clustered bootstrap CI
[PLACEHOLDER]) — at or above the pre-registered 20% floor — and it exceeds the reverse
**cop-out rate** (labeling a failed-but-solvable task `unsolvable`) by **[YY.Y pp]**: a
*directional* over-blame bias, not symmetric confusion. The bias is not an information
ceiling of the trace: an oracle-calibrated ceiling probe, trained on the certified label
but evaluated only on held-out pairs, reaches **[AUROC = CC]** while the best deployed
strategy reaches **[DD]**; per the pre-registered three-branch rule this locates the gap
in **[attribution design / an information ceiling / INCONCLUSIVE]**. A secondary,
exploratory localization (logistic regression on domain, operator type, and agent
family; not a pre-registered directional hypothesis) reports where over-blame
concentrates. The risk–coverage analysis gives the practical operating rule: the
`unsolvable` verdict is precise enough to gate retries only above confidence **[C*]**.

This paper makes four contributions:

1. **Unsolvability as a missing attribution outcome — and the demonstration that adding
   the label does not close the gap.** The label-restricted control confirms the
   formulation-level arithmetic (FBR ≈ 1.0 by construction); the headline shows deployed
   pipelines *given* the outcome still falsely blame the agent on **[XX.X%]** of
   certified-unsolvable tasks, so the blind spot is a judgment defect, not a vocabulary
   defect.
2. **A mechanically certified paired-task instrument.** Solvable/unsolvable pairs whose
   ground truth is a script-certified *required-and-no-substitute* oracle — not human or
   LLM judgment — gated by a pre-registered leakage audit (text-only AUROC **[EE]** <
   0.60 per domain), enabling measurement that never relies circularly on agent behavior.
3. **A directional misattribution estimand.** FBR (**[XX.X%]**) and its directional gap
   over CoR (**[YY.Y pp]**) across domains, backbones, and strategies with pair-clustered
   bootstrap CIs — an error an aggregate refusal rate cannot capture, and the quantity
   that determines whether infeasible tasks corrupt repair supervision.
4. **The calibration boundary of infeasibility attribution.** Per-domain risk–coverage
   curves plus the ceiling-probe control dissociating design-limited from
   information-limited failure — showing the trace *contains* the signal (**[CC]**) that
   deployed strategies fail to extract (**[DD]**).

As agents move into more complex environments, some failures come not from bad reasoning
but from impossible specifications. Our measurement shows the field cannot fix this by
adding a label: recognizing infeasibility as a first-class, *calibrated* outcome requires
changing how attributors weigh trace evidence against task specifications — and the
released instrument is the yardstick for whether any proposed change works.
