## Stage 2 — Related Work

**STAGE 2 VERDICT: REVISE** *(fired, fixed — see below)*

**Why, quoting the first assembled draft:** The four thematic paragraphs are genuinely threaded (each ends on a problem-tied limitation, not a generic one — e.g. "Coeditor's multi-round conditioning is an assistance mechanism for a single commit, not a longitudinal quality measurement"), which clears the citation-dump failure mode, and a nearest-neighbor sentence was present from the first draft (built in from the assembly rules, not a finding of this review). The actual problem was in that same opening paragraph's *framing*, not its presence: the first assembled draft read, "Coding-agent evaluation and software architecture erosion have developed as separate literatures — the former scoring patches by test outcome, the latter studying human-driven structural decay — and no work has yet connected the two to ask whether test-gated agent edits erode architecture the way unmanaged human edits do." That sentence is Bridge-Opportunity-shaped by the `research-taste-auditor`'s own taxonomy — "developed as separate literatures... no work has yet connected the two" is close to a textbook instance of the pattern `taste_audit.md` explicitly verified this idea does **not** rely on (Verdict condition 1: Opportunity = Bridge Opportunity AND Method = Synthesis/Unification — both independently checked "No" against the Stage 2/5 wording). Leaving this sentence in Related Work would not change the taxonomy label of the *paper's own* Motivation/Method (which the audit correctly scored), but it would hand a reviewer a one-sentence quote that reads exactly like the overrepresented LLM template the audit was run to rule out — a self-inflicted inconsistency between what this pipeline's own taste audit certified and what its Related Work section actually says.

**THE ONE FIX (applied):** Replace the "developed as separate literatures... no work has yet connected the two" framing with a positioning statement about the specific missing *instrument*, not a bridging move: "The closest prior work to this study sits on two different sides of the gap being measured, and it is worth naming both plainly... Between them sits exactly the instrument this paper builds: SWE-bench's acceptance protocol, held fixed, applied to the population Sas et al.'s question was never asked of." This keeps the nearest-neighbor naming (SWE-bench and Sas et al., 2021 — the closest works on the acceptance-protocol side and the erosion-measurement side respectively) but reframes the gap as a missing measurement instrument for an unstudied population, consistent with the Evidence-Gap-primary / Failure-Risk-Gap-secondary label the taste audit assigned, not a Bridge-Opportunity label it explicitly ruled out.

## Stage 4 — "Experiments" (Analysis/Finding variant: falsification, not correlation)

**STAGE 4 VERDICT: REVISE** *(fired, fixed — see below)*

**Why, quoting the first assembled draft:** The central question this stage asks in every archetype — is the claimed cause isolated from its strongest alternative — is well-served structurally: RQ3 is a genuine falsification design for the counterfactual's necessity (showing at least one trajectory pair where within-arm drift alone would have been misleading), and RQ2's Falsification condition explicitly folds in the single-shot control as the alternative-explanation check ("erosion is per-patch additive, not sequence-amplified"). Every RQ in the first assembled draft already carried an explicit Falsification condition line, not just an Expected outcome — that requirement was built into the assembly from the start and is not this review's finding. The actual gap surfaced on closer reading of RQ4 (trend-test agreement): its first-draft Setup read only "Among trajectories flagged by either the mixed-effects slope estimate or the per-trajectory Mann-Kendall test as showing any drift, compare the sign of the two readings," with an Expected outcome of "agreement in at least 80% of qualifying trajectories" — but the qualifying set ("trajectories showing any drift") is not the scale-up's fixed 54-trajectory total, it is a conditional subset whose size depends on whether RQ2 finds any drift at all. As drafted, the 80% target had no stated minimum qualifying-N, so if few or zero trajectories show drift (a live possibility — RQ2's own Falsification condition allows for exactly that outcome), RQ4 would either be vacuously satisfied or badly underpowered without the draft ever saying so. Per the mined-review stochasticity check ("repeated runs, seed control, variance measures... directly aligned with `sample_size_rationale`"), an RQ whose qualifying sample size is left unstated and can silently collapse to near-zero is the same failure mode as an uncovered claim, just hidden one level down in the conditioning.

**THE ONE FIX (applied):** Add an explicit sample-size contingency to RQ4's Setup: a stated minimum qualifying-trajectory count (10) below which the 80% target is reported as inconclusive rather than refuted or confirmed, and the qualifying-set size is reported alongside every result from that RQ (both `paper_draft.md` and `paper_draft.tex`).
